# A790: separate dashboard printers and when to remember a choice

E is agreed: a dashboard without a device profile remembers separate Receipt and Invoice
printers for each sale venue in this browser. Harbour's Receipt uses Bar receipt while
Invoice uses Office · A4. Changing Invoice leaves Receipt alone, and Hillside has its own
choices. Memory does not grant permission. Dashboard B keeps every active printer at the
sale's venue, including A4 and portable printers, for both document choices.

F is the sole next owner question. Should this browser remember a selected printer only
after the server accepts its print request (recommended), or immediately on selection,
even when you cancel the form?

With Bar receipt remembered for Harbour's F/1042, select Patio receipt, then Cancel.
Reopening Receipt suggests Bar under the recommendation, Patio under the alternative.
Recommend acceptance so abandoning the form leaves the earlier preference alone. An
accepted request would remember Patio even if paper later fails. A refusal would leave
the memory alone; an unknown response needs reconciliation of that same request.
Acceptance is not proof of paper. The final named print press remains required; selecting,
folding or reading never prints. The diagrams compare choices and are labelled “Example
only”; that label is not a proposed product action.

Neither proposal changes the phone's one Equipment setting or A796's decided handling.
Storage, expiry/reset, login sharing, first-use/unavailable fallback, general sole/zero
behavior, concurrent/late-intent ordering, device invoice memory and portable receipt-holder
enforcement remain open. The complete design, plan and build remain unapproved.

inside each drawing. These are static discussion drawings, with no product, accessibility,
hardware or legal evidence. Prior boards remain history where superseded.
