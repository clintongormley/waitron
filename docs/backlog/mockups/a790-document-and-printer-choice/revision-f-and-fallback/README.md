# A790: accepted print requests and a sole available printer

F is agreed: on the dashboard without a device profile, remember a printer only after
the server accepts its print request. Cancel and refusal leave the earlier choice alone;
later paper failure does not undo an accepted choice. An unknown response needs
reconciliation of the same request. E still separates Receipt and Invoice for every
sale venue in this browser. Phone Equipment follows A796 unchanged.

G is the sole next question, a proposal only: when opening a form with no usable remembered
printer and only one eligible printer, preselect it (recommended), or leave the choice
empty until you select it? Example: Harbour F/1042 Receipt remembers Bar receipt, now
disabled; Patio receipt is the only eligible printer. The recommendation shows Patio and
explains that Bar is unavailable. Both alternatives require the named final print action,
for example Print a copy on Patio receipt when the server designates a copy. Neither prints
or updates memory just because a choice is shown or selected. First use is the same
no-memory case. Changing an open form or rerouting a submitted request is outside G.

With several options, asking you to choose is proposed; with zero options, explaining the
problem and offering Retry is a builder proposal. Neither is approved by F. Storage,
expiry/reset, login sharing, concurrent/late memory updates, device Invoice memory and
portable receipt-holder enforcement remain open. The complete design, plan and build
remain unapproved.

Eight PNG/SVG pairs cover English/Spanish, light/dark and 390/1280 px. Final PNGs were
rendered in headless Chromium and visually inspected; native SVG text boxes were checked
inside each drawing. These static discussion drawings provide no product, accessibility,
hardware or legal evidence. “Example only” buttons label the illustration, not a proposed
product action. Prior drawings remain historical where superseded.
