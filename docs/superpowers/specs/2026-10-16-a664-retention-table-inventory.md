Use the [design’s policy definitions](2026-10-16-a664-data-retention-design.md#use-explicit-policies-and-small-evidence-groups) for C1/C2 clocks, holds, copy expiry and blocked protected removal. Legal/external claims belong to the [source register](../../compliance/research/2026-10-16-a664-retention.md). Every row below is a **DRIVER PROPOSAL**, not a finding that its deletion is permitted. `ledger`, `state` and `local` describe module classification; **appendOnly is a separate bit**. Rows are grouped by classification so a protected state table cannot be mistaken for disposable state.

All dependency/trigger descriptions are **source-reading-only constraints, behaviour unrun**. Outgoing keys include their declared delete action; incoming keys list the referring columns. Cascade is a dependency requiring review, never automatic deletion authority. “None declared” does not mean no consumer exists. Non-FK notes identify known review targets, not an exhaustive semantic dependency graph. Every row additionally requires inspection of all payloads, trigger bodies, consumers, transfer descriptors, media and copies before implementation. The design’s retained-hardware rule overrides a generic deactivation clock: retained registrations and required reactivation proof remain current until explicit deletion/retirement. See `CLAUDE.md:351` and `docs/developers/conventions-ui.md:648` for that existing contract; no runtime reactivation experiment ran here. Candidate personal fields are examples; the original research filter omitted some telephone, document, detail and actor fields, so it is not a privacy-field classifier.
