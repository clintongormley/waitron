# Customer menu public access

Proposal for Lane K, Lane G and the watcher. Customers can open, share or embed a published menu at
one venue HTTPS address that follows the serving box. Cloud checks Connected or Hosted eligibility,
including trials. The work starts on test installations. Waitron’s tunnel configuration and staff
listener currently exclude production. [Product design](2026-11-24-customer-menu-design.md#delivery), [box configuration](../../../apps/server/src/cloud-tunnel.ts), [listener startup](../../../apps/server/src/boot.ts)

| Decision | Proposed contract and who settles it |
| --- | --- |
| Serving box | **G + K.** The owner-confirmed local replacement binds the venue and both installations, revokes the old installation and moves the venue’s placement to the successor’s peer. Cloud returns while the new remote configuration is still provisioning. Reuse the placement and signed gateway manifest for routing. Before admitting menus, confirm withdrawal of the old box’s authority, stop serving its cached replies and verify that the successor’s customer listener answers. The successor uses its own registered peer and certificate. Customers see “Try again shortly” during the gap. A signed route can last up to ten minutes. For hosted emergency replacement, use the agreed `emergency-copy-confirm` result, which requires verified source withdrawal. The Cloud endpoints and hosted handback are dependencies for that path. [Local replacement](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/packages/backups/src/replacement.ts#L114-L143), [manifest lifetime](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/packages/remote-access/src/manifest.ts#L24-L26), [hosted agreement](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/docs/waitron-integration-contract.md#agreed-part-4-confirmation-18-november-2026) |
| HTTPS and tunnel | **K + G.** Use the serving box’s staff certificate on a second socket. Cloud checks that certificate with the staff hostname as TLS server name and upstream Host. It terminates public TLS on the assigned or custom host, which the box reads from the authenticated service configuration for links. Match the requested hostname to the TLS name and current signed route. Agree an optional customer destination and capability alongside the staff destination. A mixed pair serves staff and keeps the customer route closed until both ends support it. Cap customer connections before the tunnel forks its forwarder. Check that a customer forwarder failure leaves staff access working and that public traffic within the caps leaves room for staff. |
| Reads and preview | **K + G.** Pin exact GET and HEAD paths and query rules from piece 3. The box independently checks serving state and admits only the published view’s pages, data, exact photo renditions and listed fonts and app files. Prepare the view per language and refresh it on publication or relevant settings changes. Photo reads stay off the venue write lock and away from the till’s rendition queue. Preview and its assets stay on the signed-in staff listener. |
| Online status | **K + G.** Make the existing tunnel switch’s effect visible on the Online tab and warn before turning it off. Use the service view to distinguish ineligible, disconnected and ready for customers. The manager gets the reason and a next step when the tab withholds the link and QR code. |
| Cache and framing | **G + K.** The current availability gate sends `no-store` and prevents framing. Add a menu-specific policy. Before answering any request, including a cache hit, check current entitlement, the venue’s block and serving route. Key cached pages and data by venue, current route authority and language-bearing URL. Respect the box’s headers and pass cache age on, for about one minute total. Off or missing returns 404. Cache neither refusals nor the temporary 503 page. Use one-year content-named assets and verify assets named by a fresh cached page across upgrade and takeover. A visitor’s cache can still hold previously public assets after removal. Allow framing on menu pages at both ends. [Current gate](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/packages/remote-access/src/public-gate.ts#L48-L129) |
| Limits and privacy | **G + K.** Reuse the gate’s bounded forwarding, refusal handling and counters. Its current availability policy requires a browser cookie and has limits of 120 requests per source bucket per minute, 64 concurrent forwards, five seconds of upstream socket inactivity and 64 KiB per upstream response. Agree menu-specific bounds that carry photos and keep ordinary opens, embeds and link previews cookie-free. Keep short-lived source counters in memory and IP addresses out of logs. Count customer traffic separately from staff traffic and trial-extension usage. Use rate refusals under load. K caps total box work. [Current gate](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/packages/remote-access/src/public-gate.ts#L48-L129) |
| Hosted retirement | **G, then K.** Waitron stopped sending in #4266. Preserve the Cloud account owner’s venue-wide block and enforce it on live and cached reads before retiring the old reader, stored publications and copy-specific controls. Agree who can exercise a Cloud staff block. Check Connected or Hosted eligibility, including trials, on live reads and route issuance before removing the check on copy publishing. Today `/m/<venue>` can serve the last saved menu while the box is offline. Retirement removes that address, so the watcher still needs to settle the earlier offline-copy direction. Both lanes remove the three signed copy actions after Cloud has retired them. Managers switch off individual live menus in Waitron. [Existing block](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/packages/remote-access/src/guest-menu.ts#L11-L57), [owner check](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/packages/account-http/src/guest-menu.ts#L12-L28), [offline-copy direction](https://github.com/waitron-io/waitron-cloud/blob/a11928c75b101bbca7b7b7eaa4b7da06c75388a1/docs/backlog/guest-menu.md#live-forwarding-belongs-to-online-ordering-waitron-a509) |

Before implementation, agree how Cloud observes local source withdrawal and successor readiness,
the tunnel and Online status fields, exact routes and bounds, and the Cloud staff block. Settle the
offline-copy question before retiring the hosted reader. K tests listener isolation, preview and
media admission. G tests entitlement, routing, caching, embedding, limits, accounting and copy
retirement. Qualify the pair over real HTTPS with warm caches through publish, disable, republish,
takeover and outage. Check a warm cache after a block, eligibility change and withdrawal of the old
route. Flood the customer path while timing sales and loading till images. Production enablement
follows the existing remote-access gates.
