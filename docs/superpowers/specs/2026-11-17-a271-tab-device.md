**Dev first:** select the existing seeded device explicitly, keeping dev's existing id override. Every tab-auth request carries its marker even before a device is selected. A missing/invalid credential never borrows another tab's cookie. After a dev tab joins, retain the returned join id as its explicit dev device id. Issue no device proof. No adopt route, secret rotation or enrollment-permission change.

**Sign-in:** retain each tab's session token in memory and the existing person header. Reload locks again, as today. Keep the existing dev device id in sessionStorage, with memory fallback if storage is blocked. Closing a tab does not delete rows or revoke sessions. Duplicated/restored tabs may remain the same device, unsigned-in; no tab registry or coordination.

**Boundary:** accept the new tab transport only in dev; refuse its headers elsewhere. Reuse existing hash checks, revocation, device/session binding, origin checks and approved enrollment. Only explicit tab login responses return session secrets, marked no-store; never logs or URLs. Normal appliances keep cookies.

**Appliances:** a Demo or Live venue on a real box keeps one paired device per browser. No non-dev tab mode, device-proof issuing or extra pairing workflow.
