## Proposed behavior

Fresh Demo/dev tabs default to tab authentication. Each enrolment receives its own existing-format
`id.token` device proof. Reload retains that proof in sessionStorage; sign-in uses an in-memory
session token, so reload locks again. Device proof lasts for sessionStorage's lifetime; closing
does not delete device rows or revoke server sessions. Keep the existing per-tab person check.

Tab requests carry `x-waitron-tab: 1`, `x-waitron-device` and `x-waitron-session` proofs.
Missing or invalid proofs never fall back to cookies. Join and PIN responses return secrets only
to explicit tab requests, without setting cookies. Reuse server token hashes, revocation and
device/session binding; never log secrets or put them in URLs. Normal appliances retain cookies.
Common proof transport works in all modes; only Demo/dev automatically select it, avoiding
separate authentication implementations. Demo retains existing pairing approval requirements.

## Clearance decisions

Propose dev-only seeded-device adoption minting a replacement proof and ending that device's
sessions. Watcher must clear this visible consequence and the reload-lock choice. Independent
duplicate-tab/browser-restore behavior is not promised; ask the watcher if required. No tables, tab registry,
cross-tab coordination or enrolment-permission expansion.
