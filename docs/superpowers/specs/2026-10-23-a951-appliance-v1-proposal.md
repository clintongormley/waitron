## 1. Closed encoding and types

`J(x)` is the exact compact JSON spelling specified here, encoded as UTF-8, without BOM, whitespace or trailing LF. Object member order is the order in each definition/table; arrays retain the stated positional order, never sorted on receipt. Strings are printable ASCII, encoded literally except `"` and `\`, which use their two-character JSON escapes. No `\/`, `\u` or alternate escape spelling is canonical. Protocol strings contain no controls. Nested JSON body/lease strings therefore escape their quotation marks and backslashes exactly once per enclosing JSON string. Numeric values are unsigned safe integers in ordinary decimal, with no exponent, fraction, leading zero or negative zero. Compare input to `J(parsed)` after duplicate-aware parsing; JSON parsing alone is insufficient.

Reject invalid UTF-8, BOM, duplicate or unknown members, missing members, surplus array elements, wrong order, noncanonical spellings, trailing bytes, coercions and unsupported versions before requested effects or floor changes. Only explicit unions permit null. `N=0..9007199254740991`; `U=1..9007199254740991`; `H=32` lowercase hex; `D=64` lowercase hex; `I=[a-z0-9][a-z0-9-]{0,63}`. `UUID` is lowercase canonical `8-4-4-4-12` hex. `T=N` Unix milliseconds, not ISO dates. `E={"payload":base64url,"signature":base64url}` in that order; both unpadded and round-trip canonical; signatures decode to exactly 64 bytes, encoded length 86. Signed bytes are the decoded payload bytes, never the base64 characters or reserialized outer envelope.

`S=[staff,publicUpstream,probe]` is a three-element array of `U` stop generations. `W` has the same shape for withdrawal generations. `F={"installationRevision":N,"contentRevision":N,"contentDigest":D|null,"grantSequence":N,"requestSequence":N,"reportSequence":N,"trustRevision":N,"trustHistoryDigest":D|null,"epochOrdinal":N,"stops":S,"withdrawals":W}` in precisely that order. Null contentDigest is allowed only with contentRevision=0 in explicit pre-establishment state. Null trustHistoryDigest is allowed only with trustRevision=0 in that explicit state; established trust always names a complete history. Counter exhaustion closes remote admission and requires a new accepted protocol; no wrap or reset.

`B={"originId":I,"environment":"test"|"production","cloudVenue":UUID,"installation":UUID,"localVenue":I,"node":H,"machineIdentity":D,"target":I,"establishmentEpoch":I,"placementEpoch":I}` in that order. This deliberately narrows helper `I` for Cloud UUIDs and machine identity, without changing helper types. `machineIdentity=SHA256(machine Ed25519 SPKI DER)` in lowercase hex. The provisioned origin registry binds originId to one exact HTTPS origin (at most 256 ASCII bytes, no trailing slash/path/query/userinfo). No reply replaces that origin or its TLS trust. Development/preproduction maps to test, production to production by the locally verified registration mapping, never a response spelling. `fixture` is allowed only by a separate injected fixture constructor, never the live decoder.

A local UUID node maps to H by removing its four hyphens, reversibly; an already-H node is unchanged. Any other node spelling needs an explicit mapping amendment before use. The authenticated establishment record binds the actual local venue/node mapping; text resemblance is insufficient. B.target is the endpoint ID, not a hostname, cell or writer grant. B.establishmentEpoch is the current establishment/recovery epoch ID, while the independent increasing epochOrdinal orders those IDs. Epoch IDs are opaque I strings; never compare them lexically. PlacementEpoch remains a string as in helper/routing. V1 never changes it. Cell is a separate I below, not an epoch counter.

## 2. Exact request actions and authentication

All seven proposed actions use POST at `/api/installations/` plus the exact action string below, no query, redirect, browser Origin, cookie or bearer credential. Use the configured trusted HTTPS origin, JSON content type and identity encoding, with no compression. HTTP TLS trust, machine authentication, signed response trust and current Waitron authority are separate checks. The action allowlist extension is new proposed Cloud work, not a claim that these actions exist.

Machine payload bytes remain `J(["waitron-cloud-machine-v1",origin,action,installationId,operationId,issuedAt,lease,body])`. `operationId:UUID`; `issuedAt:T`; `lease` and `body` are strings. Lease is the exact compact saved control envelope E encoded as a string; body is exact J(Q), also a string. Sign with the stored installation Ed25519 private key. E is the sole outer HTTP object. Cloud verifies the stored machine key and current lease's origin/installation/venue/environment/public key, revocation and proof time before using claims. Retain the existing 60,000 ms proof window and at-most-3,600,000 ms control lease; neither confers transport or writer authority. Renew the lease through the existing serialized installation client; never hold its lock or a database transaction over a network/helper wait.

Every Q has ordered prefix `{"version":1,"requestSequence":U,"binding":B,"epochOrdinal":U,"boot":H,"nonce":H}` followed by exactly the action-specific fields below in listed order. Boot is local boot identity, nonce is fresh request correlation. One outstanding new appliance operation per installation; retries retain Q and operationId, but may refresh proof issuedAt/lease. RequestSequence is a separate anti-replay floor, never one of the three content/grant counters. All repeated bindings, counters and digests in Q, R, C, grant, Permit and Report must agree exactly with their defined current/next-epoch roles. First/recovery requests obtain their next sequence from the explicit permit; they never infer it from an absent file.

All ordinary actions may instead return `R=["refused",code]` or `["unavailable"]`. Closed codes are `invalid_schema,unsupported_version,unauthenticated,untrusted_key,wrong_purpose,wrong_binding,stale_counter,replay_conflict,content_conflict,expired,clock_untrusted,stopped,unsupported_topology,unaccepted_dependency,busy,safety_missing,recovery_required,permit_conflict,state_unavailable`. No input echoes, arbitrary errors or executable text. Transport failures/non-JSON bodies are unavailable observations, never signed success. HTTP 400/401/403/408/409/413/415/429/503 retain their actual cause; a 401 permits one lease reconciliation only, not a size/revision workaround. Installation revocation closes all remote scopes and retires that identity; do not automatically re-register it.

Cloud durably binds requestSequence to action, operationId and exact Q digest before minting a grant or committing a result. Retain eight complete operation results plus permanent sequence floors for the installation lifecycle. At a retained sequence, identical operation/action/Q recovers the same R; differing bytes/ID/action conflict. Older evicted sequences refuse as stale, never new work. Higher sequences may skip values but never reuse them. Unresolved operations block ordinary new mutations except the exact superseding-fetch transition below; status/trust inspection and safety closure remain possible. An exact retained report replay may recover from the separate report ledger even after request-cache eviction; it cannot mint a grant or move a floor. A fresh status Q uses a fresh operation UUID/sequence. No unbounded UUID ledger is promised.

A fetch acquires transport intent but performs no helper, listener, writer or fiscal effect. Keep one durable latest-fetch slot per installation, independent of the eight-entry request cache: exact operation UUID, request sequence/digest, binding/epoch, issuance floors and saved result. Retain it until a later fetch atomically replaces it, even after its signed response expires. `FetchRef` is exactly `[operationId:UUID,requestSequence:U,requestDigest:D]`. The first fetch in an authenticated epoch uses null; every later fetch supplies the latest slot's exact FetchRef. A mismatching reference conflicts; a missing established slot requires authenticated recovery, never a guessed first fetch.

A higher-sequence fetch with that exact predecessor may supersede an unanswered fetch. Cloud serializes it against the saved slot and issuance ledger, preserves every floor, and durably saves the new slot plus a strictly higher grant sequence before replying. It cannot supersede report, establishment, recovery or reconnect work. An older fetch arriving afterwards refuses by the request floor. The box saves the supersession intent before sending, accepts only the new request correlation and preserves the predecessor's immutable grant/expiry and counter floors until the newer result is validated. It must not apply both results or extend the old deadline. A delayed old response cannot replace the new pending request. Fresh response signatures cannot extend a saved grant. This bounded transition resolves fetch reply loss without human approval or an unbounded operation ledger.

## 3. Signed responses, grant domain and trust custody

Ordinary response signed bytes are exactly `J(["waitron-a951-response-v1",origin,issuerKeyId:D,action,installationId,operationId,requestDigest:D,issuedMs:T,expiresMs:T,R])`. `requestDigest=SHA256(ASCII("waitron-a951-request-body-v1\n") || UTF8(body))`, where `\n` denotes one LF byte only in domain-prefix notation. Responses use E. Verify signature, expected action/operation/body digest, configured origin, installation, issuer purpose, trust validity and clock before interpreting R. Responses live at most 60,000 ms; accepted issued time is at most 30,000 ms in the future and expires must exceed trusted wall+30,000. Exact request retries may return an expired saved response. A fetch uses the explicit superseding-fetch transition; a report uses report-status; establish/recover/reconnect retain the current Permit/result and require a fresh explicitly authorized recovery correlation if their result can no longer be authenticated. Never extend any saved response or grant locally. No response signature implies kernel apply or current writer authority.

Grant signed bytes are exactly `J(["waitron-a951-grant-v1",origin,issuerKeyId:D,B,cell:I,installationRevision:U,contentRevision:U,contentDigest:D,grantSequence:U,issuedMs:T,expiresMs:T])`, wrapped in E. Bind every field to the candidate, current registration and safety epoch. Its content digest binds endpoint, target, addresses, names, purpose mapping, peer and gateway; those bindings are not replaced by a gateway manifest. Require `0 < expiresMs-issuedMs <= 600000`, `issuedMs <= trustedWallMs+30000` and `expiresMs > trustedWallMs+30000`; no expiry grace or lease-derived extension. Grant issuer and response issuer are different keys/purposes, even when both are operated by Cloud.

Provision a distinct A951 offline root public key and origin/environment binding through authenticated local installation policy before first establishment. It is not an arbitrary key received in configuration, a TLS certificate, the machine key, staff issuer or existing lease issuer. `issuerKeyId=SHA256(Ed25519 SPKI DER)`; public keys are canonical unpadded base64url DER, Ed25519 only, at most 128 encoded characters. A root cannot be changed by an appliance reply; root replacement needs separately authenticated local provisioning preserving safety/trust floors, otherwise admission stays closed.

Trust signed bytes: `J(["waitron-a951-trust-v1",origin,originId:I,environment,rootKeyId:D,trustRevision:U,issuedMs:T,expiresMs:T,keys])`. `keys` is at most eight entries in ascending keyId ASCII order, each `[keyId:D,purpose,spkiBase64url,notBeforeMs:T,notAfterMs:T,state]`; purpose exactly `response|grant|recovery`, state `active|revoked`. No repeated IDs or SPKI across purposes; a revoked entry cannot become active again. Root signs this payload as E. Persist at most 256 lifetime seen-key identities and permanent retired/revoked tombstones in safety; omission from a newer bundle retires a previously seen key. Reintroduction is refused. Never evict tombstones to admit another key; exhaustion closes pending an accepted protocol amendment. Response keys sign ordinary fetch/report/status results; recovery keys sign establish/recover/reconnect results under the response domain. Appliance-trust returns only this root envelope. A root-signed bundle is installable only for the exact configured origin/environment, at an increasing trustRevision or identical bytes at the same revision.

The complete local trust history is ordered `{"version":1,"originId":I,"environment":"test"|"production","rootKeyId":D,"throughTrustRevision":U,"entries":Entries}`. Entries is an array of at most 256 `[keyId:D,spkiDigest:D,purpose,firstSeenRevision:U,lastSeenRevision:U,state]` records, sorted by keyId, with state `active|retired|revoked`. SPKI digest equals keyId for this encoding. Purpose is immutable; revoked dominates retired, which dominates active. Hash exact J(history) as trustHistoryDigest. This local record is constructed only by the independent verifier after validating root-signed Trust bundles; it is not accepted from a machine reply. Persist complete copies and their digest/generation in app safety and the independently root-owned verifier/supervisor safety stores before accepting the corresponding Trust revision. A crash between stores closes admission until their history is reconciled; no copy may be silently reset.

Recovery requires at least one complete authenticated surviving history from those independently protected stores, bound to the original origin/root and consistent with every surviving higher history floor. Merge all surviving seen-key sets, take minimum firstSeenRevision and maximum lastSeenRevision/throughTrustRevision, preserve every retired/revoked state, reject purpose conflicts and take the most restrictive state for each key. Reject a current Trust bundle that reintroduces any resulting tombstone. A recovery response only binds the locally verified resulting digest in F; it cannot supply or replace history. If completeness at a known higher revision cannot be established, any surviving digest disagrees without a verified transition, or no complete history survives, return recovery_required with remote admission closed. A newer trustRevision, current root-signed bundle or Cloud recovery signature alone cannot reconstruct omitted history. No tombstone is evicted to make recovery fit its bound.

Trust bundle lifetime is at most 86,400,000 ms; key validity at most 2,592,000,000 ms (30 days); at most two active keys per purpose, with overlapping validity at most 600,000 ms. Publish the successor before overlap; after overlap reject the predecessor even on saved grants/responses. Revocation acts when a higher root-signed bundle is validated and durably saved: close affected grants/paths within 1,000 ms, discard late responses and invalidate verifier evidence. Expired/missing trust closes remote scopes. Ordinary configuration cannot un-revoke a key, add trust, or preserve access with a cached signature. During partition, bounded trust/grant/observation expiry applies; no claim of instantaneous unseen revocation. Track trust, control reachability, transport validity and current authority independently. Trust rotation alone changes no content or CSR digest, unless its certificate-specific purpose policy changes separately.

## 4. Stable content and counter meaning

C is exactly this ordered object: `{"version":1,"binding":B,"cell":I,"gatewayId":I,"authorityTargetRef":I,"authorityBindingRef":D,"peerRef":D,"box4":IPv4/32,"gateway4":IPv4/32,"endpoint4":IPv4,"ports":[51821,51820,9443,9444,9445],"services":Services,"names":Names,"manifest":Manifest,"certificates":Certificates}`. Services is a unique ordered subset of `["staff","public-upstream","probe"]`. IPv4 uses dotted decimal without leading zeroes; prefixes exactly /32. Refuse IPv6/mapped forms, default/LAN/cross-venue routes and endpoint roaming. Ports are fixed positionally as box UDP, gateway UDP, staff TCP, public-upstream TCP, probe TCP. No message supplies an executable, command, path, raw private/public peer key, provider credential or arbitrary route.

Names is exactly `{"staff":Hostname,"publicHost":Hostname,"upstreamSni":Hostname,"upstreamHost":Hostname}`. Hostname is lowercase ASCII DNS labels, each 1–63 bytes, total 1–253 bytes, at least two labels, no wildcard, trailing dot, port or IP literal; hyphens only internally. Staff must differ from public/upstream; publicHost may differ from upstreamSni/Host only by this exact mapping. Manifest is exactly `{"schema":"waitron-a951-routing-v1","revision":"proposal-2026-10-23.1","digest":"271fefd892b2c0f10ffab42f8e4a832a163b244733285f08d5a0ea1dfab1b012"}`. Certificates is ordered `[staffPolicy,publicPolicy]`, each `[purpose,issuerPolicyRef:D,keyPurpose:I]`, with purpose `staff` then `public-upstream`, keyPurpose `staff-tls` then `public-upstream-tls`. Policy references resolve only in locally authenticated policy. For public-upstream, an unresolved G4 policy leaves the path closed, not a fictitious issuer. `peerRef` similarly resolves a preprovisioned gateway public-peer registry record bound to B/cell/gateway/addresses/endpoint and the locally retained box WireGuard public identity. The registry may contain public keys; the appliance message contains only its D reference. Unknown registry references refuse. Registry distribution/update is an explicit G1/T3 deployment-policy dependency, not an authority supplied by the helper fixture.

`contentDigest=SHA256(ASCII("waitron-a951-content-v1\n") || J(C))`. C contains no own digest, installation/content/grant counter, signature, report, expiry or document-source SHA. Saved canonical C bytes are the content boundary; signing envelopes and changing grant times do not change it. InstallationRevision and contentRevision are authenticated separately in both response and grant.

## 5. Relevant certificate bindings, without widening staff v1

For purpose P define projection bytes `J(["waitron-a951-certificate-binding-v1",P,origin,B,authorityTargetRef,authorityBindingRef,hostnameTriple,issuerPolicyRef,keyPurpose])`. `hostnameTriple` is `[names.staff,names.staff,names.staff]` for staff, and `[names.publicHost,names.upstreamSni,names.upstreamHost]` for public-upstream. Hash these bytes as `certificateBindingDigest(P)` (no extra prefix). It deliberately excludes whole contentDigest, counters, cell/gateway/addresses/ports, grants, transport peer and current short-lived authority observations. Thus an unrelated topology change does not invent a new TLS identity, although v1 refuses topology changes pending G5. C.authorityTargetRef names the G2 current-authority target separately from B.target (the mapped endpoint ID); the verifier must obtain their accepted relationship and compare both. Neither identifier implies currentness. The authorityBindingRef is a stable G2 identity-scope reference, not this draft's invented writer proof; real construction is blocked pending G2. A fresh observation of the same scope does not invalidate CSR work.

## 8. First establishment, HIGH WATER recovery and explicit reconnect

First establishment requires an already authenticated existing Cloud registration and stored machine key, trusted root policy, and a separate explicit first-install authorization. Provision a local root-owned, durable establishment anchor before the first request; do not infer newness from missing safety/registration/journal. The anchor is ordered `{"version":1,"binding":B,"epochOrdinal":U,"permitId":H,"operationId":UUID,"requestSequence":U,"nonce":H,"localApprovalRef":D,"expectedGeneration":U,"minimumFloors":F}`. It is local policy, not a Cloud signature or self-asserted administrator proof. The approval reference resolves to a locally validated current authorized decision; Cloud also requires its own authenticated venue/installation permission. A bare reference supplied by an application cannot manufacture either approval.

Cloud's durable one-use Permit record is ordered `{"version":1,"id":H,"kind":"establish"|"recover"|"reconnect","binding":B,"epochOrdinal":U,"nextEstablishmentEpoch":I,"expectedGeneration":U,"operationId":UUID,"requestSequence":U,"nonce":H,"localApprovalRef":D,"minimumFloors":F,"expectedStops":S,"expectedWithdrawals":W,"nextStops":S,"issuedMs":T,"expiresMs":T}`. Maximum lifetime 300,000 ms, exact single operation/binding, no renewable permit. Permit.binding is the request binding; nextEstablishmentEpoch is the result epoch ID. Establish/reconnect keep that ID and epochOrdinal unchanged; recover names a new ID and higher result epochOrdinal. Q.epochOrdinal is the expected current ordinal (the explicit initial ordinal for establish); recovery response ordinal is the Permit result ordinal. No other B field may change. ExpectedGeneration is the current root-supervised helper slot, echoed by the response; it authorizes no slot creation or bump. Unknown/missing generation evidence refuses recovery. Expected/nextStops equal for establish/recover; for reconnect each targeted element increases by exactly one and other elements stay equal. Permit creation is outside remote auto-renew: it requires current locally authenticated authorization plus Cloud's current permission through an authenticated approval channel. That channel's actual consumer mapping must be agreed with E/G before coding; neither machine proof nor an arbitrary self-signed local-admin assertion substitutes for it. No new UI, command or provider operation is specified here.

Establish consumes only an explicit unconsumed establish Permit for a registration with no prior establishment in Cloud's durable ledger, matching the provisioned anchor, with the Cloud ledger durably recording the new epoch and consumed Permit before returning a result. Existing registration or identity alone is insufficient. Save response and safety before journal/effects. The signed response's B/F/epoch must match the permit and be no weaker than the anchor. Explicit initial counter floors may be zero; S/W start at one. This is an authenticated recorded baseline, never missing-file=zero. Establish changes no fiscal identity or activation. A previously established installation cannot call establish again after files disappear.

Recover is for journal/safety damage, never first install or an intact reboot's ordinary revalidation. Propose **HIGH WATER recovery**: Cloud locks its installation ledger, verifies recovery Permit and machine, merges authenticated known maxima for installation/content/grant/request/report/trust/epoch and every stop/withdrawal scope, then returns a new opaque epoch ID with epochOrdinal strictly above every known epoch. Cloud durably saves the merged floors, epoch and consumed Permit before returning the signed result; exact retries recover the same result. Retain the current recovery Permit/result through reconciliation; superseding it requires a new authorization and cannot erase its floors. Request B names the expected old epoch; response B may change only establishmentEpoch, as explicitly named by the Permit. Content under the recovered B needs a higher contentRevision and fresh grant sequence. Do not use a new epoch to reset any other counter or local generation.

At equal contentRevision, differing contentDigest is a recovery conflict, never a choice by arrival order. Take the digest paired with the maximum contentRevision; require matching epoch ID at equal epochOrdinal and consistent authenticated identity/placement. A recovered trustRevision requires the corresponding independently root-verified Trust bytes and complete trust history/union defined in section 3, with its digest bound in F. A recovery signature cannot install trust, discard tombstones or substitute for either proof. All surviving app/helper/supervisor safety records are independent evidence: max their floors and retain every known stop/withdrawal latch. The Cloud receipt cannot lower one, and journal or registration repair cannot clear one. Persist the new recovery floor/epoch before replacing the journal; recheck under the lock before adoption. Recovery returns closed state. It restores a consistent authenticated baseline, not admission. Even a higher legitimate epoch carries known stops forward and adds a recovery hold if prior stop state is uncertain.

If Cloud's ledger is unavailable, returns state_unavailable, or cannot distinguish first install from established loss, remain remotely closed. Do not mint a registration, machine key, zero floor or bootstrap trust. If all local evidence is lost, Cloud cannot reconstruct an unreported stop out of nothing. Known external floors remain lower bounds, not proof that nothing higher existed. V1 permits recovery only when authenticated surviving/independent evidence establishes the required maxima and identity; otherwise recovery_required remains latched and remote admission is unavailable pending separately authorized recovery/G5 agreement. Restoring venue data or finding a backup does not supply endpoint safety evidence. This explicitly limits total-loss recovery rather than promising forgotten-stop reconstruction.

Reconnect is a distinct current authorization, outside fetch/grant refresh and recovery repair. It is allowed only for the unchanged, nonrevoked machine/endpoint after current local permission, Cloud permission, complete safety evidence and current G2 authority. It cannot undo the existing global Cloud-access stop that retired a machine key. Compare exact expected S/W, epoch, local generation and approval nonce under the apply lock; any intervening stop/withdrawal makes the Permit stale. Cloud consumes the exact Permit durably before returning authorization; exact retries recover that authorization, never a second decision. Locally consume and persist the signed reconnect result, next S and cleared _targeted_ latches atomically in independent safety, then produce fresh helper/verifier records. Do not lower S/W; a larger stop number without the explicit matching permit still means stopped.

Distinguish a durable operator stop from temporary closure. Persist each scope's local closure record as `{"scope":"staff"|"public-upstream"|"probe","stopGeneration":U,"withdrawalGeneration":U,"kind":"latched"|"temporary"|"unknown","cause":"disconnect"|"revoked"|"expired"|"fault"|"withdrawn","sourceRef":D|null}`. A locally authenticated disconnect is latched and only the explicit reconnect Permit may clear it. Installation revocation retires the identity and cannot be reversed by v1 reconnect. Unknown or damaged classification stays latched pending authenticated recovery. New learned stops always invalidate old evidence through the scope floors.

Ordinary grant/trust/certificate expiry, transient faults and stale observations close admission, persist a temporary result and advance the relevant removal/withdrawal floors; they do not invent a human stop. An issuer key remains permanently forbidden after retirement/revocation, but fresh grants under an independently accepted successor key may restore a temporarily closed scope. Authority withdrawal closes immediately; automatic restoration requires the actual G2 source to supply a fresh current result at or above its withdrawal floor for the same accepted target. A grant alone cannot override a withdrawal. No source adapter is supplied here.

When all evidence survives consistently, temporary closure may automatically revalidate in the same epoch with a higher authenticated grant sequence, current trust/clock/G2/path/custody evidence, no durable local stop, unchanged floor checks and confirmed cleanup of any old resources. Advance scope counters as required without lowering any; fresh local helper evidence binds their exact current values. Keep the request/CSR identity whenever its own intent remains current. No human reconnect Permit is required for that temporary path. This proposes the helper's previously open expiry/withdrawal/fault mapping and requires an explicit helper/T2/T5 amendment before code; its published bytes remain unchanged. Every new local stop uses max known targeted stop generation+1, persists the latch and closes the guard before asynchronous revocation/reporting. A stop during reconnect wins by compare-and-swap: a receipt for expected S cannot clear S+1. Merely changing resource generation, recovering an epoch, restoring a file or receiving a later grant cannot erase that stop. Helper activation must check a validated reconnect decision for a latched local stop, or the complete temporary-revalidation predicates above; higher numbers alone clear neither.
