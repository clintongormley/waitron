# A1188 part 3: PROPOSED joint-contract amendment

**Purpose:** “when the venue's box has died, the venue can be started in Waitron Cloud (emergency start).” Codex proposes four values for Lane G, following the [part 1 route](https://github.com/clintongormley/waitron/blob/0baa2c3869d2a4b5e4f7e632c081ad0b8da7a2ec/docs/superpowers/plans/2026-11-14-a1188-part1-emergency-card.md). Every field, type, route and bound below is a proposal, not Cloud agreement or qualified runtime. Watcher 2026-11-15 15:20 cleared sending this proposal to Cloud, not its values or build. Build nothing in part 3 until Cloud agrees.

**Provenance:** [Cloud contract](https://github.com/waitron-io/waitron-cloud/blob/e30473a2965a3951894c7ee603c8138ee6adefd0/docs/waitron-integration-contract.md#disposition-of-a1188s-remaining-cloud-requests), pin `e30473a2965a3951894c7ee603c8138ee6adefd0`, “Disposition of A1188's remaining Cloud requests”: “design boundaries for later joint formats and tests, not implemented effects”. Claude’s 15 November approach read recommends sending these values now. Existing machine-v1, billing-v1, display/code and staff-certificate-v1 formats stay unchanged.

1. **Fresh-node locked placement.** Cloud owns one canonical lowercase UUID-v4 `copyOperationId`, immutably binding `venueId`, `environment`, `sourceNodeId`, `sourceInstallationId`, distinct `copyNodeId`, fresh `installationId`/credentials, `selectedStream:{streamId,generation,databaseSha256}`, and `startedAt`/`expiresAt` as canonical ISO UTC instants with milliseconds. Cloud and Waitron verify distinct source/copy identities and matching venue/environment. Cloud uses its held backup key; nobody supplies a recovery key. Never import source `node.db` or its private node key. Launcher inputs are placed venue/node database paths, fresh credentials, account-key source, TLS certificate/key paths, exact emergency and trusted Cloud origins, and that operation binding/deadline. Open the venue account secret only for TOTP; AEAT/payment keys stay closed. Cloud’s placement reader stays read-only; the copy holds no bucket credential before confirmation. Locked entry starts no workers and grants no fiscal authority; database writes wait for declaration. Actual placement waits for unbuilt [A1425 part 3 / Waitron part 0](../specs/2026-11-07-restore-takes-new-identity-design.md#8-order-of-work), also recorded in [A1425](../../backlog.md). #3142 preserves an admitted spare's identity; #3172 qualifies fiscal spare joining, neither a fresh Cloud node.

2. **Emergency TLS and lease.** Cloud supplies certificate/key files for the venue’s emergency address returned by part 1’s display, the same hostname for every operation, publicly trusted by browsers; Waitron terminates TLS. The code-entry origin stays separate. This proposes replacing design §9 item 5’s staff-exchange route with launcher-delivered PEM; Cloud holds the private key. Staff-certificate-v1 stays unchanged. Reuse the control lease's origin/installation/venue/environment/public-key bindings and one-hour maximum, shortened to the copy deadline. Before confirmation, the installation may call only lease renewal (`control`) and `emergency-copy-status`; every other machine-v1 action gets 403 `emergency_hosting_installation_ineligible`. Existing invalid-proof/revoked refusals still apply; lease fields and writer authority do not change. Before exposure or re-exposure, Cloud checks those bindings, certificate/key/name/validity and current eligibility. Failure, revocation or expiry withdraws the route and stops the copy. `expiresAt = startedAt + 30 minutes`; sign-in/restart never extends it. Only later declaration confirmation cancels that stop. Production qualification remains required; local certificates are fixtures.

3. **Copy status read.** Propose machine-v1 POST `/api/installations/emergency-copy-status`, action `emergency-copy-status`, outer `{payload,signature}`, signed body exactly `{version:1,copyOperationId}`. Proof `operationId` is a fresh request UUID, distinct from the copy UUID. Response has exactly `{version:1,installationId,venueId,environment,sourceInstallationId,sourceNodeId,copyNodeId,copyOperationId,startedAt,expiresAt,asOf,eligibility,sourceLastHeardAt}`. Only the fresh copy installation can read its stored operation; IDs/dates match its binding. `eligibility` is exactly `{status:"ready",open:boolean,closedReason:null|reason}`, with open iff reason is null; reuse part 1’s ordered reasons `setting_off|level_inactive|no_payment_method|not_provisioned`, or exactly `{status:"unavailable",reason:"state_not_ready"}`; known closure wins over unrelated unknowns. `sourceLastHeardAt` is Cloud’s latest observed source heartbeat, retained while that source installation is registered, or explicit unknown `null` if none is known. Show unknown plainly; it is no evidence the box is off and alone does not forbid declaration. Existing unplugged/no-parallel-recovery/missing-minutes statements still apply. At declaration in part 4, closed/unavailable eligibility or a failed fresh read refuses; heartbeat age at `asOf` of 0–120 seconds inclusive refuses, and future timestamps are unavailable. No cached authority, sale-path read or declaration endpoint. Reuse stored-key/post-lock revalidation, Origin/selector refusal, errors, shared rate budgets, 60-second proofs, 12,000/86-character payload/signature, 4,096-code-unit lease/body, 16,384-byte request/response, five-second request/eight-second complete-read bounds, no redirects and no-store ([machine bounds](https://github.com/waitron-io/waitron-cloud/blob/e30473a2965a3951894c7ee603c8138ee6adefd0/docs/waitron-integration-contract.md#a951-configuration-and-certificate-lifecycle); [display/date bounds](https://github.com/waitron-io/waitron-cloud/blob/e30473a2965a3951894c7ee603c8138ee6adefd0/docs/waitron-integration-contract.md#emergency-hosting-display-and-code-proposed-d568)).

4. **Repeated starts.** Cloud atomically and durably permits one active locked copy and three admitted launch attempts per venue per rolling 60 minutes, surviving crashes, restarts and code rotations. A valid code while one is active returns that copy and counts nothing; same-operation retries retain its binding/deadline and count once. Failed launch ends its operation immediately; expired operations never relaunch. Reserve the allowance durably before launching; failed launches count too. Wrong-code attempts and status reads do not. Cloud tells the person when the next allowance opens; no startup-response format is added for Waitron, which never calls the code page. No owner reset flow, Waitron record or charge before part 4 confirmation.

**After agreement:** pin both revisions and shared binding/isolation/heartbeat/expiry/budget vectors. Cloud qualifies leases/routes/counters; Waitron qualifies the fixture entry's lack of writes. Real placement still waits for A1425; declaration, charging, return and writer generation remain parts 4–6.
