# Popover fallback implementation plan

**Outcome and authority.** Menus, dropdowns and help bubbles work without native Popover in setup, dashboard (including public module pages) and till. The owner chose “Build the fallback” on 2026-11-15 ~13:40, recorded in Lane F `queue.md`, POPOVER-FALLBACK. A separate Sol-high draft was shortened by the Codex driver. Claude reviewed it; the watcher clears the build. No owner design approval is claimed.

**Prerequisite.** The real row-actions/help shadow-root probe passed at 390×844 with OddBird 0.7.3; its uninitialized control failed with `popup.showPopover is not a function`. Command/limits: `~/waitron-campaign-f/receipts/popover-fallback-20261115/shadow-root-receipt.md`. This simulated missing APIs in Chromium, with a display shim for its residual native hiding CSS. Other primitives, layouts and old devices remain unqualified.

**Reuse and exclusions.** Keep existing components, positioning, events, keyboard handling and dialog guards. The library patches JavaScript selectors; verify consumers rather than rewriting every query. Exclude new controls, portals, positioning rewrites, unrelated fixes, CDNs, top-level await and target increases. The script-free server guest menu (`apps/server/src/guest-menu-page.ts:50`) needs separate delivery; ask the watcher whether it belongs here before building. Lane C overlap is allowed; resolve collisions when landing.

1. **Startup, test first.** Create `packages/ui/src/popover-startup.ts`, exporting `startWithPopover(start: () => void, failed: (error: unknown) => void): void` through `src/index.ts`. Native `popover` on `HTMLElement.prototype` means immediate synchronous `start`, without loading/patching anything. Otherwise import bundled `@oddbird/popover-polyfill` before mounting; add pinned 0.7.3 in `package.json` and regenerate `pnpm-lock.yaml`. Import rejection reports through the app’s existing `diag.record`, then mounts once; overlays remain unavailable until a successful reload. `src/popover-startup.test.ts` owns these paths, unchanged native descriptors, and distinguishing a thrown `start` from a failed import.
2. **Apps and styling.** Gate mounting in `apps/{setup,dashboard,till}/src/main.ts`; retain theme/diagnostic ordering. Each new `src/main.popover.test.ts` checks mounting waits for readiness and happens once, with no shadow roots before release; existing route tests retain route behavior. Preserve specificity with `:is(:popover-open, .\:popover-open)` in `packages/ui/src/menu-popover.ts`, `apps/dashboard/src/widgets/product-appearance.ts` and `packages/venue-service/src/dashboard/paint-grid-parts.ts` (escape the Lit string correctly).
3. **Shared acceptance.** Create `packages/ui/src/popover-fallback.test.ts`, `test/popover-fallback-setup.ts` and an isolated Chromium instance in `vitest.config.ts`, excluded from native instances. Remove APIs before imports; keep an uninitialized failing control and a display shim below component styles. Real row-actions, help-tooltip, combobox, colour-chooser, relative-time, table filters and language/theme choosers must start closed, open visibly at the correct position and dismiss outside at phone/desktop widths. Include address-lookup’s combobox and nested menu help. Own trigger re-click, toggle-driven `aria-expanded`, Escape/focus/selection, enclosing-dialog behavior, form-actions and DragEdgeScroll queries here; preserve existing assertions.
4. **Caller acceptance.** Add one missing-API open/position/dismiss case to `apps/dashboard/src/widgets/product-appearance.test.ts`, `packages/staffing/src/dashboard/rota-popup.test.ts`, and `packages/venue-service/src/dashboard/{calendar-day-box,paint-grid-parts}.test.ts`. Callers own their layout/events, shared tests own library failure modes. Verify modal/clipping hit-testing and resize/scroll placement. OddBird lacks a true native top layer: stop with the failing run and ask the watcher if required layouts fail; build no portal workaround.

**Verification and delivery.** Observe each expected red before implementing, then run the new named suites through their owning packages (`pnpm --filter @waitron/<package> exec vitest run <files>`). Retain focused native UI row-actions/help/combobox/table/dialog checks. Inspect EN/ES, light/dark, phone/desktop as RUNNER requires. Build all three apps and inspect lazy chunks/licences in their existing `THIRD-PARTY-NOTICES.txt`. Update `docs/developers/design-system.md` Browser support and this item in `docs/backlog.md`. Normal hook, current-head CI and `finish-branch` complete the gate; no whole-package local run.

**Size.** One PR, three hours’ build time after watcher clearance: 40–80 production additions, 220–360 test/support additions; report additions/removals and generated lockfile separately. Finish only when all named families/layouts pass and native startup/APIs stay unchanged.
