# A1605. Identify the certificate this box replaces

After a repair, staff can use either certificate page to match the previous entry by name and fingerprint, including on devices they get to after the box restarts. The page shows the new name too. New roots have names staff can tell apart. Existing usable roots keep their installed trust.

## Name new roots

In `apps/server/src/self-signed-cert.ts`, use a name such as `Waitron box 2026-11-26 7f3a9ed276da`, with the UTC mint date and 12 hex digits from the end of the new root’s random serial. Initial repair only knows shared network names. Show the name of the offered certificate on each page so staff can match it later. Accept the existing fixed name and this new name in the existing root-role check. Keep the other chain checks. This takes the distinct-subject idea from [A917 §5.3](../specs/2026-10-20-a917-box-local-name-design.md#53-each-authority-is-distinguishable-round-1-finding-h2), with key identifiers outside this change. Existing builds that require the fixed name will refuse a newly named root in restore or handover. Update boxes that share a root before passing new material between them.

## Keep the previous certificate’s identity for later devices

[A1573](2026-11-26-a1573-constrained-box-signer.md) requires removing the previous root. The existing repair archive includes private material and is removed after the start has stayed up for two minutes. In `box-tls-repair.ts`, take the name and SHA-256 and SHA-1 fingerprints from the first certificate in the archived public `ca.crt`. Identify a self-signed Waitron CA by its name and role, including the former fixed-name root, even if expired. Keep this read separate from operational trust checks. In the existing repair lock, durably save one small public identity file under `tls/`, named in `packages/store/src/state-layout.ts`. Save it before replacing the old root and bind it to the selected new root’s SHA-256 fingerprint. Read it only when that fingerprint matches the current root. On retries, use the already selected candidate. Use only the most recent replacement. Keep the archive cleanup and the existing backup and handover file lists.

Use this identity in the repair response, repair page and ordinary installation page, via `connection-bootstrap-page.ts`, `connection-bootstrap-strings.ts`, `trust-page.ts`, `i18n/trust-page.ts`, `trust-page-devices.ts`, `landing-app.ts` and `discovery-api.ts`. Show the name and SHA-256 together. Show the SHA-1 value in the Windows instructions because Windows displays it as **Thumbprint**. If there is no identifiable previous certificate, leave installed entries alone and offer the current one. Adjust the numbered steps and both languages of the Backup and recovery and Table service guides to point to the name and fingerprint the pages show. [Microsoft certificate dialog instructions](https://learn.microsoft.com/vi-vn/windows-server/networking/technologies/nps/nps-manage-certificates#copy-the-thumbprint-of-the-certificate).

## Test first

In `self-signed-cert.test.ts`, prove two mints for one network name have distinct subjects and that fixed-name roots in use still work. Keep the existing chain and reissue tests. In `box-tls-repair.test.ts`, compare the stored old name and fingerprints with the actual replaced certificate, including a former fixed-name root, and the download fingerprint with the new root. Exercise the read after normal archive cleanup, an absent old certificate and a different current root. In the existing connection and trust-page tests, including `trust-page.browser.test.ts`, exercise replacement, retained and unidentified cases without weakening install, refusal or reconnect checks. Open both languages and themes at phone and desktop widths. Run the changed TLS, route, browser and guide checks and the state-layout guard.

Expect about 145 added production lines and 115 added test lines, with about 50 lines removed or replaced across the instructions. Scope is certificate identification during new trust. No certificate migration, trust reset, archive retention change or change to the signer’s permitted names.
