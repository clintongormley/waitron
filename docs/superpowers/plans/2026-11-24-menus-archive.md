# Archive menus implementation plan

Lane D's MENUS-ARCHIVE implements [spec Part 2](../specs/2026-11-23-menus-list-usage-and-archive.md#part-2-archiving-a-menu) on top of #4180. In Menus, you can archive a full or set menu permanently, choose a replacement for every period it starts, and use **Filters → Show archived** to view it or copy its working contents into a new unpublished menu.

## Save the archive

- In `packages/menu/src/menu-names.ts`, check names among active menus and apply the same rule in the Menus name form and `widgets/menu-copy-dialog.ts`. Reuse `duplicateMenu` and `deactivateMenu`. Use `directMenuChildren` to name active full menus that include or place the target, including through an active include. When a new version is built, the existing document builder omits inactive sources. Leave old publications and existing queued versions intact.
- Add `GET /management-api/menus/:id/archive-impact` and `POST /management-api/menus/:id/archive` in `apps/server/src/menu-api.ts`. Use the existing menu gate and the venue-service seat in `packages/module/src/module.ts` and `packages/venue-service/src/service.ts`. Add an impact read and a replacement operation in `menu-timetable.ts`. The response names every starting and staff period, eligible replacements and affected full menus. The POST receives one replacement per starting period, re-reads usage under the same transaction, refuses stale or invalid choices and requires `venue.configure` for period changes. Move a chosen staff menu to the starting slot without duplicating it, remove the archived menu from staff choices and call `deactivateMenu` last. Preserve period names, times and floor plans. Reuse the existing permission for period reads.
- **Await watcher on service continuity.** Proposal for this plan's review is to refuse if the archive would take the last sellable menu out of an affected period or take the current shared guest menu offline. The archive refusal tells you to publish a usable replacement, or change the default menu or sharing in the existing settings. Confirm the rule with the watcher before building.

## Show the archive in Menus

- In `apps/dashboard/src/screens/menus-screen.ts` and `api/client.ts`, reuse #4180's usage display and labels, supplemented by the authoritative impact read for all affected periods. Put the existing `wt-switch` in `filters-start`. Extend `packages/ui/src/components/wt-data-table.ts` to show a standalone slotted filter, including when all menus are hidden. There is no additional filter choice.
- Use a localized `widgets/menu-archive-dialog.ts` with `wt-modal`, required `wt-combobox` replacements, `DraftScope`, Cancel and Archive. Use a read-only View of working contents for both kinds and offer Copy in the row menu. Reuse the structure and set-menu reads, allowing inactive set menus only in the read path in `packages/menu/src/set-menus.ts`. Refuse direct edits and publishing of the archived target at the existing menu write boundaries. Keep product archive cleanup and copying able to reach its working rows. Update dashboard strings, refusal text and both `apps/server/src/guide/{en,es}/products.md` Menus sections.

## Test first and deliver

- `packages/menu/src/operations.test.ts` and `archive.db.test.ts` prove active-name reuse and copying from the cleaned working copy. `packages/venue-service/src/menu-timetable.test.ts` proves all period links update and invalid choices refuse. `apps/server/src/menu-api.archive.test.ts` proves grants, rollback across menu and periods, owner-dependent service refusals and read-only access with Copy still available.
- `packages/ui/src/components/wt-data-table.test.ts` proves the standalone Filters control remains reachable with zero visible menus. `apps/dashboard/src/screens/menus-screen.test.ts` and `widgets/menu-archive-dialog.unsaved.test.ts` prove list, View, Copy, replacement selection, cancellation and the archive request. Run each named case red before its fix, then rerun the touched files and relevant seam, error and guide guards.

Show the watcher local before and after screenshots in both languages and themes at desktop and phone widths. Land after the watcher relays the owner's screenshot approval and required CI passes on the current head.
