# Archive menus implementation plan

Lane D's MENUS-ARCHIVE implements [spec Part 2](../specs/2026-11-23-menus-list-usage-and-archive.md#part-2-archiving-a-menu) after #4180. A manager can archive a full or set menu permanently, then use **Filters → Show archived** to view it or copy its working contents into a new unpublished menu. The watcher chose the continuity rules below in Lane D questions.md at 10:54 on 24 November.

## Save the archive

- In `packages/menu/src/menu-names.ts` and the Menus name and Copy forms, count active names. Reuse `duplicateMenu` and `deactivateMenu`. In `packages/menu/src/archive.ts`, use `directMenuChildren` for active full-menu dependants through active includes and the existing live and queued document reads for saved dependants. Tell managers that saved editions keep the inclusion and newly built editions omit it. Keep saved editions and activity history.
- In `apps/server/src/menu-api.ts`, add GET `/management-api/menus/:id/archive-impact` and POST `/management-api/menus/:id/archive` under `menu.manage`. Pass the same transaction to the venue-service seat in `packages/module/src/module.ts`, its binding in `packages/venue-service/src/service.ts` and period logic in `menu-timetable.ts`. Read and name used periods in active departments under `venue.view` and authorize changed periods with `venue.configure`. With missing access, refuse without disclosing period details. Leave deleted departments' retained history alone.
- Require a published, sellable full-menu replacement for every starting period, and a new staff choice only where removing the archived staff choice leaves the period with nothing sellable. Use active full menus with a live document holding offers, as in the readiness read. If none qualifies, name the period and ask the manager to publish another menu first. POST rechecks usage and choices, removes the archived staff choice, promotes a chosen staff menu without duplicating it, preserves the rest of the period and archives last. Reuse `updateMenuPeriod`.
- For the venue default, the same window asks for a different active published full menu and POST uses `setVenueDefaultMenu` in `operations.ts`. Make that setter refuse archived targets. If no published alternative exists, clear the default only with the manager's explicit Stop sharing choice when sharing is on. Use `GUEST_MENU_SETTINGS` and wake the existing Cloud delivery after commit through `boot.ts`. A new department without a default starts without a starter period.
