## Decisions and interfaces

### What you can capture and read

Planned permissions belong to the new module: `problem_report.create` granted from `staff`, and `problem_report.view` from `manager`. Neither implies `diagnostics.view`; leave existing live-log access unchanged. Till capture requires an open staff session on an active device plus `problem_report.create`, with no payment or drawer action required. Dashboard capture requires a live management session with that permission. Read/list/download require `problem_report.view` on every request. Capture returns only `{ id, capturedAt }`, never the bundle or server logs. A staff reporter cannot list or retrieve even their own stored report.

Use `POST /api/problem-reports` for the till and `POST /management-api/problem-reports` for the dashboard. Require the uploaded app to match that route; `setup` inputs are client-download only. Both host adapters call one capture service. Management routes are `GET /management-api/problem-reports?before=<cursor>&limit=25`, `GET /management-api/problem-reports/:id`, and `GET /management-api/problem-reports/:id/download?format=json|markdown`. Cursor is base64url JSON `[capturedAt,id]`, at most 256 characters, decoded and validated before use; limit is an integer 1–50, default 25, malformed input is 400. Sort newest `(capturedAt,id)` first. Every read uses this host's node id. A foreign-node or missing id answers the same `problem_report.not_found` 404. Download format is a closed enum.

No anonymous server capture route. In setup, before sign-in, on a locked/unregistered till, or after a transport/storage refusal, the same dialog offers **Download client report**. It freezes a browser-only bundle, with `serverLog.status="not_collected"` and `savedOnBox=false`; no request, credential, database or server log is needed. Show “This download contains this browser's activity only. It has not been saved on the box or sent to support.” This is the bounded default for zero-database setup, not an unauthenticated way to inspect logs. These downloads do not appear in the manager's saved-report list. Authenticated mode instead says “Saved on this box. Nothing has been sent to support.”

### Frozen wire contract

Define browser-safe types and validators in `packages/diagnostics/src/problem-report.ts`; server code imports that file through the package export, never the reverse:

- `ReportApp = "till" | "dashboard" | "setup"`.
- `ReportInputV1 = { version: 1; id: string; app: ReportApp; openedAt: string; description: string; trail: TrailEvent[]; client: ClientReportEnvironment; truncated: boolean }`.
- `ClientReportEnvironment = { build: string | null; locale: "en" | "es"; theme: "light" | "dark"; viewport: { width: number; height: number }; online: boolean; browser: "chromium" | "firefox" | "safari" | "other" }`. Collect no full user-agent, origin, hostname, device label, account, IP, storage contents or form values. Viewport integers clamp to 1–10000; build is a bounded version/hash token, otherwise null. Client environment is explicitly unverified.
- `ReportBundleV1 = { version: 1; id: string; app: ReportApp; openedAt: string; capturedAt: string; description: string; savedOnBox: boolean; client: ClientReportEnvironment; server: null | { build: string; runtime: string; environment: "production" | "preproduction"; mode: "trading" }; trail: TrailEvent[]; serverLog: { status: "collected" | "partial" | "unavailable" | "not_collected"; lines: SafeServerEvent[] }; truncated: boolean }`. Server environment comes from boot/config and `applicationVersion`, never uploaded replacements. No venue identity or module configuration is attached.
- `SafeServerEvent = { at: string; level: "debug"|"info"|"warn"|"error"; event: string; requestId: string; method?: string; routePath?: string; status?: number; durationMs?: number; code?: string }`. The projection drops params, logReason, message, stack, error objects and arbitrary metadata. Classify unknown event strings as `server.event`; retain only `http.request`, a code in the explicit safe-code catalog, or a fixed host tag vetted at its declaration. Map an eligible `errorCode` to `code`, never copy a raw error.
- `ReportReceipt = { id: string; capturedAt: string }`. `ReportPolicy = { app: ReportApp; openedAt: string }` selects the shared finite field/screen/code rules. `sanitizeReportInput(value: unknown, now: Date): ReportInputV1` throws a fixed `ReportInputError` reason from the browser-safe package; the HTTP adapter maps it to the registered domain refusal. `sanitizeTrail(events: unknown, policy: ReportPolicy): TrailEvent[]` returns fresh safe events.
- `createReportAttempt(log: DiagnosticsLog, client: ClientReportEnvironment, app: ReportApp, now: () => Date, makeId: () => string): ReportAttempt` freezes the opening snapshot. `ReportAttempt` exposes `input(description: string): Readonly<ReportInputV1>` (first call freezes description; later calls return the same input), `cancel(): void`, and readonly `signal: AbortSignal`; generation checks belong to the app adapter. `serializeReportJson(bundle: ReportBundleV1): string`, `serializeReportMarkdown(bundle: ReportBundleV1): string` and `makeClientReport(input: ReportInputV1, now: Date): ReportBundleV1` are pure and browser-safe.

Opening takes the last 200 events within the previous 15 minutes, dropping oldest events until the 64-KiB trail and 100-request-id caps fit and setting `truncated` when anything is omitted. No screenshot or DOM inspection. Freeze the trail at opening, then set intentional description text on first submission; retries reuse the exact id and payload. Description is optional, at most 2000 Unicode code points and 8 KiB UTF-8; reject over-limit text and C0/C1 controls other than newline/tab beside the field. Preserve accepted text separately, never add it to a trail/log/error parameter. Display bidi controls as escaped code points in Markdown and the read view; JSON retains accepted text. Display a permanent warning: “Your description may identify someone. Do not include passwords, payment details or personal information.” Do not promise that all typed text is automatically redacted.

### Privacy, resource bounds and retry behavior

- Keep current primitive/type checks, 300-character string ceiling and 20-field ceiling. Add event-specific field-key/value rules: `api` allows phase, method, path, requestId, status, code and the fixed `error="network"`; nav permits a screen key in the app's static catalog; crash events permit a built-in error name, code and scrubbed stack; `alerts.load_failed`/`theme.load_failed` permit code; `server-switch` carries no origins. Unknown fields/events are dropped in production and refused in strict test mode. Keep the per-app screen catalog in diagnostics so the server can independently apply it; include currently registered module-screen ids and use `unknown` for later additions. Invalid numbers, nested values and prototype keys are discarded.
- `maskPath(path: string): string` matches whole reviewed route templates from `packages/diagnostics/src/path-patterns.ts`, preserving their static positions and replacing every parameter position with `:id`, including slugs, emails and percent-encoded values. A parameter equal to another route word, such as `/api/products/menus`, still becomes `/api/products/:id`. An unmatched path retains only a recognized API prefix and masks every remaining segment. A global segment-word allowlist is insufficient because a static word can also be a dynamic value. Discard queries/fragments/origins before recording; malformed URL input becomes `:unparseable`, never raw input. Reapply the same masking on upload and to server route patterns.
- Crash scrubbing drops message entirely, including a stack's first line. Keep at most 10 frames consisting only of same-origin built application frame line/column under the fixed label `app.js`; discard function names, URL queries, absolute filesystem paths and external frames. The browser passes its origin into `scrubClientStack(stack,origin)`; canonical frames have grammar `at app.js:<positive-line>:<positive-column>`, with the 300-character total ceiling. Recognize same-origin built asset frames, then discard their original basenames as well as paths; a filename matching an output-name shape can still carry arbitrary text. On upload accept only the fixed `app.js` label and bounded positive line/column integers. On upload accept/revalidate only canonical frames, never raw browser stack URLs. A stack without recognizable frames is omitted; development source paths may therefore have no stack detail. Apply these rules to both `error` and `unhandledrejection`. Codes must be bounded recognized domain codes; unknown values become a fixed `unknown`, never arbitrary string content. Share a browser-safe declared code catalog rather than importing Node-side error registries into a bundle; add only the codes observed in the instrumented clients and retain a generic fallback.
- Read the request stream with a **128 KiB** byte limit and **5 s** abort deadline, checking actual streamed bytes even when Content-Length is absent/false. Reject malformed JSON, depth over 8, arrays, null, wrong field types, unknown top-level keys and invalid UUID/time with `problem_report.invalid` 400; oversize uses `problem_report.too_large` 413 and body timeout uses `problem_report.timed_out` 408. Accept at most 200 events, each at most 2 KiB, total sanitized trail at most 64 KiB, at most 100 unique validated request ids (`[A-Za-z0-9._-]{1,64}`). Reject structural overflows; never silently accept a truncated HTTP body. Re-sanitize every uploaded event and client field; validation cannot be skipped because the browser normally sanitizes them. Compute `input_digest` as SHA-256 of canonical submitted JSON (sorted object keys) after structural validation but before content projection, so retry equality does not change when a later build's safe-code catalog changes. Only the digest and sanitized bundle are stored.
- Use only IDs extracted from sanitized `api` events; accept no separate client-supplied server query, time range or log paths. Request ids correlate records; they do not prove who made a request. Privacy therefore depends on projection and authenticated report reading, not ID secrecy. For a new capture, the server collection window starts at `openedAt - 15 minutes` and ends at first submission receipt, preserving matching ends that arrive while you type. Existing 2-MiB/500-event/1-second read limits apply even when that interval is longer than 15 minutes. Test a dialog submitted two minutes after opening whose oldest captured request has a server line 14 minutes before opening; that line must remain eligible. An accepted retry returns its original snapshot and never extends this window. Client timestamps must be valid ISO instants; normalize them and drop events outside the opening's 15-minute window. A future opening beyond 5 minutes is invalid; an opening older than 24 hours cannot create a new row. Existing retry lookup precedes the new-report age check.
- Planned `LogReader.byRequestIds(ids, options): Promise<ReportLogRead>` takes `{ sinceMs, untilMs, maxBytes, limit, signal }` and returns `{ lines: LogEvent[]; truncated: boolean; unavailable: boolean }`. Use async bounded chunk reads over at most **six** known log filenames, newest files/tails first; stop after **2 MiB / 500 matching events / 1 s**, skip lines over **16 KiB** and torn/invalid JSON, and close handles on abort. Empty ids do no I/O. Keep `recent()` unchanged. After safe projection, cap server lines at **64 KiB**, keeping newest first during selection and storing chronological output. Missing/denied logs yield unavailable/partial status, not a failed report. Tests must distinguish exhausted budget from a complete empty match.
- Freeze on first successful insert, not on download. The read view/Markdown derives a pending label for an `api:start` without its end; add no later event and do not wait for it. Late logs, rotation, new browser activity and newer builds never change the stored bytes. Duplicate `(node_id,id)` for the same authenticated principal and identical canonical input returns the original receipt without re-reading logs. Changed input is `problem_report.conflict` 409; a different principal gets the same conflict without report data. Reauthenticate retries. A concurrent duplicate has one winner; the losing attempt reads and checks the saved row.
- Client submission has a **10 s** abort timeout covering response and body, one in-flight attempt and no automatic retry. Keep description/id/payload in memory after an uncertain answer and offer Retry or client-only download. Make description read-only while retrying an uncertain attempt so displayed text still matches submitted text; closing/reopening permits a new description under a new id and warns that the earlier attempt may already be saved. An answered validation refusal known to precede storage can restore editing with a new attempt. Closing, logout, navigation teardown, changing server target or disconnecting invalidates the UI generation; a late success cannot close a new dialog, show another operator's receipt or navigate. Closing does not undo a committed report.
- Admit at most one collection per principal and two per box, with **10 new reports per principal per 10 minutes**, a **256-key** rate map and no pending queue; saturation returns `problem_report.busy` 429 with a retry delay. A successful duplicate receipt is available without spending a new collection allowance. Expire rate keys; refuse new keys at capacity rather than evicting an active limit. On report storage/log/transport failure retain normal app operation and offer client-only download. Preserve the existing `storage.disk_full` 507 behavior; never report success before commit.

### Storage and export

Planned `bug_reports` columns: `node_id`, `id`, `captured_at`, `app`, `principal_key` (hash of app + authenticated person/device identity, no cookie/token), `input_digest`, `bundle_json` (the exact serialized snapshot), `bundle_bytes`. Primary key `(node_id,id)`, index `(node_id,captured_at,id)`, enum/size/JSON CHECKs. Use the public db column vocabulary and declared Drizzle constraints; no foreign keys to venue tables. The node id is boot's own `config.till.nodeId`, never the acting/data node or uploaded id. Every lookup, insert and purge names it. A copied `venue.db` on a different node reveals no previous node's reports; copying on the same node retains them by design.

Bound storage to **100 reports per node**, **200 rows total**, **256 KiB per bundle** (at most 50 MiB payload before database overhead). Lazily delete only this node's reports older than **30 days** on a successful capture transaction; no new timer. At capacity after that purge, refuse `problem_report.capacity` 409 and offer download; do not silently evict unread reports. A global count-only quota query intentionally counts foreign rows without reading their payloads; otherwise reads/purges remain node-filtered. Document that expiration is lazy and copied foreign rows count against capacity. No claim that these bounds reserve free disk space.

Use one short transaction for duplicate check, expired-row purge, quota and insert, awaiting statements in order; a duplicate must not purge or rebuild its report. Authentication preflight precedes bounded log I/O; recheck authentication/permissions in the final transaction. Explicitly comment this two-transaction decision at the host adapter because log I/O must not hold the write queue. Till preflight uses `requireSession(...,{passive:true})`, then a committed read of identity's `persons` row to require active status and `roleHasPermission(role,"problem_report.create")`; inside the final transaction use `assertStillSignedIn`, the same active-person check and `authorize` with the module permission. This closes the report route's checks without changing `till-session.ts` or its core-only permission option. Dashboard uses `requireManagementSession` plus `authorizeManager` in both checks, with `touch:false` in preflight and passive GETs. See `packages/identity/src/management-session.ts:47` for the dashboard's active-person check; till's current `authorize.ts:48` selects role without status, so do not assume it checks suspension.

The module has classification `classify("bug_reports","local",...)`, a mandatory descriptor with its own `__drizzle_migrations_problem_reports` set, configuration transfer `{kind:"none"}`, and backup verification declaring this table (compare preserved bytes, validate shape/size, cover source-schema zero and target-only empty). All migration sets currently go to `venue.db`; do not migrate this table into reserved `node.db`. No PostgreSQL grants or core migration. `diagnostics` keeps its current shared dependency and gains no db/module/identity dependency; the new module depends on diagnostics, db, module, identity, sync-enrolment and browser UI packages as needed. `db` must not import it, including for tests.

JSON download uses JSON serialization, `application/json`, `Content-Disposition: attachment; filename="problem-report-<validated-uuid>.json"`, `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. Markdown uses `text/markdown`, the same fixed-name rule, and a copy-pastable private-support bundle. Escape HTML, Markdown links/images and metacharacters in description; keep diagnostics JSON in a fence longer than any backtick run in its content. Never render Markdown or saved values with `unsafeHTML`; the read screen uses text nodes and preformatted text with wrapping. Do not label the full bundle safe for a public GitHub issue.

## Review focus

1. A crafted upload bypasses browser scrubbing or puts secrets under an allowed key: Task 1 and Task 3 must reject/drop it independently, while preserving legitimate codes and correlation.
2. A report loses its reply, retries after a late API end, or finishes after logout: Task 3/6 must keep one saved snapshot and isolate the current dialog/operator.
3. The box has no venue/person/database, or the server is unreachable: Task 6 must export a labelled client-only report without a server call and preserve setup drafts.
4. A copied database, full disk or oversized log reaches capture: Task 2/3 must enforce node ownership and bounds and report a refusal/partial bundle honestly.
5. A description contains script, HTML, Markdown links, bidi/control text or backtick fences: Task 1/4 must preserve intentional text safely, without executing it or implying that it is redacted.
