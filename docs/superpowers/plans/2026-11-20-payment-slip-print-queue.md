# Print card details and reprint a sale document as a copy

When staff take a connected-reader payment, the sale receipt carries the card details, and the optional payment slip carries the same details and the venue's time. When a receipt or invoice has printed, staff can choose **Reprint** on its Print Queue row and get a marked copy. This is one PR for the Lane F PAYMENT-SLIP-FIXES queue item and follows the [receipt and payments design](../specs/2026-11-17-receipt-layout-and-payments-design.md).

- [ ] **Card details.** In `apps/server/src/payment-slip-print.test.ts`, run the till's whole-bill reader payment with the slip choice off and on. Give the provider fixture a Visa ending 5838, contactless with authorisation 172858, through the capture path before the receipt or slip is built. Read the bytes of the original receipt staff explicitly ask for in both cases, and the slip in the on case. Pin the four details and exactly the expected number of slips. If the controlled sale already prints all four, trace the difference from the box before changing code. Start at the stored capture in `till-sale.ts`/`bill-payments.ts` and both document reads, including `payment-slip-print.ts`. Reuse `cardDetailsOf` and fix only the point that loses the supplied facts.

This covers the shared enqueue step for reader, typed card and cash.
