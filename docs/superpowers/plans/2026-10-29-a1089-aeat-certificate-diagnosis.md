## Global Constraints

- Certificate diagnosis only. No settings, trust-store, proxy/DNS, host environment, production/test switching, repair, saved history, automatic export or verbosity changes.
- Opening diagnosis sends no request. Saved facts stay labelled saved; current facts appear only after verified association. Read again is an explicit local inspection; Run check / Check again is a separate explicit network action. Stop changes nothing and submits no candidate material.
- Require `system.manage` and filing eligibility before vault decryption/native/network work, and re-authorize before releasing any evidence. `fiscal.view` alone permits the existing card and a visible sign-in choice. Both diagnostic authorization passes use `touch: false`; normal sign-in/session creation is a separate operation.
- One diagnostic attempt per box, no queue or automatic retry, no database transaction across child/network work, no sale or installation lock. Existing installation always performs its own checks after a separate Save.
- Keep the existing **200,000-byte request** and **100 KiB PFX** limits. Allow **30 seconds** for opening, TLS, reply reading and parsing; cap replies at **1 MiB**; allow **two seconds** for cleanup. Browser deadline: **35 seconds**. Bound startup and inspection within the same attempt budget.
- Select only `aeatEndpointFor(environment)(certKind)`. TLS verification stays on; no caller destinations, redirects, automatic alternate hosts or environment changes. Use one `consultar` for the taxpayer/current venue-local month; never submit, drain, retry the outbox or run the fiscal readiness test.
- Preserve keys, credential bytes/revision, install/alert/reminder rows, fiscal evidence and counters. Do not change `computeHuella`, hash chains, invoice numbering, `registros_facturacion`, alta builders, `registerSif` or `restoreFiscal`. Their production files, golden huella/inmutabilidad assertions and fixtures remain unedited. If execution needs such a change, stop that dependency and return exact source lines to the owner.
- Add tests/integration around existing paths; do not rewrite existing installed-card/editor, installation/concurrency or protected behavioral assertions. Generic packages never import the regime or acquire its vocabulary. No DB migration, dependency install or test execution is part of publishing this plan.
- Before execution read `CLAUDE.md`, `docs/developers/{writing-claims,conventions-ui,conventions-data,testing-guide,design-system,ci-and-gates,workflow-guide}.md` in the relevant sections. ### Wire contract (module-owned)

Define/export `CertificateDiagnosisRequest` as the strict object union below. Reject unknown keys, arrays/null, invalid enums, missing fields and invalid base64; never default a supplied null. `sourceGeneration` is an integer in `0..2147483647`; revision is an opaque string or null. Both operations use POST `/management-api/fiscal-certificate/diagnose`.

```ts
type CertificateDiagnosisRequest = {
  schemaVersion: 1;
  operation: "inspect" | "check";
  sourceGeneration: number;
} & (
  | { source: "installed"; expectedRevision: string | null }
  | {
      source: "candidate";
      expectedRevision: string | null;
      pfxBase64: string;
      passphrase: string;
      certKind: "sello" | "representante";
    }
);
```

`inspect` reads saved facts and opens/checks local material in isolation, with **zero HTTP requests**; it makes Read again concrete. `check` repeats those checks and makes at most one query. Installed input accepts no candidate fields. Candidate mode uses exactly its submitted bytes/passphrase/kind, never installed material; expected revision binds the venue context even for candidate mode. Empty candidate passphrase is a field refusal as in the editor, not an inferred replacement value. The actual installed payload is checked as stored.

Define `CertificateDiagnosisResult` with exactly these keys (all JSON, no dates/classes/buffers):

- `schemaVersion: 1`, server-generated UUID `attemptLabel`, `operation`, `source`, and transient `binding: {sourceGeneration, expectedRevision}`. Bindings are excluded from copy/log output.
- `environment: "production" | "preproduction"`; `kind: "sello" | "representante" | null`; `endpointLabel: "production-sello" | "production-representante" | "preproduction-sello" | "preproduction-representante" | null`. Labels are not arbitrary URLs. Null means current kind/destination was not established.
- `saved: null | {kind, installedAt: string}` (latest node install record, explicitly labelled saved); `association: "verified" | "unverified" | "not-applicable"`. Only installed material whose opened fingerprint **and** actual kind match that record can use its installation time as current. Candidate facts never borrow it. Missing/unusable vault material stays a local finding.
- `startedAt`, `completedAt`: ISO UTC strings; `durationMs`: finite nonnegative number; `stage: "local" | "connect" | "response" | "parse" | "complete"`; `category` from the closed list below; `httpStatus: number | null` (integer 100–599); `localFinding` from the closed list below or null. `cause: "not-established"` always. No retryability or product-bug field.
- Categories: `local-finding`, `local-ready`, `name-lookup-failed`, `connection-refused`, `deadline-elapsed`, `connection-closed`, `tls-protocol-failed`, `http-response`, `soap-fault`, `reply-unparseable`, `reply-too-large`, `query-completed`, `cancelled`, `unknown`. Local findings: `missing`, `unusable`, `too_large`, `unreadable`, `old_encryption`, `no_private_key`, `passphrase_wrong`, `expired`, `not_yet_valid`, `other_taxpayer`. An already-installed/same file is valid for diagnosis, not a `same` refusal.

`parseCertificateDiagnosisRequest(raw: unknown): CertificateDiagnosisRequest` and `parseCertificateDiagnosisResult(raw: unknown): CertificateDiagnosisResult` strictly validate/project their closed shapes; unrecognized evidence values become fixed `unknown`, never echoed strings. `copyCertificateDiagnosis(result): string` serializes only schema/attempt/source, configured labels, saved kind/time, verified-association flag, timing/stage/category/status/local finding and fixed cause. Exclude bindings, arbitrary input labels, filenames, raw bodies/SOAP, invoice data, fault codes/text, exceptions/messages/stacks/causes, PFX/keys/passphrases, tax IDs, names, subjects and network/proxy addresses. Use the same projection for any diagnostic log fields; prefer no diagnostic result logging. The existing card's identity fields stay outside this new evidence surface.

### Generic seat and child boundary

In `@waitron/fiscal`, add/export recursive `FiscalCertificateJson` (JSON primitives, readonly arrays and string-keyed objects), `FiscalCertificateDiagnosisChildResult`, `FiscalCertificateDiagnosisDeps` and these **optional** seat members:

- `diagnose?(deps: FiscalCertificateDiagnosisDeps, body: unknown, now: Date): Promise<FiscalCertificateJson>`.
- `diagnoseInChild?(input: FiscalCertificateJson, signal: AbortSignal, report: (progress: FiscalCertificateJson) => void): Promise<FiscalCertificateJson>`.
- Deps: existing `db`, `ring`, `nodeId`, `locationId`, `environment`; `signal: AbortSignal`; `clock(): Date`; `authorize(tx: Transaction): Promise<{personId: string; expiresAt: string}>`; `runChild(input: FiscalCertificateJson, signal: AbortSignal): Promise<FiscalCertificateDiagnosisChildResult>`. The child result is `{outcome: "completed"; value: FiscalCertificateJson} | {outcome: "interrupted"; reason: "deadline" | "cancelled" | "unavailable"; lastProgress: FiscalCertificateJson | null}`; no native exception crosses this seam.

No authority names, material types or evidence codes enter the generic seat. Define/export the following internal types in `certificate-diagnosis-child.ts` (the names/types in `CertificateDiagnosisResult` remain module-owned):

```ts
type CertificateDiagnosisChildInput = {
  operation: "inspect" | "check";
  material: { pfxBase64: string; passphrase: string; certKind: CertKind };
  taxpayer: { legalName: string; taxId: string };
  timeZone: string;
  environment: DeploymentEnvironment;
  startedAt: string;
};
type CertificateDiagnosisChildOutput = {
  openedFingerprint: string | null;
  kind: CertKind | null;
  completedAt: string;
  stage: CertificateDiagnosisResult["stage"];
  category: CertificateDiagnosisResult["category"];
  httpStatus: number | null;
  localFinding: CertificateDiagnosisResult["localFinding"];
};
```

Export `makeCertificateDiagnosisChild(overrides?: CertificateDiagnosisChildOverrides): NonNullable<FiscalCertificateSeat["diagnoseInChild"]>` to strictly parse internal input, call the child function and project its JSON output; production slot calls it without overrides. The opened fingerprint is solely for parent association, never public evidence. Progress contains only stage, category and nullable HTTP status; emit before native opening, upon headers, and before parsing/cleanup. The generic host bounds/caches opaque progress; the module validates it before use, including after a killed child. Neither internal type is browser-exported or logged. This is capability separation by construction, not an assertion of an OS sandbox: the child still runs Node and must not be described as unable to access the host. The child receives no DB handle/path, vault ring, cookie or fiscal writer capability; all secret input travels once through bounded IPC, never argv/env/files.
