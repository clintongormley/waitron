# Regional language versions

Draft for Claude review and watcher clearance. Sol-high authored this approach; the driver shortened it. The queued owner request authorises the feature, not this design. No implementation yet. Follow the [existing localization model](../specs/2026-08-30-localization-fallback-negotiation-design.md#two-paths--same-negotiation-shape-keyed-and-terminated-differently).

**Finish line.** A London venue keeps English (`en`), adds English (United States), and writes `en-US: fries` beside `en: chips`. Exact US requests get fries; `en-GB` and `en` get chips; other dishes inherit their English name. Blank regional fields store no copied fallback.

**Build the existing path.** Keep the settings document, translated maps, HTTP bodies and lookup resolver. Keep `contentLanguageCode` as the main-language extractor; add one canonical full-tag helper beside it. Preserve independent Valencian and country-pack defaults.

1. **Settings:** Add regional version from a main-language row using the existing add-language dialog and country combobox. Save canonical full tags; reject duplicates and versions without their main language. Deleting a main language with versions explains which versions to remove first; the API also refuses orphan lists. Removing/readding a version retains its text. Required/foreign-language rules count main languages, not versions. Use the existing FormFeedback contract in the changed dialog.
2. **Editors:** Enabled versions get independent inputs in product/customer, portion and menu/section/include names. A blank input's placeholder shows its main-language fallback; editing English keeps English (US), and clearing US restores inheritance. Shared modifier/unit fields and image-name validation preserve the same tags. Staff/kitchen names stay as they are.
3. **Translation checks:** A blank version is inheritance, never a missing translation. Main-language gaps remain required; regional counts stay zero with an inheritance explanation. All names permits overrides, using existing effective-text placeholders. Exclude versions from automatic translation targets and its enabled-language/house-style lists. Keep existing cell/baseline shapes.
4. **Guest/till/receipts:** Live wrappers and public guest-menu lookup preserve enabled exact tags, falling back to the enabled main language. Removed versions must not expose their retained text. Keep `resolveContentText` and snapshot lookup unchanged. Till staff tiles/basket keep staff names; customer sheets use the requested version and existing setup refresh. Receipts keep today's order-time wording snapshots: adding US creates no receipt-language choice or headings; reprints keep recorded names. The existing order path freezes the content-default wording (`working-order.ts:1027`, `venue-locale.ts:129`, `issuance-pass.ts:18`).
