# A582 slice 4 — help mode on tills and handhelds: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every implementer is dispatched as `subagent_type: "implementer"`.

**Goal:** a person signed in on a till or a handheld can turn help on from a "?" at the top right of
the bar, see a "?" beside the More and person menu options that have help, see badges on parts of
Counter, Floor and Order, open the guide in a full-screen sheet from a badge, and find help off again
whenever the till locks or someone else signs in.

**Architecture:** the switch (`wt-help-switch`, slice 2a) goes into `till-shell`'s bar; at phone
width the handheld bar's language chooser moves into More when the bar does not fit beside it. Menu
options take help through `wt-menu-row` (slice 2a). The till's help texts live in a new strings file
of their own, `apps/till/src/i18n/help-strings.ts`. Screen badges are `wt-help-tooltip
mode="help-mode"` in a field's `help` slot, a dialog's `help` slot, or a box the screen positions.
A new cancelable `wt-guide-open` event from `wt-help-tooltip`'s guide link lets the shell show the
guide in a sheet instead of a new tab. Help goes off in `till-app`'s one path to the lock screen.

**Tech stack:** TypeScript, Lit 3, Vitest 4.1.11 in browser mode (real headless Chromium through
Playwright) for `apps/till` and `packages/ui`; plain Vitest for the root guards under `scripts/`.

**Spec:** `docs/superpowers/specs/2026-10-18-a582-help-mode-design.md` (approved 2026-10-18). Slice 4
is its §8 item 4, drawing on §3.2 (tills and handhelds), §3.3 (badges inside menus), §4 (where text
lives), §5 (how a screen marks a part), §6 (staying on) and §7. The backlog's slice 4 points
(`docs/backlog/dashboard.md`, A582: "Slice 4 must also", "Slice 4 also carries the help-mode key of
table states", "The till's floor (A504, spec §11)", and "Left open by 3": the till's `/help` proxy
and the sheet hook) are each answered below: decisions 6, 7, 8, 11 and Tasks 8a–8b. Spec §7 asks nothing of the till: it has no always-visible "?" today (`grep -rln "wt-help-tooltip" apps/till/src` finds none).

**Base:** `main` at `be39179b0`. Every file reference is to that commit. **(read)** marks a
conclusion from reading code, not from running it. The measurements in "Measured while writing
this plan" were run, and each says what ran.

## Words used in this plan

- **badge** — the small filled "?" help mode shows on a part: `<wt-help-tooltip mode="help-mode">`.
- **help box** — the popover a badge opens.
- **the switch** — `wt-help-switch`, the "?" button that turns help on and off.
- **menu row** — `wt-menu-row`, which lays out one menu option with its badge in its own square.
- **phone width** — the till's `PHONE_WIDTH`, `(max-width: 40rem)` (`apps/till/src/widgets/language-chooser-styles.ts:4`).
- **till form factor** — `formFactor === "till"` (a counter till); **handheld** — `"phone-portrait"` or
  `"tablet-landscape"` (`apps/till/src/layout.ts:21-35`, read).
- **the sheet** — the full-screen window a till shows a guide page in.

## Decisions

1. **Where the help texts live: a new file, `apps/till/src/i18n/help-strings.ts`, not `strings.ts`.**
   Spec §4 asks for "the app's own strings tables"; this is one, in the same folder, with English and
   a Spanish table typed `Record<HelpKey, string>` so a missing Spanish text fails the type check as
   `strings.ts` does (`strings.ts:1-3`, `:1613-1614`). The reason for a separate file is the lanes:
   G and B both change `strings.ts` heavily (table above), and every help key added there would be a
   hunk beside theirs. `t()` (`apps/till/src/i18n/t.ts:28-30`) reads only `strings.ts`'s catalogues,
   so the new file has its own `helpText(key)` with the same fallback (an unknown locale, or one
   missing the key, gives English). Keys are named `help.<place>.<part>` (spec §4). The shared words
   are `help.label` "Help" / "Ayuda", `help.badge_label` "Help: {part}" / "Ayuda: {part}",
   `help.guide_link` "Read more in the guide" / "Más información en la guía" (the dashboard's words,
   `apps/dashboard/src/i18n/strings.ts:774-776`, `:3793-3795`), `help.guide_title` "Guide" / "Guía"
   and `help.guide_close` "Close" / "Cerrar" (the till has no `action.close`; `grep` finds only
   `action.cancel`). Task 1 adds the first two; Tasks 8a and 8b, the first to read them, add the three guide words.

2. **Where the switch goes.** On a handheld, in `.session` after the bar's language chooser and before
   the person's name and More — or in the chooser's place once it is in More (spec §3.2). On the till
   form factor, first in `.session`, before the person's menu and More: its chooser has been in More
   since A738. Never in More, never on the kitchen display or in kiosk mode (no bar; slice 5), never on
   the lock screen. It is `<wt-help-switch data-test="help-switch" label=${helpText("help.label")}>`.
   `#settled` (`till-shell.ts:536-542`) waits for it like the bar's other Lit children, so the
   above-phone-width fit measures it.

3. **The till form factor at phone width: the "?" goes on the bar, and the strip keeps scrolling.**
   The design's rule moves only the chooser, which is already in More there, and nothing else on that
   bar may leave: A738 put the person's name and More there on purpose. So this plan changes no part
   of A738's bar. The cost is M2: with a long name at 320 px the strip is 8 px wide. Task 2's test pins
   what must still hold (the "?", the person's menu and More inside the window, at least 44 px each, no
   sideways scroll of the page, every tab reachable by scrolling the strip), and Task 5 adds a backlog
   entry for the owner: whether the person's name should give room on a narrow till (for example two
   tap widths instead of three at phone width, which M2's numbers say would give back 44 px). That is
   a change to A738's look, so it is his call, not this slice's.

4. **The handheld's language chooser at phone width: it moves to the END of More, after Theme, as the
   same `layout="group"` row the till form factor's More already uses.** Where: last in More, after the
   person's section (whose last item is the theme choices, `#operatorActions`, `till-shell.ts:762-766`).
   Reasons, each read: (a) on a short phone More is already taller than its room and Log out falls
   below its edge (`docs/backlog.md:2268-2274`); A681's look measured that a three-row group placed
   before Log out pushed Log out below the visible menu at 360×640, 360×740, 320×740 and 390×664
   (`docs/developers/design-system.md:4904-4906`), so the end of the menu is the one place a new group
   cannot push Log out further down; (b) Theme then the languages is the order the dashboard's account
   menu settled (slice 2b, owner's answer B to Q41: "the language choices move into the account menu
   beside Theme"); (c) the till form factor's More draws the same `#chooser("group")`
   (`till-shell.ts:813`), so the two devices offer the same control. Form: `#chooser("group")`, which
   dispatches the same `wt-locale-selected` as the bar's chooser (`wt-language-chooser.ts:151-152`), so
   `till-app` handles it unchanged. When: only on a handheld (`formFactor !== "till"`), only at phone
   width, and only when the bar does not fit with the chooser on it — `#wraps()` (`:544-549`) run at
   phone width for this one step, as spec §3.2 says. By M1 that moves it at 320 px and keeps it on the
   bar at 360 and 390 px, in both languages. Above phone width it never leaves (spec: "The '?' never
   leaves, like the language chooser").

5. **Help goes off in `#setScreen("lock")`, the one door to the lock screen.** Every path that locks
   calls it: logging out from the bar and the idle logout (`#onLogout`, `till-app.ts:15442-15482`;
   `#onIdle`, `:1910`), a move to another server (`#onServerChanged`, `:1855-1869`) and boot (`:3301`).
   A new person can sign in only from the lock screen (`@logged-in` on `till-lock-screen`, `:16030`;
   `#onLoggedIn`, `:4150-4155`), so a change of person always passes through it. A profile switch keeps
   the same person (`#enterSignedIn(…, switched = true)`, `:4157-4160`) and keeps help as it was.
   Turning help off when `till-shell` disconnects was rejected: the shell is rebuilt on every language
   change (`keyed(currentLocale(), …)`, `:16583-16585`) and replaced by the clock-in page, so help
   would go off at the wrong times.

6. **Which menu options get help (six), and none on the bar's own buttons.** Profile (both form
   factors), Settings (till form factor), Equipment, Transfers and Pass (handheld More), and Fix my
   hours (the person menu, both). Their labels say least of what they do (texts and receipts in
   "Help texts" below). Find a bill, My hours, My schedule, Kitchen and Log out are left without, as
   their labels say what they open. A bar button gets no badge in this slice: on the till form factor
   the bar's buttons sit in `.till-strip`, which scrolls (`overflow-x: auto`, `:143`), and a badge
   hung 16 px over a button's top corner would be cut off by it, as slice 2 measured for a scrolling
   table (its plan's M4, M5). An item that has moved into More gets its badge there.
   While touching `#menu`, Task 4 deletes its `formFactor === "till"` Settings button (`:793`): `#menu`
   is drawn only when the form factor is not the till (`:928`), so that line has been unreachable
   since A738.

7. **The guide sheet is needed in this slice, and one badge uses it.** The Products guide has a
   section written for the till, "Read a dish's nutrition at the till" (`{#nutrition-at-the-till}`,
   `apps/server/src/guide/en/products.md:255-275`), whose claims match the menu browser: a hold opens
   the information window (`apps/till/src/widgets/menu-browser.ts:110-113`) and Shift+F10 or the
   context-menu key does too (`:641-644`). The menu browser's badge (Counter and Order) links to it. No
   other till part this slice marks has a guide section, and no new guide page is written (spec §4: a
   screen's change writes its guide; this slice changes no screen's behaviour). The link opens in the
   sheet: `wt-help-tooltip` dispatches a cancelable `wt-guide-open` when its link is clicked; the shell
   cancels it and shows the page in a `wt-modal size="full"` holding an `<iframe>` and a Close button
   (spec §3.2: "a full-screen sheet over the till with a Close button, never a new tab"). The guide
   page follows the till's theme by itself: it reads the same `waitron-theme` storage key on the same
   origin (`GUIDE_THEME_KEY`, `guide-pages.ts:44-46`, read).

8. **The key of table states ("What the colours mean", A893) is NOT built in this slice.** The backlog
   says it "follows whatever look A893 settles" (`docs/backlog/till.md:1355-1357`), and A893 waits for
   the whole of A757, whose slices 3–6 and 8 are not built (`docs/backlog.md:2137-2140`); A757's later
   slices change how a table shows its state (one state per table on the map, zone tabs carrying a
   state — `docs/backlog/till.md:1335-1345`). A key written now would describe states that are about to
   change. Task 12 moves that point out of A582 into A893's entry, as its own line. Floor still gets
   the badges A504 asked for (spec §11 point in the backlog): the Update layout banner and Needs moving.

9. **A887 is already done by A738.** A887 asks that the English guides and the till say one word for
   an order set aside; the guides say "parked order" and the till now says Park and Parked orders
   (above). Task 5 checks both with `grep -n "parked order" apps/server/src/guide/en/*.md` and
   `grep -n '"action.hold"\|"held.title"' apps/till/src/i18n/strings.ts`, and deletes A887's entry and
   detail if they agree.

10. **The till's badge is 32 px with a 24 px circle (spec §3.2), set once on `till-shell`'s `:host`**
    (`--wt-help-badge-target: 32px; --wt-help-badge-size: 24px`). Custom properties inherit into the
    slotted screens and the drill overlay, both inside the shell. A menu row sets its own badge target
    to `--wt-tap-min` (`wt-menu-row.ts:24-29`), so a menu badge is 44 px with the 24 px circle. A
    32 px badge hangs 16 px past its box, which overflows `wt-modal`'s 12 px side padding at phone width
    and reaches 4 px above `wt-disclosure`'s 12 px top padding (backlog, "Slice 4 must also"; the
    390 px case in `wt-help-tooltip.slots.test.ts:370-394`). Task 7 makes each of those paddings at
    least half the badge target: `max(<today's value>, calc(var(--wt-help-badge-target) / 2))`. The
    dashboard's target is 24 px, so its paddings stay what they are (12 px = 24 / 2). On a till, the
    disclosure's top padding grows from 12 to 16 px at every width; the modal's side padding is
    `clamp(12px, 3vw, 24px)` (`--wt-modal-inline-padding`, `packages/ui-core/src/tokens/structure.css:66`),
    which is under 16 px only below about 533 px wide (3vw < 16 px), so only there does it grow, to
    16 px. Either way it grows whether help is on or off, so turning help on moves nothing (spec §3.1).


11. **No badges on Counter's payment buttons in this slice.** Spec §3.2 names "the payment buttons"
    among the parts Marc sees badged. Lane F's open `feat/a739-payment-window` is redesigning the

## Global constraints

- General code English only (`CLAUDE.md` §3): Spanish only in `apps/till/src/i18n/help-strings.ts`.
  Tests read Spanish expectations from that file, never as literals.
- Every `wt-help-tooltip` outside `apps/setup` carries the literal `mode="help-mode"`; a bound mode
  fails `scripts/help-tooltip-mode.test.ts`.
- A guide path is written only by `apps/till/src/help-guide.ts` in the till (Task 8a extends
  `scripts/guide-links.test.ts` to say so).
- Every colour, space and size reads a `--wt-*` token; no hex, `rem` or `em` (`packages/ui/src/no-hardcoded-chrome.test.ts`, `scripts/style-token-names.test.ts`).
- Coverage 98/98/98/95 in `apps/till`, `packages/ui` and the root; never closed by an exclude.
- A shared `wt-*` event is named `wt-*`, carries `detail`, and is dispatched `bubbles: true, composed: true` (`CLAUDE.md` §3).
- A test that changes the language restores it; a test that turns help on turns it off in `afterEach`
  (`setHelpMode(false)`), because the switch is module state.
- TDD: each step's failing test is run and seen failing before the code. Every focused run is
  `pnpm --filter @waitron/till exec vitest run <files>` (or `@waitron/ui`), and its `Tests` count is
  read, never the exit status of a pipe. Before a browser run, check `memory_pressure | grep free`.
- Every implementer runs `pnpm format:check` and the package's `typecheck` before committing, and
  commits with `git commit -s`.
- An implementer past about 150 tool calls stops at a passing or cleanly failing point, commits, and
  hands over: done, left, files, each check's state.

## Review focus

The cases most likely to bite someone that no single task's main test is about. Each has its test in
the task named.

1. **Language change with help on.** The shell is rebuilt on a language change
   (`keyed(currentLocale(), …)`). Help must stay on, the rebuilt switch must read as pressed, and an
   open menu or box must not leave a stray popover. Test in Task 1.
2. **Resizing across the phone width with More open.** The chooser must not jump between the bar and
   More under the finger. Test in Task 2.
3. **Help turned off while a box is open in a menu or on a screen.** The box must close
   (`wt-help-tooltip`'s `updated`, `wt-help-tooltip.ts:122-124`). Test in Task 4 (menu) and Task 9 (Park).
4. **The guide sheet open when the till locks** (idle logout while reading a guide). The sheet must
   close with the shell; the next person must not find it open. Test in Task 8b.
5. **A badge tapped while a button beside it is disabled** (Park while the basket is empty). The badge
   must still open its box: help is for exactly the person who does not know why a button is off.
   Test in Task 9.
