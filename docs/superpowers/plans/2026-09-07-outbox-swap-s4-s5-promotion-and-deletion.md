# Outbox → native replication, step 4 (swap S4 + S5): promotion/return on LSNs, the outbox deleted — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make native logical replication the ONLY carrier between nodes: `waitron-provision instance` leaves `waitron_migrator` owning every table; a standby adopts by subscribing (initial copy) instead of pulling an outbox; promotion narrows the promoted node's subscription to the ledger publication; a fenced node's "drained" is read from `pg_replication_slots` against a fence-LSN watermark; rejoin is wipe-and-re-adopt; a returned box reconciles its membership before it can sell; and the application outbox (`sync_log`/`sync_cursor`/`sync_peers`/`sync_config_conflicts`, the capture triggers, the pull/retention workers, `/sync-api/*`, the bearer token, the SP-2b park gate and the settings-conflict gate) is deleted — with the fiscal-fidelity suites the owner signs on.

**Architecture:** `@waitron/sync` becomes the thin native layer (`publications.ts` + `ensurePublications`, `subscriptions.ts` + more verbs, new `names.ts`, `drain.ts`, `status.ts`) — pure SQL builders + readers over an injected owner connection, no role vocabulary, no `@waitron/provisioning` at runtime. `@waitron/provisioning` migrates AS the migrator through the session `role` option over the admin's own credentials (so ownership is right on first run and re-run without reusing the migrator's password). `apps/server` rewires adopt (subscribe-disabled → local finish once the copy is ready → enable; the mirror boots in an "adoption-pending" mode until the copy completes), promotion (narrow after the PONR, self-healing at every primary boot), retire/rejoin/box-status (slot reads against a fence LSN), a returned box's boot-time membership reconciliation, and deletes every outbox path. The fiscal module owns the fidelity suites; `apps/server` owns the every-table copy matrix and the full §4.2 arc on the two-node fixture.

**Tech Stack:** TypeScript, pnpm workspace, Drizzle (`sql.raw` for utility DDL Postgres will not bind), PostgreSQL 18 (`postgres:18-alpine`), Testcontainers (`@waitron/db/testing/two-node.js`), Vitest, `pg` 8.22 (honours `options=` in a connection URI — measured; `createPostgresDb` builds a `Pool`, `packages/db/src/client.ts:102`).

**Spec:** `docs/superpowers/specs/2026-09-05-outbox-to-native-replication-swap-design.md` (S4 = §4, S5 = §7; also §2.2, §2.4, §3, §5, §6, §9, §11, §12, §13) and `docs/superpowers/specs/2026-09-05-drop-rls-squash-and-outbox-deletion-design.md` §3 **step 4**. Empirical basis: `docs/superpowers/specs/2026-09-05-native-replication-post-rls-prototype-findings.md` plus the six probes recorded below.

## Owner decisions (2026-09-07) and driver rulings (2026-09-08)

Owner, 2026-09-07 evening: (1) ownership fixed at CREATION time, never `REASSIGN OWNED`; (2) the replication credential rides the mirror bundle; (3) adopt fails loudly rather than half-join; (4) build now, the owner signs the fiscal evidence at LAND by reading the PR + the fidelity suites' output.

Driver rulings after the fresh-context plan review (2026-09-08), each a mechanism choice inside the approved design:

- **Ruling C2 — the drain watermark.** `confirmed_flush_lsn >= pg_current_wal_lsn()` is NOT monotone: after the carrier disables its subscription (spec §4.2 step 4) `confirmed_flush_lsn` freezes while the fenced box keeps writing WAL (session keepalives, autovacuum, checkpoints), so the compare decays to false forever. Use a **fence-LSN watermark**: the box records `pg_current_wal_lsn()` in `deployment.fence_lsn` when it enters the fenced/read-only state; the guard is `confirmed_flush_lsn >= fence_lsn && !active`, both monotone. Spec §4.1 sanctions the fence-LSN form. A dead box (no `fence_lsn`) takes the operator's `--accept-loss` path (spec §4.2 step 2). Cost if wrong: a wipe could run before the tail is on the carrier — bounded by the `!active` half (the carrier disables only after it read drained) and the probe receipt.
- **Ruling C7 — membership after gossip is deleted.** Deleting the pull worker deletes membership gossip; a box that died before it was fenced comes back with a stale chart naming itself serving-primary and would sell while the promoted cloud is also primary (CLAUDE.md §5). **Task 8** adds a boot-time reconciliation: a node booting as primary with a configured cloud peer best-effort fetches the peer's current membership document (a new authenticated `GET /management-api/membership`) BEFORE opening the sale path; a higher-term fencing document sends it read-only; unreachable → proceed (it cannot have been superseded without a reachable cloud AND a human promotion — the MVP's accepted window, now closed the moment connectivity returns). Cost if wrong: a partitioned superseded box keeps selling until it can reach the cloud — the window the human-promotion MVP already accepts.
- **Ruling I3 — no slot drop in rejoin.** Probe F: `DROP DATABASE … WITH (FORCE)` as the migrator-owner drops an INACTIVE slot with the database; rejoin already gates on `!active`, so the wipe reclaims the slot for free. Delete `dropPeerSlot` from rejoin and the migrator→`waitron_repl` grant (a §3 "never widen a grant" violation). Keep a `waitron_repl`-authenticated `dropReplicationSlot` verb (tested, no step-4 caller — step-5 orphaned-slot reclamation and the operator SKIP runbook are its callers).

Six probes on `postgres:18-alpine` (PostgreSQL 18.6, roles `rolsuper = f` unless named superuser), each with its failing case written first (scripts in the session scratchpad; the receipts are pasted here):

- **A — migrate as the migrator, first run AND re-run.** In ONE transaction on the admin handle: `set local createrole_self_grant = 'set'`, then `create role waitron_migrator login createrole …` (a `createdb createrole` admin) → the admin gets SET-membership (`pg_auth_members`: `waitron_migrator ← prov_admin set_option=t`). `create database wt owner waitron_migrator` succeeds. Control: over a PLAIN admin connection to that database `create table` fails `permission denied for schema public`. With `options=-c role=waitron_migrator`: `current_user = waitron_migrator`, the table is migrator-owned, `app_user` (created by the migration) is migrator-created so the migrator holds ADMIN OPTION and can `grant app_user to waitron_migrator` and `create role waitron_app login in role app_user`; the plain admin cannot (`no possible grantors`). A fresh admin session with the role option on a re-run creates a migrator-owned table. `pg` 8.22 parses `?options=-c role=waitron_migrator` into `connectionParameters.options = "-c role=waitron_migrator"` (the space encodes as `+` and decodes correctly).
- **B — the drain/status reads need no extra grant.** A non-superuser reads `pg_replication_slots` (`confirmed_flush_lsn`, `wal_status`, `safe_wal_size`) and `pg_current_wal_lsn()` unmasked; the subscription OWNER reads `pg_stat_subscription` / `pg_stat_subscription_stats` unmasked.
- **C — subscription creation facts.** `CREATE SUBSCRIPTION … WITH (enabled=false, copy_data=true)` (connect on) populates `pg_subscription_rel` (state `i`) at CREATE; a publication name absent on the publisher only WARNs and leaves `pg_subscription_rel` EMPTY. `ALTER SUBSCRIPTION … SET PUBLICATION <ledger> WITH (refresh=false)` after a disable: a row already in WAL for the dropped publication's table did NOT arrive after re-enable; the kept table's row did (spec §13.4 verified).
- **D — a disabled subscription's slot retains WAL.** An inactive slot retained 22 MB after 20 000 1 KB rows (`wal_status=reserved`). On a standby, the apply of the primary's own writes generates that WAL, so spec §2.2's "primary's disabled subscription back to the standby" would exhaust `max_slot_wal_keep_size` in weeks and be `lost` when the drain window needs it. **Dropped from the design** (Task 10 records it in the spec): the drain window is served by the promoted node's own subscription, narrowed — which exists in every failover.
- **E — the fence-LSN watermark is monotone.** L0 = `pg_current_wal_lsn()`; 10k rows into an UNPUBLISHED table with the sub ACTIVE → `confirmed_flush >= L0` and `>= current_wal` both true (keepalives cover unpublished WAL). DISABLE, 10k more → `>= L0` still TRUE, `>= current_wal` FALSE (3.2 MB behind), `active=f`. So `confirmed_flush >= fence_lsn && !active` holds after the disable where the raw compare does not.
- **F — DROP DATABASE reclaims an inactive slot.** As the migrator-owner (`options=-c role=`) from a maintenance db, `DROP DATABASE pub WITH (FORCE)` with one INACTIVE logical slot → succeeded, database and slot gone. Control: an ACTIVE slot → `ERROR: database "pub2" is used by an active logical replication slot`.

Two design facts from the code maps, not probes:

- **A native initial copy cannot coexist with `adoptVenue`'s scaffold inserts**: tablesync `COPY`s every published table, and a pre-inserted primary PK fails the COPY, which retries forever. So adopt no longer inserts rows; the reserved-identity `establish` (whose inserts FK to the copied tenant/location rows) moves to a boot-time finish step gated on every `pg_subscription_rel` row reaching `r`. **Consequence (C6):** the mirror restarts into a database whose initial copy is still running (spec §2.2: "minutes over a WAN"); boot must not touch tenant-scoped rows until the copy completes — Task 5's adoption-pending boot mode.
- **`tenant_credentials` is reclassified `local`.** The decisive reason is `membership.node_key`: both nodes hold `(tenant_id, "membership.node_key")` (`packages/credentials/drizzle/0000_credentials_baseline.sql:9` PK; `apps/server/src/node-identity.ts`). Classified `state`, the primary's key copies to the standby BEFORE the finish step, and `establishReservedStandbyIdentity`'s idempotence guard (`tryGetCredential(NODE_KEY_PURPOSE) !== null → return`, `apps/server/src/reserved-identity.ts:69-73`) then reads the primary's blob and silently no-ops — the standby never gets its node row, reserved series or reserved SIF and is un-promotable while believing it is established; in the other order the copy conflicts on the PK and stalls. Either is fiscal-grade. As `local`, `fiscal.aeat` and `payments.stripe` also stop travelling — nothing is lost because a blob sealed under one node's ring cannot be opened under another's (GCM auth fails, `packages/credentials/src/purposes.ts` header). Track B item 2's shared-ring design is what would change that.
