# A1188 part 2: saved facts and the till's emergency link

**Ask:** “when the venue's box has died, the venue can be started in Waitron Cloud (emergency start).” Source: Lane J `queue.md`, A1188; [design](../specs/2026-10-29-a1188-cloud-emergency-start-design.md) §§1,3,11. The design header records owner approval on 2026-10-29, not approval of this plan. Separate Sol/high draft, corrected by Codex after Claude's first read; watcher clearance is required before publication/build. Part 1b is merged (#3316, `2f8f72120a`).

**Finish line:** a loaded till offers the emergency address when its main box disappears, including without a spare. Until Cloud's display endpoint and P6 permit hosting, no real venue gets an open entrance. After that dependency, staff can open Cloud's code page; this part supplies neither hosting nor activation.

Paths: **S** = `apps/server/src/`, **T** = `apps/till/src/`.

**Storage choice for the watcher:** recommend the bounded address/open/codeIssuedAt/asOf hints reserved in the part 1 plan, surviving a box restart during a Cloud outage. Claude proposes simpler process-memory-only facts; the design does not explicitly require disk persistence. Retain disk only if the watcher settles that finding in its favour. Do not save prices or change the dashboard's restart behaviour to justify a separate slice.

**2a: saved hints and setup delivery.** The system delivers nonsecret hints to loaded tills; the visible entrance follows in 2b. In S`cloud-client.ts`, keep optional registration/staff-origin-bound hints in existing `cloud/connection.json`, never emergency code. After credentials validate, ignore malformed/>16-KiB hints. Drop optional hints before saving if needed to preserve the 64-KiB credential limit. Reuse durable `save` and waiting `run(..., true)`: fetch outside the lifecycle turn, re-read registration, then merge/save only when registration/address/open/codeIssuedAt changes. Retain request-generation/asOf ordering in memory. Replacement/revocation/disconnect invalidate hints; confirmed false replaces true; outage/state_not_ready retains hints. Preserve concurrent lifecycle changes; both capture callers already take the same turn.

Expose synchronous `emergencyHints(staffOrigin)` as `{address}|null`, only for matching registration/origin with `open === true && address !== null`. Warm its small process-local projection during existing validated reads/saves; cold/invalid Cloud state means null, never a failed till read. No filesystem, key rebuild, database query or Cloud request in the getter. Leave asOf/stale/issue date off till setup.

Extend S`cloud-worker.ts`'s minute pass: active installation/primary only, isolated emergency refresh sharing `emergency()`'s throttle/Retry-After; failure must not skip guest-menu/certificate work. S`boot.ts` uses exactly the card's `deps.managementOrigin` and a deferred getter because till mounting precedes Cloud construction.

Export existing `authorityForRoles` through `packages/identity/src/index.ts`. S`till-setup.ts` filters role descriptors with `holds(authorityForRoles(...), "node.manage")`: fixed built-in order, then custom `name_folded`. No people query. `completeTillSetup` receives memory hints outside the database lock; include optional `cloudEmergency` address/roles before hashing. S`till-api.ts` supplies it consistently for `/api/till` and `/api/menu-state`. Extend T`api/client.ts` and `#applyVenueSetup` in T`till-app.ts`. Reuse current revision/no-zone/kitchen/profile refreshes; retain across failed reads/sign-out, clear on server change. No new PIN-screen polling: locked tills follow changes after sign-in through existing setup refreshes.
