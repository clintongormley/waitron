# Printing does not wait for discovery

**Authority:** PRINT-DISCOVERY-WAIT, `/Users/clintongormley/waitron-campaign-e/queue.md`, watcher assignment 2026-11-14 04:25. Separate Sol high-effort draft, corrected by the Codex driver after Claude's review. The watcher clears implementation; no owner design approval is claimed.

**Finish line:** Jobs print during discovery; sweeps stop dialling at window expiry despite clock offsets; discoveries stay listed through the next pass. Reuse existing workers, generation/wake/results handling, queue merging, relative probe lifetimes and classifier cache. Keep the agent database-free. No UI, storage, endpoint, scheduler framework, lease redesign or inventory caching. Real-box throughput remains open.

## Build inline, test first

1. **Relative window:** In server `print-api.ts`, send `discoveryExpiresInMs: number | null` after long polling, from `until - repliedAt`. Keep management start/renew's absolute `discoveryUntil`. In `packages/print-agent/src/{client,agent}.ts`, decode finite `(0,180_000]` durations and derive the local deadline at receipt. Invalid/closed data stops scanning without dropping jobs. Preserve backward-step checks. Trace/port every consumer, including `invoice-claim.test.ts` and server `print-api.printer-wiring.test.ts`.
2. **Independent workers:** In `packages/print-agent/src/agent.ts`, retain `discover()` and add one typed-check in-flight slot, started by `tick()` with no separate timer. Each worker classifies its results; the scan worker owns `ippOnly` fallback. `tick()` merges completed results using the existing synchronous address deduplication. Preserve queue metadata/ambiguity and pass spacing. Typed requests work during scanning and with discovery closed; retain their origin/reset checks. Reset discards both workers' old results; primary changes discard typed results only, preserving local discoveries. Accept a duplicate bounded IPP query when both workers concurrently miss the existing cache; add no serialization mechanism.
3. **Replay:** Repeat completed scan results only while the discovery window is open. A completed empty or throwing pass replaces the old snapshot with empty. After closure, stop repeating acknowledged results; retry a final unsent snapshot until a pull succeeds, including one from a pass completing late. Failed/aborted pulls retain pending results; older acknowledgements cannot erase newer ones. Typed hits remain reportable only during their target lifetime. Scan replay refreshes `scannedAt`/`lastSeenAt` (listing, Pair admission and office marks), never paired/visible timestamps, until the next completion or closure.
4. **Actual sweep deadline:** Extend `Host.scan(kinds?, deadline?: number)` in package `host.ts`/`testing/fake-host.ts`; forward through app `{host,linux-devices}.ts` and `LinuxDeviceOptions.scanNetwork`. Export the existing network-scan composition outside its ignored block, injecting interface listing, connection, mDNS and clock dependencies for tests. Call real `sweepPort` directly there, eliminating the untested `liveSweep` forwarding wrapper. Add `deadline?/now?` to `SweepOptions` in app `sweep.ts`; before each dial, skip expiry and use `min(timeoutMs, remainingMs)`. Capture the initial remaining allowance and refuse `deadline - now() > allowance` after a backward step. Keep subnet/pool limits and partial hits. Leave typed socket limits and mDNS timing unchanged; no new failover policy.
5. **Address decision:** Keep `printer-probes.ts`'s literal unicast acceptance/exclusions. The PR explicitly accepts public IPv4 receiving a bounded Get-Printer-Attributes POST on port 631 regardless of the typed port: a manager deliberately selects an agent-reachable printer, including routed/loopback targets. The rationale is no longer “sends no bytes”. Preserve IPv6's IPP skip; no address-validation change.
