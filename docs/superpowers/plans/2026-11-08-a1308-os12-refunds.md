# A1308 refunds, PR 1 of 2: the `refunds` table, and refunds before the invoice move into it — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **OWNER LANDS THIS PULL REQUEST** (design §10 "Refunds: one `refunds` table, in its own slice";
> build order: refunds, "Owner lands: yes (money and the refund trigger)"). It holds only the refunds
> change.

**Goal:** Make `refunds`, the one table for money given back before or after the invoice, with every
protection of `bill_payment_refunds` and `tender_refunds`, one guard trigger with a branch per kind, the
set-once `drawer_opened_at`, and a `created_at` index; move refunds before the invoice
(`bill_payment_refunds`) into it. os13 moves refunds after the invoice.

**Architecture:** A refund's kind is which of its keys is set: `bill_payment_id` (before the invoice)
or `sale_id` with `tender_id` (after); no kind column (tables-ordersales.md §1.11, "CHECK exactly one
kind"). The table is built whole in this PR, both kinds' CHECKs and indexes included and tested with
direct rows; only the bill kind's code moves here. Renames go through a committed script (rules §1);
kind filters are hand edits, listed in the PR.

**Tech stack:** TypeScript, Drizzle ORM on `node:sqlite`, Vitest.

**Spec:** [tables-ordersales.md](../specs/2026-11-02-rationalisation/tables-ordersales.md) §1.11, §4,
§5 (bill_payment_refunds / tender_refunds → refunds), §6 item 8, §7; README §10, §5 U11;
[tables-devices.md](../specs/2026-11-02-rationalisation/tables-devices.md) §3 (the `drawer_opened_at`
clause and its stand-in test); [tables-people.md](../specs/2026-11-02-rationalisation/tables-people.md)
(attendance's `created_at` index). Rules: [slice rules](2026-11-08-a1308-slice-rules.md).

**First line of the PR description:** "Every venue is reset: core; backups and exports from before
this cannot be restored or imported." Second line: "Owner lands: money and the refund trigger."

## What it builds

1. `refunds`, core set, `ledger`, not append-only (its outcome moves under the guard trigger), never
   deleted. Columns: the union of the two tables at HEAD
   (`packages/db/drizzle/0000_baseline.sql:1151-1183, :1579-1630`) less `location_id` (slice 5 dropped
   it), plus `drawer_opened_at` (text, null): `id`, `bill_payment_id`, `sale_id`, `tender_id`,
   `submission_id`, `fingerprint`, `applied_amount`, `tip_amount`, `reason`, `authorized_by`,
   `requested_by`, `attested_by`, `attestation_note`, `source`, `device_id`, `node_id`, `method`,
   `manual`, `provider`, `provider_payment_ref`, `state`, `created_at`, `completed_at`, `failed_at`,
   `sent_at`, `send_count`, `refs_before_send`, `provider_refund_ref`, `provider_status`,
   `last_lookup_at`, `next_retry_at`, `drawer_opened_at`. `node_id` and `method` become nullable (null on
   the bill kind); `manual` keeps `not null default false`.
2. Keys: `bill_payment_id` → `bill_payments`, `sale_id` → `sales`, `tender_id` → `tenders`, `device_id`
   → `devices`, `node_id` → `nodes` (all restrict, as today); `authorized_by`, `requested_by`,
   `attested_by` → `persons` (U11).
3. CHECKs (each today's, named for the new table, applied per kind where today's differ):
   - `refunds_kind_ck`: `(bill_payment_id is not null) <> (sale_id is not null) and (sale_id is null) =
     (tender_id is null)`.
   - `refunds_kind_columns_ck`: on the bill kind, `node_id`, `method`, `provider`,
     `provider_payment_ref`, `provider_status`, `last_lookup_at`, `next_retry_at` are null and `manual =
     0`; on the tender kind, `node_id` and `method` are not null.
   - `refunds_state_ck`, `refunds_source_ck`, `refunds_source_device_ck`, `refunds_completed_at_ck`,
     `refunds_failed_at_ck`: identical on both tables today.
   - `refunds_amounts_ck`: the bill kind keeps `bill_payment_refunds_amounts_ck`'s rule; the tender
     kind keeps `tender_refunds_amounts_ck`'s (whole numbers, total 1 to 99999999999999).
   - `refunds_sent_ck`: per kind likewise (`_sent_ck` of each).
   - `refunds_attestation_ck`: both tables' rule (they say the same thing).
   - Tender kind only (today only on `tender_refunds`): `refunds_method_ck`, `refunds_reason_ck`,
     `refunds_provider_ck`, `refunds_provider_status_ck`, `refunds_refs_ck` — each written as
     `sale_id is null or (<today's expression>)`.
4. Indexes: `refunds_bill_submission_key` unique `(bill_payment_id, submission_id) where bill_payment_id
   is not null`; `refunds_sale_submission_key` unique `(sale_id, submission_id) where sale_id is not
   null`; `refunds_pending_tender_key`, `refunds_pending_capture_key`, `refunds_provider_event_key` (today's
   three partial uniques, predicates unchanged); `refunds_recovery_idx` (as `tender_refunds_recovery_idx`);
   `refunds_created_at_idx (created_at)`.
5. Triggers in `packages/db/triggers/core.sql`: `refunds_guard_update` and `refunds_no_delete`
   (Task 2), replacing the two `bill_payment_refunds_*` triggers here and the two `tender_refunds_*` ones
   in os13.
6. Row types with guards (Task 1): `BillRefundRow` and `TenderRefundRow`, so no server file handles the
   nullable kind columns by hand.
7. The bill kind's code moved onto `refunds`; `bill_payment_refunds` deleted.

## Global Constraints

- Rules §1–§9. Every refund behaves as today: the same states, the same refusals, the same money.
- `drawer_opened_at` is set at most once and never cleared (tables-devices.md §3).
- `refunds` is never deleted. Its request columns never change; `state` and the outcome columns move only
  while `pending`; `drawer_opened_at` is set once, in any state, and never changes after.

### Task 1: The table and its row types

**Files:** `packages/db/src/schema/refunds.ts`, `refunds.test.ts`; `packages/db/src/classification.ts`;
`packages/db/src/testing/seed.ts`.

**Interfaces (exported from `@waitron/db`):**
- `type RefundRow = typeof refunds.$inferSelect`.
- `type BillRefundRow = RefundRow & { billPaymentId: string; saleId: null; tenderId: null; nodeId: null;
  method: null }` and `isBillRefund(row: RefundRow): row is BillRefundRow` (`row.billPaymentId !== null`).
- `type TenderRefundRow = RefundRow & { billPaymentId: null; saleId: string; tenderId: string; nodeId:
  string; method: "cash" | "card" }` and `isTenderRefund(row: RefundRow): row is TenderRefundRow`
  (`row.saleId !== null`).
- `requireBillRefund(row: RefundRow): BillRefundRow` and `requireTenderRefund(row)`: throw
  `Error("refund <id> is not a bill refund")` (a fault in Waitron, not a user refusal) when the guard fails;
  server code reading one kind by a kind-filtered query narrows with these.
- Test helpers `seedBillRefund(db, values)` and `seedTenderRefund(db, values)` in
  `packages/db/src/testing/seed.ts`, each filling its kind's required columns.

### Task 2: The guard trigger

**Files:** `packages/db/triggers/core.sql`; `packages/db/src/trigger-refusals.ts`;
`scripts/behavioural-triggers.test.ts`; `packages/db/src/schema/refunds.test.ts`.

`refunds_guard_update` raises `REFUND_CHANGE_REFUSAL` unless:
- every column of `bill_payment_refunds_guard_update`'s and `tender_refunds_guard_update`'s fixed lists is
  unchanged (`id`, `bill_payment_id`, `sale_id`, `tender_id`, `submission_id`, `fingerprint`,
  `applied_amount`, `tip_amount`, `reason`, `authorized_by`, `requested_by`, `source`, `device_id`,
  `node_id`, `method`, `manual`, `provider`, `provider_payment_ref`, `created_at`); and
- **bill branch** (`old.bill_payment_id IS NOT NULL`): today's bill trigger's two alternatives
  (`0000_baseline.sql:3079-3094`) unchanged; **tender branch** (`old.sale_id IS NOT NULL`): today's tender
  trigger's two alternatives (`:3354-3375`), which also hold `provider_status`, `last_lookup_at`,
  `next_retry_at` in the "unchanged" alternative; and
- `(old.drawer_opened_at IS NULL OR new.drawer_opened_at IS old.drawer_opened_at)` (tables-devices.md §3).

`refunds_no_delete` raises `REFUND_DELETE_REFUSAL` on every delete.

- [ ] **Step 1: Write the failing tests** in `scripts/behavioural-triggers.test.ts` (replacing the bill
  refund cases, same assertions with the new constant), each with refused and accepting writes, for each
