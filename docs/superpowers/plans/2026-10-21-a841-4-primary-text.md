## Decisions this plan makes (the design left them open)

**D1. TDD here means the guard is the failing test for the twelve `color:` moves.** A CSS token
swap on a screen has no behaviour a screen test would fail on first. Task 1 writes the guard, runs
it, and watches its tree case fail listing exactly the twelve text sites (table rows 1-8, 10, 11,
14, 15); the moves make it pass. The one moved site the guard cannot see, the printers screen's
redeclared token, gets its own failing browser test (Task 2), with the two tokens set to different
values so the test fails if the site reads the wrong one.

**D2. Both `apps/setup` link rules move too** — `form-styles.ts:49` and `initial-setup-screen.ts:26`.
The design calls its two setup uses optional (lines 1871-1872): `form-styles.ts:49`, a link, which
moves, and `provisioning-screen.ts:41`, the spinner, which stays as a graphic. Three
reasons: Waitron's own blue is 4.33:1 on the light page, under 4.5:1, so it is a readability fix
with or without a theme; setup already reads the token (`apps/setup/src/screens/recovery-allocation.ts:76`),
so it is there; and the guard then needs no setup exemption, so `GRAPHIC_USES` holds graphics
only. The setup spinner (row 12) and the logo's fill stay.

**D3. The guard keys an allowlisted use by file plus the selector of its rule, never a line
number.** Each `GRAPHIC_USES` entry must match exactly one declaration: none (the use was removed)
or two (a second rule with the same selector in that file) fails the tree case, so the list
shrinks and does not quietly grow. The selector is the rule's text up to its `{`, with comments
removed, `<style…>` and `</style>` tags blanked, and whitespace folded to one space; an inline
`style="…"` has no rule and is reported with an empty selector.

**D4. The diagnostics warn line moves to `--wt-color-primary-text`, and its comment's false clause
goes.** The comment at `diagnostics-screen.ts:60-61` says "there is no dedicated warning token, so
warn borrows the primary accent"; `--wt-color-warning` is declared at `colors.css:26`. But no rule
holds `--wt-color-warning` at 4.5:1 as text on the surface the log sits on (`.log`,
`diagnostics-screen.ts:47`): it is held at 4.5:1 as text only on the station fills
(`contrast-rules.ts:241-246`), and at 3:1 as a table mark (`:214`), so switching to it would trade one unchecked text colour for
another. The rule stays on the brand's text colour; the comment keeps only "Unknown levels fall
through to the inherited text colour."

**D5. The guard's logic lives in the `.test.ts` file and is exported from it**, as
`tooltipsOutsideHelpMode` is (`scripts/help-tooltip-mode.test.ts:22`). The root project's
`coverage.include` is `scripts/**/*.mjs` and one `packages/db` file (`vitest.config.ts:119`), so
logic inside a `.test.ts` is not measured and needs no include entry; moving it to a `.mjs` module
would bring it under 98/98/98/95 and buys nothing a unit case does not.

**D6. The guard reads literals, not raw text, in `.ts` files, and only `<style>` blocks in `.html`
files.** A raw-text scan that removes `/* … */`
comments reads `"image/*"` as the start of a comment and blanks everything up to the next `*/`.
Probe (`probes/hazard.mjs`, `hazard-output.txt`): for
`const accept = "image/*"; css\`.x { color: var(--wt-color-primary); }\`; const g = "a/*/b";` the
raw scan printed `[]` and the literal scan `[{"line":2,"selector":".x"}]`. So `.ts` files are
parsed with `ts.createSourceFile` and only string and template literals are read. Each `${…}` is
blanked to spaces WITH its `${` and `}` (unlike `help-tooltip-mode.test.ts:29-35`, which blanks the
expression only), so a binding's braces never count as a rule's and a selector keeps its prefix:
`` css`.tone-${t} { color: var(--wt-color-primary) }` `` is keyed `.tone-`. CSS comments are removed
inside each literal; a literal holding both an `"image/*"` and a later `*/` would still hide what
lies between, a miss the header names. `.css` files are read whole. An `.html` file is blanked
outside its `<style>…</style>` blocks before anything else, so its markup (an `accept="image/*"`)
can neither open a comment nor join a selector: `git ls-files 'apps/*.html' 'packages/*.html'` lists
six files, five with a `<style>` block (`apps/dashboard/index.html`, `apps/setup/index.html`,
`apps/till/index.html`, `packages/fiscal-verifactu/src/custodian/tool.html`, `packages/ui/index.html`),
none holding `/*` today. Inline `style="…"` in an `.html` file is therefore not read (a miss).
Probe (`probes/cases-v2.mjs`, `cases-v2-output.txt`): an `.html` `<style>` rule after an
`accept="image/*"` is keyed `.h` on its line; a TS template's `<style>.n { … }` is keyed `.n`, not
`<style>.n`; a `// color: var(--wt-color-primary)` code comment is not refused.

**D6a. The guard reads the files `git ls-files` lists, not a directory walk** (controller ruling).
Three packages write HTML coverage reports into an untracked `coverage/` folder
(`apps/dashboard/vitest.config.ts:119`, `packages/ui/vitest.config.ts:117`,
`apps/till/vitest.config.ts:77`), and each `*.ts.html` report embeds the source, so a walk would
read stale copies and the pre-push hook's root run would refuse a push for files nobody committed.
Probe: with an untracked `packages/ui/coverage/a841-probe.ts.html` holding a `<style>` rule in the
button colour, the directory walk (`probes/scan-ts.mjs`) read 2556 files and reported
`packages/ui/coverage/a841-probe.ts.html:2`; the `git ls-files` selection (`probes/scan-v2.mjs`)
read 2555, none under `coverage/`, and reported only the 17. Selection copies
`scripts/style-token-names.test.ts:95-106`: `git ls-files -z -- apps packages`, `cwd` the repo root,
`env: isolatedGitEnv()` (the `GIT_*` variables cleared, `:46-60`), `timeout: GIT_SPAWN_TIMEOUT_MS`,
filtered to `.ts` (not `.test.ts`), `.css` and `.html`.

### Task 1: The guard, and the twelve text sites move

**Files:**

- Modify: the twelve sites (table rows 1-8, 10, 11, 14, 15), one line each;

**Interfaces:**
- Produces, exported from `scripts/primary-coloured-text.test.ts`:
  - `type PrimaryColourDeclaration = { line: number; selector: string }`
  - `primaryColourDeclarations(source: string, kind: "ts" | "css" | "html"): PrimaryColourDeclaration[]` —
    `"ts"` reads string and template literals only, each `${…}` blanked with its delimiters (D6);
    `"css"` reads the whole source; `"html"` blanks everything outside `<style>…</style>` blocks
    first. In each piece read, `<style…>`/`</style>` tags and CSS comments are blanked (keep
    newlines, so lines map back), then a declaration is a match of
    `/(?<![\w-])color\s*:\s*var\(\s*--wt-color-primary\s*[,)]/gi`. The selector: scan back from the match to the unmatched `{`
    (counting `}` and `{`), then back to the previous `{`, `}` or `;`; the text between, whitespace
    folded, trimmed; `""` when there is no `{`.
  - `type GraphicUse = { file: string; selector: string; draws: string }`
  - `GRAPHIC_USES: readonly GraphicUse[]` — the five rows that stay (9, 12, 13, 16, 17), file and
    selector exactly as in the table; `draws` one short phrase ("the add tile's + icon", "the
    provisioning spinner's ring", "the card-waiting spinner's ring", "the column chooser's eye
    icon", "the − and + icons").
  - `sourceFiles(): string[]` — D6a's selection, repo-relative paths.
  - `unlistedDeclarations(found: ReadonlyMap<string, readonly PrimaryColourDeclaration[]>, allowed: readonly GraphicUse[]): { offenders: string[]; stale: string[] }` —
    `offenders`: every declaration no entry names, as `` `${file}:${line} ${selector}` ``, sorted;
    `stale`: every entry that matched other than exactly once, as `` `${file} ${selector} (found ${n})` ``.

- [ ] **Step 1: Write the guard file.** Header comment, in the shape of
  `scripts/help-tooltip-mode.test.ts:1-9`: the rule ("Text in the brand colour reads
  `--wt-color-primary-text`; `--wt-color-primary` paints fills, lines, outlines, icons and spinners",
  pointing at `docs/developers/design-system.md` → Colour) and "Weaker than its name: it reads TEXT"
  with every miss: a rule that sets another token to the brand colour
  (`--wt-color-text: var(--wt-color-primary)`); `fill:`, `stroke:` (an SVG `<text>`),
  `-webkit-text-fill-color`; a `var()` inside another function (`color-mix(…)`, `rgb(from …)`);
  `currentColor` or `inherit` from a parent in the brand colour; any colour set from script
