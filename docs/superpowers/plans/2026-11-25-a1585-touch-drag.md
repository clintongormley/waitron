# A1585: Keep touch holds on the till

**Finish line.** Hold a dish in **New order** or a course heading, wait for the outline, then drag and release where it belongs. A stationary hold still opens dish details where it already does. The menus for moving dishes or groups remain available.

**Reproduction.** On Chromium 159, the existing `touchGesture` sends trusted touch input but the default Chromium mode skipped `contextmenu` during a 1,050 ms hold. With `--enable-features=SyntheticPointerActions`, the same CDP `Input.dispatchTouchEvent` on the real New order row sent a trusted touch `contextmenu` after 652 ms. The test failed because the till left it uncancelled. The headless run still moved the dish and recorded no `pointercancel`. The owner saw the browser menu on the Pixel Tablet. The physical retest stays open under A773.

## Regression first

- Add a Chromium instance in `apps/till/vitest.config.ts` for the new touch-menu test file, with the alternate input mode confined to that instance. Reuse `touchGesture` and the draft fixture behind `till-table-order-screen.drag.a11y.test.ts`. Send a held touch, move and lift. Require that Chromium emitted a trusted touch `contextmenu`, that the component cancelled it and that the dish reached the existing course. A short tap still selects a row. If the new instance cannot reuse `parkTouch` unchanged, confine cleanup to that test context.
- Use the same browser input on a held-group heading and a stationary dish hold in `widgets/sent-orders.ts`. Assert the group reorder and opening details where the hold belongs. Keep existing mouse and keyboard assertions in the drag and sent-order suites. Check a right-click on an affected row is still available to the browser.

## Smallest fix

- Add `preventTouchContextMenu(event: PointerEvent)` to `packages/ui/src/gestures.ts` and export it from `packages/ui/src/index.ts`. It cancels only touch menus. Attach it to the existing drag targets in `screens/till-table-order-screen.ts` and `widgets/sent-orders.ts`, and to the existing touch-for-details targets in `widgets/sent-orders.ts`, `widgets/basket.ts` and `widgets/last-added.ts`. Keep the basket's existing check that the hold belongs to the line and leave its buttons and fields alone.
- `widgets/menu-browser.ts` and `wt-floor-map.ts` already cancel context menus and use their own keyboard behavior. `wt-floor-plan-canvas.ts` starts table moves without waiting for a hold. Keep the shared recognizer's pointer dispatch and those existing bindings. No new handle, timing, layout, order command or server change.
- Add one instruction for moving an unsent dish by touch to the **Taking an order on a phone** section of the English and Spanish `apps/server/src/guide/*/table-service.md` guides. Keep the tablet test open in `docs/backlog/printers.md` until the owner reports the result.

**Checks.** See the new cases fail on current code and pass after the fix. Run the changed touch suite, existing draft drag, basket, sent-order and last-added cases, UI gesture tests, the pointer registration and guide link guards, and Lane H's fiscal and published-menu gates. Inspect the draft drag captures in both languages, themes and widths. Use the normal hook and current-head CI before landing.

**Expected size.** About 20–35 added product lines including imports, 65–115 test and fixture lines, and two short guide additions. No generated changes.
