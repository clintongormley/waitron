### Bind every operation to its node and recovery generation

`RoutingOrigin` is a required part of preparation, acceptance, lookup, fencing, inventory and acknowledgement for print and Invoice saves, not a hint to be rewritten by the receiving node. `OperationIdentity` carries that origin plus the request/save key on every operation route and client method. The server compares the complete origin to its trusted current origin **before creating or looking up protocol rows**, and refuses mismatches without changing the origin or allocating a fresh key. Intent and result carry that same origin; preparation rejects an intent/envelope mismatch. Add originating-node and epoch mismatch to Task 1 canonical/parse tests and Tasks 4/7/9 refusal tests, including re-preparing an old key on another node, not just accepting an absent foreign row.

Concrete proposal for G4 agreement: an injected `RoutingOriginSource.current(): RoutingOrigin` reads the configured node id and a UUID recovery epoch from private node-owned `document-routing-origin.json`. First activation creates it through the approved A947 activation path, before enabling these operations; an ordinary restart retains it. The approved restore/reimage path allocates a new epoch before serving commands, even when node id is retained or a database/counter goes backwards. No clock-derived epoch, automatic startup minting, archive import of another node's origin or fallback from a missing file. Missing or unqualified origin keeps delivery and competing Invoice-save commands unavailable without blocking sales. G4 must release and qualify the activation/restore interfaces before this adapter or any live cut runs; plan publication is not that qualification.

Add `apps/server/src/document-routing-origin.ts` and its focused test in Cut B/Task 4. Trace `apps/server/src/archive-entries.ts`, `state-secrets.ts` and `restore.ts` with A947 before integration: keep this private origin out of portable archive/bucket restoration. Test normal restart retention, same-node restore with a lower acceptance counter, foreign-node preparation, stale boot and an origin file missing beside existing journal rows. Retain old rows/tombstones; do not make them fresh by renaming their origin. A cloned server/disk that preserves every identity still needs A947's fencing/recovery qualification; this local file does not establish that an old writer stopped.

Dashboard preference keys remain appliance/venue/document, with no extra expiry or reset. Across recovery epochs retain the remembered printer id and filter it through current offers. Compare sequence integers only inside the same origin. Obtain the current origin through an authenticated current offers/recovery exchange before allowing a new accepted result to update that key; delayed old-origin responses cannot replace a newer result. A current-origin acceptance may supersede the earlier provenance only after outstanding old-origin uncertainty is resolved under G4. Test reverse replies across epochs where the old counter is larger, confirming the newer current-origin result wins and ordinary reopening clears no preference. Unknown work from an earlier epoch is held for qualified recovery, never resubmitted under the new origin. Full loss of the old journal remains an explicit blocked recovery case, not a no-duplicate-print guarantee.

The server resolves printer kind and location rather than trusting a body kind/location. It checks the confirmed appliance id against its own configured identity before preparation or acceptance, refusing foreign-node operations rather than making them fresh. Canonical encoding includes every `RoutingOrigin` member, the complete normalized intent, resolved printer kind and sale location; language and context never disappear on replay. Authorization credentials are runtime inputs, never canonical intent. A fingerprint checks equality, not permission. Reject unknown enum values, arrays/coercions and explicit null except the fields whose types above admit null. Shared parsers throw a plain `TypeError` with the invalid field; server adapters translate that to existing `management.request_invalid`, keeping server error registries out of shared code. A request-key/intent mismatch uses existing `submission.id_reused`.

Register new domain codes `document_delivery.designation_changed`, `document_delivery.context_changed`, `document_delivery.request_unavailable`, `document_delivery.foreign_appliance`, `device.invoice_revision_stale` and `device.invoice_save_unavailable` in `apps/server/src/errors.ts`, with 409 status mappings and EN/ES wording in both apps. Designation/context refusals carry the refreshed authorized offer for review; invalid-printer errors retain existing codes. No error/log payload carries credentials or customer details.

Context is server-authored and round-tripped as a stale-context check, not as authority. F2 reprint offers only Receipt and duplicate designation. Existing F1 original/copy comes from the shared delivery state. If the same id resolves to conflicting printer kinds, refuse it rather than infer cross-table uniqueness.

Preserve language choices only where the current surface offers them. Otherwise `languages` contains only the recorded document language and `language` is still part of the canonical intent.
