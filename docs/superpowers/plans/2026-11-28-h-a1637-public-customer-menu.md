# A1637 public customer menu on the box

A test venue can serve its published customer menu over a separate HTTPS socket so Cloud can pair its gateway. The dashboard preview stays on the signed-in staff route. The two repositories qualify the public link on mobile data together. Cloud enablement, dashboard sharing controls, dish pages, uploaded fonts and hosted-copy retirement stay in their delivery steps. [Joint design](../specs/2026-11-25-customer-menu-public-access.md) · [Delivery 6](../specs/2026-11-24-customer-menu-design.md#delivery)

## What Cloud can request

- Connect to the signed route's tunnel IPv4 address on **8443**, with the staff hostname as TLS server name and HTTP Host. The tunnel companion forwards only the gateway's traffic to `customer-menu.sock` beside `staff.sock`. The box admits only a serving test primary with remote access on and a matching staff certificate and Host.
- Accept only GET and HEAD with an empty query string, including refusal of a trailing `?`. `/` returns a list of online menus, redirects when there is exactly one, and returns 404 when there are none. `/<address>` redirects to `/<address>/<default-language>` with a relative `Location`. Return 302 for redirects. `/<address>/<language>` returns HTML with the snapshot embedded. Use the stored address and enabled canonical language tag. Reserve `/<address>/<language>/dish/<id>` for its later delivery. Existing Cloud availability and challenge paths keep their gateway handling.
- Serve `/_customer-menu/assets/<built-file>` from the built guest app's exact asset list, including any bundled fonts, and `/_customer-menu/{favicon.ico,favicon.svg,apple-touch-icon.png}`. Photos use `/_customer-menu/photos/v1/<64-lowercase-hex>.<jpg|png|webp>/<square|display>/<x>-<y>-<zoom>.webp`. Serve only recipes listed by the current public view. Small uses square at up to 480 × 480, large uses display at up to 1,600 pixels on the longer side, and None lists no images. Keep replies within Cloud's 2 MiB limit.
- Give successful HTML and redirects at most 60 seconds of freshness and allow framing. Content-named photos and build assets get one year. Stable icon paths get 60 seconds. Return 404 for an off or missing menu or an unlisted path, 429 for overload and 503 for a temporarily unavailable view. D643 PR 1c needs to forward the relative redirects and their cache headers. Its disabled PR 1b gateway currently accepts 200 as the only success status.

## Build and verify

- **Published view.** First fail `apps/server/src/customer-menu-public.test.ts` on the real menu fixtures. Check that only active regular menus with a live publication appear, that staff-only photos and all photos under None return 404, and that a committed switch-off, republish, language or style save changes the next view. Build `customer-menu-public-view.ts` with `readLiveDocuments`, `readContentLanguages`, `publicGuestMenu` and `readPresentations` for the displayed products. Use `customerMenuAppearanceFor` and Lane K's `prepareMenuAppearance` plus `CustomerMenuSnapshot` from #4546, with Waitron's built-in defaults. Invalidate on the relevant committed changes, coalesce refreshes and withhold a dirty view while rebuilding. Read on the store's committed read path. Use the existing photo renderer under a customer-only cache, with one render at a time.
- **HTTP and packaging.** First fail the listener tests on the new socket and the built Chromium smoke on a request to the real handler. Add a dedicated handler in `customer-menu-public.ts`, hook its lifecycle into `boot.ts` and reuse the staff certificate file watcher and failure cleanup. Add the guest build directory to `config.ts`, `environment-variables.ts` and `deploy/Dockerfile`. Reuse the built snapshot slot and escape `<` before embedding JSON. Test GET and HEAD, relative redirects, cache and framing headers, denial of staff and unlisted asset paths, and a stepdown on an already open socket. Bound the box to 120 requests per second and four concurrent requests, including photo work. Verify a sale and till image read finish during a controlled photo flood on the box.

Check that a missing or stopped customer proxy leaves 443 working. Qualify both listeners over real HTTPS before handoff to D643, including an unavailable box and a fresh page's assets after restart. The paired Cloud run owns takeover, upgrade continuity, blocking and the mobile switch-off proof.
