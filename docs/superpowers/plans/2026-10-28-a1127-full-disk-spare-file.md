# A1127: on a full disk, the box frees a recovery's copy with the help of a spare file — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Every implementer is dispatched as `subagent_type: "implementer"`; one that passes about 150 tool calls with its task unfinished stops at a passing or cleanly red point, commits, and returns a handover (done, left, files, each check's state).

**Goal:** the box keeps an 8 MiB spare file in its state folder. On a nearly full disk, the two paths that free a backup recovery's copy (the start's emptying of a discarded recovery, and the repair page's Start-again flow beside a stopped one) delete the spare first, so the venue locks can be taken and the copy deleted; the next start with room writes the spare back. The repair page gets a full-disk answer it can explain, and the start's full-disk page stops sending the person to somebody else.

**Architecture:** a new server module, `apps/server/src/spare-space.ts`, releases and tops up `<state>/spare-space` (name exported by `@waitron/provisioning` as `SPARE_SPACE_FILE`). `runEntry` (`apps/server/src/node-entry.ts`) tops it up on every start with room and passes the state folder down to `resolveFirstSetupEntry` (`apps/server/src/first-setup-entry.ts`), whose `emptyDiscardedRecovery` and repair app release it. The recovery's originals walk (`packages/provisioning/src/first-setup-backup-workspace.ts`) leaves it out. Three resolution routes answer `storage.disk_full` on a nearly full disk; the setup app and the recovery page get new words.

**Tech stack:** TypeScript, Node `fs/promises` (`open` with `O_NOFOLLOW`, `FileHandle.sync`), `crypto.randomBytes`, Hono, Vitest (real temporary folders; the small real filesystem of `apps/server/src/testing/full-disk.ts`; browser mode for `apps/setup`), Playwright Chromium for the look.

**Spec:** [`docs/superpowers/specs/2026-10-28-a1127-full-disk-spare-file-design.md`](../specs/2026-10-28-a1127-full-disk-spare-file-design.md) — read it first; every decision and receipt is there. The owner's answer is in `~/waitron-campaign/questions.md`, heading "OWNER ANSWER — A1042 full disk: A". Measurements: `~/waitron-campaign/a1127-measure/README.txt`.

**Review path:** FULL. It changes when venue locks can be taken on a full disk (concurrency) and what a backup recovery's originals walk reads (a cross-package contract). It touches no fiscal record. The PR lists the design's OPEN QUESTION Q1 for the owner.

**Open question:** Q1 (what the box says when nothing more can be freed) blocks nothing: Tasks 6 and 7 build its option A, and only those words change if the owner picks otherwise.
