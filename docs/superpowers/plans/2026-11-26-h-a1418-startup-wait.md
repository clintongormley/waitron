# A1418 slice 4 implementation plan — wait after an unexpected stop

A solo main box with backup streaming configured pauses before selling and filing after a power cut. It starts as soon as it gets a clear answer, or after 60 seconds of silence. Staff see why it is waiting, and managers get an email if it starts without confirmation. A planned restart and a box with no bucket skip the pause. [Approved design §§3, 6 and 9](../specs/2026-11-07-a1418-box-stop-intent-design.md) · [Landed replacement stop](2026-11-26-h-a1418-replacement-stop.md)

## 1. Decide whether the box can start

- Write failing cases in `stream-host.test.ts` and `boot.stop-mark.test.ts` first. Check no new sales or filing during a real boot wait, a clear answer releasing it, a newer verified pointer going straight to the saved replacement hold, and a late verified pointer stopping a box that started after silence. A hung read must be aborted at the deadline. Show that restart and unconfigured storage introduce no blocking read. Re-run `boot.start-check.test.ts` and `boot.restore.test.ts` for the peer and restore paths.
- In `stream-host.ts`, reuse the existing configured bucket, pointer read, solo chart test and local key verification. A successful absent-pointer read or a verified pointer for this box at or below its held term clears the wait. A verified newer pointer takes the existing replacement path. An unreadable or unverifiable answer means keep waiting. No bucket configured means nobody to ask. Reuse the same replacement verdict in the running observer. Keep the enrolled-peer reader as it is.
- In `boot.ts`, apply the pause before commerce and filing are mounted, only to a solo serving primary with a configured bucket and no restart mark. Read the restore phase before first-start processing, and exempt that restore boot even if it finishes processing its marker. Leave paired starts, mirrors, fences and the existing saved stop on their current paths. Extract the existing waiting-listener wiring into `startup-wait.ts` to make room within the `boot.ts` cap.
- Use the existing waiting lifecycle in `waiting-start.ts` with a bucket reason, an immediate first read and one steady 60-second deadline covering retries and an in-flight read. Abort on expiry or shutdown, discard results after leaving, and release listeners before continuing. Keep the bucket wait free of an admin bypass. If replacement verifies before expiry, save it and mount the existing hold before mounting commerce. Failure to write the stop fails that boot. After silence, start the existing observer and record `start.selling_unconfirmed` through `stop-alert.ts` and the normal mail duty. Declare the code in `errors.ts` and word it in `box-alert-email.ts` and Dashboard `alert-messages.ts`. Check the email copy in `box-alert-email.test.ts`.

## 2. Show why the box is waiting

- Use the existing waiting page in `waiting-page.ts` and `i18n/waiting-page.ts`, in English and Spanish. `node-api.ts` adds `waitingFor: "bucket"` to the waiting box's reply. `server-router.ts` tracks that reason for the answering main box while no box accepts sales. Clear it on a failed probe, an older reply without the field, or a selling reply. The existing lock-screen message and signed-in notice use the new wording through `till-lock-screen.ts`, `till-app.ts`, `server-connection-notice.ts` and `i18n/strings.ts`.
- Assert the page and probe together in the boot test. In `server-router.test.ts`, check a reason-only change updates the till without changing the selected box. Check the notice text in the lock-screen suite. Update `servers.md` and `till-notices.md` in both guide languages, `docs/backlog.md` and the affected startup rule and receipt in `CLAUDE.md` and `docs/developers/conventions-data.md`.

Budget about 260–380 product lines and 230–330 test lines. Run the touched suites, the alert and guide guards, both file caps, and Lane H’s fiscal and menu gates unedited. Use a disposable copy to prove removing the wait exposes commerce or filing before the answer. The shutdown action and its administrator wait, Cloud, early claims and a different identity at the same term stay with their own slices.
