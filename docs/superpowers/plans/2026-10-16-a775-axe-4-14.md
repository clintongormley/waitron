**Goal:** land axe-core 4.14.0 with every accessibility test green, by fixing what the new check
finds rather than switching the check off.

**Why:** axe-core 4.14.0 turns on `label-content-name-mismatch` by default (changelog: "Enable rule
by default (#5421)"; in 4.13.0 the rule carried the `experimental` tag, which axe skips). The rule
fails a button, option, link, cell or other control that has an `aria-label` or
`aria-labelledby` when its visible text is not, word for word and unbroken, inside the name a
screen reader announces. That is WCAG 2.5.3, Label in Name: _"For user interface components with
labels that include text or images of text, the name contains the text that is presented
visually."_ The rule's matching (read from `axe.js` 4.14.0, `labelContentNameMismatchEvaluate` and
`isLabelContainedInName`): both texts are lower-cased, text in parentheses is dropped, anything
that is not a letter or a number becomes a space, and the visible words must appear as one
unbroken run of the name's words. The rule only looks at controls with an `aria-label` or
`aria-labelledby`, exactly as the ACT rule it implements does (ACT 2ee8b8, "Applicability": _"The
element has an aria-label or aria-labelledby attribute"_). A control named by its own content
always contains its visible text, so it is outside the rule by construction.

The branch's first commit (`84b267d2f`) bumped axe-core to `^4.14.0` in `packages/ui`,
`packages/ui-core`, `apps/setup`, `apps/till` and `apps/dashboard`; `pnpm-lock.yaml` resolves
4.14.0 (checked with `node -p "require('axe-core/package.json').version"` from each of the five
package folders: `4.14.0` each). The branch is red until the tasks below land.

**Group A, why not the APG's current pattern.** The APG marks the button-plus-listbox pattern
`wt-combobox` follows as deprecated (its "Collapsible Dropdown Listbox" page: _"This pattern has
been deprecated … The select-only combobox should be used as an alternative"_). That same page
names the button exactly as this fix does: _"aria-labelledby="ID_REF1 ID_REF2" … The first element
is a span containing text Choose an element: . The second element is the button itself; the button
text is set to the name of the currently chosen element."_ Moving to `role="combobox"` changes the
role every test and screen reader meets, needs `aria-controls` (the experiment's 44
`aria-required-attr` failures) and puts two comboboxes in one widget (the open list's search box is
already one). That is a larger change worth its own backlog entry; this branch keeps the button and
fixes its name.

**Group B is a change to a documented decision.** `design-system.md`'s `wt-combobox` row says a
described row "is then named by its label alone (`aria-labelledby`) with the description as its
`aria-describedby`" (A210, #1070). The ACT rule axe implements treats all visible inner text of an
option as label text, so that contract fails WCAG 2.5.3 as axe and the ACT rule read it. The plan
names the row by its whole content; the PR description must call this out for the owner.

**Group D keeps a decision's purpose.** `wt-language-chooser.test.ts` has "a page's ::part rules
swap the name for the code, and the trigger keeps the full name". The fix keeps the full name in
the screen-reader name ("ES Español") and adds the drawn code.

**Nothing here touches a sign-in route, a device route or the server.** The language chooser is
drawn on the till's sign-in and lock screens, and only its trigger's accessible name changes. All
changes are browser UI and their tests; no risk trigger is touched, so this takes the light review
path (no per-task reviewer), with the plan-vs-spec read and the Codex run-it seat in
`/finish-branch` as usual.

## Global constraints

- Read `CLAUDE.md` §1 and §4, `docs/developers/testing-guide.md` and the `wt-combobox`, "Accessible
  names" and "Accessibility testing (axe)" parts of `docs/developers/design-system.md` first.
- Never narrow axe's rule set, never add a rule exclusion, never mark drawn text `aria-hidden` just
  to take it out of axe's reading. The fix is always one of two shapes: (1) **name from content** —
  remove the `aria-label`, so the drawn text is the name, and add context the eye gets from the
  layout as visually hidden text; or (2) **an `aria-label` whose words include the drawn text as one
  unbroken run**.
- A visually hidden span uses the component's own `.visually-hidden { ${visuallyHiddenStyles} }`
  rule (from `@waitron/ui`'s `base-styles`). Add the rule where the component lacks it. Every task
  that adds one checks, in a test, that the span's `getBoundingClientRect().width` is at most 1 —
  the first day-cell experiment passed axe with its "hidden" text on screen.
- Put hidden spans beside a drawn element, never inside it (`.date`, `.station`), so a test that
  reads a drawn element's `textContent` keeps reading only what is drawn.
- **For a name-from-content fix, a green a11y file proves nothing about the name.** axe's matcher
  (`labelContentNameMismatchMatches` in `axe.js` 4.14.0) skips any control with no `aria-label` or
  `aria-labelledby`, so deleting the `aria-label` turns the file green whatever the button now
  says. The evidence is the `toHaveAccessibleName` read-back test plus the 1 px check; run the
  read-back test once against the unfixed component (or with the hidden span deleted) and watch it
  fail before trusting it.
- A test that read `getAttribute("aria-label")` and now meets a name from content is rewritten to
  `await expect.element(page.elementLocator(el)).toHaveAccessibleName(...)` with the same words;
  keep what it checked. Every changed assertion is named in the commit message and, by the final
  task, in the PR description (the lane's rule: a check may change when the dependency changes what
  it checks; the test's purpose must survive).
- Name every new or changed string in both `en` and `es`.
- Comments: only an invariant or a non-obvious why. The one worth writing at each site: why the
  context is visually hidden text rather than an `aria-label` (one line, pointing at WCAG 2.5.3).
- Local runs are focused (the files each task lists); CI runs the package suites. Check free memory
  first (`memory_pressure | grep free`); stop only processes you started.
- Unset `AI_AGENT` and `CLAUDECODE` to see output (`env -u AI_AGENT -u CLAUDECODE pnpm exec vitest
  run …`). A run that prints no `Tests` count proves nothing.
