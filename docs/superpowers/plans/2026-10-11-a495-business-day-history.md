# A495 business-day history implementation plan

> **Execution:** the driver implements inline, task by task. Read `superpowers:executing-plans` and, before writing product code or tests, `superpowers:test-driven-development`. No mandatory implementation agents. Checkboxes track execution; this planner has implemented none of them.

**Goal:** schedule a future business-day start while preserving existing report grouping and recorded closes.

**Architecture:** retain the location's initial start and read dated changes through one shared browser-safe boundary resolver. Core owns the timeline; venue-service owns schedule compatibility; server routes serialize and validate future writes. Activation is a read of the timeline, including after restart.

**Tech stack:** existing TypeScript, SQLite/Drizzle, Intl, Hono, Lit and Vitest/Chromium. No new dependency or tool installation.

**Spec:** [A495 design](../specs/2026-10-11-a495-business-day-history-design.md). Read it first, including the verbatim requirements and source trace.

## Global constraints

- Only future start changes. Effective date is today plus 2 through plus 366 venue calendar days. One pending change, editable only before the preceding day starts. Explicit stored time zone, no machine/browser defaults.
- Preserve initial cutover and every effective change; retain the time zone history lock. Refuse scalar cutover edits through the general editor; equivalent values remain no-ops. No compatibility/data conversion or shipped migration edits.
- No edits anywhere in `packages/fiscal-verifactu`, fiscal hash/invoice allocation, daily-close hash generation/shape, saved closes or their goldens. No money/VAT algorithm change.
- Real database tests use `useVenueDb`. Rejected requests assert the domain code. Each behavioral increment begins with a test, an observed expected red, minimal code, then an observed pass; compilation/fixture failure alone is not the intended red.
- Deletion controls run in a disposable isolated checkout containing the candidate tree, with installed dependencies; never swap old files into the feature checkout. Restore experimental edits there and remove that checkout when done.
- Focused local behavior checks, normal push hook once, scoped coverage/current-head CI. No automatic whole-workspace run, no hook bypass. Commit only via `git commit -s`, with hooks intact.
- One completed Claude run-it whole-branch review during `finish-branch` after initial rebase. The owner approves landing; do not merge from unattended campaign authority.

## Review focus

1. Queued save/cancel reaches the transition lock boundary while waiting, or an editor observes an ABA revision sequence (Task 3).
2. The repeated DST hour changes a live day label backwards, or the 26-hour transition replays early service (Tasks 1, 4).
3. A future-dated close/event or dormant schedule escapes checks and later disagrees with historical reports (Tasks 2–4).
4. A past/future week or yesterday's grace uses today's start, and a stale browser preview enables Save (Tasks 4–5).
5. A persisted scheduler deadline changes on restart, or configuration cloning transports a source timeline (Task 6).
