# Printer Discovery Freshness Implementation Plan

A clock correction during printer setup can hide a report while the device is still reachable. Staff should be able to find, pair or register a freshly reported printer for the usual length of time across a forward or backward clock correction. This slice covers in-memory discovery reports and their server callers. The [owner's steady-clock request and discovery inventory](../../backlog/box.md#one-steady-clock-helper-instead-of-hand-written-clock-step-back-guards) define the scope. Lane H's 07:02 watcher assignment names this slice.

- [ ] Add the failing tests in `apps/server/src/print-api.test.ts`. Extend “drops a reported device once its last report is older than fifteen seconds” to hold the steady clock while stepping the wall clock by a day in either direction. Assert that the report stays listed with its original ISO `lastSeenAt`, then advance the steady clock to 15,000 and 15,001 ms and assert that the row disappears only at the second read. Give the open-window case (“keeps listing devices reported once per slow scan pass”) a steady-clock advance. Use the office registration cases to check that the named agent's newer report wins after a backward wall-clock step (including a newly unprintable report). Keep the existing same-pull printable preference. Run the new assertions against the old implementation and record the failures.
- [ ] In `print-api.ts`, take one `steadyNow()` reading for the reports in a pull. Track the latest report's steady timestamp (for age and ordering) alongside its epoch `lastSeenAt` (for the dashboard's date and probe matching). Move the scan, pairing, visibility and agent Bluetooth capability stamps and their readers to the steady clock. Keep the 15-second visibility limit and 60-second capability limit, including their endpoints. Keep capability expiry timers and change events and exclude the new report timestamp from the inventory change comparison. Use the existing steady discovery deadline for listing, Pair, Forget and receipt-versus-office address checks. Return the existing epoch `discoveryUntil` on start and renew and keep the duration calculation for agent pulls.
- [ ] In `discovery-listing.ts`, make `withinTtl(at, now, ttl)` compare elapsed milliseconds on the steady clock. Keep `isListed(at, now, discoveryEnd)` and its 15-second closed and 45-second open limits, with the longer limit ending at the discovery deadline. In `page-printers.ts`, pass the steady report timestamp and current window readings through the existing `PagePrinterDiscovery` and `DiscoveryWindow` interfaces in `page-printers-api.ts`. Pick the latest matching queue by the steady report timestamp in `print-api.ts`, using one shared timestamp per pull to preserve the printable tie-break.
- [ ] Keep the held-printer, Pair and Forget, queue-visibility and Bluetooth capability assertions in `print-api.test.ts`, advancing each clock where its behaviour depends on it. In `discovery-listing.test.ts`, pin absent reports and the inclusive boundaries on either side of window closure. Use `page-printers.test.ts` for registration's existing cutoff and refusal assertions. Update the direct registration fixtures in `configuration-transfer.test.ts`, `invoice-page-print.test.ts` and `page-print-api.test.ts` if the field names change. Run the changed server test files and the Lane H queue gates. Remove the discovery inventory row in `docs/backlog/box.md` and sign off the commit.

Expected size is 70–110 changed production lines and 180–300 changed test and fixture lines, counting additions and deletions, plus the backlog row.
