## What it builds

1. The `outgoing_mail` table as jobs.md §2 drafts it, with every kind the design names in its kind
   list (`invoice` and A1002's `role_membership_changed` included), plus one column the draft lacks,
   `seq`, so rows due at the same moment are claimed in a fixed order (decision D).
2. The queue API in `@waitron/db`: `enqueueMail`, `cancelMail`, `readMail`, `MAIL_LIFETIME_MS`.
3. The sender, `apps/server/src/mail-sender.ts`:
   - it touches only rows of kinds it has an owner for;
   - it resolves the delivery (saved server, practice inbox or unconfigured) inside the claim
     transaction; while email is unconfigured it leaves rows untouched and logs no error (A);
   - the claim commits before SMTP; the owner words the mail at claim and may cancel it;
   - `rejected` (N1: refused, or never reached the server) is retried with back-off; `unknown` or an
     abandoned claim is never sent again; a row still waiting past `not_after` is `expired` (a row
     being sent ends only when its claim lapses, as `unknown`); a row whose owner's claim throws
     waits its back-off as `rejected`, `mail.claim_failed`, so it blocks nothing; a row waiting for
     a retry holds no claim and no address;
   - it takes the stop signal as `signal` and re-checks it and the primary role inside the claim
     transaction and again between claim and send (N3); a claim stopped there is **released** back
     to `pending`, because nothing reached the server (B);
   - a test seam between its first read and the claim transaction (N4);
   - rows due together are claimed by `next_attempt_at`, then `queued_at`, then `seq` (D).
4. The `account_action` owner, for all three purposes (password reset, invitation, email change).
5. Boot: the sender runs on the full start (`if (!fencedOrMirror)`, primary only) with that owner,
   after boot has awaited `abandonMailClaims`; the repair, restricted and waiting starts start none
   (3a-iii adds an account-mail sender to the repair start, with the producers).

### Task 3: The sender

**Interfaces — produced (FIXED; the registry later slices plug into):**

```ts
export interface ClaimedMail {
  id: string; kind: OutgoingMailKind; dedupeKey: string; subjectId: string | null;
  personId: string | null; requestedBy: string | null;
  params: Record<string, string | number | boolean | null>;
  attempts: number;   // including this one
  queuedAt: string; notAfter: string;
}
export interface MailMessage { subject: string; text: string; html?: string; attachments?: SendMailOptions["attachments"] }
export type MailSettlement =
  | { status: "sent" }
  | { status: "rejected"; failureCode: OutgoingMailFailureCode; serverRefused: boolean }
  | { status: "unknown"; failureCode: OutgoingMailFailureCode }
  | { status: "expired" };

/** One per kind; a new kind is one owner in the list boot passes to startMailSender. */
export interface MailKindOwner<Prepared = unknown> {
  readonly kind: OutgoingMailKind;
  readonly deliveryRule: MailDeliveryRule;          // 3a-i
  /** Waits after the 1st, 2nd, … rejected attempt; [] = the queue never retries this kind. */
  readonly retryDelaysMs: readonly number[];
  /** The furthest ahead of now this kind sets next_attempt_at; a row further ahead was set before
   * the clock stepped back and is due at once. At least max(retryDelaysMs). */
  readonly longestWaitMs: number;
  /** In the claim transaction. null cancels the row. A throw rolls the claim back and the row waits
   * its back-off as rejected, mail.claim_failed. Its effects must be safe to repeat: a claim
   * released before sending is claimed again later. */
  claim(tx: Transaction, mail: ClaimedMail, now: Date): Promise<{ recipient: string; prepared: Prepared } | null>;
  /** After the claim committed. A throw ends the attempt rejected, mail.compose_failed,
   * serverRefused false: nothing reached the server, so the back-off applies (N1). */
  compose(prepared: Prepared, mail: ClaimedMail): Promise<MailMessage>;
  /** In the transaction that records the outcome. Not called for a cancel or a release; `prepared`
   * is absent for an expiry and an abandoned claim. */
  settle(tx: Transaction, mail: ClaimedMail, outcome: MailSettlement, now: Date, prepared?: Prepared): Promise<void>;
}
export type MailTransport = (smtp: SmtpConnection, message: Omit<SendMailOptions, "from">) => Promise<SmtpSendOutcome>;
export interface MailSenderDeps {
  db: Database;
  owners: readonly MailKindOwner[];
  now: () => Date;
  isPrimary: () => boolean;
  signal: AbortSignal;
  resolveDelivery: (tx: Transaction, rule: MailDeliveryRule) => Promise<EmailDelivery>;
  send?: MailTransport;                 // default sendSmtpMessage
  /** N4, tests only: awaited after the first read and before the claim transaction opens, with no
   * lock held, so a test can change state "before the claim". */
  beforeClaim?: () => Promise<void>;
  log: Logger;
}
/** processed: the pass wrote something — claimed, cancelled, expired or abandoned a row. mailId is
 * null when it only expired or abandoned rows (decision F). */
export type MailPassResult =
  | { processed: false; emailUnconfigured?: true }
  | { processed: true; mailId: string | null; subjectId: string | null };
export const MAIL_CLAIM_LEASE_MS = 60_000;
export function runMailPass(deps: MailSenderDeps): Promise<MailPassResult>;
export function runMailLoop(deps: MailSenderDeps & { sleep?: (ms: number, signal: AbortSignal) => Promise<void>; minTickMs?: number /* 500 */; maxTickMs?: number /* 60_000 */ }): Promise<void>;
/** At start: each `sending` row of an owned kind → unknown, mail.claim_abandoned, finished; settle without prepared. */
export function abandonMailClaims(tx: Transaction, owners: readonly MailKindOwner[], now: Date): Promise<number>;
/** Boot's entry, called after boot has awaited abandonMailClaims: runMailLoop with a
 * createLoopWaker sleep that `bus` wakes on every `outgoing_mail` change; unsubscribes when the
 * loop ends. Throws at once if two owners share a kind or an owner's longestWaitMs is below its
 * largest retry delay. */
export function startMailSender(deps: MailSenderDeps & { bus?: LiveEvents; maxTickMs?: number }): Promise<void>;
```

**One pass**, in order. Each write is its own `withTransaction`; "owned" means a kind in `owners`.

0. `signal.aborted` or not `isPrimary()` → `{ processed: false }`, no read.
1. One plain read (no transaction, so an idle pass takes no write turn): any waiting owned row
   (`pending`, or `rejected` and unfinished) past `not_after`, any owned `sending` row whose claim
   lapsed, or any due owned row? None → `{ processed: false }`.
2. `await deps.beforeClaim?.()` (N4).
3. Claim transaction:
   - re-check `signal` and `isPrimary()`; either fails → write nothing, `{ processed: false }` (N3);
   - owned **waiting** rows past `not_after` (up to 20) → `expired`, finished, `settle(expired)`.
     A `sending` row is never expired: it ends only when its claim lapses (next line);
   - owned `sending` rows with `claimed_at <= now − lease` or `> now + lease` → `unknown`,
     `mail.claim_abandoned`, finished, `settle`;
   - resolve the delivery once for each rule the owners use: `resolveDelivery(tx, rule)` (A). The
     two rules can disagree (3a-i, Task 2's note), so each is resolved separately;
   - pick one due owned row of a kind whose rule is not `unconfigured`: `status in (pending,
     rejected)`, unfinished, `next_attempt_at <= now` or `> now + owner.longestWaitMs`, ordered by
     `next_attempt_at, queued_at, seq` (D). If due rows exist but every one's rule is
     `unconfigured`, leave them untouched: the result is `{ processed: true, mailId: null,
     subjectId: null }` if this pass expired or abandoned anything, else `{ processed: false,
     emailUnconfigured: true }`;
   - `owner.claim` → `null`: `cancelled`, finished, `{ processed: true, mailId, subjectId }`; else
     `sending` with `recipient`, a fresh `randomUUID()` `claim_token`, `claimed_at`, `attempts + 1`,
     guarded on the status it was picked in. The resolved delivery is kept in memory for step 4;
   - **`owner.claim` throws:** the claim transaction rolls back. A second transaction marks that
     row `rejected`, `mail.claim_failed`, `attempts + 1`, waiting until
     `now + retryDelaysMs[attempts − 1]`, or finished when the delays are spent (no settle; the
     owner never claimed it), and logs `mail.send_failed` with that code. The next pass takes other
     rows first (its `next_attempt_at` is now later), so one bad row blocks nothing.
4. Outside: `compose` (a throw → `rejected`, `mail.compose_failed`, `serverRefused: false`).
   **Re-check `signal` and `isPrimary()` (N3); either fails → release (B):** back to `pending`,
   `claim_token`, `claimed_at` and `recipient` cleared, `attempts − 1`, guarded on the token; no
   settle; return `{ processed: true, mailId, subjectId }`. Else
   `send(delivery.smtp, { to: recipient, ...message })`; a transport that throws counts as
   `unknown`, `email.test_refused`.
5. Record, guarded on `id`, token and `sending`: `sent` → finished; `unknown` → finished;
   `rejected` → if `attempts <= retryDelaysMs.length` **waiting**: `next_attempt_at = now +
   retryDelaysMs[attempts − 1]`, and `claim_token`, `claimed_at` and `recipient` cleared, because a
   queued row holds no address until it is being sent (jobs.md §2, `recipient`); else finished,
   keeping its claim and address as the record. `settle` with `prepared` (the `rejected`
   settlement carries `serverRefused`). Nothing updated → no settle.
6. Any outcome but `sent`: `log("error", "mail.send_failed", { kind, mailId, errorCode })` — no
   address, name or person id.
