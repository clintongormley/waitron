# Address suggestions on the box

Dashboard staff who can edit venue details can pick a suggestion in either address form, correct it, and save it with the existing Save button. Both forms open immediately and work by hand. The till gets the same server operation in this piece. Its window, the wording and privacy notices for all four forms, and the live Cloud trial follow the [finish plan](2026-11-24-address-lookup-finish.md).

## Share the box operation

- [ ] In `apps/server/src/cloud-address-lookup.ts` and `cloud-client.ts`, reuse the setup client's validation and signed `address-lookup` exchange. The registered box uses `leaseState` and `recordRefusal`. Use one deadline for lease and exchange, carry the request's abort signal, and keep each call independent. The Cloud wire carries the existing `suggest` and `validate` bodies, a fresh operation ID per call and the same workflow ID for a search and its choice. Setup keeps its own sign-in and availability behavior.
- [ ] Add `apps/server/src/address-lookup-api.ts`, wired through `boot.ts`, `venue-settings-api.ts` and `till-api.ts`. Both routes take a bounded JSON body and return `Cache-Control: no-store`. The dashboard's `POST /management-api/address-lookup` requires `venue.configure`, the same permission as both forms' saves. The till's `POST /api/address-lookup` uses the signed-in person's `take-orders` device and staff gates and the invoice-options zone check for the current bill or new order. Finish authorization before calling Cloud and release any database turn first. Only accepted search or choice fields go to Cloud. Keep address queries and suggestions out of storage and logs.
- [ ] For `available`, both routes read the box's current registration state without a Cloud call. At Cloud commit `43c343cde8`, the signed endpoint accepts only `suggest` and `validate`. Show search when the local connection is eligible. If Cloud refuses the service as unavailable or over its cap on a search or choice, return `available: false` and hide search for that form visit. An expired workflow can start fresh on the next typed query. The box never sends a test address or retries a lookup automatically.
- [ ] Start with failing tests in `cloud-address-lookup.test.ts` and new `address-lookup-api.test.ts`. The exchange tests check the signed bodies, matching replies, refusal mapping and cancellation. The route tests check the permission and zone refusals, the absence of Cloud calls from refused requests or availability reads, and the sanitized response on each authorized path. Register the till action and zone cases in their existing inventories.
