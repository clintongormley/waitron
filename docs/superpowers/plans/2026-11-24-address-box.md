# Address suggestions on the box

Staff can choose a suggestion in the dashboard’s Venue card and registered-address window, edit the filled fields and save through the existing forms. Both forms open immediately and work by hand. Proposed cut for watcher clearance: put the till route with its form in ADDRESS-TILL so it lands with a caller. ADDRESS-WORDS adds attribution beside chosen fields and the remaining privacy notices. ADDRESS-PROOF runs the live Cloud trial. [Finish plan](2026-11-24-address-lookup-finish.md)

## The box asks Cloud

- [ ] In `apps/server/src/cloud-address-lookup.ts` and `cloud-client.ts`, share the setup exchange and validation. The box’s address operation uses `leaseState`, `recordRefusal` and one deadline for lease and exchange, with the request’s abort signal. Recheck the caller and the primary role after any lease wait and check that the registration remains current before sending and before returning results. Keep setup’s tab checks and refusal behavior.
- [ ] Wire `POST /management-api/address-lookup` in `apps/server/src/address-lookup-api.ts`, `venue-settings-api.ts` and `boot.ts`. Follow `cloud-api.ts` for the primary check and bounded JSON body. Require `venue.configure`, check the exact fields for `available`, `suggest` and `validate`, release the database turn before network calls and send `Cache-Control: no-store`. Add the route to `packages/diagnostics/src/path-patterns.ts`. Requests use the existing signed bodies and a fresh operation ID for each call. The box stores and logs no query or suggestion.
- [ ] All three requests check local connection and a cooldown in memory for that registration before calling Cloud. The existing Cloud endpoint accepts only `suggest` and `validate`. A connected box therefore learns that Cloud is disabled on its first search after restart or after the cooldown. Keep the unavailable message on the open form and hide search on later openings during the cooldown. An explicit Cloud 503 uses a minute. For 429 `rate_limited`, use Cloud’s `Retry-After` if valid, up to a day, else a minute. At Cloud commit `43c343cde8`, minute, workflow, daily and monthly limits share that error, so use the delay instead of trying to tell them apart. Keep the workflow across rate limits, including the ninth search in the trial, so they never start another reservation automatically. On a 410 `expired`, the browser adapter drops that workflow so the next typed search starts fresh. A choice retires its workflow even if the reply is lost. Network errors, conflicts and malformed replies show the unavailable line and keep manual entry available. No automatic resend.
- [ ] Start with failing tests in `cloud-address-lookup.test.ts` and new `address-lookup-api.test.ts`. The signed exchange owns status, cooldown, deadline and cancellation cases. The route owns permission, primary and malformed-body refusals and checks that availability and refused calls send no lookup to Cloud.
