# A1084 late dish routing implementation plan

When the kitchen agrees to make a dish after its period ends, use that period's routing. A Lunch mojito confirmed at 14:05 goes to the Downstairs bar. A dish ordered from the current menu and a late dish sent without asking still use current-period routing. Station availability and fallbacks use the time of routing.

The ask is [A1084 in the backlog](../../backlog/service-periods.md#a1084-a-confirmed-late-dish-routes-by-the-period-running-when-it-is-sent-not-the-period-the-kitchen-agreed-for) and the 23 November queue. Git log and blame trace the Upstairs assertion to `56202e3637` ([#2051](https://github.com/clintongormley/waitron/pull/2051)). D33 records the controller's decision to defer routing by the agreed period to A1084. The recorded owner answer to Q39 covers the confirmation and PIN. Record that reason and the reversed station assertions in the PR's changed-test section.

## Save the period at agreement

- In `packages/venue-service/src/menu-timetable{,-types}.ts` and `packages/module/src/module.ts`, carry the period id with its name in `endedMenus`. Reuse that match for both fresh and stored dishes in `apps/server/src/working-order.ts`. Save its id with the existing name and confirmer through `LineContextInput.late`, `LineContextColumns` and `recordLateSendMarks` in `packages/venue-service/src/operations.ts`. Copy the id on line splits. Leave it empty for unasked marks or when confirmation could only identify the menu. Keep the confirmation wire shapes and the ticket name.
- Add nullable `latePeriodId` to `packages/db/src/schema/orders.ts` as a snapshot reference that survives a period's deletion. Guard it in each branch in `packages/db/triggers/core.sql`. On a placed or paid bill, the first-mark exception requires an empty old id and writes id and name together. Rebuild the core baseline and state the venue reset on the PR's first line. Use disposable venues for validation.

## Use the same routing rules for fire, hold and release

- Extend `MakerResolver.makers` in `packages/module/src/module.ts` with an optional `periodId`, and `extraMakers` with an optional period id per keyed pick. In `packages/venue-service/src/routing-store.ts`, reuse the routing snapshot and lazily resolve period ownership for overrides. Apply the selected period in the order's routing department only. A deleted or foreign period uses the running period. An applicable period with no line on the cell uses the cell's base target. `routing.ts` keeps the station status and fallback decisions at the time of routing.
- In `apps/server/src/working-order.ts`, share one batched lookup by period in `fireLines`, `heldNoRouteLines` and `apps/server/src/station-move.ts`'s `rerouteHeldAtRelease`. Send each extra's recorded agreement in `insertSplitExtras`. Retain existing explicit station choices and the conditions that allow held work to move at release.
