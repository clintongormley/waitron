# A1627 PR 1 · Clock in and Welcome back

[Owner-approved design](../specs/2026-11-26-till-handheld-redesign-design.md) §§7.14–7.15 and §13, frame `ca` 1, 2 and 5. After signing in, staff see **Check your times** when an answer is due, **Clock in** with their published shifts for today, or **Welcome back** with **End break** if they left a break open. **Not now** opens the till without changing their record. The You section, the break strip and clock-out sheet follow in the next PR. Frame `cb` and **Ask a manager** follow in the My hours PR, using the approval reads already on main in A1623.

1. **Clock state.** In `apps/server/src/till-clock-state.ts`, project `breakStart` (the same `eventAt` and `offsetMinutes` pair as `shiftStart`, or `null`) from the effective live entry while `on_break`. Mirror it in `apps/till/src/api/attendance-api.ts`. Keep `shiftStart` and all action admission and write rules. In `apps/server/src/till-clock-api.test.ts`, first fail on the timestamp and offset of an open break and check that clocking in, working again and clocking out return `null`. Keep existing response assertions and add the new field where they compare the whole response.
2. **Sign-in.** In `apps/till/src/till-app.ts`, reuse the existing attendance gate, clock controller and cancel path. Choose the break prompt after Check your times when appropriate, including the branch without attendance questions. End break uses the existing action and resumes work after the server confirms it, including the existing read-back after a lost reply. Keep the current Retry, notice and session behaviour. While the Clock in page is open, read `listMyShifts` once for the same local-date window as `till-schedule-screen.ts` via `scheduleWindow(now, 1)`. Show the returned published shifts with their stored offsets and descriptions, including both parts of a split shift. A slow or failed read leaves the clock actions usable. Bind the result to the current sign-in and clear it when leaving the page. In `till-app.clock.test.ts` and `till-app.attendance.test.ts`, first fail on the published shift surviving a read, a late response for the previous person being discarded, and a returning worker answering questions before End break becomes available. Exercise both End break and Not now, checking the submitted action and the resulting destination.
3. **Screens.** In `apps/till/src/screens/till-clock-in-screen.ts` and `till-attendance-questions.ts`, use the frame's typography, spacing and action placement with the existing design tokens, `wt-button` and `wt-foot-button-bar`. Show initials and a greeting, shift or break details and the action time as a preview. The box still dates the write. Use the stored offset formatter from `widgets/attendance-history.ts` for shift and break times and the shared `TickingClock` for elapsed minutes. Put English and Spanish wording in `apps/till/src/i18n/strings.ts`. Use existing screen and axe suites for both prompt modes in light and dark and the question actions. Update both `apps/server/src/guide/{en,es}/staff.md` and the open-work sentence in `docs/backlog.md`.

Run each named behavioural test before changing its code and again after. Run the changed suites with `pnpm --filter @waitron/server exec vitest run src/till-clock-api.test.ts` and `pnpm --filter @waitron/till exec vitest run src/till-app.clock.test.ts src/till-app.attendance.test.ts src/screens/till-clock-in-screen src/screens/till-attendance-questions`, then focused type, guide and size checks. Capture the matching `ca` frames at 390 px in both themes and languages. Lane P reviews before the pictures go to the owner for landing approval. Estimate 300–430 product lines and 160–250 test lines including fixture edits.
