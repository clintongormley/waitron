# A1627 PR 1 · Clock in and Welcome back

[Design](../specs/2026-11-26-till-handheld-redesign-design.md) §§7.14–7.15 and §13, `ca` frames 1, 2 and 5. The spec status records approval of §7.14 on 27 November. After sign-in, staff see **Check your times** when it has questions, **Clock in** with the current or next published shift, or **Welcome back** with **End break**. **Not now** opens the till without a new time entry. The You section, break strip and clock-out sheet follow in PR 2. My hours and **Ask a manager** follow in PR 3 using A1623's approval reads.

1. Add `breakStart` to `apps/server/src/till-clock-state.ts` and `apps/till/src/api/attendance-api.ts`. Use the effective live entry's `eventAt` and `offsetMinutes` while `on_break`, and `null` otherwise. Cover the cross-node case without a shift start in `till-clock-state.test.ts` and check the field through start and end break in `till-clock-api.test.ts`.
2. In `apps/till/src/till-app.ts`, reuse the sign-in gate and clock controller. A normal sign-in offers Clock in for `out && firstClockIn` and Welcome back for `on_break`. Apply this with or without attendance questions. **Answer later** makes the same choice without answering when sign-in questions have loaded or their read failed, provided the clock state is known. Let staff return to work while a read is still pending, the clock read was refused, an answer is uncertain, or they are dismissing questions opened from the menu. End break resumes work after confirmation or successful read-back. A fresh read that shows the break already ended resumes work as well. Cover these transitions and Not now in `till-app.clock.test.ts` and `till-app.attendance.test.ts` with `apps/till/test/clock-app.ts`. Give the fixture a `listMyShifts` mock returning `[]`.
3. Key `till-clock-in-screen.ts` to the sign-in. Only Clock in reads `listMyShifts`, using `scheduleWindow(yesterday, 2)`, the local calendar window from yesterday up to tomorrow, exclusive. Show a shift containing the current time, including one across midnight, otherwise the next one starting today. Reuse the shift's stored offsets and description. Leave the action available if the roster is absent or the read is pending or fails. Test the shift selection, a late response after sign-out, the empty roster and successful Clock in while a rota read is pending. Use `TickingClock`, the existing time formatters, `wt-button` and `wt-foot-button-bar`. Put the existing floor initials circle in `packages/ui/src/components/wt-initials.ts` with 44 px for the floor and 72 px for the sign-in page. Add token and axe cases. Style `till-attendance-questions.ts` to match `ca` and give **Answer later** and **Not now** distinct English and Spanish keys in `i18n/strings.ts`. Use the neutral Spanish greeting “Hola de nuevo, {name}”.

Run each changed test red then green for new behaviour. Run both server clock suites, both till app and screen clock and attendance suites including axe, every clock-state fixture's suite, `wt-initials` tests, type and guide checks.
