1. **Host operations.** Extend `scripts/box/{network-host.mjs,network-host.test.mjs}` with `handleNetworkRequest(line, deps?) -> Promise<string>`, retaining read assertions. Scan discovered NetworkManager wireless objects: request/observe completion, read SSID bytes/strength/security, drop empty SSIDs, preserve other valid SSID bytes, deduplicate deterministically and cap at 32. Scan takes the mutation lock and answers `busy` while a change runs. Join takes existing WPA2/WPA3 personal fields; forget resolves SSID against discovered infrastructure profiles. Commands, paths and interfaces never come from requests. Capture/bound command output; journal verb/actor/permission before mutation, never credentials or raw errors. Keep reads available during changes with their three-second command budget; propose twelve seconds for scan within the socket unit’s fifteen.

2. **Apply and reconcile.** Add `scripts/box/{network-change.mjs,network-change.test.mjs}` and `deploy/box/{waitron-network-change.service,waitron-network-watch.service}`. Verify encrypted host identity before every state access. The shell takes nonblocking `flock` in the existing root-only `/run/waitron-box-state/` before forwarding scan/join/forget. Under that lock, durably record pending kind/SSID, host-generated/discovered UUIDs, previous selection and public outcomes in root-only `/var/lib/waitron-host/network.json`, then start the fixed change unit without waiting. Another pending mutation answers `busy`; the record contains no password. The worker unit enters through shell `flock` on that same fixed file; Node never takes a flock itself. Both units require `/var/lib/waitron-host` and `/boot` mounts and start after NetworkManager. Failure to start the worker returns `host_failed` and clears the newly pending operation. Acceptance answers `{ok:true}`; later reads report `running`, `applied` or existing change refusals, separately from boot-copy success/failure. Retain pending reconciliation until durable cleanup completes.

   Credentials enter root-only NetworkManager keyfiles on the encrypted system, at host-owned fixed candidate paths; use `nmcli connection load`, then `nmcli --wait 60 connection up uuid <host UUID> ifname <discovered interface>` or `nmcli --wait 10 connection delete uuid <discovered UUID>`. Keep the candidate non-autoconnecting until activation succeeds and retain the previous profile until then. Failed joins remove their candidate and restore/verify the prior connection. An interrupted running join is refused on restart without replaying its credentials. After success demote the old profile from autoconnect rather than delete an unrelated saved network; the watcher settles this visible choice alongside selection. Proposed worker cap: 90 seconds. Read only the selected profile’s `GetSecrets`, call `decideWifiBootCopy`, then the publisher factory with a real mount inspector. Check encrypted host identity and `/boot`’s ext4 UUID against the installed `/etc/fstab` (`deploy/box/install-dev.sh:79–82`), with ownership/no-follow checks; missing/wrong mounts never write underneath. Measured boot files stay untouched.

   The watch unit observes `nmcli monitor` before its initial reconciliation, discards monitor text, and rereads authoritative settings under the lock on events and every unlocked start. Repair interrupted publication without replaying obsolete credentials; cable attachment alone keeps configured Wi-Fi. Persist copy status across socket processes; only verified publication reports `current`. `network.read` replaces its call to the in-memory `wifiBootCopyStatus()` placeholder with the persisted result, using its three-second runner for host inspection; unreadable state answers `change:null` and copy `failed/io-failed` while retaining wired/current observations. Profile ambiguity and failed observation must never masquerade as cable-only removal.
