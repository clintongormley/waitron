# Keep the till floor visible during its first read (A1630a)

[Design §§7.16–7.17, 9.11 and 13](../specs/2026-11-26-till-handheld-redesign-design.md). Lane F queue, A1630. Proposed first PR. Aim for three hours, 250–340 product lines and 180–240 test lines added.

**What staff get.** When Floor opens with its first read still pending, its frame and available navigation appear immediately. At 300 ms the content shows quiet grey shapes. At 5 s, “Still waiting for the box…” sits over them. At 15 s, “Can't reach the box” replaces the banner at the same position with WiFi help and **Try again**. A quick read shows no shapes. A refresh keeps the last floor. A retry issues a fresh read and a superseded reply cannot replace it.

1. **Share the building blocks.** Add `packages/ui/src/components/wt-placeholder.ts` and export it from `packages/ui/src/index.ts`. The parent sets the size and placement. The primitive reads `--wt-color-surface-sunken` and `--wt-radius-md`, is decorative and has no animation. Add it to the workbench and design system. In `apps/till/src/state/first-read.ts`, share the 300/5,000/15,000 ms transitions and clean up timers on settlement, replacement and exit. In `apps/till/src/widgets/first-read-notice.ts`, share the overlay, using localized status text, the existing decorative `wt-spinner`, `wt-button` and the existing offline title and WiFi copy. Keep the retry button outside the status announcement.
2. **Use them on Floor.** Wire the first-read state in `till-app.ts` around `#loadFloorData` and use the existing `floor-refresh` event for retry. Pass the same attempt's abort signal to both reads, adding optional `ReadOptions` to `FloorApi.listZones` in `api/floor-api.ts`. Reuse the existing response ordering and session checks. In `screens/till-floor-screen.ts`, put the overlay in the content frame. Use rectangular placeholders at known table positions if the app has layout but no displayed floor data. Use a neutral placeholder for the map when positions have yet to arrive. Localize the waiting and retry wording in `i18n/strings.ts`. Keep the existing refresh and error behavior for a floor already shown. Keep the Counter queues' timed retry.
3. **Test first.** The placeholder's Chromium tests prove token painting, no focusable content, and axe and forced-colors coverage. `state/first-read.test.ts` uses a fake clock to check the three boundaries, fast completion and cleanup when an attempt is replaced. In `till-app-boot-and-counter.test.ts`, enter Floor with a deferred reply, check retry actually reissues both reads, return replies out of order, and confirm a refresh preserves the displayed floor. Run the focused suites and UI guards. Compare `cf-light.html` and `cf-dark.html` at 390 px, capture both themes and languages at phone and till widths in both orientations, and send the comparison to the watcher for Lane P and the owner. Update the bilingual table-service guide where the retry is explained and record the remaining uses in the backlog.
