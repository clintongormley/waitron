# KDS-1 — Stations, routing & the per-line ticket rework — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the one-row-per-order prep model with per-line/per-station kitchen tickets — stations, routing, a station-display screen, and the ready→floor loop — making a multi-station kitchen (and tab rounds) actually work.

**Architecture:** A `kitchen_stations` config table (one default) + routing columns on catalogue (`categories.station_id`, `products.station_id`); a new `ticket_items` table (per line, snapshotted station, `queued→preparing→ready`) that **replaces `order_prep`**; fire points create tickets, a per-line advance verb bumps them, a per-station read groups by order; a session-gated till station-display (kanban ⇄ rail); and an extension to FP-1's floor read for "N listos". All non-fiscal.

**Tech Stack:** TypeScript, Drizzle + PostgreSQL (RLS), Hono, Lit + Vite, `@waitron/ui`, Vitest (+ browser), Testcontainers + PGlite.

**Spec:** [docs/superpowers/specs/2026-08-17-kds-1-stations-routing-tickets-design.md](../specs/2026-08-17-kds-1-stations-routing-tickets-design.md) — read alongside; every task argues from it.
