(owner, 2026-11-04; README R1), so it folds into `print_jobs` as `a4` jobs with three page columns, and
`document_page_reprints` names a print job instead.

header), and this plan's text is the design it follows.

## What it builds

`print_jobs` gains (null unless stated):

| Column (drizzle) | Type | Rule |
| --- | --- | --- |
| `page_document` (`pageDocument`) | enum `invoice`, `receipt` | set exactly on `a4` |
| `page_language` (`pageLanguage`) | `label` | set exactly when `page_document = 'receipt'` |
| `page_designation` (`pageDesignation`) | enum `original`, `duplicate` | set exactly when `page_document = 'receipt'` |

CHECKs: `print_jobs_page_document_ck` (`enumCheck`), `print_jobs_page_designation_ck` (`enumCheck`:
the same values as #2455's `document_page_jobs_designation_ck`), and `print_jobs_page_ck`:
`(kind = 'a4') = (page_document is not null) and (page_document is 'receipt') = (page_language is not
null) and (page_document is 'receipt') = (page_designation is not null)`. dv13's `a4` invoice jobs
write `page_document: 'invoice'` (one line in `reserveInvoiceDelivery`'s `a4` branch).

`document_page_jobs` is deleted. Its queue columns are `print_jobs`' own (status, claim, generation
→ the job's claim token, attempts, hold); its frozen language and designation are the page columns;
its `receipt_handover` is `handed_over_by`/`handed_over_at` (dv11); its `person_id` (the original
operator) is not kept on the job: the copy audit row names who asked. Its outcome columns
(`reported_*`, `failure_code`, `expired_at`) have no home on a job: an F2 page's outcome is its job's
`status` and `last_error`, as a receipt printed on a thermal printer has today.
`document_page_reprints.page_job_id` becomes `print_job_id` with a key to `print_jobs` (restrict); the
table stays append-only.

## Decisions this plan makes

1. **Three columns on `print_jobs`, not a second queue** (open to the owner): R1 and §1.7 ("Every
   print goes through this table, A4 included") rule out a second A4 queue; the three columns are the
   least an `a4` job needs to draw an F2 page, which, unlike an F1 invoice, has no delivery record
   holding its designation. If A790 Cut B has landed, stop: its writers and readers need re-planning.
2. **`document_page_reprints` is re-pointed, not moved.** Moving copy audits to `activity_log` is the
   orders slice's (`2026-11-08-a1308-os9-sale-activity.md` moves `receipt_reprints` to
   `sale.copy_printed`); it should fold this table with it (open question to its plan).
3. **`document_delivery_requests`, `document_delivery_sequences` and `device_invoice_save_operations`
   stay as A790 built them.** They are `local` journals (no key to a `state` table may exist,
   CLAUDE.md §3), so R4 gains nothing by turning their JSON results into columns; their rows outlive a
   job (tombstones without expiry, A790's plan); R3 does not apply. R6 would read
   `next_acceptance_order` from `max(acceptance_order) + 1`; left as built, because Cut B allocates it
   in the accepting transaction by design and its retention is not settled (open question).
