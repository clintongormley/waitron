# Products Category field · Lane D, piece 5

Managers can select or create a category while editing a product in Products or Menu Structure. Creating a category saves it with its colour immediately, so it stays if the product edit is cancelled. The owner asked to add a category “first (or during the process), including setting the colour.” Piece 6 owns browser Back and piece 7 owns the list. The existing Menu Structure entry point opens existing products. [Design §6, Delivery and Spanish](../specs/2026-11-24-products-list-redesign-design.md#6-adding-and-editing-a-product)

## Implementation

- In `packages/ui/src/components/wt-combobox.ts`, give an action option an opt-in `actionLabelForSearch(text)` callback. Render it first through filtering, even on an exact match. Initial keyboard focus and typing prefer the first matching choice when one exists. Home and ArrowUp can reach Add, and Enter selects Add when it is the only match. Send trimmed search text with that action's `wt-combobox-action` value. Keep existing action and `allow-add` behavior. Remove the link appearance and its dedicated tests and documentation.
- In `apps/dashboard/src/widgets/`, move `renderCategories` markup from `product-editor.ts` into `classification-fields.ts` to make room under the editor's 2,000-line cap. Put the ordinary Category field (`name="primary"`) between Name/photo and Available. Keep No category, unavailable wording, tree order, field refusals and current defaults. Show the category's effective colour from `categoryColorSource` before the path, using the existing `.chip` style and `isStoredColor`. Keep the variant's read-only path first and null category on save. Scope the first-row offset to the variant path and remove the obsolete Change wording from the dashboard.
- Add `apps/dashboard/src/widgets/category-create-form.ts`. Follow `unit-form.ts` for the compact `wt-modal`, `draftScopeFor`, Cancel/Escape and `closeSaved`. Focus required Name, seeded from search. A nonblank seed is immediately savable through `saveActionState` with `savableAtOpen`, including in the submit guard. The seed is part of the opening draft. Inside starts at the chosen category or `categories.none` and uses `categoryTree`. Stage Colour with `colorField`, starting at No colour. Use `FormFeedback` and `categoryRefusalErrors(error, submitted.parentId)` for inline refusals and allow retry. Use `folders.add_category` for the Add category heading and submit. Add the search action labels **Add category…** / **Añadir categoría…**, **Add category “Vermouths”** / **Añadir categoría «Vermuts»**, and **Inside** / **Dentro de** in `apps/dashboard/src/i18n/strings.ts`.
- Extend `apps/dashboard/src/state/product-child-create.ts` and `apps/dashboard/src/widgets/product-editor-dialog.ts` for the category child. Pass the search text with the open event and capture the draft's category as the starting parent. Register the form in `CHILD_FORMS` and return focus to `primary` after it closes. Submit `createCategory({ name, parentId, color })`, accept the saved id into the existing product draft and keep returned category rows available to Category and Inside until the live list has included each one. Clear those rows on editor close. Let the existing `listCategories` watchers refresh through the same notification as the Products tree's Add. Skip the `changeChoices` callback for categories in the shared dialog so neither screen falls through to a courses read. Keep generation checks for late replies.
