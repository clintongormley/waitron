**Goal:** `node_membership` stops keeping a copy of its document's term, and the person who handled
an alert is a checked key to `persons`.

**Architecture:** Two schema edits in core's set, each with its refusal and acceptance tests. The
membership "save only if newer" compares inside the signed document with `json_extract`.

**Not here (plan review, 2026-11-08):** the day-start history protection (appendix §1.9, §8.5) is
built by slice 5d (its item 7, with `DAY_START_HISTORY_REFUSAL`), which creates `day_cutover_changes`.

**Tech Stack:** Drizzle on `node:sqlite`, Vitest.

**Spec:** [tables-venuebox.md](../specs/2026-11-02-rationalisation/tables-venuebox.md) §1.4 (`term`
dropped), §1.5 and §7 "People area"
(`incidents.acknowledged_by` gets a key to `persons`, README U11), §5 (the `node_membership` row).

**Lands:** the lane (rules §6).

**Pull request's first line:** "Every venue is reset: core; backups and exports from before this
cannot be restored or imported." (rules §2).

## What it builds

1. **`node_membership.term` goes** (`packages/db/src/schema/node-membership.ts:25`). Both writers
   stop writing it (`packages/db/src/node-membership.ts:83-89` and `:112-121`), and
   `persistNodeMembershipIfNewerTx`'s `setWhere` becomes
   `` sql`json_extract(${nodeMembership.document}, '$.body.term') < ${term}` `` — the same "save
   only if newer" (appendix §1.4, §5). The document stays verbatim (it is signed).
   `verifyCoreBackupData`'s copy check goes with the copy (`packages/db/src/backup-evidence.ts:161-170`
   selects `id, document` and drops the `row.term === BigInt(document.body.term)` comparison).
2. **`incidents.acknowledged_by` → `persons.id`, on delete restrict**
   (`packages/db/src/schema/incidents.ts:43`; README U11: persons are anonymised, never deleted).
   Its writers pass a signed-in person or `null`: `packages/core/src/incidents.ts:323` takes
   `input.personId`, `apps/server/src/venue-zone-repair.ts:92` the manager's id, and
   `packages/fiscal-verifactu/src/clock-stop-incidents.ts:65, :159` pass `null` ("the system"). A
   null is not checked by the key, so those stay valid.
