# KDS-3 — Expo / pass — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dedicated expo/pass display that aggregates every open order across all stations by course, with the pass's levers — fire a course, bump a whole course ready, mark a course away — and an "en camino" floor hint.

**Architecture:** `ticket_items.away_at` (dispatched) + an `expo` value on KDS-2's `fire_control` enum; a cross-station `listExpoQueue` read; `bumpCourseReady`/`markCourseAway` verbs (reusing KDS-2's `fireCourse`); an `enRoute` extension to the floor read; a session-gated `till-expo-screen`. Non-fiscal.

**Tech Stack:** TypeScript, Drizzle + PostgreSQL (RLS), Hono, Lit + Vite, Vitest (+ browser), Testcontainers + PGlite.

**Spec:** [docs/superpowers/specs/2026-08-17-kds-3-expo-pass-design.md](../specs/2026-08-17-kds-3-expo-pass-design.md).
