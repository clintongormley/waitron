# A951 Connection Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement approved tasks inline. Steps use checkbox syntax. Read `superpowers:test-driven-development` before writing implementation or test code. This document authorises no execution.

**Goal:** Give the box durable, scoped remote reachability while keeping `.local` independent and customer routes denied until their separate product agreements exist.

**Architecture:** Staff TLS passes through Cloud and ends at the box. Customer HTTPS ends at Cloud for filtering, then crosses WireGuard through independently authenticated upstream HTTPS to a separate box listener. A node-local reconciler applies authenticated transport intent; neither connectivity nor its certificates grant writer, recovery or fiscal authority.

## Global constraints

- `.local` is the venue default; the optional staff name needs separate qualification. Keep the Cloud step soon after go-live; do not move it into go-live.
- A951 is reachability only. It supplies no publication, pause, per-service switches, customer pages or offsite booking/order queue.
- Local boot and sales must not call or await Cloud, public DNS, remote certificates or WAN. An unrelated local authority/fiscal/storage refusal still applies.
- Keep four certificate contexts: local CA/leaf, box staff, box public-upstream, Cloud browser-facing public. Keep machine, WireGuard and TLS private keys separate.
- Preserve installation configuration revision, appliance content revision and transport-grant sequence as three distinct counters. Preserve staff v1's existing meaning of `revision`.
- Staff CSR v1 remains opt-in and test-installation-only. No issuer generalisation, production retry workaround or environment switching.
- Expiry/revocation closes admission **and established connections** for the affected remote path. Shared transport withdrawal closes both; staff/public certificate failure closes only its own path.
- A947 owns current writer identity, fencing, promotion, clocks, fiscal naming and old-node return. D88's answered recovery choice is cold recovery, not a running follower.
- Do not edit fiscal invariants, golden tests, shipped migrations or another lane's reservations. Coordinate shared files before an authorised implementation starts.
- Payload inspection at Cloud is distinct from retention. A980/D101 owns scoped processing, location, access and retention acceptance; no period or provider authority is selected here.
- Implementation uses fail-first tests, behavioral assertions and `git commit -s`. Every production cut takes the FULL branch review and current-head CI path below.

## Review focus

1. A stop races a ready CSR or a repaired replacement file: durable stop wins before any listener reopens (T2, T6, T8, T11).
2. A grant refresh looks like new content: only the grant counter/deadline changes; pending staff v1 work survives (T1, T5, T7).
3. An archive is authentic but malicious, or a module resolver aliases private state: reject endpoint authority before any restore write or export (T2, T11).
4. A long-lived TLS/keep-alive connection survives expiry or trust withdrawal: close that connection while the other listener and local client continue (T4, T8, T10).
5. A move commit reply is lost while the old gateway is partitioned: reconcile the saved operation, withdraw/wait out old admission, never activate another writer (T11).

## Proposed storage and internal interfaces

**Plan decision proposed for owner approval:** keep node-owned durable files under fixed `<stateDir>/connection/`, not `venue.db` or reserved `node.db`. W1 supplies a sync/rename pattern; W9 explains why a local-classified schema still transfers secrets and why `writeFileAtomic` alone is insufficient. This choice changes no migrations, module classifications or fiscal identity. Reassess only if the accepted A947 adapter cannot provide the required local binding without a store change; amend this plan rather than adding a table opportunistically.

Keep synced `<stateDir>/connection/safety.json` (stop, establishment identity/epoch and high-water marks) independent of replaceable `journal.json` there and the existing Cloud registration/replacement files. The journal holds complete authenticated candidate bytes/digest, phases, current/active references, operation identities, pending ack bytes, key references and certificate intents. Use immutable `certificates/<purpose>/<generation>/` directories and one synced `active.json` pointer per purpose, all within that private root. These runtime paths are proposed local names, never supplied by Cloud. Proposed local caps: 256 KiB per safety/journal record, one in-flight move, one current request per certificate purpose, one pending apply acknowledgement, and at most two complete generations per purpose. Validate those caps against accepted complete messages at G1/G3/G4; never truncate valid state or reset floors to fit.

Use 0700 directories and 0600 files, exclusive temporary creation, no symlink traversal, same-directory rename, file sync and containing-directory sync. Serialize changes with one short in-process apply lock while the owning server holds its venue lock. Offline tools do not write this state beside the server. The privileged helper owns its kernel effects and enforces its own accepted deadlines even if the app dies. No network wait, issuer call or helper wait holds a Cloud connection-file lock or database transaction.

Advance the synced safety floor before publishing a journal that may cause an outside effect; tie both to a local generation/digest. Two renames are not a transaction: if a crash leaves the floor ahead of the journal, close remote admission and recover that exact-or-newer intent through authenticated control. Do not repair the mismatch by lowering a floor. A stop needs only the independent safety write to win; journal repair cannot clear it. Crash tests must exercise these intermediate disk states, not assume both files switch together.

First establishment requires an authenticated enrollment/recovery result, never “missing file means revision zero”. If established safety state is missing/unreadable, close and request authenticated recovery with an agreed new epoch. Replacing only the journal cannot erase stop/floors. If all local evidence disappears, the accepted Cloud establishment/recovery protocol must distinguish that from a first install; missing evidence cannot authorise access. Local stop clears only through a separately authorised current reconnect/recovery bound to its new generation, never by repair/reimport.

The following signatures are **provisional internal interfaces**, not wire agreements. Define their exact TypeScript types in T1; implement the codec only against accepted messages. `Bytes` means immutable saved UTF-8 bytes, not reserialized JSON; `Digest`/`Id` are validated opaque strings, and revisions/sequences are distinct branded safe integers.

- `Binding`: origin, environment, Cloud venue/installation, local venue/node, machine key identity and accepted authority/target reference. `AuthorityObservation`: current/unknown/refused, target/reference, freshness and withdrawal generation supplied by G2. It contains no permission for A951 to activate a writer.
- `Candidate`: `Binding`, protocol/capabilities, installation revision, appliance revision/digest, placement epoch, peers/addresses/explicit ports/names, route manifest revision/digest, relevant certificate-purpose bindings and optional move predecessor/phase. `Grant`: candidate digest/revision/epoch/installation, increasing grant sequence, issued/expiry times and accepted trust identity.
- `Policy`: accepted contract/manifest pins and all byte/count/time/network/trust bounds, with no assumed timer defaults. `Clock`: `wallMs(): number`, `elapsedMs(): number`, `trustedAfterBoot(): boolean`; remote deadlines never modify fiscal clocks.
- `Safety`: establishment/recovery epoch, binding, installation/appliance/grant high-water marks and stop generation. `Journal`: complete candidate/grant bytes plus decoded references, received/applying/applied/failed/ack-pending/stopped/expired phase, actual observations and bounded predecessor state.
- `ConnectionState.read(): Promise<{safety: Safety; journal: Journal | null}>`; `update(expectedGeneration: number, change: StateChange): Promise<number>`; `stop(reason: StopReason): Promise<number>`. `StateChange` is a closed union of validated phase/counter/intent updates, not arbitrary paths or executable values.
- `AuthoritySource.read(binding: Binding): Promise<AuthorityObservation>`; `ApplianceControl.receive(signal: AbortSignal): Promise<{candidate: Candidate; grant: Grant; bytes: Bytes}>`; `report(reportId: Id, body: Bytes, signal: AbortSignal): Promise<AckReceipt>`; `recover(signal: AbortSignal): Promise<RecoveryReceipt>`. Endpoint/action spellings come only from G1/G5.
- `Helper.execute(operation: HelperOperation): Promise<KernelObservation>`; operations are prepare-peer, scoped-rules, inspect, activate, remove with accepted typed fields and fixed owned resource IDs. `RemoteListeners.close(scope: "staff" | "public" | "both"): Promise<void>`; `inspect(): Promise<ListenerObservation[]>`; `load(purpose: Purpose, generation: Id): Promise<ReloadReceipt>`.
- `reconcileConnection(deps: ReconcileDeps, signal: AbortSignal): Promise<void>` consumes state/control/helper/listeners/authority/clock/policy. `runConnectionWorker(deps: ReconcileDeps, signal: AbortSignal): Promise<void>` schedules it without overlapping turns. `Purpose` is staff or public-upstream; neither denotes local CA or Cloud public TLS.
- `CertificateIntent`: purpose, full binding, installation revision, relevant appliance certificate-binding digest, local/stop generation, hostname, key generation/reference, CSR bytes/digest, current remote request/predecessor, exact submit ID/body, attempt/next-time/deadline and last installed request ID. `CertificateStore.stage(intent: CertificateIntent, chain: string): Promise<Id>`, `select(intent: CertificateIntent, generation: Id): Promise<ReloadReceipt>` recheck current intent under the apply lock.
