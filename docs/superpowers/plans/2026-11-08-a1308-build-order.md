## Batch 2 — area slices

Each area also moves its server code into its own package (the CI redesign of 2026-11-08), at the
point its plans name, so code moves once.

**Order of areas (owner, 2026-11-09: the proposed order).** Since A1461 (owner, 2026-11-08) a pull request
runs only the changed packages' own tests, so moving an area out of `apps/server` saves that area's
test time on every pull request that does not touch it, and the rest of the server's on every one
that touches only it. Modelled saving per pull request, from A1459's per-file test times (8 November,
1,280 files) replayed over the last 60 merged pull requests (#2523–#2615, about one day, 40 of them
touching `apps/server`): file layout ~1,070 s, floor and kitchen ~890, venue and box ~880, orders and
sales ~860, runner ~370, fiscal ~330, people ~310, devices ~290, payments ~140, menu ~60 (its tests
already live in `packages/catalogue`), environment ~10. The biggest unknowns: one day of pull
requests is a small window, and about 15% of server test time (27 `boot.*` and 22 `till-api.*` files)
belongs to no area until the move is designed. So, within each lane, after the dependencies:

- **Lane 1:** the location sweep → venue and box → orders and sales → refunds → devices and printing
  → environment variables → the file layout (the largest saving; it waits for A1379 part 2 to land).
- **Lane 2:** floor and kitchen → menu and photos → payments pa1–pa4 → people and working time →
  pa5 → the job runner → fiscal. (Menu saves little; running the job runner before it is the
  alternative if lane 2 should save CI time sooner.)
