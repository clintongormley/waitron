# A1308 file layout fl2: every temporary folder under `<state>/scratch/`, emptied at every start

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers are dispatched as `subagent_type: "implementer"`.

**Goal:** Every working folder the server, the restore command and a staged restore make lives
under one folder, `<state>/scratch/`, which every start empties once it holds the venue folder; crash
reports older than seven days are pruned at every start, not only on a low disk.

**Architecture:** The layout module (fl1) gains `SCRATCH_DIR = "scratch"`, and the existing staging
names become children of it: backup staging `scratch/backup`, restore staging `scratch/restore`, and
the `stream-restore-*`, `restore-entry-*`, `waitron-setup-holdings-*` and `waitron-node-copy-*`
folders are made directly in `scratch/`. One function, `emptyScratch`, replaces the name-matching
sweeps (`restoreLeftovers`, `clearRestoreLeftovers`, `start-space.ts:78-88`) at the two places a start
sweeps today. Who may delete what while the box runs does not change: Box status's Free still deletes
only dumps and `backup-encrypt-*` folders in backup staging, inside the staging turn.

**Tech Stack:** TypeScript 7, Vitest 4.1.12, `node:fs/promises`.

**Spec:** [`files.md`](../specs/2026-11-02-rationalisation/files.md) §1 ("Everything temporary moves
under `<state>/scratch/`"), §3 rows 15, 21, 22, 24, 39, 41, 46 and the A1390 note after §3, §4
"Unencrypted copies", §5 T2. Slice rules: [`2026-11-08-a1308-slice-rules.md`](2026-11-08-a1308-slice-rules.md).

## What it builds

1. Layout entries: `SCRATCH_DIR`; `BACKUP_STAGING_DIR` becomes `"scratch/backup"`,
   `RESTORE_STAGING_DIR` becomes `"scratch/restore"`; the top-level `stream-restore-` and
   `restore-entry-` prefix entries are removed from the table (they now live inside `scratch/`).
2. In `apps/server/src/scratch.ts`: `listScratch(stateDir, log): Promise<string[] | null>` (the
   entry names inside `<state>/scratch/`; null when it is missing, unreadable or a symbolic link)
   and `deleteScratchEntries(stateDir, names, log): Promise<number>` (deletes exactly the named
   entries, never `scratch/` itself; never throws; logs each failure as
   `storage.start_cleanup_failed` with `errno`). `emptyScratch(stateDir, log)` is the two in a row,
   for callers that already hold the venue folder.
3. `freeSpaceAtStart` (`start-space.ts:62-162`) uses them in place of `deleteStagingLeftovers` and
   `restoreLeftovers`, keeping its lock logic (`:89-118`) exactly, including the order at `:94-99`
   for a missing venue folder: list first, check again that the venue folder is still missing, then
   delete only what was listed (a restore makes the venue folder before its first working folder,
   so anything made after the listing is a live restore's and is left). `bootServer` calls
   `emptyScratch` in place of `clearRestoreLeftovers` (`boot.ts:1199`); the summary
   `storage.start_leftovers_deleted` stays in `freeSpaceAtStart` (`:122`).
4. Crash reports older than `CRASH_REPORT_KEEP_MS` are deleted at every start (files.md row 39): the
   crash-report loop (`start-space.ts:135-149`) moves before the early return at `:120-124`; rotated
   logs are still deleted only below the floor or when forced.
5. Makers re-pointed: `first-setup-database-holdings.ts:96` and the node copies
   (`backup-sweep.ts:224`, `sealed-state.ts:144`) make their folders in `<state>/scratch/`
   (not in `scratch/backup`: `backup-sweep.ts:222-223` says why the node copy stays outside staging);
   `restore-stream.ts:200-202,300` and `restore-request.ts:576` make theirs in `scratch/`.
6. `restore-staging-dirs.ts` keeps only the prefix and `STAGED_RECOVERY_DIR` constants its makers
   use; `restoreLeftovers`, `clearRestoreLeftovers` and the two prefix lists are deleted.
7. Guard `scripts/no-tmpdir-scratch.test.ts`; `scripts/backup-staging-touchers.test.ts` keeps its
   allowed list (`BACKUP_STAGING_DIR` is still the name it matches), its literal pattern becomes
   `"scratch/backup"`, and its header names the start's two sweeps as above.
8. T2's result, run on the box (Task 4), recorded in the PR.
