# A1623 Hours approval implementation plan

Managers review finished days in **To approve** on the dashboard and their till. Workers answer edits in **Check your times**. Recorded minutes count while approval waits. Exports label approval and disputes.

Use [redesign §§7.14–7.15 and §13](../specs/2026-11-26-till-handheld-redesign-design.md#714-pass-3-clocking-in-and-out-hours-the-cash-drawer-and-a-waiters-float), frame `cc` 1–3. Lane K builds the worker's **My hours** (`cb`) from the status in PR 1. Keep payroll closure and the existing clock flow. [Adviser L8](../../compliance/asesor-laboral-questions.md#l8-a-disagreement-over-a-days-hours-is-keeping-both-versions-enough-added-2026-11-27) runs in parallel. Run focused tests before and after each fix.

1. **Day record and worker reads** (~425 product, 355 tests, 120 generated). In `packages/workforce/src/`, append an approval to `schema/time-entries.ts` with the manager, recording time and digest of the ordered effective entry IDs for one person and work date. Date it at the day's first effective clock-in. A finished day has completed work and no open shift on that date. The latest digest must match. Reuse `maySelfApproveAttendance` for own days, subject to watcher clearance. Carry the optional field through `chain.ts`, `chain-hash.ts`, `record-reads.ts`, `record-projection.ts`, `pay-period-chain.ts`, `backup-verification.ts`, `handover-return.ts` and `personal-data.ts`. Keep old hash bytes and skip the automatic-clock work queue for approvals. Add status to `hours-reads.ts` and the scoped day read in `attendance-reads.ts`. Test automatic and overnight work, open and second shifts, a retime across midnight, unchanged totals, and approval hashes on backup/return. Rebuild the workforce baseline, disclose the venue reset, run schema guards and add the dated A10 pointer.
2. **Dashboard** (`cc` 1–2, ~430 product, 330 tests). Extend the existing Team correction screen, attendance API, `management-attendance-api.ts` and workforce queue. Rename it **To approve**. Show requests, disputes and finished days. Per-person Hours still shows edits waiting for the worker and opens the editor for any date. Batch approval takes the shown person/date/digest triples. Check every day in one transaction and refuse a stale batch before any write. Keep pending requests, proposals and disputes outside bulk approval. Test permission, staleness and the three sections.
3. **Corrections and disputes** (`cc` 2–3, ~400 product, 360 tests). Extend `attendance-contract.ts`, `attendance-response-commands.ts`, `attendance-responses.ts`, `corrections.ts` and the dashboard proposal dialog. Use an explicit link in command receipts for superseding a request or dispute. Edit one existing time per proposal, with recorded and requested times, the resulting total and a reason. Use the existing worker prompt. Taking the worker's time settles to their previous request or their clocked time. Where neither exists, offer Edit. Keep both versions and the dispute in history. Recommend one manager decision covering the exact resulting day when the manager saw it and the worker has agreed where needed. Settle this with the watcher. Test replacement, another dispute, resolution and acceptance after payroll close.
4. **Till** (`cc` 1–3, two PRs at ~295/245 and ~450/330 product/test). In `till-attendance-api.ts`, add manager queue/day/actions under `workforce.correct` and `clock-in`. Remove worker PIN approval through `attendance-api.ts`, `state/attendance.ts`, `till-app.ts` and the worker dialogs in the same PR. Update till profile and session guards. Then add the counted `till-shell.ts` menu item and manager queue/editor, using existing worker questions. Test role boundaries, worker requests and replies. Update staff guides in both languages.
5. **Export** (~245 product, 215 tests). Extend `packages/workforce-es/src/{record-export,registro-jornada}.ts` and verify both PDF and Excel. Show current and frozen approval status, keep totals and dispute history, and preserve representative redaction. Update the workforce backlog.
