# A1623 Hours approval implementation plan

Managers review every finished day in **To approve** on the dashboard and their own till. Workers answer edits in **Check your times**. Recorded minutes count while approval waits. The export marks approval and disputes.

Follow [redesign §§7.14–7.15 and §13](../specs/2026-11-26-till-handheld-redesign-design.md#714-pass-3-clocking-in-and-out-hours-the-cash-drawer-and-a-waiters-float), frames `cc` 1–3 and worker waiting in `cb` 4. Lane K builds the `cb` My hours redesign from the server reads below. The desk and till use the same workforce commands. Clocking and payroll closure are separate work. [Adviser L8](../../compliance/asesor-laboral-questions.md#l8-a-disagreement-over-a-days-hours-is-keeping-both-versions-enough-added-2026-11-27) runs in parallel.

Assume a settled change to effective times needs fresh day approval and only admins may approve their own finished days. Approve all checks the versions shown before writing any approval. Run each focused regression test before and after its fix.

1. **Day record** (~410 product, 350 test lines, plus generated files). In `packages/workforce/src/`, add a day-approval entry to the existing `schema/time-entries.ts` chain. Record the approver, time and revision of that person's exact effective entries for the work date. Use the clock-in date for overnight shifts. Carry the marker through `chain.ts`, `chain-hash.ts`, `record-reads.ts`, `record-projection.ts`, `record-period.ts`, `pay-period-chain.ts` and `backup-verification.ts`. Test recorded totals, automatic and overnight finishes, open shifts, a later shift or correction on the same date, self-approval, and live and backup hash verification. Regenerate the workforce baseline and run the schema and append-only guards.
2. **Corrections and disputes** (`cc` 2–3, ~280 product, 250 test). Extend `attendance-contract.ts`, `attendance-response-commands.ts`, `attendance-responses.ts` and `corrections.ts`. Reuse the proposal, command receipt and worker reply. Link a replacement edit or the manager's choice to take the worker's time to the original request or dispute. Keep the prior versions and their authors, dates and reasons in history. Command tests cover a replaced request, a second dispute and an accepted edit against a frozen period.
3. **Dashboard and worker reads** (`cc` 1–2, `cb` 1–4 reads, ~490 product, 380 test). Extend `management-attendance-api.ts`, `attendance-request.ts` and workforce's `attendance-reads.ts` and `hours-reads.ts`. Give the existing Team correction screen and proposal dialog the three `cc` sections, any day's times and reason, and Approve all. Keep per-person Hours. Existing worker hours/day reads return status for A1627. Route tests cover manager permission and a stale batch. Browser tests cover grouped actions and recorded and requested times beside the edit.
4. **Manager till and worker PIN removal** (`cc` 1–3, two PRs at ~290/240 and ~450/330 product/test lines). Add manager queue/day/actions to `till-attendance-api.ts`, and remove the PIN path and its worker UI together through `attendance-api.ts`, `till-app.ts` and `attendance-day-dialog.ts`. Then add the counted menu item to `till-shell.ts` and the queue/editor screen. Reuse `till-attendance-questions.ts` for actor, proposed time, reason and reply. Route tests check signed-in permission and profile boundaries. Browser tests cover menu, edit and worker reply. Update both staff guides.
5. **Export** (~250 product, 230 test). Extend `packages/workforce-es/src/{record-export,registro-jornada}.ts` for PDF and Excel. Verify pending and disputed status, kept history, unchanged minutes, frozen snapshots and representative redaction. Add the dated pointer to A10 decisions 7 and 9 and update the workforce backlog.
