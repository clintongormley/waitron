# A1623 Hours approval implementation plan

Managers review finished days in **To approve** on the dashboard and their till. Workers answer edits in **Check your times**. Recorded minutes count while approval waits. Exports label approval and disputes.

Use [redesign §§7.14–7.15 and §13](../specs/2026-11-26-till-handheld-redesign-design.md#714-pass-3-clocking-in-and-out-hours-the-cash-drawer-and-a-waiters-float), frame `cc` 1–3. Lane K builds the worker's **My hours** (`cb`) from the status in PR 1. Keep payroll closure and the existing clock flow. [Adviser L8](../../compliance/asesor-laboral-questions.md#l8-a-disagreement-over-a-days-hours-is-keeping-both-versions-enough-added-2026-11-27) runs in parallel. Run focused tests before and after each fix.

1. **Day record and worker reads** (~425 product, 355 tests, 120 generated). In `packages/workforce/src/`, add `day-approvals.ts` and append a `day_approval` entry with its own shape branch in `schema/time-entries.ts`, the manager, recording time and digest of the ordered effective entry IDs for one person and work date. Date it at the day's first effective clock-in. A finished day has completed work and no open shift on that date. The latest digest must match. Reuse `maySelfApproveAttendance` for own days. In `chain.ts`, allow the self-approval flag on a manager’s own day approval as well as on the existing correction shape. Carry the optional field through `chain.ts`, `chain-hash.ts`, `record-reads.ts`, `record-projection.ts`, `pay-period-chain.ts`, `backup-verification.ts`, `handover-return.ts` and `personal-data.ts`. Keep old hash bytes and skip the automatic-clock work queue for approvals. Add status to `hours-reads.ts` and the scoped day read in `attendance-reads.ts`. Workforce tests cover finished days, automatic and overnight work, open and second shifts, retimes, unchanged totals, self-approval, and hashes on backup/return. Rebuild the workforce baseline, disclose the venue reset, run schema guards and add the dated A10 pointer.
2. **Dashboard** (`cc` 1–2, ~430 product, 330 tests). Extend the existing Team correction screen, attendance API, `management-attendance-api.ts` and workforce queue. Rename it **To approve**. Show requests and disputes, and add `apps/dashboard/src/screens/attendance-finished-days.ts` for Finished days and Approve all. Per-person Hours still shows edits waiting for the worker and opens the editor for any date. Batch approval takes the shown person/date/digest triples. Check every day in one transaction and refuse a stale batch before any write. Keep pending requests, proposals and disputes outside bulk approval. Server tests cover batch refusal and permissions. Dashboard tests cover all three sections.
3. **Corrections and disputes** (`cc` 2–3, ~400 product, 360 tests). Extend `attendance-contract.ts`, `attendance-response-commands.ts`, `attendance-responses.ts`, `corrections.ts` and add a full-page editor in `apps/dashboard/src/screens/attendance-day-editor.ts`. Use an explicit link in command receipts for superseding a request or dispute. Show all times in the day (frame `cc` 2), with the recorded and requested times beside a change, Worked would be, required Why, and Save and send to the worker. Keep adding a missing time. Use the existing worker prompt. Taking the worker's time settles to their previous request or their clocked time. Where neither exists, offer Edit. Keep both versions and the dispute in history. Approving a worker’s request, or a worker accepting a manager’s edit, approves the exact resulting day the manager saw. If the rest of the day changed, send the day to To approve. Test replacement, another dispute, resolution and acceptance after payroll close.
4. **Till** (`cc` 1–3, two PRs at ~295/245 and ~450/330 product/test). In `till-attendance-api.ts`, add manager queue/day/actions under `workforce.correct` and `clock-in`. Remove worker PIN approval through `apps/till/src/api/attendance-api.ts`, `state/attendance.ts`, `till-app.ts` and the worker dialogs in the same PR. Server tests cover refusal, permissions, profile and zone rows. Add `apps/till/src/screens/{till-hours-approval-screen,till-hours-day-editor}.ts` and `apps/till/src/widgets/till-hours-approval-menu-item.ts` for the ☰ count, without raising file caps. Till tests cover refusals, removal of the PIN path, the count and screens. Update staff guides in both languages.
5. **Export** (~245 product, 215 tests). Extend `packages/workforce-es/src/{record-export,registro-jornada}.ts` and verify both PDF and Excel. Show each day’s approval status, keep totals and dispute history, and preserve representative redaction. Update the workforce backlog.
