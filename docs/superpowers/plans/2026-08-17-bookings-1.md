# Bookings-1 — Staff-entered table reservations — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A staff-entered reservations surface — a `bookings` entity, a day-list dashboard screen, a seat-opens-a-tab action, and a "Reservada HH:MM" indicator on the floor.

**Architecture:** A tenant+location `bookings` table (local `date`+`time`, a `booking_status` lifecycle, optional links to a TS-1 `dining_tables` row and to the tab opened on seat); a dedicated `booking-api.ts` (`purchasing-api.ts` `gated()` pattern, `booking.manage`); a dashboard day-list screen (`purchases-screen` template); and an FP-1 floor-read extension. All non-fiscal.

**Tech Stack:** TypeScript, Drizzle + PostgreSQL (RLS), Hono, Lit + Vite, `@waitron/ui`, Vitest (+ browser), Testcontainers + PGlite.

**Spec:** [docs/superpowers/specs/2026-08-17-bookings-1-staff-reservations-design.md](../specs/2026-08-17-bookings-1-staff-reservations-design.md) — read alongside; every task argues from it.
