# Time-ordered row IDs

Newly minted Waitron row IDs sort by minting millisecond to reduce writes to old database pages. Existing and supplied IDs keep their values. Use the UUIDv7 layout with UTC milliseconds at the start and a random tail. IDs from one millisecond have random ties. Browser-minted IDs carry the browser's time. [RFC 9562 §5.7](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.7)

**Generators.** Export `newRowId()` from `packages/shared/src/ids.ts` through the existing barrel. Use `Date.now()` and the random tail of the platform UUID so the bench can set the clock. Point `packages/db/src/schema/columns.ts`'s `newId` there, preserving its return shape and the existing Drizzle defaults across db, bookings, VeriFactu, node-db, payments and workforce, subject to the exceptions below. The SQL generator in `change-feed.ts` writes transient change rows that `schema/change-log.ts` deletes inside the transaction. Keep it random. Starting migrations and stored IDs need no edits.

**Explicit writers.** Use `newId` for server bill actions, parties, working orders, portion and printed-bill splits (including the indexed cohort IDs), upgrade sales and print-agent enrolment. Convert core sale lines and replacement, menu categories, extras, options and modifiers, identity account creation and configuration transfer's new row keys. Use `newRowId` for dashboard extra items and option labels and the till's working-order draft, which become row keys. Use the same generator in the demo option-list and sales seeds and bench row builders. Keep explicit old and adverse-order fixtures. The review brief lists the individual generator sites.

**Random IDs.** Keep request keys, credentials, claims, codes, revisions, temporary keys and signed operation IDs random. Name `randomUUID` explicitly in the node and sign-in-challenge defaults, fiscal installation and series mints in `allocation.ts`, `drain.ts`'s technical incident token, `attendance-capture.ts`'s command key and `box-alert-email.ts`'s episode ID. Keep `verifactu_records.id` random because `drain.ts` sends it to AEAT as `RefExterna` after hashing. Fiscal hash inputs and invoice numbering stay as they are. The Cloud mail sender signs the separate random claim token. Short box names and box handover bindings retain random node IDs.

**Exposure and ordering.** An unauthenticated device join returns its own newly minted request ID, with a separate proof token. Guest-menu anchors are counters and media URLs use a content hash. Stripe and refund replay keys derived from row IDs carry mint time while keeping their existing derivation. Check invoice delivery links and signed evidence during verification. Preserve ID tie-break tests, including menu-copy order and the three adversarial payment, tender and zone suites named in the review. Fix their clock and supply ordered tails through the same generator input so they still demonstrate the incorrect order.

**Checks and measurement.** Start with failing tests in shared `ids.test.ts` for a known timestamp, increasing milliseconds and distinct same-millisecond IDs. In db `schema/columns.test.ts`, exercise a defaulted insert beside an explicit old ID. Run affected server, till, menu, setup, import and delivery cases. Update version checks only for converted writers and keep the unedited VeriFactu write-path, immutability and three huella suites.

Use lane-owned copies of one compatible checkpoint (build a short one if needed) and the same Linux bench runtime, date, seed, profile and 250 bills on both commits. Run `pnpm bench build` through the next day, then compare checkpointed `venue.db` files with the research run's `tools/pagediff.mjs` under `/srv/waitron-bench/lean-m-20261117`. Record the actual history length, sales, old pages changed, new pages and bytes. An equal or higher old-page count on the candidate fails to demonstrate the gain. The exploratory mock also changed random protocol IDs, so its count is a reference. Update the backlog with the measured scope.
