**Goal:** each menu has exactly one Device Home Page — the shortcut list it already owns — edited
from a fixed row in the Structure tree; the Home page tab edits two display settings (Handheld and
Till: columns, Colours or Thumbnails, which block follows search) over a live draft preview; the
published menu carries the shortcuts and both settings, and each device draws the half its form
factor picks. Named layouts and the device profile's per-menu layout choice go.

**Architecture:** one browser-safe rule file, `packages/catalogue/src/device-home.ts`, holds the
types' defaults and ranges, the block order with its divider, the tile fill, the name folding, the
menu index and the grid's column rule; the server's validation, the till's menu browser and the
dashboard's preview all use it. Storage is six `NOT NULL` columns with defaults on `menu_details`
and one dropped table, generated by drizzle-kit with no table rebuild. The published document goes
to format 3 with a `home` block; a device only ever reads the live version.

**Tech stack:** TypeScript, drizzle-orm on `node:sqlite`, drizzle-kit 0.31.11, Hono, Lit, Vitest 4
(browser mode for `@waitron/ui`, `@waitron/dashboard` and `@waitron/till`).

**Spec:** `docs/superpowers/specs/2026-10-05-w93-device-home-page-design.md`, and the owner's queue
item W93 quoted in it. Read the spec's Decisions before any task; they are settled.

## Why the task order differs from the suggested one

- **The shared rules come first (Task 1), before storage.** The storage task's import check and
  the column defaults read `homeDisplayProblem` and `HOME_DISPLAY_DEFAULTS` from
  `device-home.ts`, so the rule file must exist first. It is pure, touches no storage, and stays
  green on its own.
- **Dropping the table forces the per-profile choice out in the same task (Task 2).** The drop
  removes `deviceProfileHomeLayouts`, so every reader of it — the catalogue's four per-profile
  functions, two management routes, the configuration transfer, the classification, the venue
  service's resolver and the dashboard's profile section — must go in the commit that drops it,
  or the tree does not compile. To keep the till out of Task 2, the served menu keeps its
  `homeLayoutId` and `layoutFallback` fields for one task, filled with the menu's default and
  `null`; Task 3 removes them.
- **The working model and the published format are one task (Task 3).** The named-layout
  functions, the document's `homeLayouts`, the served menu's fields and the till's single read of
  them are one contract: removing any one breaks the others' compile. Task 3 changes them together
  and makes only the change the till and dashboard compilers force; the till's new drawing (Task
  5) and the dashboard's new screens (Tasks 6–8) follow.
- **The dashboard is split into two widgets and then the screen (Tasks 6, 7, 8),** so each widget is
  test-first in isolation and the Menus screen changes once. Between Task 3 and Task 8 the
  dashboard's old Home page tab still compiles but calls routes Task 3 removed; nothing on the
  branch is released in between.
- **Owner gate.** Task 2 edits three guards under `scripts/` (spec question 1), including the
  first half of `scripts/catalogue-engine-neutral.test.ts`'s file list, because that guard fails
  by name as soon as a listed file is gone (`scripts/catalogue-engine-neutral.test.ts:78-82`) and
  Task 2 deletes `schema/home-layouts.ts`. Task 3 makes the list's second edit under the same
  answer: Task 3 cannot start before Task 2 is done, and Task 2 is done only once the answer is in.
  If Task 2 reaches its gate with no owner answer, Tasks 1 and 4 do not depend on it and may run
  meanwhile.
- **Canvas cards follow the menu's setting.** Spec Decision 7 (as revised): a till canvas card
  that sets no column count follows the menu's setting for the device; a card's own count wins.
  Task 5 builds that.

## Review focus

1. **A draft never reaches a live device.** A shortcut added, or a display setting changed, after a
   publish leaves both offers routes and `/api/menu-state` serving the published home block until
   the menu is published again. Pinned in Task 3 (`till-api.sell-published.test.ts`).
2. **"Menu first", then a section, then Home.** On a device whose order is `menu_first`, opening a
   section from the menu block and pressing the breadcrumb's Home returns to the arranged home with
   the menu block first, not a shortcuts-first view. Pinned in Task 5.
3. **A shortcut block holding only missing targets.** It is not drawn at all, no divider shows, and
   the menu block keeps an accessible name; on the dashboard preview too. Pinned in Tasks 5 and 7.
4. **Many columns on a narrow screen.** Handheld at 6 columns on a 300 px wide browser and Till at
   10 on a narrow one show fewer columns, never a tile below the minimum width, and the reading
   order row by row is unchanged. Pinned in Tasks 5 and 7.
5. **Thumbnails with nothing to show.** In Thumbnails mode a product with no image and no colour
   draws the neutral tile with its name and price; a section with an image keeps its "Section"
   word. Pinned in Tasks 5 and 7.

/** The first key of `patch` holding a value `device` cannot take, or null. An absent key is not
 * checked. The columns have no CHECK, so this is the whole of the range's enforcement. */
export function homeDisplayProblem(
  device: HomeDevice,
  patch: { columns?: unknown; tiles?: unknown; order?: unknown },
): keyof HomeDisplay | null {
  const { min, max } = HOME_COLUMN_RANGE[device];
  const { columns, tiles, order } = patch;

    columns !== undefined &&
    !(typeof columns === "number" && Number.isInteger(columns) && columns >= min && columns <= max)

  if (order !== undefined && !(HOME_ORDERS as readonly unknown[]).includes(order)) return "order";
  return null;
}

type DocumentSection = Extract<DocumentMember, { kind: "section" }>;

export interface HomeIndex<P> {
  /** Keyed by section id: every section with something to order somewhere beneath it. */
  sections: Map<string, DocumentSection>;
  /** Keyed by product id: each product the structure reaches and `offerOf` answers, once. */
  products: Map<string, P>;
}

export function indexDocument<P>(
  members: readonly DocumentMember[],
  offerOf: (menuItemId: string) => P | undefined,
): HomeIndex<P> {
  const index: HomeIndex<P> = { sections: new Map(), products: new Map() };
  const walk = (list: readonly DocumentMember[]): boolean => {
    let holdsSomething = false;
    for (const member of list) {
      if (member.kind === "product") {
        const offer = offerOf(member.menuItemId);
        if (offer === undefined) continue;
        holdsSomething = true;
        // A product placed twice keeps its first place: a Map keeps a key where it was first set.
        index.products.set(member.productId, offer);
      } else if (walk(member.members)) {
        holdsSomething = true;
        index.sections.set(member.sectionId, member);
      }
    }
    return holdsSomething;
  };
  walk(members);
  return index;
}

/** The menu's root, its Device Home Page section and both display settings. */
async function requireMenuHome(tx: Transaction, menuId: string): Promise<HomeRow> {
  const [row] = await tx.select().from(menuDetails).where(eq(menuDetails.menuId, menuId));
  if (row === undefined) throw new AppError("catalogue.not_found", { catalogueId: menuId });
  return {
    rootSectionId: row.rootSectionId,
    homeSectionId: row.homeSectionId,
    handheld: { columns: row.handheldColumns, tiles: row.handheldTiles, order: row.handheldOrder },
    till: { columns: row.tillColumns, tiles: row.tillTiles, order: row.tillOrder },
  };
}

export async function setHomeDisplay(
  tx: Transaction,
  menuId: string,
  device: HomeDevice,
  patch: { columns?: unknown; tiles?: unknown; order?: unknown },
): Promise<void> {
  await requireMenuHome(tx, menuId);
  const field = homeDisplayProblem(device, patch);
  if (field !== null) throw new AppError("menu.home_display_invalid", { device, field });

    ? { handheldColumns: patch.columns, handheldTiles: patch.tiles, handheldOrder: patch.order }
    : { tillColumns: patch.columns, tillTiles: patch.tiles, tillOrder: patch.order };

  if (Object.keys(changes).length > 0)
    await tx.update(menuDetails).set(changes).where(eq(menuDetails.menuId, menuId));
}

import { LitElement, css, html, nothing } from "lit";
import { customElement, property, state } from "lit/decorators.js";
import { baseStyles } from "../base-styles.js";
import { delegatesFocusShadowRootOptions, dispatchWtChange, uniqueId } from "../interactive.js";

/** A labelled whole-number range that shows its value. */
@customElement("wt-slider")
export class WtSlider extends LitElement {
  static override shadowRootOptions = delegatesFocusShadowRootOptions;

  static override styles = [
    baseStyles,
    css`
      :host {
        display: grid;
        gap: var(--wt-space-1);
        max-width: var(--wt-field-max-width);
      }
      .row {
        display: flex;
        align-items: baseline;
        justify-content: space-between;
        gap: var(--wt-space-3);
      }
      [part="value"] {
        font-weight: var(--wt-font-weight-bold);
        font-variant-numeric: tabular-nums;
      }
      input {
        width: 100%;
        min-height: var(--wt-tap-min);
        margin: 0;
        accent-color: var(--wt-color-primary);
      }
      input:focus-visible {
        outline: var(--wt-focus-ring);
        outline-offset: var(--wt-focus-offset);
      }
      :host([disabled]) {
        opacity: var(--wt-opacity-disabled);
      }
      .error {
        margin: 0;
        color: var(--wt-color-danger);
        font-size: var(--wt-font-size-sm);
      }
    `,
  ];

  @property() label = "";
  @property() name = "";
  @property({ type: Number }) min = 0;
  @property({ type: Number }) max = 10;
  @property({ type: Number }) step = 1;
  @property({ type: Number }) value = 0;
  @property({ type: Boolean, reflect: true }) disabled = false;
  @property() error = "";
  @state() private shown: number | null = null;

  readonly #id = uniqueId("wt-slider");

  #onInput(event: Event): void {
    event.stopPropagation();
    this.shown = Number((event.target as HTMLInputElement).value);
  }

  #onChange(event: Event): void {
    const value = Number((event.target as HTMLInputElement).value);
    this.shown = null;
    this.value = value;
    dispatchWtChange(this, event, { value });
  }

  override render() {
    const errorId = `${this.#id}-error`;
    return html`<div class="row">
        <label for=${this.#id} part="label">${this.label}</label>
        <span part="value" aria-hidden="true">${this.shown ?? this.value}</span>
      </div>
      <input
        id=${this.#id}
        type="range"
        name=${this.name || nothing}
        .min=${String(this.min)}
        .max=${String(this.max)}
        .step=${String(this.step)}
        .value=${String(this.value)}
        ?disabled=${this.disabled}
        aria-invalid=${this.error ? "true" : nothing}
        aria-describedby=${this.error ? errorId : nothing}
        @input=${this.#onInput}
        @change=${this.#onChange}
      />
      ${this.error ? html`<p class="error" id=${errorId} role="alert">${this.error}</p>` : nothing}`;
  }
}

    "wt-slider": WtSlider;

}
