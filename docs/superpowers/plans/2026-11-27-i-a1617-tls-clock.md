# A1617. Keep the box's certificate usable when its clock is corrected

A device that already trusts the box can reconnect after the box's start confirms the time, even
if the box previously issued its HTTPS certificate while running fast. While that start waits,
keep serving the saved certificate and defer issuing a replacement.

The queue's 04:25 assignment comes from the certificate entry in
[Finish the clock work](../../backlog/box.md#the-boxs-certificate-issued-under-a-wrong-clock).
On main at `2a93a48d7b`, the local Node HTTPS probe issued a leaf three days ahead under a
correctly dated authority. The correct-clock control returned 200. The HTTPS repair request then
failed with `CERT_NOT_YET_VALID`. HTTP landing reached repair and returned 200 with the same
leaf while the box still ran ahead. After the clock correction, entry selected the existing HTTP
bootstrap and its repair kept the authority byte for byte. The running HTTPS listener still
refused the client. A fresh HTTPS listener with that repaired leaf returned 200 using the old
authority. A complete first mint while ahead also future-dated the authority and needs the
existing new-trust recovery.

1. In `apps/server/src/boot.ts` and `box-secrets.ts`, use the existing start-clock hold for the
   full start that would already wait. Defer its `ensureLeaf` write before confirmation. Keep
   the existing pre-bind check on an already confirmed start and for modes with no hold. After a
   deferred start is confirmed, run the check through the existing clock watch, in the clock
   correction's turn. Reuse `ensureLeaf`'s validity checks and locked writes. On reissue,
   load the saved pair into the live box HTTPS listener with `setSecureContext`. Use the
   existing warning path if signing or loading fails.
2. In `discovery-api.ts`, `landing-app.ts` and `box-tls-repair.ts`, pass the same hold to the
   repair operation mounted by that running box. Check it inside the existing recovery lock,
   before the repair writes a replacement. A healthy repeat still reads the current state.
   The entry's existing HTTP bootstrap remains available if a future-dated certificate keeps
   the full start from opening. It repairs under the retained authority when that authority
   is usable, then Continue starts a fresh listener. An operator certificate, trust replacement,
   first setup and starts without the existing clock hold use their current paths.
3. Begin with failing cases in `boot.start-clock-gate.test.ts`: a saved leaf missing a required
   name keeps its original serial during the wait, then serves the new name after confirmation.
   A leaf issued three days ahead keeps its serial through the wait, then a real TLS connection
   verifies under the original CA after correction and confirmation. In `box-tls-repair.test.ts`,
   check the same pending hold on the repair write and a healthy repeat. Run those files and the
   trading TLS and landing/discovery suites. Repeat the HTTP bootstrap probe as the restart
   control. Remove the completed entry and its bundle pointer from `docs/backlog/box.md` and
   update the historical clock table in `docs/developers/conventions-data.md`.

Expected change is about 100 lines of server code and 140 lines of tests, plus the backlog and
clock notes. The existing clock decision, signing authority and repair route supply the inputs.
