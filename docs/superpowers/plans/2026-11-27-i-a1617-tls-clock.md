# A1617. Keep a replacement box certificate usable when its clock runs fast

A device that trusts the box's authority can connect after the box replaces its HTTPS
certificate, even if the box ran several days ahead when it signed the replacement.

The [backlog entry](../../backlog/box.md#the-boxs-certificate-issued-under-a-wrong-clock)
and Lane I's 04:25 queue item name the defect. On main at `2a93a48d7b`, Codex used the real
issue and repair functions and real local listeners. A correct-clock client reached `/health`
with a correctly dated leaf. With a replacement issued three days ahead it got
`CERT_NOT_YET_VALID` on the HTTPS repair request. The public HTTP route answered 200 and
kept the leaf while the box still ran ahead. After the correction the existing HTTP bootstrap
repaired the leaf under the same authority, and a fresh HTTPS listener accepted the original
client trust. The running listener kept serving its old leaf. A first mint while ahead also
future-dated the authority and needed new trust.

The assigned Claude reviewer proposed dating the replacement HTTPS certificate from its
retained authority. This also lets boot replace a leaf to add the box's own name or IP address
before devices need that name to connect. The queue asks to defer issuing during the existing
clock wait and reissue after confirmation. Use the smaller route below if the watcher clears
the change of approach.

1. In `apps/server/src/self-signed-cert.test.ts`, write the failing case first. Mint the authority
   on the test client's actual clock, reissue the server leaf three days ahead under that
   authority, then use a real TLS handshake that trusts it and names a SAN newly added by the
   replacement. Expect the client to connect. Main refuses with `CERT_NOT_YET_VALID`. Check the
   leaf's validity interval is contained in the root and signing certificate's shared window.
2. In `apps/server/src/self-signed-cert.ts`, set the replacement server leaf's start time to
   the later of the root and signing certificate's start times. Keep the current expiry cap and
   current authority checks. Every call to `reissueServerLeaf` gets the date from the same place.
   This proposal covers replacements under a current authority. An already future-dated leaf
   uses HTTP Repair and Continue after correction. A future-dated authority uses the existing
   new-trust flow. First mint and client certificate dates are outside this item.
3. Run `self-signed-cert.test.ts`, `box-secrets.test.ts`, `box-tls-repair.test.ts` and
   `connection-bootstrap.entry.test.ts`. Use the existing retained-trust bootstrap as the
   recovery control. Remove the completed entry and its pointer from `docs/backlog/box.md`,
   update the bundle count, and add a dated pointer by the historical clock-table receipt in
   `docs/developers/conventions-data.md`.

Expected size is 5 to 15 lines of server code and 20 to 40 lines of test, plus the backlog and
clock notes.
