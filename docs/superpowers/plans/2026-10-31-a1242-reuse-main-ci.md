# A1242: reuse equal-tree pull-request CI

> Execute inline with the executing-plans skill. Authority: the owner's A1242 queue entry,
> 2026-10-31 04:15, which authorises build, FULL finish-branch and land-branch.

**Goal:** avoid repeating tests on main when the merged tree has successful PR CI.

**Design:** keep classification and its publishing decision unchanged. A new verifier in
`scripts/ci-reuse.mjs` emits a separate reuse decision. Only main push events may reuse.
Read the associated merged PR, both commit trees, the latest exact-head run of this workflow,
and its exact attempt's complete jobs through GitHub's API. Require the same repository,
successful changes/lint/root-guards/ci jobs, every workflow job present and final, and no failed
or cancelled job. Re-read the source run after its jobs to reject an attempt changing underneath
the check. Missing, malformed or unavailable evidence retains normal CI.

All jobs upstream of ci except changes skip on verified reuse. The aggregate still validates
its current jobs through both existing checks; selected coverage merges may skip only with a
verified reuse output and concrete source run id. Publish and main-tag-guard retain their gates.
Nightly, weekly, mutation.yml and per-push concurrency remain unchanged. This deliberately
reuses PR scoping as authorised by A1242; a different merged tree retains main's full path.

Review corrections: every checkout selects the PR head for PR events, and the PR trigger
selects main, so the candidate's PR checks run against the head whose tree is compared. Lint
and root guards retain diagnostics after a changes failure. Refusal tests observe API reads;
the workflow guard refuses a tolerated verifier crash. The Git fixture's case budget includes
all twenty sequential command timeouts. Earlier-main health and skipped image-smoke policy
remain owner decisions before landing; the candidate retains the initially specified scoped reuse.
