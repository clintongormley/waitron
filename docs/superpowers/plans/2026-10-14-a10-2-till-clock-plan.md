**Goal:** Let an admitted, signed-in person record their own start, breaks and finish on a clock-enabled till or venue handheld.

**Architecture:** Add one profile action and a small self-service server adapter over the landed workforce library. Keep clock state separate from the operator's login session: the app coordinates the first-sign-in page and logout, while the tab shell presents the name menu. Reads and writes use server time and the existing venue transaction queue.

**Tech stack:** TypeScript, Hono, Drizzle/SQLite through `useVenueDb`, Lit/shared `wt-*` controls, Vitest with real Chromium.

**Specs:** Read the full `docs/superpowers/specs/2026-10-12-a10-clocking-in-and-out-design.md` (part 2 and decisions 1–4) and `docs/superpowers/specs/2026-07-22-workforce-and-time-record-design.md`. ## Constraints and executable defaults

- Implement **only part 2**. No end-of-day discovery/automatic closure, pending questions, corrections, manager PIN flow, period scheduler, hours screen or export. Keep all workforce writers/hashes/projections, fiscal builders/chains/allocation, golden tests and migrations unchanged.
- Carry the owner's UI words: big **Clock in** with **Cancel** beside it; Cancel lets you work without clocking in and the next sign-in asks again. Clock actions live **behind the person's name in the top bar**, with a clock-state dot; they fold into handheld **More**. **Clock out also logs out. Log out alone leaves you clocked in.** Nothing optional interrupts entry to work.
- **Part-5 intermediate:** omit My hours until part 5 supplies its screen. Do not point it at My Schedule, add an hours placeholder, or draw a disabled/dead action. Part 2's split explicitly names clock/break items; the full decision still requires My hours in this menu when part 5 lands, never after sign-in. - Routine default: add `clock-in` to new Counter and Handheld starter profiles. Preserve the empty tablet default and KDS defaults; an operator tablet can explicitly enable clocking. Existing saved profiles opt in through Device profiles; no stored-profile rewrite.
- Any active person admitted by the current profile may clock **only themselves**, irrespective of staff/supervisor/manager/admin role. No manager override and no new managerial permission. Enforce the person with `canUseDeviceProfile`, not a client permissions list. Keep all other permissions and login refusals intact.
- Use the deployment node/location; refuse a session device in another location. Live state is person-wide, as the library is; an open state at another location is shown with clock actions unavailable and an explanatory message. Do not create a second shift or close another location's shift from this device. Log out and normal till use remain available.
- Interpret “day” for the first-sign-in prompt as the device location's **business day**, using its time zone, cutover and scheduled cutover history. Prompt only when state is `out` and there is no qualifying `in` in that location's current business-day window. Cancellation stores no persistent “asked” flag. After a completed shift that day, the menu still offers Clock in. An old open shift remains working/on-break across midnight/cutover; part 3 owns its automatic closure.
- Clock out during a break calls `breakEnd`, then `clockOut`, in **one write transaction at one server instant**. This ends the break without counting it as worked time; never write a fabricated automatic end.
- Requests may carry only `expectedEntryId`, a server-issued last-entry id or null. Reject person/time/location/node/origin/offset/override fields. No offline buffer, automatic POST retry or client clock. A lost write response triggers an own-state read before another action.
- A10-1 owner rulings remain fixed: every admin qualifies for self-approval; automatic ends count immediately and retain separate worker acknowledgment. This part implements neither process.
