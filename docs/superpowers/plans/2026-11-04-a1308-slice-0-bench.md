# A1308 slice 0: the bench and the protection list — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** give every later A1308 slice two tools: a list of every protection in the schema that can
be compared before and after a change, and a year-of-trading venue with timings of the paths that
matter, measured before and after a change.

**Architecture:** both tools live under `apps/server/scripts/`, which is typechecked and whose
`*.test.ts` files run, and they use the server's own test helpers without any CI wiring. The
protection list reads a freshly built database through the real `applyMigrations`. The bench drives
the real routes through `app.request`, with no network and no background work, so its dataset is
rebuilt by the same code on any later schema instead of depending on today's tables.

**Tech stack:** TypeScript run by `tsx`, `node:sqlite` through `@waitron/store`, Hono, Vitest.

**Spec:** [the design](../specs/2026-11-02-rationalisation/README.md), §6 and §9 step 1. Read the
[A760 runbook](../../operations/a760-migration-squash.md), "Comparison and preservation contract":
this plan builds its `inventory` (as `protection-list list`) and `compare`, and
[the A760 plan](2026-11-04-a760-squash-into-eight-sets.md) uses them.

**Status under the A1308 hold:** changes no table, needs no freeze, and may start at once.

## Global Constraints

- No migration, schema file, table, column, index or trigger changes.
- Nothing the bench or the protection list writes goes inside the repository. Their unit tests run in
  `apps/server`'s suite, so keep them small; building and measuring the year never run in CI.
- Volumes, copied from the appendices: 250 bills a day × 360 days = 90,000 bills; 4 lines a bill on
  average; 2–3 kitchen rounds a bill; 4 tills, 2 kitchen screens, 3 thermal printers; about 150
  dishes; 6 floor zones; 2 departments; about two thirds of bills paid by card (60,000 payments a
  year).
- Timed paths have no pass mark. The rule is before against after, on one machine (`README.md` §6).
- Today's `sessions` and `attendance_operation_facts`, which become `till_sessions` and
  `staff_activity`, and print job payloads stay unpruned in the dataset (`README.md` U10).
- Stop only processes you started, by recorded id. Bound long runs by activity, as tracked background
  work.
- Every commit `git commit -s`; plain English in commit messages and the PR.

## Review Focus

1. **A same-name protection whose body changed.** A CHECK, trigger, index expression or foreign key
   action changed under an unchanged name must show as `changed`, never `EQUAL`. Pinned in Task 2.
2. **SQL text the reader could misparse.** Unnamed CHECKs, a `)` or `--` inside a quoted string, a
   multi-line trigger body. Each must round-trip. Pinned in Task 1.
3. **A timing that measures its own setup.** Only the final request of a case is inside the timer;
   a case run on an empty table proves nothing. Pinned in Task 6.
4. **The year crossing clock changes.** Europe/Madrid changes its clocks twice in the year, and the
   venue's business day and the fiscal clock stop both read the clock. Bills spanning 01:00 UTC on
   both Sundays must complete with no `floor_today.out_of_date` and no clock refusal. Pinned in Task 4.
5. **A build stopped halfway and resumed.** Append-only tables cannot be cleaned, so a resumed build
   restarts from the last finished day's copy, never from a half-traded folder. Pinned in Task 5.

## Out of scope, by decision

Each is measured by the slice that needs it (`README.md` §6): `tables-fiscal.md` §8's 500,000 rows
and `tables-menu.md` §8's version and image counts, which exceed a year's trading; `jobs.md` §8's
archive against Cloud's limit and its loaded service simulation. Figures from a loaded machine are not
this bench's.

### Task 1: Read a built database into a list

**Files:**
- Create: `apps/server/scripts/protection-list/sql-tokens.ts`,
  `apps/server/scripts/protection-list/read-schema.ts`, and a `.test.ts` beside each
- Modify: `apps/server/package.json` (script `"protection-list": "tsx scripts/protection-list/cli.ts"`,
  added in Task 3)

**Interfaces:**
- Produces:
  - `normaliseSql(sql: string): string`: removes whitespace between tokens only; quoted identifiers,
    string literals and comments-as-tokens handled by a quote-aware tokeniser.
  - `checksIn(createSql: string): { name: string | null; expression: string }[]`: every table and
    column CHECK, named or not.
  - `readSchema(db: DatabaseSync): SchemaList` where `SchemaList` holds, for each table and view:
    `pragma_table_list` options (STRICT, WITHOUT ROWID), ordered `pragma_table_xinfo` columns (name,
    type, nullability, default, hidden or generated, primary-key position), foreign keys with both
    actions, CHECKs, every implicit and explicit index (`pragma_index_list`, `pragma_index_xinfo`:
    unique, origin, key order, collation, descending, partial predicate, expression SQL), triggers
    (target, event, WHEN, full body, relative creation order on the same table), and every row of
    every table as typed tuples with BLOBs byte-exact. Each object also carries its stored `sql`,
    its `sqlite_schema` rowid and CHECK conflict clauses, because
    [A760's `preserve`](2026-11-04-a760-squash-into-eight-sets.md) needs them.

  holds `)` and `--`, each with its exact expression. In `read-schema.test.ts`, on an in-memory
  database built from a fixture covering every kind listed above: assert each field read, a BLOB

### Task 2: Compare two lists

**Files:**
- Create: `apps/server/scripts/protection-list/compare.ts`, `compare.test.ts`

**Interfaces:**
- Consumes: `SchemaList` from Task 1.
- Produces: `compareSchemaLists(before: SchemaListFile, after: SchemaListFile): Difference[]`, where
  `Difference` is `{ kind: "missing" | "changed" | "extra"; composition; phase; object; before?; after? }`,
  and `formatDifference(d): string` printing the runbook's format
  (`missing trigger products_media_image_fk_parent_delete`,
  `changed table sales.check[sales_source_ck].expression`), under a header line
  `DIFF composition=… phase=…`. Tables named `__drizzle_migrations_*` and their rows are left out of
  the comparison and counted separately in the file. **Set order, journals, owning set, rowids and
  stored `sql` are never compared:** 17 sets becoming 8 must print `EQUAL`. Trigger creation order is
  compared per table, timing and event, the only order that can change behaviour. Installers run
  after a set's SQL, so merging sets may legitimately move an insert trigger ahead of an update one.

- [ ] **Step 1: Write the failing tests.** Accepted as equal: reordered keys and rows, whitespace
  outside quotes. Refused, each asserting the exact `Difference`: a missing table, index, CHECK, FK
  or trigger; an extra object; and a **same-name** change to an FK action, CHECK body, index
  expression, index predicate, column type, column default, primary-key position, unique column
  list, trigger body, the order of two triggers with the same table, timing and event, a BLOB byte
  and a seeded value. Refused: either
  side with zero objects (a comparison of nothing is a failure, not `EQUAL`). Accepted: two lists
  that differ only in set order, journals, owning set, rowids, stored `sql`, or the order of triggers
  on one table that differ in timing or event.
- [ ] **Step 2: Run, and see them fail.**
- [ ] **Step 3: Implement** with no allowance list and no normalisation beyond `normaliseSql`,
  sorting by stable keys, and the bookkeeping exclusion. `sqlite_sequence` is compared, not excluded.
- [ ] **Step 4: Run, and see them pass.**
- [ ] **Step 5: Commit.**

**Payment mix,** to land on the appendices' counts rather than be found out after a full build: 45%

**At the end of each day,** in-process, what boot would run in the background:
- Filing: `drain({ db, resolveClient, skipRetryMs, environment }, now)` against `createFakeAeat` from
  `@waitron/verifactu/testing`, calling `setServerNow(now)` first: its default date is 2026-07-21, a
  later record comes back `rechazado` 1112, and three in a row hold every record after them.
  `environment` matches the rows' `entorno`. The fake cannot go through boot: `slot.ts` hard-wires

- Attendance: `beginAttendanceDiscovery` is started **once** for the whole build. Step it with

- Daily close: `recordDailyClose`, called directly. Neither boot nor a route calls it today, so it is
  the bench's addition, and the PR says so.

**Give timers a turn:** `await` a `setImmediate` every 25 bills. Synchronous `node:sqlite` starves the

### Task 6: Time the paths

**Files:**
- Create: `apps/server/scripts/bench/measure.ts`, `measure.test.ts`, `compare-timings.ts`,
  `compare-timings.test.ts`
- Modify: `apps/server/scripts/bench/cli.ts`

**Interfaces:**
- Consumes: `openBenchVenue`; a built year.
- Produces:
  - `bench measure --venue <dir> --out <file> [--samples 200] [--rounds 3]`, working on a copy-on-write
    copy (`cp -c -R`) so the built year stays clean. The result records median, 95th percentile, max
    and count for each case and round, plus machine, Node version, commit, seed and `volume.json`'s
    total.
  - `bench compare --before <file> --after <file>` prints one row per case: before, after, and
    `slower` when after's median exceeds before's highest round median by over 10%, `faster` the
    other way, `same` otherwise. It refuses two results with a different seed, profile or machine.
    It always exits 0: it reports, and a person reads it. (2026-11-10, A1474: results also record
    SQLite's version and whether it has STAT4, and compare also refuses two results that differ in
    Node, SQLite or STAT4, or that do not record them; see `docs/developers/testing-guide.md`, "The
    bench".)

| Case | Request timed | Set up first, outside the timer |
| --- | --- | --- |
| `payment.partial` | `POST /api/working-orders/:id/payments`, part of the bill | a served open bill |
| `payment.final` | same route, clearing the bill, which also issues the sale | a served open bill |
| `sale.counter` | `POST /api/sales` | the till signed in |
| `filing.pass` | one `drain(...)` of 50 waiting sales against the fake AEAT, with `now` stepped past the send gate (`drain.ts:220-255`) | 50 issued, unfiled sales; assert all 50 accepted |
| `floor.read` | `GET /api/tables/state` | 15 seated tables |
| `floor.open` | `GET /api/zones` then `GET /api/tables/state` | 15 seated tables |
| `kitchen.queue` | `GET /api/stations/:id/queue` | 30 open items on the station |
| `kitchen.screen` | `GET /api/device/station-screen` with the `kds` device's cookie: a kitchen display has no signed-in person | 30 open items |
| `kitchen.pass` | `GET /api/expo/board` | 30 open items |
| `kitchen.pass-screen` | `GET /api/device/pass-board` with the `kds` device's cookie | 30 open items |
| `dashboard.open` | `GET /management-api/session/me`, `/reports/overview`, `/reports/overdue-orders` | a manager's session, a day's trading |

Use raw `app.request`, never the helpers' `send`, which adds its own reads. The floor, kitchen and
report reads take the write lock (`packages/db/src/tenancy.ts:30-42`), so an idle database shows
their best case. The result file says `"load": "idle"`; a loaded measurement belongs to the slice
that needs one (`jobs.md` §8).
