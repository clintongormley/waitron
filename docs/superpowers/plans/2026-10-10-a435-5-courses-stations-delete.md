# Courses and kitchen stations deletion implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** You can permanently delete a course or prep station after seeing its impact, reuse its name, and keep recorded orders and kitchen work intact.

**Architecture:** Reuse `DeleteImpact` and `wt-delete-dialog` from A435-2. Server operations recompute impact on their caller's transaction; venue-service owns removal of its routing and screen settings. Existing `active = false` means permanently deleted for these two kinds, with a hard delete only for a course with no references before cleanup.

**Tech Stack:** TypeScript, Drizzle over SQLite, Hono, Lit, Vitest with real venue databases and Chromium.

**Spec:** [Delete and archive design](../specs/2026-10-08-delete-and-archive-design.md), step 5 only, including its 2026-10-10 station-inventory correction.

## Review focus

1. A ticket arrives after impact: deletion must refuse with its domain code and leave every setting unchanged (Task 5).
2. A period routes to a station its base cell does not name, or another period hangs off a removed base: disclose and remove the correct rows without double counting (Task 4).
3. A stored draft names a now-deleted course: sending or editing that retained choice still works, but a new line cannot select it (Task 3).
4. A device/profile loses its last explicit station: an empty choice must never become permission to see every station (Tasks 4, 8).
5. A departed dialog's read, Retry or Confirm fires on a replacement opening: it must not affect the replacement or send its request (Tasks 7, 8).

### Exact deletion contract

Use the existing `DeleteImpact = { target: { id, name }, refusals, ends, removes }` from `packages/shared/src/delete-impact.ts`, unchanged. No course/station-specific wire type or new shared dialog primitive is needed. Both kinds have `ends: []`.

| Kind | Exported server interface in new file | Wire |
| --- | --- | --- |
| Course, `apps/server/src/course-delete.ts` | `readCourseDeleteImpact(tx: Transaction, cfg: TillConfig, id: string): Promise<DeleteImpact>`; `deleteCourse(tx: Transaction, cfg: TillConfig, id: string): Promise<DeleteImpact>` | `GET /management-api/courses/:id/delete-impact`, `DELETE /management-api/courses/:id`, both 200 with full impact |
| Station, `apps/server/src/station-delete.ts` | `readStationDeleteImpact(tx: Transaction, cfg: TillConfig, id: string): Promise<DeleteImpact>`; `deleteStation(tx: Transaction, cfg: TillConfig, id: string, now?: Date): Promise<DeleteImpact>` | `GET /management-api/stations/:id/delete-impact`, `DELETE /management-api/stations/:id`, both 200 with full impact; no delete body |

Each file has one private rules reader used by impact and delete. Station refusal order is fixed: default, bound screens, preparation. Declare new errors in `apps/server/src/errors.ts`, import that registry at the throwing file, and map all three to 409 in management:

- `station.is_default`: `{ stationId: string }`, targets `[impact.target]`.
- `station.screen_in_use`: `{ stationId: string; count: number }`, targets distinct bound devices.
- `station.work_in_progress`: `{ stationId: string; count: number }`, count ticket rows, targets distinct orders with the existing order/table display label.

Course refuses nothing. Both operations first require an active row in `cfg.locationId`; unknown, wrong-location or already-deleted ids use the existing not-found code and params. A repeat Delete is not-found, not a second cleanup or eventual hard delete. Throw the first current station refusal before any write.

Impact items omit zero counts. Counted rows have `targets: []`; named targets are deduplicated by id and sorted with `createLabelComparator`, then id, as in printer deletion. Exact keys:

- Course: `course_products` counts every product whose default will clear; targets empty.
- Station core: `station_unsent_lines`, `station_draft_lines` count lines, `station_printers` names distinct printers, `station_made_here` names devices, `station_timing` counts its timing row.
- Station module: `station_routing_cells`, `station_routing_periods` count actual rows removed; `station_device_screens`, `station_profile_screens` name distinct devices/profiles; `station_daily_states` counts owned rows; `station_daily_destinations` names distinct other stations whose destination clears. Removing station-specific screen-removal notices is part of `station_device_screens`; include their devices too, without double counting.

PATCH containing its own `active` key, of **any** value, returns 400 `management.request_invalid`, `{ field: "active" }`. Reject presence before the empty-patch return. Ordinary edits on deleted ids, including `{}`, return 404 after authorised lookup. `DELETE courses/:id?disable=…` rejects the presence of `disable` with 400 `{ field: "disable" }`; do not silently reinterpret old callers as permanent deletion. Lists ignore the obsolete `includeDisabled` query and never reveal deleted rows. Remove that query from all clients.
