# A1308 environment, PR 7 of 8: one list of every variable — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One module declares every `WAITRON_*` variable a Waitron program reads, with its type,
default, rule, whether it is secret, which programs read it and its one source. Every TypeScript
reader reads through it, so a name the list does not declare does not compile. At start the box logs
one line naming any `WAITRON_*` it does not know, and any name found in a box file that the file does
not own. One guard holds the list and the print agent's own list against every `WAITRON_*` written
anywhere in the repository.

**Architecture:** The list is pure data in `@waitron/shared` (the package every other package
already depends on), so the server, the commands in other packages and the tests can import it; the
print agent, which imports nothing from this repository (CLAUDE.md §3), exports its own short list
from its `config.ts`. `readVariable(env, name)` is a typed accessor that returns the raw value; it
changes no reader's handling of an empty value. A committed script turns every
`env.WAITRON_X` read into `readVariable(env, "WAITRON_X")`. The box's three files
(`trading.env`, `secrets.env`, `backup.env`) are each read for their own names only, so a stray name
in the wrong file is ignored and reported rather than silently winning.

**Tech Stack:** TypeScript, Vitest.

**Spec:** [`environment.md`](../specs/2026-11-02-rationalisation/environment.md) §1 "One list", E2,
E3, §2 (the target list), §4 "Upgrades and migrations", §5 measures 2 and 6;

## Global Constraints

- An empty value counts as unset (`isUnset`, `apps/server/src/env-value.ts:5-7`); `readVariable`
  does not change that, and readers keep their own `isUnset` calls.
- No refusal for any name (environment.md §1, owner 2026-11-04). The start only logs.
- A log line carries names only, never a value (CLAUDE.md §3: values may be secrets).
- `@waitron/shared` stays browser-safe: the list module imports nothing from Node.
- `@waitron/shared` is mutation-tested with a floor of 90 (CLAUDE.md §2); the module's functions get
  tests that kill their mutants (Task 1).

## Review Focus

1. A box whose `backup.env` carries `WAITRON_NODE_ID` must not become another box: the name is
   ignored there and reported; `trading.env`'s own value is used.
2. The unknown-name line must not appear on an ordinary box: the image's own `ENV` names

   list with those sources, and the start passes the print agent's names as `alsoKnown` (Task 2).

   `isUnset`, `WAITRON_CREDENTIALS_KEY_PREVIOUS=` and no version is "neither", not a half rotation.
5. The rename script must not touch an assignment (`env.WAITRON_X = …`), a `delete env.WAITRON_X`,
   an object key (`{ WAITRON_X: … }`) or a test file.
