# A980 staff data actions implementation plan

The existing staff ZIP shows the remaining non-fiscal actions attributed to the person and the workforce decisions they made about other staff. Both download routes use the same parts and retain their existing authorisation and final recheck. The scope is [A980 in the backlog](../../backlog/data-protection.md#a980--data-protection-waitrons-side) and [design §2.1, row s12](../specs/2026-10-22-a980-data-protection-design.md#21-staff), narrowed by the Lane K queue at 02:25 on 23 November.

## Read the recorded actions

- Add `apps/server/src/personal-data-staff-actions.ts` and register `staff-actions.json` in `personal-data-export-api.ts`. Select the person's bill editor, draft owner and line credit rows, identifying the order or draft and line by number or id. Those fields describe the attribution the box still holds. Include handled alert code and time, activity kind and time, the role and status of non-invoice mail, receipt handover time and job id, and the current settings module and save time. For mail, distinguish being the subject from requesting it and allow both roles on one row. Select only those fields and useful row identifiers. Omit customer data, notes, activity and settings payloads, mail addresses, parameters and bodies, and print bytes and claim tokens.
- Add `packages/workforce/src/personal-data-decisions.ts`, with `workforceDecisionsPersonalData(db)` exported through `index.ts`. Register it alongside the existing workforce-gated time record in `personalDataServerParts`. `workforce-decisions.json` records decisions matching the download subject as the decider or authoriser. Include absence outcome, dates and decision time, swap outcome and decision time, published rota period and time (including superseded versions), and attendance action and time. Use record ids for reference. Omit absence kind and notes, swap shift details, attendance reasons and changes, and other staff's contact details. Keep their own existing workforce files. Omit each new file when it has no rows.
- Move `readHistory` from `personal-data-service-actions.ts` to `packages/module/src/personal-data-history.ts` as `readPersonalDataHistory`, with a server-side subpath in `packages/module/package.json`. Reuse its bounded rowid pages and yield for the new parts' history reads after the initial write-lock turn. Use explicit projections, deterministic sort order and the existing `jsonFile`. Keep sales, invoice and document tables, unpaid departures, deferred closures, recovery pack data, schema and permissions outside this change.

## Prove the added rows belong in the download

- Start with `apps/server/src/personal-data-staff-actions.test.ts`, “exports only the subject's remaining non-fiscal actions”. Seed other actors, a dual-role non-invoice mail and invoice mail. Assert the exact file, roles, selected fields and no file for an uninvolved person. Move the nine covered actor columns from `NOT_YET` to `READ` in `personal-data-actions.coverage.test.ts` without weakening its inventory checks.
- In `packages/workforce/src/personal-data-decisions.test.ts`, “exports only decisions made for other staff”, use two deciders and include a superseded published rota, a draft and an attendance self-confirmation. Assert the exact four decision lists, the omission of private material, and no file without matching decisions. Update the roster column classification in `packages/workforce/src/personal-data.coverage.test.ts` alongside that proof.
- In `personal-data-export-api.workforce.test.ts`, verify both parts arrive through the ZIP wiring and workforce decisions are absent when workforce is off. Add both filenames to the English and Spanish README inventory in `apps/server/src/i18n/personal-data-readme.ts`. Run the new test files and the changed inventories, ZIP, README and existing service-action test files with each package's `pnpm exec vitest run`. The existing service test continues to check yielding between pages.
- Remove the finished workforce bullet and the covered core columns from `docs/backlog/data-protection.md`, leaving the fiscal and other-module work. Update the A980 summary in `docs/backlog.md`.
