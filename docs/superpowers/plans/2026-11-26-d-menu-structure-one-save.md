# Menu Structure table and Save implementation plan

[Menu editor redesign, delivery 2(d)](../specs/2026-11-24-menu-editor-redesign-design.md#delivery)

A manager can arrange and price an ordinary menu in Structure, save it in one press, and review the saved changes before publishing. Use the save request from #4338 and the ordinary-menu variant rules from #4390. Price overrides and retirement of its requests belong to 2(e). Home page and publishing keep their own workflows.

## Draft and Save

- Add `menu-structure-draft.ts` beside the table. Take the latest complete read whenever clean, including on return from Price overrides. While dirty, hold the owned lists and prices for the owner's last-Save-wins behaviour. Keep IDs on moves and assign UUIDs on additions. Stage all adds, moves, removals and section or folder edits through the existing menus, pickers and dialogs. Use the same Remove for single and selected rows and confirm only when a removed section has contents. Send only owned lists, folder overrides and explicit prices. Keep each price keyed independently of its placements. Omit it when a staged removal takes off its last placement, and restore it on re-add before Save. Let the server report drops caused by external catalogue or include changes.
- Wire `saveMenuStructure(id, input)` in `api/menu-api.ts` and put Save handling in `widgets/menu-structure-save.ts`, with calls from `screens/menus-screen.ts`. Use `draftScopeFor`, `saveActionState` and a fixed `wt-form-actions` bar. Cancel confirms and restores the latest saved state. Navigation asks before leaving dirty Structure. Show an outlined Review and publish while dirty, even on a previously up-to-date menu. Offer Save and review or Keep editing. Open Preview only after Save succeeds. Keep the draft on a refusal and locate its row or field from the submitted array index, with a bar message if no row can show it. A price refusal marks its shared field at every placement and focuses the first one shown. Name dropped items from the submitted draft. Commit the draft on success, then refresh through `MenuReadController` using the write revision and show refresh failures as read failures.

## Table and prices

- Add prices to the existing coordinated menu read in `apps/server/src/menu-api.ts`, `api/menu-api.ts` and `api/live-queries.ts` by returning existing `menuPrices` rows. Seed explicit prices from `override` and `variants[].price` for every reached product, including included-only and sold-out dishes. For each distinct direct include in the draft use one passive combined read for its tree and prices. Use the returned `combined` offers with `combineOffer` and the product library's current base and variant prices. Replace read-only children and price sources as those reads refresh. One price per product or variant drives all its placements and names the other paths while edited.
- Rework `widgets/menu-structure-table.ts` and extract price cells and row presentation below the file cap. Reuse its tree, reorder and search, `wt-price-input`, the in-place product editor and Preview's photo and icon treatment, including the root and variants. Show Name, Price and pinned actions with the spec's counts and Unavailable labels. Show set-menu prices as text and keep pricing on their own page. Remove Structure's immediate-write feedback and Undo. Add the five filters and match variant names. Keep grips in normal view and desktop Select, swap them for checkboxes in phone Select, and keep Move…, Remove and Done together. Keep section links and return focus.

## Checks and delivery

- Start with failing cases in `menus-screen.structure-move.unsaved.test.ts` for no early write, one complete Save, Cancel and tab leave, Save and review, and a refusal or a dropped row. In `menu-structure-draft.test.ts`, check moved IDs, shared prices and clashes across staged includes and live source updates. Prove preservation of included-only prices and clean refreshes, removal and re-add, and unavailable fields when an active variant appears. Extend `menu-structure-table.test.ts` for variant search, phone Select and an included dish with an editable price but a fixed placement. Check the new read part alongside the existing combined-read route cases in `apps/server/src/menu-api.test.ts`.
- Rewrite the affected English and Spanish Products guide sections, the Structure paragraphs in `docs/developers/design-system.md` and the pointer in `docs/backlog/menu.md`. Say in the guide and PR that Price overrides remains through 2(d). Show the watcher the required screenshot matrix at 1440 and 390 px before landing and wait for the owner's recorded answer. Expect about 950 added production lines and 430 added test lines, with immediate-write code and its obsolete expectations removed.
