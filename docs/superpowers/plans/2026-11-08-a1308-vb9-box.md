# A1308 venue and box, PR vb9: the box's own facts are one `box` row in `node.db` — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Every rule in
> [the slice rules](2026-11-08-a1308-slice-rules.md) applies ("rules §n"). Implementers are
> dispatched as `subagent_type: "implementer"`.

**Goal:** `node.db`'s five one-row-per-box tables — `node_recovery_key`, `node_signing_key`,
`node_mode`, `node_mirror_link`, `node_primary_key` — fold into one `box` row per box, each old table
a column group that is all set or all empty. A replaced recovery key, a rotated signing key and a
changed role each leave an event in `node_handover_events`.

**Architecture:** One new file, `packages/node-db/src/box.ts`, is the only code that writes `box`:
one typed writer per column group, plus a sweep of other boxes' rows. The existing modules
(`mode.ts`, `recovery-key.ts`, `mirror-link.ts`, `primary-key.ts`, and
`packages/credentials/src/node-signing-key.ts`) keep every exported name and signature and delegate
their writes to it, so callers do not change. The three handover tables and A947's `node_pair_link`
stay tables of their own.

**Tech Stack:** Drizzle on `node:sqlite` (`node.db`), Vitest.

**Spec:** [tables-venuebox.md](../specs/2026-11-02-rationalisation/tables-venuebox.md) §1.17, §1.18,
§3 (the `box.*` events), §5 (the `node_mode`/`node_signing_key` rows and the write-path row); README
§5 U5 (the second-box column groups kept), §10 "Applied as the design" (the box's events stay in
`node.db`, in `node_handover_events`, with no operation id).

**OWNER LANDS THIS PR** (rules §6, AEAT sending). The box's singleton role decides whether it sends
to AEAT: `apps/server/src/singleton-pass.ts` gates the filing pass on it, read through
`deployment-holders.ts:31` → `readNodeMode`, which this PR rewrites. No value, step or refusal is
meant to change; the owner lands it because a mistake here would stop or double the box's filing.

**Pull request's first line:** "Every venue is reset: node; backups and exports from before this
cannot be restored or imported." (rules §2). Second line: "FISCAL: rewrites where the singleton role
that gates AEAT submission is read and written; owner lands."

   **The role group is nullable, a decision of this plan** (the appendix's table has `mode` not null,
   default `primary`; README §11 leaves exact column lists to the builder): first setup writes no
   `node_mode` row today (`packages/provisioning/src/first-setup-start-again-deletion.ts:405-414`
   allows 0), and A947 3b's G.3 refuses a start when no role is recorded
   (`docs/superpowers/plans/2026-11-04-a947-3b-spare-hosts-store.md:1694-1700`). Once first setup
   writes the box row for its keys, "no row" can no longer carry that meaning, so "no role recorded"
   is a null role group. `readNodeMode` reads a missing row or a null group as sole primary, as a
   missing row reads today (`packages/node-db/src/mode.ts:19-27`).
2. **`packages/node-db/src/box.ts`**, the one writer:
   `writeBoxRecoveryKeyTx(tx, nodeId, { verifier, keyName })`,
   `writeBoxSigningKeyTx(tx, nodeId, sealed: { ciphertext, iv, authTag, keyVersion })`,
   `writeBoxRoleTx(tx, nodeId, { mode, singletonRole })`,
   `writeBoxMirrorLinkTx(tx, nodeId, link: MirrorConnection)`,
   `writeBoxPinnedKeyTx(tx, nodeId, pinned: PinnedPrimaryKey)` — each an upsert on `node_id` that sets
   only its own group and its `*_changed_at`/`*_at` stamp — and `deleteBoxRowsOtherThanTx(tx, nodeId)`.
   `scripts/write-path-tables.json` gets one entry, `"box": ["packages/node-db/src/box.ts"]`, in place
   of the five (`:6-10`). **The guard is weaker than its name:** the group writers are exported,
   because `packages/credentials/src/node-signing-key.ts` must call `writeBoxSigningKeyTx`, and the
   guard judges a file's text, not a call chain, so any file may write a group by calling them.
   "Each group has one writer, called only from its module" is a review check, not a guard. The
   plan says so in `docs/developers/conventions-data.md`'s write-path section (`:918-953`) and in
   the guard's header beside the `box` entry.
   **The role rules the writers keep** (today's behaviour, `packages/node-db/src/mode.ts:51-102`,
   rewritten for a group with no column defaults; each has a case in Task 3):
   - An empty role group reads as `{ mode: "primary", singletonRole: "primary" }` (as a missing row
     does today, `:27`).
   - `setNodeModeTx(…, "mirror")` writes `{ mirror, secondary }`; `setNodeModeTx(…, "primary")`
     writes `{ primary, <stored singleton role, or "primary" when the group is empty> }` — it keeps the
     stored singleton role, as today's update leaves it (`:59-64`).
   - `setSingletonRoleTx(…, role)` with an empty group or no row writes `{ primary, role }` (today's
     insert took `mode` from the column default, `:91-94`); otherwise `{ <stored mode>, role }`, and
     `box_role_valid_ck` refuses `primary` on a mirror as today.
   - `setPrimaryRoleTx` makes **one** write of `{ primary, primary }` (no longer two delegated
     writes), so promoting a mirror appends one event.
   - Readers return `null` for an empty group, never an object of nulls: `readMirrorLink`,
     `readPinnedPrimaryKey`, `readRecoveryKey` (and its `Verifier`/`Name` reads) and the signing-key
     read check the group's first column; a direct port of `primary-key.ts:19`'s `row ?? null` would
     return an object of nulls on every main box that has keys but no pin.
