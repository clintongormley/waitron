# A436 · Sign in on the kitchen display

A cook can sign in on a station or pass screen while the queue stays in view. **Move to station** shows their name on the receiving station's card. Signed-out displays keep serving the queue. The owner's [8 October request](../../backlog/till.md#a436--a-kitchen-display-with-someone-signed-in-logged-out-only-after-a-long-idle-time) asks for no automatic sign-out or a long wait.

## PR 1 · Sign in and use the existing move attribution

- Put **Sign in** beside the kitchen screen's controls. In `apps/till/src/till-app.ts` and `screens/till-lock-screen.ts`, reuse the staff picker and PIN pad in a bounded section above the queue. Scroll the picker when needed, including at phone width. Keep the board mounted and its device language. Show **Log in** when the admitted roster has at least one person. After sign-in, show the cook's name and **Log out**. The read-only pass monitor keeps its current header. Sign-out clears the tab's person and sends the existing request with that person's header.
- In `apps/dashboard/src/screens/device-profiles-screen.ts`, expose the existing job-role admission control for kitchen displays. In `apps/server/src/till-api.ts`, reuse the admitted roster and PIN route, including throttling, current admission, device proof recheck and existing attendance sign-in. Refuse a change between kitchen display and any other form factor during PIN checking. In `till-session.ts`, confine kitchen sessions at the shared ordinary-till session check. Use the current device type and the existing session row. Extend `endSessionsNotAdmitted` to end sessions when a manager moves a device out of a kitchen profile. It already ends them on entry. The database bars changing an active device’s profile type in the profile editor.
- Pass the signed-in tab's person header through the existing kitchen API client. `device-api.ts` and `station-move.ts` already store a matching person and the device for Move to station. `station-queue-moves.ts` and the till's `widgets/station-queue.ts` read and display the name. The display acts when the tab has no matching session. Preserve action, station and pass-zone checks. Other kitchen verbs keep their current actors and attendance effects. Close/Reopen for today still takes a manager's PIN. This slice uses the stored Never setting. If you leave without signing out, the next person’s moves still carry your name until someone signs out.

## PR 2 · Configure the idle wait

Expose the existing **Auto-logout after (minutes)** field on kitchen profiles, with blank for **Never** and the existing positive-duration validation. Use 30 minutes in the help example. Remove the kitchen-only null rule in `packages/layouts/src/device-profile.ts` and `packages/db/src/schema/device-profiles.ts`. Rebuild the core starting migration and disclose the preproduction reset. Use the kitchen setup poll to apply a saved timeout and `apps/till/src/session-activity.ts` to time it. Taps and keys reset the wait. Live refreshes do not. Idle sign-out follows the same path as **Sign out**, leaving the queue and wake lock on.
