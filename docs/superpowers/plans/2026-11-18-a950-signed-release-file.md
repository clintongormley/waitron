The existing release job can attach a file that proves which Waitron and print-agent images belong to each numbered release. A real release still needs the declaration and CI checks in the [release guide](../../operations/release.md). The owner chose “GitHub secret for now” (18 November, 20:22, relayed in Lane F’s queue). Before the first signed release, the owner provisions the secret and supplies current and spare public keys for `deploy/box/release-keys/`, with the spare private key kept offline. Actual keys and box wiring are later work.

- [ ] Add `verifyReleaseList(bytes, trustedPublicKeys)` and `signReleaseList(release, privateKey)` in `scripts/box/release-list.mjs`. Use Node Ed25519 with PEM keys (SPKI public, PKCS#8 private). Verify the exact decoded bytes of the UTF-8 JSON `payload` before parsing it. The envelope carries base64url `payload` and `signature`. The version-1 payload has `format`, `kind: "release"`, numeric `version` (X.Y.Z), `prerelease`, `sourceSha`, `platform` and `images` with named `app` and `printAgent` digests. Write stable fields in fixed order so a same-key retry produces identical bytes. B3’s qualified USB asset can reuse the signature format with its own payload and a minimum installer compatibility integer starting at 1.
- [ ] In `.github/workflows/ci.yml`, add IDs and job outputs for both push digests. Keep declaration extraction tied to the app digest. The tag-only release job uses a `release` environment to be configured for tag refs `v*` before setting `WAITRON_RELEASE_SIGNING_KEY`. A bounded step runs `scripts/release/sign-release-list.mjs` to write and verify `waitron-release.json` against the committed keys. It skips when neither keys nor secret are configured and refuses partial or mismatched configuration. A separate bounded upload step uses `scripts/release/github-release.sh` after the declaration upload. An identical asset on retry succeeds. Different bytes refuse. Update `docs/operations/release.md` and both A950 backlog entries.
- [ ] Start with failing checks in `scripts/box/release-list.test.mjs`, `scripts/release/sign-release-list.test.mjs`, `scripts/release/github-release.test.mjs` and `scripts/ci-workflow.test.mjs`. Verify either trusted key, reject wrong keys, edits, wrong kind and missing image roles. Exercise correct digest mapping, absent/mismatched signing configuration and asset retry without replacing an existing file. Run those four files with root Vitest before and after implementing.
- [ ] Next, wire signed manual installs through the checked installer. Use the signed source SHA for its existing GitHub HTTPS downloads. The dormant Cloud-hold discovery adapter stays untouched. Proposed prereleases keep numbered declarations and carry the signed prerelease flag. The next plan pins how release tooling sets it. Follow with the signed rollout file, the locked release-to-release rehearsal, window and status/email. Paired upgrades await A947.
