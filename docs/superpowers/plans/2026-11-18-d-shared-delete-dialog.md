# Share the dashboard hardware delete dialog

Devices, Payments and Printers use one dashboard widget for Delete. Managers see the same confirmation, words and results for devices, readers, receipt and kitchen printers, and A4 printers. This completes the shared-dialog bullet in `docs/backlog/architecture.md`, under A435 loose ends.

- In `apps/dashboard/src/widgets/hardware-delete-dialog.ts`, add `HardwareDeleteDialog` for the existing `wt-delete-dialog` and its `DashboardQueries` impact read. Its `open(id, opener, query)`, `close()` and `render(testId, copy)` share the dialog state and event bindings. It exposes the current target and whether Delete is sending so each screen can handle a row vanishing. Keep passive live refreshes, separate read and action errors, and a check that late completions still belong to the same opening.
- In `apps/dashboard/src/screens/devices-screen.ts`, `payments-screen.ts` and `printers-screen.ts`, replace the copied state and handlers with the widget. Pass the current delete request and the existing handlers for a vanished row, destination for focus, and list refresh. Keep the reader's extra acknowledgment and its impact retry on `reader.provider_disconnected`. Keep the two printer routes and the detail page's redraw before returning focus to Add. Keep each screen's existing wording, test selectors and close-on-disconnect behavior. Agent Delete, Unpair, and the other A435 bullets stay outside this change.
- Start in `apps/dashboard/src/widgets/hardware-delete-dialog.test.ts`. Mount the widget with the real `wt-delete-dialog` and `DashboardQueries`, replacing only API responses. Check that the first read enables Delete, a refresh or retry leaves a send refusal visible, and a send that finishes after the dialog reopens has no effect on the new target. Drive a held response to completion before asserting. Run the new file before writing the widget to observe the failure, then run it green.
- Run the existing `devices-screen.test.ts`, `payments-screen.delete.test.ts` and `printers-screen.test.ts` unchanged. They pin the real requests, reader acknowledgment, A4 route, live removal, refresh failure and focus. Check the same confirmation on desktop and phone in both languages and themes. Delete only the completed backlog bullet. Expect about 180–235 production lines added, 310–355 removed, and 110–150 test lines added.
