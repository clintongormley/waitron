# A980 — service actions in a staff data download

The existing personal-data ZIP includes `service-actions.json` for the person's recorded service actions and `department-transfers.json` for the transfers they resolved. Staff download their own copy; administrators use the existing permission and fresh sign-in checks for another person's. The [A980 design, row s12](../specs/2026-10-22-a980-data-protection-design.md) and [remaining actions](../../backlog/data-protection.md) are the basis for the watcher's Lane H assignment of 2026-11-22 09:02.

## Build

- Add `serviceActionsPersonalData(db: Database): PersonalDataPart[]` in `apps/server/src/personal-data-service-actions.ts` and register it in `personal-data-export-api.ts`. Defer reads until the existing first authorization turn ends. Read each core table in batches of up to 500 primary keys, in key order up to the last key seen at the start of that table's read. Read only those keys with the subject filter, use the normal committed reads outside the write queue, and yield to the server between pages. Reuse one paging routine for the seven sources. Sort each output list by its recorded time and key after reading. Keep the existing recheck before sending.
- **Order events** from `order_events.actor_id, from_person, to_person` show `kind`, `at`, the stored `party_id, group_id, draft_id, line_id, from_order_id, to_order_id` and all matching `yourPart` roles (`actor`, `from`, `to`), once per event. **Groups** from `order_groups.submitted_by, fired_by` show the group id and the subject's submission (`created_at`) or firing (`fired_at`). **Parties** from `parties.opened_by, closed_by, allergy_answered_by` show the party id and only the subject's corresponding action times. The README explains that a group action may appear as an event and a group record.
- **Dish moves** from `ticket_item_moves.moved_by_person_id` show the line and both station ids with `moved_at`. **Amendments** from `order_amendments.actor_id` show the bill's order number, `kind` and `event_at`. **Cancellations** from `line_service_cancellations.actor_id` show the line id and `cancelled_at`. **Late confirmations** from `working_order_lines.late_confirmed_by` show the line id, order number and `sent_at` if present. The line stores no separate confirmation timestamp. Omit `service-actions.json` when all seven lists are empty.
- Add `VENUE_SERVICE_PERSONAL_DATA` in `packages/venue-service/src/personal-data.ts`, export it from `index.ts` and register it in `packages/composition/src/modules.ts`. The module part reads `department_transfer_requests.resolved_by` during the existing initial read turn, in one query, as the adjustments part does. Return order number, source and destination department ids, `status` and `resolved_at`. A withdrawal counts for the person who resolved it. Omit the file when there are no matches.
- Explicitly select the fields needed for those outputs. Leave out raw person and device ids, event detail, party names, bill labels and names, table names, allergy answers, notes and free-text reasons. Add no schema, index or permission changes. Draft ownership and transfers only sent by the subject stay in the backlog. Move the twelve actor columns above from `NOT_YET` to `READ` in `personal-data-actions.coverage.test.ts`; trim the matching backlog entries and keep transfer sender attribution open. Describe both files in `apps/server/src/i18n/personal-data-readme.ts` and `apps/server/src/guide/{en,es}/staff.md`.
