# A538 Archive S3 Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` for the owner's chosen **native inline** execution, task by task. Steps use checkboxes. This draft is **needs-owner-review**; no build or live run starts before approval.
>
> _2026-10-13: the owner approved the four proposed defaults as written on 2026-10-12, and plan Task 1 is built as A538-1._
>
> _2026-10-14: the rehearsal ran against Amazon S3 as A538-10; its receipts, and what they do not show, are in [docs/receipts/a538/](../../receipts/a538/README.md)._

**Goal:** Give encrypted archives an off-box S3 destination and record a small, owned Amazon S3 rehearsal without widening fiscal or Cloud recovery behavior.

**Architecture:** Extend the stream package's SDK seam with cancellation and bounded file transfers. The server retains archive policy and its existing file cipher/restore validation, stores dashboard settings in a sealed configuration, and exposes an independent archive recovery pack. A separate opt-in runner exercises the real S3 paths and owns every fixture and teardown action.

**Tech Stack:** TypeScript, Node, existing AWS SDK v3 commands, SQLite through `useVenueDb`, Vitest, Lit, pinned Litestream v0.5.17. No new transfer library.

**Spec:** [2026-10-12-a538-archive-s3-design.md](../specs/2026-10-12-a538-archive-s3-design.md).

## Global constraints

- Every new setting/default is **proposed** until the owner approves the design and plan before **17 October 2026**. Native execution is already chosen.
- Default upload-plus-retention and restore-transfer budget **15 minutes**; status **30 seconds**; cleanup **10 seconds**; transport idle **30 seconds**; SDK **3 attempts** including the first. Transfer setting accepts **30 seconds to 24 hours**.
- Multipart part size `max(8 MiB, ceil(fileBytes / 10,000))`, at most **64 MiB**, sequential; reject more than **10,000** capped parts (625 GiB). At most one part is buffered.
- Archive namespace `<selected-prefix>/archives/<venueId>/`; same-stream choice snapshots at Save. One archive bucket plus optional local destinations. No Google Drive.
- Keep WBA1/WBK1 framing, existing passphrase semantics, validate-before-placement, fresh fiscal installation and working-time continuation. No fiscal logic, golden-huella or `inmutabilidad` edits; retain existing behavioral assertions.
- Raw environment configuration is authoritative and read-only in the dashboard. Secrets stay sealed or externally injected; no ordinary readback and no ordinary configuration-export leakage.
- No data migration or backwards-compatibility reader before Waitron is live. Do not edit shipped migrations. No new schema is expected because the vault already stores purposes.
- Real AWS is never default CI. Runtime-only `waitron-rehearsal` profile, verified region currently `eu-north-1`, key expiry **2026-11-03**, owned bucket `waitron-rehearsal-waitron-<random>` only. No IAM/STS/KMS work.
- Live fixture limits: **32 MiB** archive, **1,005** tiny delete objects, **128 MiB** total uploaded bytes; denial control **60 seconds**, admin teardown **2 minutes**. Synthetic data only.
- Work in registered feature worktrees. Each production checkpoint has red-first focused tests, signed-off commit, normal hook, applicable whole-branch review and current-head CI through `finish-branch`; ask the owner before landing unless that exact build item gains landing authorization.
- No whole-workspace local package test run solely to finish. A focused pass must print a test count. Real rehearsal receipt retirement is a later docs-only change, not assumed here.

## Review focus

1. A headers-first response that never finishes must be cancelled during body consumption; Task 1 exercises it over actual local HTTP, not an injected promise alone.
2. A retention listing that includes another venue, malformed name or repeated continuation token must delete nothing outside a complete valid archive set; Tasks 1–3 exercise it.
3. A successful local upload with a failed bucket must never look like a successful off-box copy; Task 3 asserts the destination flags and rendered distinction in Task 6.
4. A secret-only settings change in another tab must invalidate displayed recovery material while preserving staged edits; Tasks 4 and 6 exercise revision behavior.
5. An abort after a remote part succeeds, or a disk-full download, must leave no partial local output and either remove the owned remote upload or report exact unresolved cleanup; Tasks 2 and 9 exercise it.
