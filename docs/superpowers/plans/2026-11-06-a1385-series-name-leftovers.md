## Decisions

**A1226 (decided here, conservative):** nothing on a page sends a real select unless **Make the series was pressed on this page load** and nothing that press confirmed has changed since. The page's own re-checks otherwise only compare clocks and ask for a preview. The countdown of a wait the box already recorded, shown after a reload or after Compare clocks, ends in that read-only re-check: when the wait is over, the page offers Make the series and the person presses it. Why this breaks nothing: the box keeps a recorded wait current for a minute past its target (`hour-selection.ts:456-460`), so a press within that minute takes the name at once; a later press records a fresh 90-to-150-second wait, which the person was already going to sit through on any new attempt. The guides already describe this: "Choose **Make the series** once the page allows it" (`apps/server/src/guide/en/backup-recovery.md:141-142`; Spanish `es/backup-recovery.md:153-154`).

- Restore page: "pressed" is cleared by `#invalidate` (key, either declaration, Clear, disconnect: `recovery-hour.ts:186-193`). Compare clocks does not clear it.
- Setup page: "pressed" is cleared by `#clear`, `#edit` and a person's **Check again** (`#compare` unticks the review, `first-hour.ts:292`, so the press's confirmation no longer stands).
- After Compare clocks with no second clock, the restore page no longer says "It carries on by itself once the box reaches the internet, or on the other device if you carry on there." (it would not be true); it still says it after Make the series.

**The Cloud entry (decided by M1):** no fix to the download path; Task 1 pins M1 as a test. What M1 found instead (refused at placement whenever no internet clock answers then, on a page that sends the person to "whoever installed this box") needs an owner decision: Q2. Not built.

**A1223 (default for Q1, built):** treat a stored pick found taken as a fault in Waitron and say so; do not build an automatic new attempt. Task 7 re-runs A1207's M-b2 probe first; if any server or provisioning run reaches the refusal, stop and report, because then it is not a fault-only state.

## Owner questions

**Q1. A setup or restore whose own chosen name turns up in the box's records before it finishes.** Today the page says "The series cannot be made yet: this box's records already hold a series for the minute this box would use." and offers nothing; "yet" is false, because waiting never helps. A1207 found no run outside hand-edited test data that reaches it (M-b2: three module tests that insert the record by hand; no server case). A new attempt by itself would mean a new restore or setup event chosen by each of three different screens, and for a restore already staged it would mean going back to the page after the restart.
*Recommended default (built in Task 7):* call it a fault in Waitron, in the words under "Words for the owner"; no automatic new attempt.
*Alternative:* build the automatic new attempt (a design of its own; not in this PR).

**Q2. A restore refused when the box places the backup.** Example: a Cloud restore downloads, the box restarts to place it, and at that moment the tax agency's site does not answer the box's time check (M1). The box refuses (`sif.allocation_invalid`, `second_clock_missing`), and the start-failure page says "Waitron could not start. Ask whoever installed this box to look at it." (M2), which sends the person to somebody else. Choices:
- (a) Give `sif.allocation_invalid` its own start-failure words. They are chosen by error code alone (root `CLAUDE.md` §3, recovery page), so one sentence would have to fit every reason, from "no internet clock" to Q1's fault.
- (b) Let the start-failure page choose words by code and reason. This changes the owner's 2026-09-26 rule that the page's words are fixed by the error code.
- (c) When placing a backup whose name was already chosen under two agreeing clocks, the box no longer asks for a second clock again; it still refuses if its own clock is behind the minute it chose (`hour-selection.ts:431`). This changes what the box checks before it uses a name.
*Recommended:* (c), because it removes the refusal rather than wording it, and a Cloud restore cannot be finished today on a box whose internet clock fails at the wrong moment. It is a fiscal check, so it is yours. *Default if unanswered:* nothing built; Task 8 adds a backlog entry.
