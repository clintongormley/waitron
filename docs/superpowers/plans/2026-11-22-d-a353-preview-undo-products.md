# A353 PR 3. Undo product placement changes from Preview

The 09:02 Lane D queue assignment takes up PR 3 of the [parent plan](2026-11-06-a353-preview-undo.md#pr-3--products-in-this-menus-own-lists). The owner's ask for Preview Undo is recorded in [the menu backlog](../../backlog/menu.md#a353--previews-changes-an-undo-link-that-puts-one-change-back-to-the-live-version). PR 2 landed in #4021.

When you add, move or remove a product in a menu's own lists, use **Undo** on Preview to restore its published placement where one write can do it. Preview reads again after the write. Changes from included menus keep their existing Edit action. Section, include, order and shortcut changes belong to later PRs.

- Extend the existing planner in `packages/menu/src/menu-undo.ts`. Compare the published and working offer paths using section IDs. Resolve each affected list through the existing Structure snapshot, stopping at included menus. Match a removal to the stored member ID. To put a product back, find its nearest preceding published sibling still held in that list and insert after it. Use the first position if none remains. Count using stored members so siblings absent from Preview still count.
- Undo a single own addition with `removeSectionMember`. For a move, one added path is a remove, one lost path is an add, and one lost plus one added path is a single `moveSectionMembersInto` so the menu keeps the offer and its prices. For a complete removal, restore only one published own placement whose list still exists, when no stored placement remains anywhere in the menu tree, including through an include, and the published offer had no own dish or variant price. Leave multiple independent moves and unresolved lists without an action.
- In `apps/dashboard/src/api/client.ts`, pass optional `position` through `addSectionMember`. The existing route in `apps/server/src/menu-api.ts` already accepts it and calls `addMember`. Keep the existing request for ordinary adds. Map the three commands in `api/menu-undo.ts` and send through the same Structure write queue and list scope in `screens/menus-screen.ts`, using the destination for moves. Reuse the existing Preview action, refresh and refusal display. Add watcher-settled bilingual refusal wording in `i18n/strings.ts` and the parent plan.
