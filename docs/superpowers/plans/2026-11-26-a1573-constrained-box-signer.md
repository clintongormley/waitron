# A1573. Limit what the box’s retained signing key can vouch for

Staff install one public certificate and open the till and dashboard at the box’s names and private IPv4 addresses. The device refuses HTTPS for sites outside that limit when only the box’s retained signing key vouches for them. [Owner’s ask and phone receipt](../../backlog/setup.md#a1573-a-box-certificate-that-cannot-vouch-for-other-websites-on-android).

**Mint and serve.** In `apps/server/src/self-signed-cert.ts`, make a self-signed public root with path length 1. Use its key once, in memory, to sign an intermediate with a distinct subject and key, path length 0, and the current critical DNS and IP limits. Give the intermediate no extended key usage so it can sign both kinds of leaf. Sign each leaf with the intermediate’s subject and key. Leave name limits off the root so the real chain tests isolate the intermediate’s limits. [RFC 5280 §4.2.1.9–10](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.2.1.9).

**Keep the three files.** `ca.crt` holds the root alone. `ca.key` holds the intermediate certificate followed by its key, using the combined PEM pattern of `server.pem`. Serve the server and client leaves followed by the intermediate. Share chain validation across `box-secrets.ts`, `box-tls-repair.ts`, `box-tls-install.ts` and `backup-verification-secrets.ts`. Check certificate roles, signatures, validity and the exact chain. Refuse a signer sharing the root key. A valid leaf can still serve using the chain in `server.pem` if the signer file is missing. Reuse the lock, install list and repair records. An old one-certificate set takes connection repair with new trust. Devices must remove the old root, and existing preproduction pairs must reset and rejoin on the new build.

**Carry and trust.** The backup and handover lists keep their paths (`packages/store/src/state-layout.ts`, `packages/handover/src/manifest.ts`). Restore a new backup with its original root. Old TLS material needs new trust, and an old backup cannot pass the new certificate check. `mirror-bundle.ts`, `mirror-bundle-fetch.ts` and `adopt.ts` keep the signed bundle fields, with the adopter validating the root and signer before writes. Peer HTTPS and the spare store trust only the root. No schema change. B3’s later preboot work must update its direct-issuer check. Operator-provided TLS is outside this slice.

**Test first.** In `name-constraints.test.ts`, use the product chain with the root alone trusted. Accept box names and private IPv4, refuse an outside name and public IP, and use an unrestricted test chain to show the cause. Check that no key in a fresh mint, repair candidate or join bundle matches the new root. Use `box-secrets.test.ts`, `box-tls-repair.test.ts`, `box-tls-install.test.ts`, `landing-app.test.ts`, `adopt.test.ts`, `spare-join.e2e.test.ts` and `spare-pipe.test.ts` for leaf renewal, old-set repair, interrupted install, root-only download, bundle refusal and live server/client TLS. Use `backup-verification-secrets.test.ts` and `boot.restore.test.ts` for backup validation and placement. Update the HTTPS step in `.github/workflows/image-smoke.yml` to verify the served chain against the downloaded root. Check the print agent’s existing pinned fetch with a served chain in `apps/print-agent/src/server-ca.test.ts`.

Before landing, repeat the allowed, refused and control requests on a second Android phone and an iPhone. Record the versions and installed root. Update the backlog and operator instructions. Estimate 250–350 product lines and 350–500 test and fixture lines in one pull request.
