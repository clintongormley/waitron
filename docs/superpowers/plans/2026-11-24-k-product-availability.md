# Set product and variant availability from the dashboard

[Products list design, delivery piece 3](../specs/2026-11-24-products-list-redesign-design.md#delivery) · Lane K queue, PRODUCTS-LIST-3

A signed-in menu manager can set one product or variant, or several together, available or unavailable in one request. Tills read the changed flags on already published menus. A refused batch saves none of its changes. The dashboard controls arrive in piece 7. No schema change or venue reset.

1. **Route.** Add `PUT /management-api/products/availability` in `apps/server/src/menu-api.ts`. Read `{ productIds: string[], available: boolean }` using `isPlainObject` and `idList`. Return 400 `management.request_invalid` for an empty or repeated list, or a non-boolean flag, with the field named. Reuse `gated` for `menu.manage`, one transaction and the revision header. Return 204 with an empty body. Reuse `runBodyIds("product.not_found")` so an unknown body ID answers 400.
2. **Write.** Add `setProductAvailability(tx, productIds, available)` to the already exported `packages/menu/src/product-items.ts`. Reuse its batched existence check with `ProductScope`: retain today's top-level restriction for folder actions and allow catalogue products and variants for availability. Apply `updateProduct(tx, id, { available })` in request order. The existing writer refuses deleted rows or variants of deleted parents as 409 `product.archived`. Its existing timestamp write accompanies availability. The till overlays current availability when it reads published offers.
3. **Checks.** Start red in `apps/server/src/till-api.availability.test.ts`. Mount the dashboard menu API with a real manager session, using the existing published dish and variant. Set the variant on, the dish off, the dish on, then both off in one request. Check the 204 and both flags in both zones after each write, preserving the other row's flag and the price. In `apps/server/src/menu-api.test.ts`, send a valid row followed by a deleted one. Assert 409 `product.archived` with its `productId`, no revision header and the first row unchanged. Check 400 `product.not_found` with the unknown ID, 400 `shared.invalid_id` for a malformed ID, the malformed and duplicate inputs, 401 `management_session.required` and 403 `authorization.not_permitted`. Run those two files red then green.
4. **Records.** Register the exact route in `packages/diagnostics/src/path-patterns.ts` and add its red-then-green case to `instrument-fetch.test.ts`. Document the request and the malformed-ID refusal in `docs/developers/product-categories.md` and the existing live availability rule in `docs/developers/products.md`. Update the Products list backlog entry. Tell Lane H the route and merge SHA after landing.
