# Set product and variant availability from the dashboard

[Products list design, delivery piece 3](../specs/2026-11-24-products-list-redesign-design.md#delivery) · Lane K queue, PRODUCTS-LIST-3

A signed-in menu manager can set one product or variant, or several together, available or unavailable in one request. The change reaches the existing menu and till reads. A refused batch saves none of its changes. This piece has no controls, schema change or venue reset.

1. **Route.** Add `PUT /management-api/products/availability` in `apps/server/src/menu-api.ts`. Its body is `{ productIds: string[], available: boolean }`, with one or more product row IDs. Variant IDs name the variant rows. Use `isPlainObject`, `idList` and the existing `runBodyIds("product.not_found")` boundary. Refuse an empty list and a value other than a boolean with the existing validation codes. Deduplicate IDs before the write. Use the route's existing `gated` transaction with `menu.manage` and its revision header. Return `{ productIds, available }` on success.
2. **Write.** Add and export `setProductAvailability(tx, productIds, available)` in `packages/menu/src/product-availability.ts` and `packages/menu/src/index.ts`. Use `batches` and `notCustomItem` to check the requested rows exist in the catalogue. Report a missing or custom-item ID as `product.not_found`. Pass only `{ available }` to the existing `updateProduct` for each distinct row, in turn in the caller's transaction. That writer already refuses an inactive row or a variant whose parent was deleted. It writes the availability and normal update timestamp. The parent and its variants each keep their own availability bit. The existing product and menu readers, publication and change notifications carry the result.
3. **Checks.** Extend the real management route fixture in `apps/server/src/menu-api.test.ts`. Start red for setting a single variant and a whole product separately, then a batch including both sorts of row. Assert the resulting manager list values, unchanged siblings and unchanged price. Check a valid row followed by a deleted row leaves the first row unchanged. Pin the codes for a missing or custom row, an empty list, a malformed value and a signed-in staff member without `menu.manage`. Run the changed suite and `packages/menu/src/active-available.test.ts` after the fix to exercise existing till visibility. Keep any independent till write behaviour in its existing suites.
4. **Backlog and handoff.** Update the Products list entry to leave the later pieces open. Tell Lane H the route and merge SHA once this lands so its row and selection controls call the same request.

Estimate 60–85 production lines and 100–150 test lines in one pull request. The whole-branch review covers the permission, row selection and combined write.
