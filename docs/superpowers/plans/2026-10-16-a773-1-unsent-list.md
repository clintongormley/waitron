## Concrete data and interface decisions

**Placement.** Retain feature `Place = fire | new {slot, afterGroupId?} | join {groupId}` and wire
`slot: number`, `joinGroupId: string|null`, `afterGroupId: string|null`. Fire is `0/null/null`;
new is positive slot with optional held anchor; join is slot 0 with join id. Keep T7's implemented
`insertSlotAfter(slot: number|null): number`, `moveSlot(from,to)` and
`setLinePlaces(indexes,place,shift?)`. A slot's rows share one anchor. `position` orders stored
draft rows; `slot` orders new groups. Explicit moves persist until a course edit or stale-target
refusal requires re-placement; unrelated catalogue/group refresh never sorts the draft again.

**Bill ownership.** Add `order_drafts.bill_id` FK to `working_orders`; application/wire types require
`billId: string`. The additive SQL column can be nullable for pre-live stored rows; such a row is
refused as invalid on use, never interpreted as main bill. Newly created drafts always supply it;
no backfill. The final open draft key is **bill_id WHERE state = open**, replacing the earlier
`(party_id, owner_id, bill_id)` rule. T24 adds persistent `bill_edit_states` and exact
`BillEditState`, `BillEditExpected`, `BillDraftSnapshot` interfaces from ownership design §4.
First accepted nonempty save/Recall acquires; last Send/resolution releases that bill and advances
its retained editorVersion. No other bill participates. Creating/saving/sending
requires that same bill of that party, open and not payment-locked. Submit takes its bill from the
draft, never from a body fallback. Presented/paid/abandoned bills refuse without moving the draft.

**Group identity.** Keep `order_groups.position` as mutable firing order. Add `display_number`
(`displayNumber: number`, additive default 0 for pre-live rows, new groups require a positive value)
and `number_party_id` (`numberPartyId`, FK parties, nullable only for old rows rejected on use).
Allocate `displayNumber = max(numbers currently in, or originally allocated by, this party)+1`
inside the submission transaction, including removed groups and Fire-now batches. Never change it
after first send, or reuse a number after its group moves to another party.
Reorders/insert-after change positions only. Party joins preserve existing number/origin pairs;
if numbers collide, qualify the heading with the originating table label rather than renumbering
printed tickets. New numbers are allocated above both sets. Read a closed origin's label from
`parties.tableNames`, the snapshot `closePartyTables` keeps before removing its memberships;
read current memberships only while that origin remains open. Test duplicate numbers after the
source party has closed in T5; do not impose a unique number-per-party
index that conflicts on joins. Unsent new groups show prospective numbers; only server-assigned
numbers are authoritative after Send. HOLD/FIRE/correction ticket numeric labels read displayNumber,
while queue order/reminders continue reading position. Course text on tickets remains A773-2.

Add an index on draft_id; declare all constraints in TypeScript and generated SQL.
Core owns these generic draft-to-bill references; state that reason in the signed-off commit.
Keep fresh lines in order_draft_lines unchanged. Recalled rows need no menu_item_id, so a sent

`source:{line:TabLine,extras:TabLine[],netAmount:string}`. `DraftLine` is their union. Fresh
