# A1308 fk4 — today's map lives on the live table and the zone: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Every step also
> follows [the A1308 slice rules](2026-11-08-a1308-slice-rules.md) ("rules").

**Goal:** `floor_today_tables` (a live table's place, seats, name and "taken off" on today's map)
becomes columns on `dining_tables`, and `floor_today_zones` (each room's business day, revision and
the layout its last reset used) becomes columns on `floor_zones`.

**Architecture:** both tables are unique on their parent (`floor_today_tables_table_key`,
`floor_today_zones_zone_key`), so the parent row holds them. "Has a today's row" becomes
`dining_tables.on_floor = 1`; a CHECK keeps every today column empty while it is 0. "No today's
record" becomes `floor_zones.today_business_day is null`, with `today_revision` defaulting to 0, which
is what an absent row read as (appendix §1.1). Two small helpers in `@waitron/db` keep the today
columns' old field names in one place, so most call sites change only their table.

**Tech stack:** TypeScript, Drizzle on `node:sqlite`, Vitest, the slice-1a rebuild command, slice
0's bench (if landed).

**Spec:** [README](../specs/2026-11-02-rationalisation/README.md) §4 ("a physical table is three rows
with one job each"); [appendix](../specs/2026-11-02-rationalisation/tables-floorkitchen.md) §1.1
(`today_*` on `floor_zones`), §1.3 (the "today" group of `dining_tables`), §5, §8 items 2, 6 (the
today half) and 7.

**First line of the pull request:** "Every venue is reset: core; backups and exports from before
this cannot be restored or imported."

**Who lands:** the lane (rules §6).

## What it builds

- `dining_tables` gains `on_floor` (flag, default 0), `today_seats`, `today_fixed` (flag, default 0),
  `today_x`, `today_y`, `today_width`, `today_height`, `today_shape`, `today_rotation`, `taken_off`
  (flag, default 0), `today_name`, with the seats CHECK, the seven placement CHECKs on the `today_*`
  group, and `dining_tables_off_floor_ck`: `on_floor = 1` or every `today_*` null and `today_fixed`,
  `taken_off` 0 (appendix §1.3; fk5 adds `merge_id is null` to it).
- `floor_zones` gains `today_business_day`, `today_revision` (default 0), `today_set_id` (key to
  `floor_plan_sets`), `today_layout_revision` (default 0), `today_occurrence`.
- `floor_today_tables` and `floor_today_zones` are deleted.
- `packages/db/src/floor-today-columns.ts`: the select shape `todayOf`, the type `TodayRow`, the
  writer `todaySet`, the constant `OFF_FLOOR`.
- The room's print (`roomPrints`) includes `on_floor`, because a spare on today's map and a table off
  it now carry the same null place (Review Focus 1).
- The export leaves every new column out (appendix §1.3: "The configuration export adds every
  `today_*`, `on_floor`, `taken_off` … to `dining_tables`' `omit` list"), proven by the round-trip
  test fk2 created (§8 item 6, today half).
- Appendix §8 item 7, measured in Task 6, with its fallback written there.
