# Idle box gateway recovery

**Finish line.** An idle box running the WireGuard companion can carry remote staff traffic again within 90 seconds of a gateway replacement. The replacement keeps the same Cloud endpoint and key but starts without the old encrypted session. The box recovers without a person opening a page to prompt it. Lane G owns the separate outside check of both Cloud routes.

**Cause.** Lane G saw 32-byte keepalives reach the same endpoint while the standby had no handshake. It saw a new exchange at about 142 seconds. With periodic venue traffic, recovery took 21.841 seconds. Cloud #1325 records both runs in `docs/gateway-reconnection-measurements.md`. Linux WireGuard starts its missing-reply handshake timer on outgoing data. Its send path excludes empty keepalives from that timer.
See Linux [send.c](https://github.com/torvalds/linux/blob/8dac6df92a2e66e2098bbc69061964cfe7e8375b/drivers/net/wireguard/send.c#L242-L259) and [timers.c](https://github.com/torvalds/linux/blob/8dac6df92a2e66e2098bbc69061964cfe7e8375b/drivers/net/wireguard/timers.c#L92-L105).

In Lane J’s isolated Docker check, the current companion missed 90 seconds with no new handshake. A fresh run with a one-byte datagram sent through `wg-cloud` at 0, 6 and 12 seconds completed both a fresh handshake and a staff echo at 16 seconds. Each gateway interface started with handshake 0. The box kept the same interface in the traffic run.

**Change.** In `deploy/tunnel/peer.sh`, use the existing two-second configuration loop to send one small UDP datagram on every third active pass. Use the installed `socat` with a one-second deadline. Bind the packet to `wg-cloud` and send it only to the current gateway's private WireGuard address on UDP port 9. The packet needs no listening service or reply. Reset the cadence when the peer is stopped or reconfigured. A failed send leaves the forwarding process and peer in place. The change applies to the optional companion on main today, and uses the same loop when #3808 changes how the peer forwards staff connections.

**Check.** Extend `scripts/tunnel-container-smoke.sh` with a timed gateway replacement after its staff echo succeeds. Recreate only the gateway interface with its original key, address and port. Check that the replacement starts without a handshake and that the box keeps its interface. First watch the test fail against the shipped script at the 90-second deadline. Poll only the replacement's handshake before opening a fresh staff request, so the test cannot supply the missing tunnel traffic itself. With the change, require a fresh handshake and the original echo by the deadline. Retain the existing off, input-filter and key-retention checks. Run this smoke and `pnpm exec vitest run scripts/tunnel-container.test.mjs`. Record the scope in the A951 backlog entry and send the tested revision to Lane G for its outside check.

**Size.** About 12–16 production lines, 30–40 test lines and a short backlog note. Reuse the companion and the isolated Docker smoke. The scope is an idle box recovering at the same Cloud endpoint. DNS changes, Cloud election, new capabilities and network listeners stay outside this change.
