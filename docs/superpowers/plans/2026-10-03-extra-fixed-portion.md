## Risks to check during implementation

- The core sale-line snapshot touches an append-only table. A generated rebuild, an old migrated venue, or a lost trigger is a stop-and-investigate result, not a reason to edit old SQL. Check the actual generated migration and upgrade path.
- Price is rounded once **per pick**. A result that rounds after multiplying by three gives 0.04 € in the 0.27 €/kg example and fails the contract.
- A saved child's physical amount is not a pick count. `perDishOptionQuantity` may remain valid for plain options, but an extras caller using it will silently print or edit the wrong amount.
- Unit and precision warnings are advisory. Validate a newly entered or changed portion against current precision, but preserve an unchanged saved amount and publish it exactly. Existing held orders keep their frozen facts; a sale from a published offer has no display-precision refusal.
- The existing fiscal golden checks a fixed basket and a fixed NIF; it is a regression gate for unchanged paths, not a proof of the new extra case. The new real-sale test supplies that case.
