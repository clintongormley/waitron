# A841 slice 8 — the logo on the screens: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manager picks the venue's logo (and an optional one for dark screens) in the Look card's
editor, sees it in the preview and on the saved card, and every screen that drew Waitron's mark —
the dashboard banner, a handheld's bar, the till and handheld sign-in — draws the venue's logo
instead, following each screen's Light / Dark / Follow device setting, with "Powered by Waitron"
under both sign-in forms.

**Architecture:** Two pull requests (D1). **8a, the editor side:** the plate token, one shared
primitive that draws a venue logo in a fixed box (`wt-venue-logo`), the draft's logo rules, a
`venue-logo` mode of the existing image picker field, the Logo field, the preview's banner strip,
the saved card's Logo row, the image library's wording and link, and the guide's Logo section. The
logo is stored by slice 7's routes; no live screen changes yet. **8b, the live surfaces:** the
`/api/theme` answer's logo typed and checked, a venue-logo state beside the venue theme sheet in
`packages/ui/src/venue-theme.ts` (waiting / none / a logo, with failures reported back), a
`wt-powered-by` primitive, then the banner, the dashboard sign-in, the handheld bar and the till
sign-in reading that state, and the guide's "Where your logo shows".

**Tech Stack:** TypeScript, Lit 3, Vitest 4.1.x in real headless Chromium (`packages/ui`,
`packages/ui-core`, `apps/dashboard`, `apps/till`, `packages/media`'s dashboard), Markdown guides
served by `apps/server`.

**Spec:** `docs/superpowers/specs/2026-10-19-a841-theme-editor-design.md` — section 16 item 8
(lines 2578-2586) is the scope. Detail: section 4 (lines 451-660, the Look card, step 8 and the
product-text table rows 637-647), section 7 (lines 1382-1387, each image follows the Theme
setting), section 8 (line 1400), section 8a (lines 1406-1597 for the screens; 1598-1709 are slice

## Decisions this plan makes (the design or the brief left them open)

**D1. Two pull requests.** The work is 19 implementer tasks and two visual checks, past the brief's
twelve. **8a — the editor side** (Tasks A1-A9, visual A10) and **8b — the live surfaces** (Tasks
B1-B8, visual B9). Each leaves main working: after 8a a manager can set, preview, save and remove a
logo, the library names its use, and every live screen still draws Waitron's mark exactly as today
(the guide says so); 8b then puts the saved logo on the screens. 8b is branched from main after 8a
lands (its tasks import 8a's `wt-venue-logo` and the plate token).

**D2. One shared primitive for the logo's box, `wt-venue-logo`, in `packages/ui`.** Six places draw
the same thing — an image fitted inside a fixed box, a dark image or a plate on dark screens, an
empty box while waiting, a report when it fails: the banner, the handheld bar, the till sign-in, the
preview's two strips and the saved card's row. A second app (the till) needs it, so it belongs in
`packages/ui`, with the primitive's token-painting test and its axe test in both themes (CLAUDE.md
§3). The editor's own picture box is **not** this primitive: it is a button-adjacent picture always
on the plate's white, drawn by the image picker field (D7). "Powered by Waitron" is a second
primitive, `wt-powered-by` (B3), because both apps draw it.

**D3. Which image a box draws is decided by the host's computed `color-scheme`, not by a
`<picture>` source.** The design names `<picture>` with `darkLogoMedia` (line 1382). The plate must
switch with the image, and a `<picture>` would switch the image in the browser while the plate
waited for script; one boolean read from `getComputedStyle(host).colorScheme === "dark"` drives
both. It follows the nearest theme root, so inside the preview's `data-theme="dark"` panel it
answers dark on a light page with no extra property (probe P3). It is read again on
`subscribeThemeChoice` (`packages/ui/src/theme-choice.ts:76-81`) and on a `change` of
`matchMedia("(prefers-color-scheme: dark)")`; neither sends a request to `/api/theme`. The image is
the browser's to fetch, as the design accepts ("both versions are already in the stylesheet and the
stored copy", line 1386). The dashboard's own Waitron lockup keeps its `<picture>` (unchanged).

**D4. `--wt-color-logo-plate`** is declared `#ffffff` in all four blocks of `colors.css`, directly
after `--wt-color-scrim` (light `:30`, media-dark `:165`, forced light `:293`, forced dark `:420`).
`deriveTheme` does not write it: `THEME_COLOURS` (`packages/ui-core/src/theme/tokens.ts:3-26`) is
unchanged, so no sweep, warning count or token-list length moves. The guard
`tokens.test.ts:17-26` excludes it beside the scrim (Changed test checks). Its light and dark values
are both white (design line 1517).

**D5. The live logo is a state beside the venue sheet** (8b, B2), so no surface fetches anything:
`currentVenueLogo()` answers `{ kind: "waiting" }`, `{ kind: "none" }` or `{ kind: "logo", logo }`.
Before `startVenueTheme` runs it is `none` (so every existing test that never starts the theme keeps
Waitron's mark). `startVenueTheme` makes it the stored copy's logo (or `none`), or `waiting` when
there is no stored copy; the first applied answer makes it that answer's logo, even when its hash
equals the stored copy's; the start-up fetch ending with nothing applied (refused, failed, not JSON,
the 5 s limit) turns `waiting` into `none`. A box that fails to load calls
`reportVenueLogoFailure(logo)`, which turns those addresses into `none` until an answer names other
addresses. Listeners hear only real changes. `VenueLogoController` redraws a Lit host on change.

**D6. Box sizes, read from tokens** (design lines 1442-1449): `size="banner"` 40 px tall
(`calc(var(--wt-space-6) + var(--wt-space-2))`), at most 160 wide (`calc(var(--wt-space-6) * 5)`);
`size="bar"` 32 tall (`var(--wt-space-6)`), at most 128 (`calc(var(--wt-space-6) * 4)`);
`size="sign-in"` 96 tall (`calc(var(--wt-space-6) * 3)`), at most 320 (`calc(var(--wt-space-6) *
10)`). The image is `block-size: 100%`, `inline-size: auto`, `max-inline-size: 100%`,
`object-fit: contain`, so a small image is drawn up to the box (line 1543) and nothing is stretched
or cropped. With the plate the box keeps its outer size and the image sits `var(--wt-space-1)` (4 px)
inside, on `var(--wt-color-logo-plate)` with `var(--wt-radius-sm)` corners (line 1515). While no
address is set the box keeps its height and has no width (D13). The preview strip uses `bar`; the
saved card's row uses `banner`.

**D7. The Logo field reuses the department Receipt tab's picker**, `dashboard-image-upload`
(`department-receipt-editor.ts:706-720`), in a new `venue-logo` mode (A4): with no image, one dashed
"+ {addLabel}" button; with one, the picture on `--wt-color-logo-plate` (not a button), then
**Replace** (opens the same `media-image-picker`) and **Remove**, each a `secondary` `wt-button`
(picture 17). The receipt `logo` mode is untouched. Picking or uploading needs `image.manage`, as
today (design line 1582). The field (`dashboard-theme-logo-field`, A5) holds two of them: the main
image, and under "For dark screens (optional)" the dark one, offered only while there is a main
image; Remove on the main image clears both (line 1421).

**D8. The draft.** `sameDraft` counts the logo (light names equal, dark names equal with absent and
`undefined` the same), so the quiet-Save rule, the leave question, `#adopt` and Use Waitron's look's
quiet state all see it. Use Waitron's look already empties it (`waitronLook`). Cancel drops it (the
scope's restore closes the editor, `look-card.ts:403-419`). The save carries it through
`normaliseChoices` to slice 7's routes; no route changes.

**D9. Refusals beside the field** (CLAUDE.md §3, "by what the error CARRIES"): `theme.invalid` with
`field: "logo.light"` puts "That image is no longer in the image library. Pick another." under the
main image, and `field: "logo.dark"` puts it — or, for `reason: "dark_without_light"`, "Add the main
logo before a version for dark screens." — under the dark image; both mark the picker `invalid`, put
"Correct the highlighted fields to continue." at the bottom, focus the first invalid control, and
never disable Save. A logo change clears them. `image.changed` stays a bottom message through
`codeMessage` (its wording is registered by the media module's strings,
`packages/media/src/dashboard/strings.ts:196-199`). A logo refusal inside the name dialog (first
save, Save as new theme…) stays at the dialog's bottom, as every non-name refusal does there today.

**D10. The preview's banner strip** (picture 17): one strip at the top of each panel, the panel's
logo (the draft's light image on the light panel, the dark image or the plate on the dark one, by
D3) or, with no logo, Waitron's lockup in that panel's drawing, then the tenant's legal name. The
legal name reaches the preview as `legalName` from `dashboard-app`'s `venueName`
(`dashboard-app.ts:1001`) through `dashboard-appearance-screen` and the Look card. The draft's names
are drawn through `liveMediaImage(name, "display")` bound to the primitive's `light` and `dark`
attributes.

**D11. The saved card's Logo row** is second, after Theme in use (picture 20): "None", or the image
in a `banner` box (alt `""`), then "Dark screens: own version" or "Dark screens: on a light plate".
The image follows the page's own Theme setting (D3), so a dark dashboard shows the plate.

**D12. The banner rule** (CLAUDE.md §3, design lines 1455-1462): the venue logo replaces only the
picture before the name; the legal name, full width, stays. Its alternative text is `""` in the
banner (the name is beside it) and the legal name in the handheld bar and on the till sign-in.

**D13. Before the first answer, while loading, on failure** (design lines 1548-1552, 2211-2218).
`waiting` draws an empty box of that place's height and no width in the banner (`banner`) and the
handheld bar (`bar`), and an empty `sign-in` box on the till sign-in; no "Powered by". `none` draws
today's screen: Waitron's lockup in the banner, the word in the handheld bar, nothing on the till
sign-in, no "Powered by". `logo` draws the venue's logo and "Powered by Waitron". A failed load
reports itself (D5) and the place falls back to `none`'s drawing, "Powered by" included.

**D14. Help mode adds nothing.** No control on the Look card carries a help badge today (receipts
above); the field's two hints are text under the pictures, as the design's table and picture 17
give them and as the house rule wants a short explanation ("a hint, not a '?' button"). No new
`wt-help-tooltip`, so `scripts/help-tooltip-mode.test.ts` sees nothing new.

**D15. The counter till's bar is unchanged in slice 8**: it draws neither the venue's logo nor
Waitron's word, exactly as since #1905 (`till-shell.ts:996`); slice 14 adds the logo there. A
counter till still shows the logo on its sign-in screen and "Powered by" under it.

**D16. The till sign-in before anyone signs in** reads only what needs no session: the stored copy
applied by `startVenueTheme` at start, `/api/theme` (unauthenticated), the image renditions
(served with no session, design section 13), and `/api/till`'s `themeHash` and `venueName`
(unauthenticated), whose `followVenueTheme` brings a newer answer. A signed-out till runs no poll,
so it follows a change at its next start or sign-in, as its colours do (design line 2264).

**D17. The library's link** for a `theme_logo` use is `/manage/appearance`, and its words "Logo of
theme {name}" (English), "Logotipo del tema {name}" (Spanish). The link does not open the theme's
editor: the Appearance page lists every theme (slice 13), and the guide says to press Edit on it.

**D18. Spanish product text** is proposed in the tasks (the design leaves it "to be written with
the strings"); the PR lists every new pair for the owner.

**D19. `VenueThemeAnswer.logo`** becomes `VenueLogoAddresses | null` with `export interface
VenueLogoAddresses { readonly light: string; readonly dark: string | null }`, and
`isVenueThemeAnswer` refuses any other `logo` (slice 7's "Left for later slices"). A stored copy
with a malformed `logo` is then ignored like any malformed copy (`readStored`, `venue-theme.ts:28-37`).
