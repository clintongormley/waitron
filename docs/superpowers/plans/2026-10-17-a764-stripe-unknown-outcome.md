**Private coordination decision:** In `provider.ts`, use a module-level `WeakMap<Database, { collecting: Set<string>; resolving: Set<string> }>` and a private accessor `activityOf(db: Database)`. Keys are payment references; separate database objects have separate registries. Register collection synchronously before its first transaction/await; release in `finally` after its last write/return/throw. This covers creation, pre-stamp waits, polling, best-effort reader cancellation and settlement. No age-based eligibility and no instance-owned registry.

Keep public `AbandonedAttemptAudit.personId: string` for manager calls; change private `Settle.audit` to `{ personId: string | null }`. Introduce private `resolveInactiveAttempt(paymentRef: string, now: Date, personId: string | null): Promise<AbandonedAttemptOutcome>`; both public manager resolution and automatic sweep use it. Acquire resolution ownership synchronously before any await, only if neither set holds the reference; hold through cancel, re-read and atomic write, release in `finally`. A busy manager call answers existing `unknown/ambiguous`; a busy sweep skips/counts nothing and requests another pass. A stale row still raises `payment.not_found`; a sweep catches only that expected concurrent-winner result, not arbitrary failures.
