# A1308 pp6 — the working-time chain's head is read from its newest entry: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to build this plan task by task. Steps use checkbox
> (`- [ ]`) syntax. Every step also follows
> [the A1308 slice rules](2026-11-08-a1308-slice-rules.md) ("rules" below), which this plan cites
> and does not repeat.

**Goal:** `workforce_chains`, a mutable copy of each node's newest `time_entries` row (its id,
hash, sequence number and recorded time), is deleted. Appending a clock event reads the newest row
through the existing unique index `time_entries_chain_position_uq (node_id, sequence_no)`. The
legal record's own protections (append-only triggers, hash chain, unique chain position) do not
change.

**Words used here.** The *working-time record* is `time_entries`, the legal clock-in/clock-out
record Spain requires (the registro de jornada). Each node keeps one *chain*: every entry carries
the hash of the entry before it and a sequence number one higher. The *head* is the newest entry of
a chain.

**Architecture:** `selectHead` in `packages/workforce/src/chain.ts` becomes one indexed query on
`time_entries`; `readChainHead` no longer creates a row; `attemptAppend` no longer updates one. The
record read that listed chains from `workforce_chains` lists a person's nodes from `time_entries`.
The backup check that compared the head row with the newest entry goes, because there is nothing
left to compare.

**Tech stack:** TypeScript, Drizzle on `node:sqlite`, Vitest.

**Spec:** [README](../specs/2026-11-02-rationalisation/README.md) §3 R6, §5 U6 (`workforce_chains`
deleted, "a pointer or counter read from its source instead"); [people
appendix](../specs/2026-11-02-rationalisation/tables-people.md) §1 `time_entries` (the head query),
§5 (`workforce_chains` rows), §6 item 3, §8 item 4.

## What it builds

- `selectHead(tx, key)` reads
  `select id, entry_hash, recorded_at, sequence_no from time_entries where node_id = ? order by sequence_no desc limit 1`
  and maps it to today's `ChainHead` (`chain.ts:40-46`): no row gives
  `{ sequenceNo: 0, lastEntryId: null, lastEntryHash: null, lastRecordedAt: null }`, exactly what a
  fresh `workforce_chains` row held (`workforce-chains.ts:16-19`).
- `readChainHead` returns `selectHead` directly; the insert-then-reselect (`chain.ts:68-86`) and
  its `attendance.append_contention` branch go.
- `attemptAppend` stops updating the head (`chain.ts:172-180`). Its high-water clamp
  (`chain.ts:110-114`) reads `lastRecordedAt` from the newest entry, which is the value the head
  stored (appendix §1: "the clamped `recorded_at` it writes is non-decreasing per chain").
- `record-reads.ts:103-114` enumerates chains with
  `select distinct node_id from time_entries where person_id = ?` (served by
  `time_entries_person_chain_idx (person_id, node_id, sequence_no)`) instead of joining
  `workforce_chains`.
- `packages/workforce/src/backup-verification.ts`: `workforce_chains` leaves `immutableTables`
  (`:10`), the head comparison (`:161-188`) goes, and the module's check list loses `head` (`:18`,
  `:35-39`).
- `workforce_chains` is deleted from the schema, `packages/workforce/src/schema/index.ts`,
  `index.ts:51`, the classification (`classification.ts:8-9`, `:15-19`) and every list naming it.
- `apps/server/src/attendance-discovery.ts:184-187` (the `clock` scan's endpoints read each chain's
  `sequence_no` from `workforce_chains`) reads `select node_id as key, max(sequence_no) as endpoint
  from time_entries group by node_id`. pp11 deletes this code; until then it must keep working.
- The backlog: delete "**`workforce_chains`: decide the remaining DELETE restriction (A805
  follow-up).**" from `docs/backlog/architecture.md` "What A1308 retires".

   does not name `time_entries_chain_position_uq`. The design's fallback: keep `workforce_chains`.
   Stop; the watcher confirms.
2. Any `time_entries` hash, sequence or `recorded_at` assertion in `chain.test.ts`,
   `clocking.test.ts`, `corrections.test.ts` or the registro de jornada tests changes (rules §5.3).

   finds only `chain.ts` at `a086eedfb7`.
