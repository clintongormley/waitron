# Use a profile’s default card reader at Pay

When an administrator saves a free default for a till already on **Use default**, the till should offer that reader at **Pay**. When the administrator replaces it, the signed-in till should pick up the replacement without a reload. The reported real-box symptom was **None** despite a named default. Saving a default after enrolment is one way to reproduce it. The report does not establish when that profile was saved or whether another device held the reader.

Expect no resolved reader on current main. Check that on a shared profile the till holding the old default follows a replacement and that a reader held or in use elsewhere stays with the other device. Keep and rename the existing test for two tills on Use default with no previous holder.
- [ ] In `packages/payments/src/device-readers.ts`, capture the old default’s holder if it is on this profile and on **Use default**, before `setProfileReaderList` overwrites the profile and releases obsolete holds. Keep explicit choices still on the list. With several eligible devices and no previous holder, leave the reader for staff to claim on the intended till via **Use default**.
