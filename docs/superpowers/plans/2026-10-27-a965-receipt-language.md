# A965 receipt language implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement inline, task by task. Read the TDD skill before writing implementation or tests. Follow each failing-test-first cycle below. Use one final Claude run-it whole-branch review during `finish-branch`; do not dispatch automatic per-task reviewers.

**Goal:** Give Spain's receipt vocabulary English resources, move payment and refund wording into that vocabulary, and render payment slips and samples in their receipt language without letting the operator's language change a Spanish receipt.

**Architecture:** Keep `ReceiptLabels` in `@waitron/country`, translated resources in `@waitron/country-es`, and lookup in `@waitron/country-packs`. Keep receipt words, number/date formatting, and recorded names as separate inputs. Pass the saved sale language to payment slips and an explicit receipt language through every sample caller; capture the office sample's language before its deferred document fetch.

**Tech stack:** TypeScript, existing country packs, Drizzle/SQLite, Vitest, Chromium browser tests, and the existing thermal/PDF/raster renderers. No new dependency.

**Spec:** [A913/A965 acceptance](../../backlog/architecture.md#a913s-fix-items-general-code-english-only), [A965 backlog entry](../../backlog.md), and [A754 sample ruling](../../backlog/printers.md#decisions-and-deliberate-limits). Read these with this plan.

## Lookup and wording policy

Keep **`receiptLabelsFor(locale: string): ReceiptLabels`**. Add `en-GB` to `SPAIN_RECEIPT_LABELS`, not to `SPAIN.invoiceLocales`. Exact `es-ES`/`ca-ES`/`gl-ES`/`eu-ES` select their existing sets; exact `en-GB` selects English. Bare `es`, `en`, `ca`, `gl`, `eu`, unknown `fr-FR`, `en-US`, and unlabelled `ca-ES-valencia` still select Spanish through this shared lookup. Do not add prefix matching or locale normalization. This is a label policy, not a new date/money fallback: leave existing Intl formatting and the till's unsupported-format fallback unchanged. API validation still rejects unsupported requested receipt languages before lookup.

Preserve refund acknowledgment's distinct existing selection: headings select `es`/`ca`/`gl`/`eu` by the language's first subtag, otherwise English. Resolve those heading resources via the canonical receipt keys; the alias table contains locale codes only. Row labels use the exact shared lookup, except the existing `language.startsWith("en")` path selects the English resource. Thus bare `ca` keeps its Catalan heading and Spanish fallback rows, and unknown `fr-FR` keeps its English heading and Spanish rows. Pin these renderer fallbacks without admitting such requests through the API. This move does not authorize broadening or repairing that legacy policy.

Extend `RECEIPT_LABEL_KEYS` with string-valued keys, retaining the existing `Readonly<Record<… , string>>` contract:
