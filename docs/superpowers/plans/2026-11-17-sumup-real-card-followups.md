## Reader battery

[SumUp status API](https://developer.sumup.com/api/readers/get-status/), read 17 November: “Provides the last known status for a Reader.”; “Battery level percentage”; “Timestamp of the last activity from the device”. Range is 0–100. Owner evidence: 1.67 with activity at 15:22Z persisted while charging; a 17:41Z read returned 100 with activity at 17:36:33Z. Scale is known; freshness is not guaranteed.

4. Proposed watcher policy: use battery only at timestamp age 0–10 minutes; suppress missing/invalid/future timestamps. Ten minutes is our choice, not SumUp's guarantee. SumUp adapter rejects nonnumeric/nonfinite/out-of-range levels before rounding; retain zero and 99.6→100.

SumUp maps last_activity or null in `sumup-client.ts`. Undefined preserves other providers; null suppresses unknown battery. Generic `readerBatteryPercent(status, now)` in new `packages/shared/src/reader-battery.ts` and its index export owns validation/freshness without provider names. Dashboard battery cell and server `alert-sources.ts` use it after cache retrieval; keep connectivity separate, reuse polling, add no timer.
