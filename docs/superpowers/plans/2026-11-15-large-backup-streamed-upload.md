# Large backup streamed upload — implementation plan

**Authority/outcome.** The watcher’s 2026-11-14 23:31 note in `~/waitron-campaign-j/questions.md` authorises planning without another dataset build. Staff will preview, stage and restore backups over 256 MiB through existing browser requests. Separate Sol/high draft, driver source check, Claude review/corrections and watcher clearance precede build; no owner design approval is claimed. The original queue ask and watcher words accompany the external review brief.

**Evidence.** [A1533’s recorded month](../../backlog/setup.md#recovery-operations-still-buffer-whole-database-files) is 144,176,735 encrypted bytes; multiplying by 12 gives **1,649.97 MiB**, a linear 360-day estimate, not a measured year. The year remains unmeasured. Snapshot-inclusive validation peaked at 743 MiB near 256 MiB input, excluding HTTP receipt. Reuse `validateArtifactFile`, existing scratch layout, source hashing and durable restore flow.

1. **Receive.** Add `apps/server/src/setup-archive-upload.ts` and its test. Inject the receiver from `boot.ts` through `SetupDeps`. Stream raw/multipart bodies with backpressure into an owned 0700 folder/0600 file under `<state>/scratch/restore/`, while boot holds the venue-folder lock. Return path/length/disposal. Reuse the `provisioning` latch: stage claims it through validation and releases it in `finally`; preview/restore retain their current lifetimes, including restore-until-restart. Fiscal/configuration/email checks see it busy (`setup.already_provisioning`/409); no separate slot flag. Close handles/cancel reads/remove input on failure, disconnect and request completion; successful durable publication transfers ownership. No per-chunk fsync.

   Proposed input ceiling: **4 GiB**, with declared/counted bounds, 256 KiB multipart overhead and existing field/JSON limits. Check free space while writing against `START_FREE_SPACE_FLOOR`; refuse unknown/insufficient space. Drop the draft’s three-copy formula: gzip expansion is governed by the existing decoder budget, not an input-size multiplier. Input/validation capacity failures answer `restore.archive_resource_limit`/507. Pin `@fastify/busboy` 3.2.0 (`apps/server/package.json`, `pnpm-lock.yaml`); use generated npm notices, audit packaged vendored licences and supplement only a demonstrated omission. No custom parser or new wire protocol.

2. **Connect three browser routes.** In `setup-api.ts`, change `/restore/preview` and raw/multipart `/restore`; in `setup-recovery-preparation-api.ts`, change `/recovery/stage`. Accept artifact-first/last. Preserve each route’s duplicate/unknown-field rules. Keep `/recovery/preparation`’s unused archive multipart branch and shared emergency-handover `readUpload` at 256 MiB. Browser wire shapes stay unchanged.

   Add internal `ArchiveFileRestoreRequest` in `restore-request.ts`, file staging in `recovery-preparation.ts`, file preview in `recovery-backup-preview.ts`, and `boot.ts` wiring. Call `restore.ts`’s `validateArtifactFile`; map ENOSPC/EDQUOT there as well as during receipt. Authenticate the complete ciphertext before decode/database use. File requests run both existing snapshot-binding checks, including refusal beside saved version-2 Cloud state; buffer/Cloud callers retain their behavior. Stream the exact replay-hash byte sequence, never hash-of-hash. Reuse `recovery-source.ts`’s file SHA-256 for source binding; deliberately accept post-receipt file passes rather than expand the validation callback contract. Artifact-first forms require replay hashing after the credentials arrive. After validation, move/flush the archive into `publishRestoreFlow` before its marker. Check abort before publication; preserve auth/origin/owner, old-box and busy checks.

3. **TDD by owner.** Watch new behavioral cases fail, implement minimally, then rerun green. Receiver tests own multipart ordering/refusal mapping, bounds without Content-Length, slot release, modes, cancellation and cleanup; small-disk cases inject a smaller reserve. Existing route suites own forwarding/refusals/replay hashing. `restore-request.test.ts` owns snapshot checks, durable retry and validation-refusal-before-publication; `restore-artifact-file.test.ts` owns capacity mapping. Extend `restore-full-disk.e2e.test.ts` using its small filesystem. Keep buffer-snapshot/browser assertions; no repeated codec tests. Run focused server suites `setup-archive-upload`, `setup-api.recovery-preview`, `setup-api.recovery-input`, `setup-recovery-preparation-api`, `restore-request`, `restore-artifact-file`, `restore-full-disk.e2e`, `boot.setup-routes`; setup’s `api/recovery-{copy,input,preparation}` suites; server typecheck/build. Require executed counts and generated busboy notices.

4. **Qualify and document.** Generate streamed synthetic 320/640 MiB artifacts outside Git; exercise real HTTP raw/multipart paths, compare peak memory/exact hashes and refusal/cleanup after tag-only tampering. Propose retaining Node’s 300-second receiving limit, for watcher decision. The ideal payload bound is `min(4 GiB, throughput × 300 s)`, before overhead: the scaled year needs 46.14 Mbit/s; 4 GiB needs 114.53 Mbit/s; 20 Mbit/s allows about 715 MiB. Qualify throttled success and timed-out-upload cleanup on a real listener with a shortened test timeout. Node’s 408 lacks a domain envelope; `api/client.ts:274` falls back to `server.internal`, so record the resulting generic failure, without promising slow-link success. Update `docs/backlog.md`, `docs/backlog/setup.md`, `docs/developers/conventions-data.md`, naming remaining buffered preparation/handover, Cloud download/upload/capture and configuration paths. No dataset rebuild, schema, fiscal, ledger or timeout-policy work. Forecast production +320–420/−90–150, tests +260–360/−20–50, support +30–60/−0; generated lockfile +10–30/−0, docs +50–80/−5–15. One usable PR within three active hours; checkpoint/ask watcher if exceeded.
