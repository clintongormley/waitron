# SP-1a — Module contract + migration source inversion: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Introduce a `WaitronModule` descriptor each package owns and a static `ALL_MODULES` composition list, and make that list — not the hand-kept `migrations.manifest.json` — the runtime source of which migration sets boot runs, behaviour-preservingly.

**Architecture:** A new `@waitron/module` leaf package holds the `WaitronModule` type + a pure `orderedMigrationSets` helper. Nine descriptors (one per existing migration set) are assembled into `ALL_MODULES` in `apps/server` (the composition root); `boot.ts` derives its migration set list from it. Tested `expected/appliedSchemaVersion` primitives are added for SP-2 to consume later. No enablement, no ordering graph, no route/sync/card conversion — those are later slices.

**Tech Stack:** TypeScript, Drizzle ORM, PostgreSQL 18 (Testcontainers), Vitest, pnpm workspace.

**Spec:** [docs/superpowers/specs/2026-09-04-module-sp1a-contract-and-migration-source.md](../specs/2026-09-04-module-sp1a-contract-and-migration-source.md) (and its parent [module-system-architecture](../specs/2026-09-04-module-system-architecture-design.md))

## Global Constraints

- **Behaviour-preserving.** After this slice, boot must migrate the **same nine sets in the same order** in both trading and setup mode. The pin is a deep-equal of `orderedMigrationSets(ALL_MODULES)` against the current `manifestSets()`.
- **The migration descriptor is manifest-shaped** `{ name, table, from }` (the `MigrationSet` type at `packages/migrations/src/manifest.ts:9`) — **never** an `import.meta.url`-derived folder (esbuild collapses those; `manifest.ts:57` explains why). `boot.ts:505` keeps using `migrationOptionsFor(sets, config.migrationsRoot)` unchanged — only the *origin* of `sets` moves.
- **`ALL_MODULES` (with the `from` folder strings) lives in `apps/server`** (the composition root, exempt from the english-only guard). `@waitron/module` holds only the type + pure helpers (no domain vocabulary). Run `pnpm vitest run scripts/english-only.test.ts` and confirm green with no `SPANISH_WORDS` change.
- **Coverage floors** for a new non-browser package: statements 98 / lines 98 / functions 98 / branches 95.
- **`TESTCONTAINERS_RYUK_DISABLED=true`** for any real-Postgres test; `pnpm reap` if a run is interrupted.
- **Every commit:** `git commit -s`.
- Work from the `feat/module-sp1a` worktree.

## Task 2: Schema-version primitives

**Files:**
- Create: `packages/migrations/src/schema-version.ts`
- Create: `packages/migrations/src/schema-version.test.ts`
- Modify: `packages/migrations/src/index.ts` (export them)

**Interfaces:**
- Consumes: `MigrationSet` (`./manifest.js`).
- Produces: `expectedSchemaVersion(set: MigrationSet, root: string): number` (the module's journal head — `entries.length` from `<resolved from>/meta/_journal.json`, resolved the same way `migrationOptionsFor` resolves folders) and `appliedSchemaVersion(db, set: MigrationSet): Promise<number>` (row count of `__drizzle_migrations_<…>` — `set.table`, returning 0 if the table is absent). Consumed by SP-2 (not wired here).

- [ ] **Step 1: Write the failing tests.** `schema-version.test.ts`: (a) unit — `expectedSchemaVersion` equals the entry count of a fixture journal; (b) real-PG (`useTemplateDb`/manifest) — `appliedSchemaVersion(db, coreSet)` equals `expectedSchemaVersion(coreSet)` after a full migrate, and a partially-migrated fixture DB (apply only the first N of a set into `__drizzle_migrations_x`) reports N, visibly lower than expected (the state where the two answers differ — CLAUDE.md §1). Model the real-PG harness on an existing `packages/migrations` or `packages/db` real-PG suite.

- [ ] **Step 2: Run, watch fail.** `TESTCONTAINERS_RYUK_DISABLED=true pnpm --filter @waitron/migrations test schema-version` → FAIL (not defined).

- [ ] **Step 3: Implement.** `schema-version.ts`: `expectedSchemaVersion` reads and JSON-parses `<folder>/meta/_journal.json` and returns `entries.length` (reuse the folder resolution from `manifest.ts` — export a helper if needed rather than duplicating the path logic). `appliedSchemaVersion` runs `select count(*)::int as n from "<set.table>"` guarded so a missing table (`42P01`) yields 0. Never string-concatenate the table name unsafely — `set.table` is a fixed identifier from the descriptor; validate it matches `^__drizzle_migrations_[a-z_]+$` before interpolation (CLAUDE.md §3, utility-statement discipline).

- [ ] **Step 4: Run, watch pass; prove by deletion.** Confirm PASS; then break `expectedSchemaVersion` to return a constant and confirm the "visibly lower" test goes red; restore.

- [ ] **Step 5: Commit.** `git commit -s -m "feat(migrations): expected/appliedSchemaVersion primitives (SP-1a)"`

- [ ] **Step 1: Write the pin test first.** `apps/server/src/modules.test.ts`:

```ts
import { describe, expect, it } from "vitest";
import { manifestSets } from "@waitron/migrations";
import { orderedMigrationSets } from "@waitron/module";
import { ALL_MODULES } from "./modules.js";

describe("ALL_MODULES is the migration source of truth", () => {
  it("derives exactly the manifest's sets, in order", () => {
    expect(orderedMigrationSets(ALL_MODULES)).toEqual(manifestSets());
  });
  it("lists nine modules with the manifest's names in order", () => {
    expect(ALL_MODULES.map((m) => m.name)).toEqual(manifestSets().map((s) => s.name));
  });
});
```
