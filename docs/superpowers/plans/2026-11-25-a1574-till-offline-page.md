# A1574 PR 1 · Open the till when the box is unreachable

After one trusted online visit, opening the installed till without a connection shows “Can't reach the box. Check that this phone is on the venue's WiFi.” The page keeps checking and opens the requested till page when the box answers. The [owner's second slice](../../backlog/till.md#a1574-a-till-that-cannot-reach-the-box-says-so) covers connection notices on screens that are already open.

## Build

1. Start with a failing Chromium check in `apps/till/src/offline-navigation.test.ts`. Use a separate browser context and a loopback HTTP fixture from `apps/till/test/offline-navigation.ts`, through a browser command in `apps/till/vitest.config.ts` as in `test/native-reload.ts`. Start with a live till page and wait for worker activation, cut the connection, and open `/till/` and a saved `/till/tabs/…` page. Assert that the notice appears and the till does not boot. Restore the connection with a new live page and assert that the original URL opens that newer page automatically.
2. Emit a stable `/till/offline-worker.js` with `apps/till/vite.config.ts`, using the existing manifest asset pattern. The worker source in `apps/till/offline-worker.js` carries one self-contained page from `apps/till/src/i18n/offline-page.html`. Use browser language for English and Spanish on this unsigned-in page. Use native text sizing, light and dark colour schemes, a heading and the WiFi instruction. On open and about every five seconds after a failed check, fetch the current origin's `/health` without caching, with a bounded wait. Any HTTP answer triggers a reload of the original URL. Retain the page between failed checks.
3. Register the worker for `/till/` from `apps/till/src/main.ts` after the existing trust check allows boot, on a secure context in a built till. Let startup continue if registration is unavailable or refused. Handle only same-origin GET document navigations at `/till/`, `/till/tabs` and its descendants. Fetch the original request and pass every HTTP response through, including redirects and errors. Use the embedded page only when the fetch fails. Keep all application documents, assets, API traffic and writes out of worker storage. The saved page reads no session, device or box list. A reachable box's normal boot still uses `ServerRouter` to follow the main box. A first-ever offline visit needs the browser's own error page.
4. Keep a tested retirement recipe at the same worker URL in `apps/till/README.md`. A replacement worker activates promptly and unregisters itself, with no fetch handler and no forced reload of open tills. Add the reconnect instruction to both `apps/server/src/guide/{en,es}/till-notices.md` and leave the open-screen notice in `docs/backlog.md` and `docs/backlog/till.md` for PR 2.

## Checks and size

- The Chromium fixture serves the emitted worker and proves recovery, pass-through for an HTTP refusal and redirect, ordinary dashboard and API responses, and removal with an already-controlled page. The Server's `boot.spa-mount.test.ts` checks the worker URL is JavaScript with `no-cache` and `/sw-probe.js` still answers 404. Run the unchanged `trust-check.test.ts` and `api/server-router.test.ts` cases for certificate and routing behaviour. Build `@waitron/till` and check the built worker, then look at both languages and themes at phone and desktop widths.
- Estimate 85–130 added product lines and 90–150 added test and fixture lines, plus the guide, backlog and removal instructions. No dependency or schema change.

## Platform references

- The Service Workers specification's [Handle Fetch algorithm](https://w3c.github.io/ServiceWorker/#handle-fetch) describes how it returns the original response or a network error. Chrome's [offline fallback example](https://web.dev/articles/offline-fallback-page) supplies its own page when a network navigation throws.
- Chrome's [worker retirement guidance](https://developer.chrome.com/docs/workbox/remove-buggy-service-workers#deploy_a_no-op_service_worker) calls for a replacement at the same URL with no fetch handler. The existing till opts into operating system text scaling in `apps/till/index.html`.
