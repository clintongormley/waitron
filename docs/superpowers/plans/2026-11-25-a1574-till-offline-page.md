# A1574 PR 1 · Open the till when the box is unreachable

After one trusted online visit, opening the installed till without a connection shows “Can't reach the box. Check that this phone is on the venue's WiFi.” The page keeps checking and opens the requested till page when the box answers. The [owner's second slice](../../backlog/till.md#a1574-a-till-that-cannot-reach-the-box-says-so) covers screens that are already open. The installed entry `/till/` and saved `/till/tabs/…` URLs are in scope. First-ever offline visits and the bare `/till` alias still use the browser's own page.

## Build

1. Start with a failing Chromium check in `apps/till/src/offline-navigation.test.ts`. Use an isolated browser context and a loopback HTTP fixture in `apps/till/test/offline-navigation.ts`, exposed through a browser command in `apps/till/vitest.config.ts` like `test/native-reload.ts`. Start on the live till, wait for worker activation, then cut the connection. Check that `/till/` and a saved tab URL show the message without booting the till. Restore the box with a new live page and check that the original URL opens it automatically.
2. Build one self-contained response from `buildOfflineWorker()` in `apps/till/src/offline-worker.ts`. Use the same builder in the fixture and in a separate asset plugin in `apps/till/vite.config.ts` that emits the stable `/till/offline-worker.js`. Put the English and Spanish strings in `apps/till/src/i18n/offline-page.ts`. Select the first supported browser language like `trust-instructions.ts`. Use the till's text-scale opt-in, native text sizing and light and dark colour schemes. About every five seconds, make one uncached, bounded read of the current page's own URL with HTML accepted. Keep the page visible while disconnected. Any HTTP answer triggers a reload of the requested URL. The initial navigation uses the browser's network timeout.
3. Register for `/till/` from `apps/till/src/main.ts` after `isTrustBroken()` allows boot. A small `apps/till/src/register-offline-worker.ts` helper guards production and secure context, and absorbs an unavailable worker or a refused registration. Start it without awaiting it. Activate a replacement promptly without claiming or reloading current pages. Handle same-origin GET document navigations at `/till/`, `/till/tabs` and its descendants. Fetch the original request and return every HTTP response, including redirects and errors. Return the stored page when the network fetch rejects. The worker stores no application pages, assets, API traffic, writes, personal data or box list. Normal boot on an answering box still uses `ServerRouter`.
4. Proposed for watcher clearance: add **Check the connection** / **Comprueba la conexión** to the page. It opens the same till URL with `waitron-check-connection=1`, which the worker lets the browser navigate directly. This restores the native certificate warning when a device has lost trust, as a failed fetch alone cannot tell a certificate error from an outage. Strip this flag after a successful boot so later visits keep the normal fallback. Keep `/sw-probe.js` and the existing repair path. Retain the owner's “this phone” wording for this slice unless the watcher changes it. Use “No se puede conectar con el servidor. Comprueba que este teléfono está conectado a la red WiFi del local.” in Spanish.
5. Document retirement in `apps/till/README.md`: stop registering and ship a no-fetch replacement at the same URL for returning devices. It activates and unregisters without reloading open tills. Keep the replacement source in `apps/till/retire-offline-worker.js` for the recipe and the browser test to use. Update both `apps/server/src/guide/{en,es}/till-notices.md` and their `table-service.md` trust sections. Leave the open-screen notice in `docs/backlog.md` and `docs/backlog/till.md` for PR 2.

## Checks and size

- The Chromium fixture checks offline opening, automatic recovery to the newer page, redirect and HTTP refusal pass-through, empty Cache Storage, and retirement with a controlled page. The connection link gets a real HTTPS check: after a trusted online visit, swap to an untrusted certificate on the same origin and check that the link reaches Chromium's certificate error. Bound the waits and let the fixture own its listener and browser context. A built-till smoke check exercises real registration and confirms it can boot after a worker refusal. `apps/till/src/register-offline-worker.test.ts` checks the registration helper's skip and rejection cases.
- Keep `trust-check.test.ts`, `api/server-router.test.ts` and `apps/server/src/boot.spa-mount.test.ts` passing. Build `@waitron/till`, check the emitted worker URL is served as JavaScript with `no-cache` and `/sw-probe.js` still answers 404. Look at both languages and themes at phone and desktop widths.
- Estimate 105–165 added product lines and 120–185 added test and fixture lines, plus guide, backlog and removal instructions. No dependency or schema change.

## Platform references

- The [Service Workers specification](https://w3c.github.io/ServiceWorker/#handle-fetch) covers returning a response or a network error. Chrome's [offline fallback example](https://web.dev/articles/offline-fallback-page) supplies a page when a navigation fetch throws.
- Chrome's [worker retirement guidance](https://developer.chrome.com/docs/workbox/remove-buggy-service-workers#deploy_a_no-op_service_worker) calls for a replacement at the same URL with no fetch handler. The existing till opts into operating system text scaling in `apps/till/index.html`.
