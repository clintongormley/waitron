# A1186 Cloud trial offer implementation plan

> **For agentic workers:** Implement inline with `superpowers:executing-plans`, task by task. Read `superpowers:test-driven-development` before product code or tests. The separate plan author is required for this milestone; routine implementation does not require implementer/reviewer pairs. The driver owns ONE fresh-context plan review.

**Goal:** Invite you to explore Waitron Cloud's optional level-2 trial after ordinary setup, without making Cloud part of setup completion.

**Architecture:** Add one information card to the existing completion screen, linking to the local Cloud services page. Keep sign-up, trial selection, payment and billing authority in Cloud. Reuse restart readiness and add one tab-only flag identifying a successful fresh setup; add no persistence, table, API, billing field or tutorial progress.

**Tech stack:** Existing Lit screen, `wt-card`, setup EN/ES catalogue and `--wt-*` tokens. Proposed static [mockup](../../backlog/mockups/a1186-cloud-trial-offer/README.md).

**Spec:** This plan contains the UI specification. Commercial decisions come from [Cloud billing design at PR705's merge commit](https://github.com/waitron-io/waitron-cloud/blob/4064f3044f4826235e399070e564a94e4dd7bdd0/docs/superpowers/specs/2026-10-29-cloud-billing-design.md), §§2, 4, 5 and 10. Its front matter still says “draft for owner approval”; the driver's handoff identifies PR705 as merged. Neither statement proves a billing runtime exists.

## Driver calls and prerequisite gates

**D1, proposed entry:** Treat completion as A1186's smallest independent entry. Put the card last, after existing choices, hours, device/key notices and backup nudge. Mockups show ready Preparation; propose the same card for Live. Do not build A250.

**D2, optionality:** No dismiss control, saved preference or progress mark. Leaving through Dashboard or Till skips the offer. Re-entry is **Dashboard → Settings → Cloud services**, not a promise to reopen the one-time completion page. This information card does not require A1185's billing display or shared-contract fields.

**G1, complete journey before release, OPEN:** Keep this milestone as proposed docs/mockups until the downstream local Cloud services → Cloud trial journey works. Record accepted Waitron and Cloud revisions and exercise new-account email verification, existing-account sign-in, venue selection/binding, deliberate trial acceptance, 30-day terms, no payment details to start, usage limits and return to Waitron. Include an already connected venue, an expired local session, insufficient local permission, Cloud offline and missing Cloud origin/configuration. A person must have a supported way forward or a clear way to leave at each step. Pairing alone must neither select a trial nor configure services.

The current missing-configuration branch (`cloud-services-screen.ts:267–268`) offers only a paragraph, with no connection action. Therefore a working Cloud trial alone does not open G1. Record the local missing-configuration remedy and any sign-in/destination gap as prerequisites for the lane owning that connection flow; agree their concrete behaviour and qualify them before implementing this offer. A1186 does not redesign billing, authentication or configuration. If those capabilities are unavailable, keep the build parked. Qualify that downstream capability before Task 1, without pretending the new invitation already exists. After implementing it, Task 2 exercises the complete setup → local page → Cloud journey. Current inspection supplies no runtime evidence for G1. A merged design, configured origin or registration does not open it. Invent no query parameters, trial endpoint, wire field or placeholder price.

**D3, connection entry:** Use **Explore Cloud services**, a same-tab local anchor to `/manage/cloud`, not Open Cloud or Start trial. G1 must qualify the connection page followed by Cloud's account journey; a new setup destination is not required by this proposal. If qualification needs a new local control or wire contract, stop that integration and name the exact prerequisite for its owning lane. Do not expand into A1185. A1185/A1187/A1188 remain Lane B; A1189 remains Lane A.

**D4, transient eligibility:** Add `cloudTrialOfferEligible: boolean`, initially false, as a private shell state and a done-screen property. Set it true only in the current successful `#onProvisionRequested` result, including completion of an interrupted fresh setup publication, immediately before switching to Done. Clear it in `#clearProvisionOutcome` (already called by provision, adopt, archive and bucket starts) and at the start of the Cloud `restore` action. Pass it in the existing Done binding. Never set it from mode, Cloud registration, restore success or a saved value. This is an in-memory completion outcome, not trial/progress tracking. Existing readiness, rebuild and mirror meanings stay intact.

## Visibility and behaviour contract

| Completion input/state                                                | Proposed card                   | Existing content                                                                                                                                                                                    |
| --------------------------------------------------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prepare` or `live`, ready, eligible fresh setup                      | Show                            | Preserve rows, mode, hours, key and backup content in existing order.                                                                                                                               |
| `demo`                                                                | Hide                            | Keep Demo destinations and backup suppression; no offer on throwaway demo data.                                                                                                                     |
| Intent absent                                                         | Hide                            | Do not infer a new venue or trial eligibility from legacy/restore completion.                                                                                                                       |
| `rebuilt`, including prepare/live intent                              | Hide                            | Preserve device steps, key and backup suppression; no recovery upsell.                                                                                                                              |
| `mirrorJoin`, any intent/readiness                                    | Hide                            | Preserve stalled-join page and key warnings exactly.                                                                                                                                                |
| Restart waiting, network `TypeError`, 5xx, or successful status read  | Hide until existing `ready`     | Preserve polling, announcements, disconnect cleanup and existing links. Readiness stays the existing heuristic, not a new health guarantee.                                                         |
| Ready, but Cloud origin missing, Cloud offline, or staff lacks rights | Same information and local link | Setup makes no Cloud/configuration read. Release remains blocked until G1 establishes a supported destination in these states; the current missing-configuration paragraph supplies no next action. |

Archive/Cloud restore or any completion with `cloudTrialOfferEligible === false` hides the card even if the retained intent is prepare/live.

Do not change fiscal setup, recovery, authorization, restore, polling or backup semantics. No Cloud request on render, link creation, locale change or skip. No credentials, payment fields or trial status in setup. A staff session with `system.manage` permits connection; the separate Cloud owner account permits billing choices. No new local owner role.
