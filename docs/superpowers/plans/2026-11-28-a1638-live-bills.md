# Keep the open bill and Make now current across tills (A1638)

While you keep a bill open, show dishes another till sends to that bill and update **Still to pay
at this table** when any bill at the table changes. When a dish is voided, remove its **Make now**
instruction from the Counter that received it. The three reports are from
[#4535](https://github.com/clintongormley/waitron/pull/4535#issuecomment-7233171093).

## PR 1 · Refresh the open table order

- [ ] In `apps/till/src/till-app-live-connection.test.ts`, use the existing table and live-stream
  fixtures. While the same bill stays open, change the answers for its lines and sent groups,
  deliver the matching live event, and assert that Hake appears. In a separate case, change a
  sibling bill and the Floor answer from €108.90 to €126.40 (€89.90 + €36.50). Assert the displayed
  table total and kept bill selection. Observe both failures before editing the app.
- [ ] In `apps/till/src/till-app.ts`, the live refresh calls `#rereadBillsOnTimer`, which refreshes
  lines only while Pay is open. The footer reads `orderParty.outstanding` from the Floor snapshot.
  Reuse the current-bill line and group reads and the same-party Floor read for the visible order.
  Keep the draft refresh and background bill-following rules. Reuse the existing read ordering
  and party, bill and session checks so a late explicit read cannot put back an earlier answer.
- [ ] Delay an explicit read, deliver a live change with newer lines or totals, then return the
  old answer. Assert the new display survives. Run the focused live suite and the amount and
  bill-switch cases in `till-app-parties.test.ts`. About 40 product and 100 test lines.

## PR 2 · Reconcile the Counter instruction after a void

- [ ] In `apps/till/src/till-app-boot-and-counter.test.ts`, issue a Make now card with Hake and a
  second dish. Void Hake through the observed path, deliver the live notification, and assert
  that only Hake disappears and stays gone when the card is restored from storage. Pin the
  order status and the stored line or ticket change with the real server path before picking a read.
- [ ] `apps/till/src/state/make-now-controller.ts` only adds and dismisses instructions today.
  Reuse the existing device connection and reconcile only pending instructions for that device
  against committed order state. Prefer the existing zone-checked order read if it covers the
  reproduced status. Check cleared and newly added instructions when a read finishes. If the
  reproduction needs a change to the server contract, bring the exact gap to the watcher first.
  About 70 product and 100 test lines for the existing-read route, including wiring in `till-app.ts`
  and `api/client.ts` if the current response needs its order reference carried to the controller.

Keep pricing, payment, inventory, screen layout and live-stream protocol out of these changes.
Use the existing stream and the existing timed fallback. Run the changed test files before each
checkpoint. Check `docs/backlog.md` and `docs/backlog/till.md` at each merge for any stale entry.
