# Keep the open bill and Make now current across tills (A1638)

While you keep a bill open, show dishes another till sends to that bill and update **Still to pay
at this table** when any bill at the table changes. When a dish is voided, remove its **Make now**
instruction from the Counter that received it. The three reports are from
[#4535](https://github.com/clintongormley/waitron/pull/4535#issuecomment-7233171093).

## PR 1 · Refresh the open table order

- [ ] In `apps/till/src/till-app-live-connection.test.ts`, use the existing table and live-stream
  fixtures. Open the Counter's bill on the handheld, send Hake from the Counter, and deliver the
  live change. Assert Hake appears before a bill switch. The report gives no initial selection.
  `sentSections` projects the selected bill, so pin that selection for this test. Separately,
  change a sibling bill and the Floor answer from €108.90 to €126.40 (€89.90 + €36.50). Assert the
  displayed table total and kept bill selection. Observe both failures before editing the app.
- [ ] In `apps/till/src/till-app.ts`, the live refresh calls `#rereadBillsOnTimer`, which refreshes
  lines only while Pay is open. The footer reads `orderParty.outstanding` from the Floor snapshot.
  Reuse `#refreshTableLines`, `#readGroups`, `#readCurrentOrders` and `#showGroups`. Reuse
  `#retakePartyFromFloor` for the canonical total on order changes, limiting the full Floor read
  to changes that can affect amounts. Keep the background bill-following rules and staged input.
  Reuse the read ordering and party, bill and session checks so a late explicit read cannot
  put back an earlier answer.
- [ ] Delay an explicit read, deliver a live change with newer lines or totals, then return the
  old answer. Assert the new display survives. Run the focused live suite and the amount and
  bill-switch cases in `till-app-parties.test.ts`. About 40 product and 100 test lines.

- [ ] In `apps/server/src/line-cancel-api.test.ts`, use the real send and void to pin the bill's
  status and the resulting line state. In `apps/till/src/till-app-boot-and-counter.test.ts`, give
  Make now two dishes, fully void Hake, and assert only Hake disappears and stays gone on restore.
- [ ] Have `apps/server/src/made-here.ts` return each instruction's `workingOrderId` with its

  Verify cards received or restored against the signed-in till's existing `getTabLines` read for
  open and placed bills. Remove only verified full voids for the same device and pending items.
  Keep instructions when their order cannot be read or identified. If the existing read cannot

  read gap to the watcher before changing any route. This PR covers full voids.
  About 100 product and 120 test lines for the existing `/lines` read path.
