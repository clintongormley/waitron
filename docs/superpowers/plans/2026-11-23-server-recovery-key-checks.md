# Share recovery-key checks in server tests

A server test file can reuse the result of checking the same recovery key against the same stored verifier. Tests that watch real derivations still see the work they ask to observe. This is the recovery-key part of “Server test time levers left after A1297” in `docs/backlog/ci.md`, assigned to Lane I as `SERVER-TEST-RECOVERY-KEY-REPEATS`.

## Shared setup

- [ ] In `apps/server/src/testing/staged-hour-restore.memo.test.ts`, drop the staged fixture import and count real scrypt calls through a suite-local crypto mock. Keep its exact-pair, concurrent, refusal, retry and event-loop assertions. Fold in the host test's count for a repeated refusal and for the same secret against another stored verifier. With setup absent, the three concurrent calls and one later call produce four derivations against an expected one.
- [ ] Register `src/testing/recovery-key-check-setup.ts` in `apps/server/vitest.config.ts`. Move the existing partial `@waitron/identity` mock into it and wrap only the package's exported `verifySecretAsync`. `verify-pin.ts` and `verify-password.ts` import their verifier directly from `secret-hash.ts`. A suite with its own package mock keeps control of that import. Keep the map inside the lazy factory, keyed by secret and full stored verifier. Share the pending promise, remember true and false, evict rejections, and yield one real event-loop turn on a hit.
- [ ] Give `src/testing/watched-scrypt.ts` a predicate that tells setup when a secret is watched or faulted, or all derivations are being watched. Bypass both reading and filling the map for such calls. Warm an exact pair before observing or faulting it. The existing test of deriving outside both write locks in `src/recovery-operation.test.ts` must still report one derivation. In the owning memo suite, inject a one-shot scrypt fault without opting out so the retry tests eviction itself. Removing the bypass in a disposable copy must hide the watched derivation or fault.
- [ ] Remove the duplicate package mocks from `apps/server/test/hour-recovery-host.ts` and `apps/server/src/testing/staged-hour-restore.ts`. Retire the host counter and its case in `src/hour-recovery-host.test.ts` once the shared suite carries those assertions. Keep the memo suite's path so the duration table still places it on its existing shard.
- [ ] Run `pnpm --filter @waitron/server exec vitest run` with `staged-hour-restore.memo.test.ts`, `hour-recovery-host.test.ts`, `hour-recovery-staged.test.ts`, `recovery-operation.test.ts`, `break-glass.test.ts`, `live-conflict-recovery.test.ts`, `recovery-pack-api.test.ts`, `pin-check-ahead.test.ts` and `own-password-ahead.test.ts`. Record the initial count failure and the passing counts.
