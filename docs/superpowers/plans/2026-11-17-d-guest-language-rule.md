Claude proposes a general alternative: a tag containing a variant subtag is its own main language, identified by its canonical `Intl.Locale(...).baseName`; a tag without a variant reduces to its base language. That retains today’s `ca-ES-valencia` identity without naming a language in code. It also makes other variant tags independent main languages and stops folding other Valencian spellings into one tag. The picker can take variant entries from its existing pack-supplied official locales. Labels need a decision: on this Mac, `Intl.DisplayNames` prints “Catalan (Spain, Valencian)” in English and “catalán (España, Valenciano)” in Spanish, rather than the current short names (driver ran Node’s real API). Keeping short labels would need pack-supplied label data. Recommend the generic identity rule; ask the watcher to clear the label choice and identity semantics before estimating or building that part. No receipt/till/kitchen behavior change is cleared here.

**Contract for Cloud lane G to copy:** offered tags are main first, then the saved venue order. Canonicalize tags with `Intl.Locale`, discard extensions, ignore invalid preferences. For each preference, try its exact tag, then remove trailing parts one at a time, then take the first offered tag with the same base language. Finish that preference before trying the next. Parse Accept-Language in descending positive `q` order, header order on ties; guests ignore malformed entries, zero weights and wildcards. An explicit `lang`, even empty or invalid, becomes the sole preference through the same matcher and never falls back to the phone. No match means main; ignore `language`. Wording matches the shown language against the registered bundles, then main, then English, preserving the selected bundle’s actual tag.
