## Smallest build and existing code

Keep the existing cache, in-flight map, secret bucket selection, 32-bit fingerprint and delay/idle helpers. Each bucket retains one named owner plus one shared overflow record. Live owners cannot be displaced by a different fingerprint; overflow remembers the maximum count, unlock time and last activity of live contributions from other addresses. Add an explicit occupied flag for the named owner so time zero and fingerprint zero remain valid; shared history uses the existing timestamp-based idle rule. Only `fold` writes overflow; only `fresh` reads it for an address without a live owned counter. The cache and held attempt already carry that address’s history, so add no other merge points or in-flight slot reservations.

Both records use `pinThrottleIdle` independently. Skip an already-lapsed entry before folding it, including a timestamp over 60 seconds ahead after a backward clock step, so it cannot expire a live shared record. Reuse `MAX_BUCKET_FAILS`, retry rounding and existing idle/success/error rules. `wouldRefuse` uses the same lookup as `begin` and changes nothing. Keep public signatures, normalization, caller responses and hashing work unchanged.

**Capacity policy, cleared by watcher 09:40 and retained with corrected limits at 10:02:** an address with no owned counter can inherit another address’s overflow count/wait, including before its first attempt. This prevents count loss under saturation but can impose waits on unrelated addresses. Success must never clear overflow or another owner. Own-success relief: retain a zero-count finished cache entry through the existing bounded trim rather than discard it, so this successful address starts fresh while cached; once evicted it can inherit live overflow again. Other addresses still inherit overflow. This changes which successful keys `tracked()` includes, not its existing cap. The PR explains both the wait and inherited count: each wrong password can open a minute’s wait even after the spray stops, until successful sign-in or 15 minutes of that address’s own inactivity; shared history expires after 15 minutes without a contribution. A correct password works after the current wait. Run-it reviews identified this longer effect; the watcher explicitly cleared retaining the behavior with corrected wording at 10:02, with no mechanism change.

**Memory:** lazily allocated fixed arrays: owner 22 bytes/counter (existing 21 plus occupied byte), overflow 17 (count and two times), total `65,536 × 39 = 2,555,904` payload bytes per allocated throttle, plus the existing cache/in-flight maps. Map storage remains bounded by the larger of 1,000 or the number of concurrent attempts, not absolutely bounded against unlimited simultaneous requests. No claim of exact per-address histories under arbitrary floods.
