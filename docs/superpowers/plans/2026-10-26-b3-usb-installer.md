# B3 USB Installer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, after separate build authority. Steps use checkbox (`- [ ]`) syntax for tracking. A separate documentation author supplies this plan; a fresh reviewer must review it before execution. This document author neither builds nor dispatches that reviewer.

**Goal:** Deliver the six approved go-live slices, 1, 2, 3, 5, 6 and 8, with an unattended USB install, encrypted disk, managed screen, qualified release assets and safe same-box Prepare-to-fresh-Live configuration handoff.

**Architecture:** Build a release-pinned Debian disk and a smaller downloading installer. A restricted host service owns host operations, retained disk-key delivery and durable cutover evidence outside the removed venue. Existing setup/import and module boundaries remain authoritative; bind them only after reorientation on released A1042 code.

**Tech Stack:** Debian 13 amd64, mkosi, signed Debian boot chain, dracut, TPM 2.0, LUKS2, btrfs, Docker, NetworkManager, cage/Chromium, existing Node/Lit/Vitest tools. Proposed host tools are small `.mjs` files under `scripts/box/`, measured by root coverage; the recipe must install a pinned host Node runtime with notices. No new workspace package is assumed.

**Spec:** [complete approved-with-changes design](../specs/2026-10-21-b3-usb-installer-design.md), §§0–20 and preserved P1–P59 plus the dated P60–P62 interface bounds. Read both documents. Spec §7.5's complete proposed policy awaits the sole owner unlock-policy answer and actual client/Linux qualification.

These numbers are conditional on the owner's answer, not settled product policy. TLS does not prove the unsigned startup image honest.

## Review Focus

1. A disk looks partly like Waitron after interrupted header writes, or two internal disks match. Expect zero unattended erase/open, not a fallback to a convenient target. Tasks 1.1/2.1/1.3.
2. A second browser races the owner after Prepare removal. Expect ordinary fresh Live claim/preview, but no disk-key disclosure or repeat erase. Tasks 8.1/8.3.
3. Power fails after deletion intent, or storage fills before/after handoff durability. Expect intact practice before commitment and safe phase continuation afterwards, with the new Live venue protected. Tasks 8.2/8.3.
4. Restore/spare changes venue/node identity while the destination disk differs from the source sheet. Expect destination UUID/key and protected first delivery before a usable admin session exists. Tasks 8.1/8.4.
5. Another preboot client floods wrong keys, or startup/peer identity is spoofed. Expect shared delay, no plaintext form, honest tamper limits, wrong-disk refusal, no shell/second TPM unseal. Tasks 1.2/1.3/6.1.
