# Keep CI on the server when the pnpm cache is slow

## Finish line

Jobs on our disposable runners finish Node setup and reach their checks through the existing
frozen pnpm install. GitHub-hosted jobs still use the existing pnpm cache. Qualify both paths in CI.

## What failed

- `ci-run-story.sh` places the failed jobs on our server, using the first-attempt jobs API for main because the helper shows its later rerun. [Main 44359772777/1 lint](https://github.com/clintongormley/waitron/actions/runs/44359772777/job/134997963205) reached 92.9% and 97.6% of a 177,466,126-byte archive at the two Node setup deadlines. [PR 44368424650/1 server shard 4](https://github.com/clintongormley/waitron/actions/runs/44368424650/job/135029629291) reached 37.8% twice, at last reported rates of 0.6 and 0.5 MiB/s. The archive needs at least 1.41 MiB/s to finish in 120 seconds, before setup and extraction. The second attempts found Node locally. Four main jobs and 11 PR jobs reached the second deadline before any check ran.
- On the failed lint and shard jobs, checkout produced about 48.8 MB of git packs in 3–9 seconds for the whole step, and the npm command installed pnpm in under a second. The npm log does not say how many bytes came from the registry. Node setup steps peaked at four overlapping on the main run and 11 on the PR. The earlier passing server run peaked at six, and its [lint](https://github.com/clintongormley/waitron/actions/runs/44279533864/job/134716579091) finished the same archive at 6.3 MiB/s. [GitHub's shard 10 in the failed PR](https://github.com/clintongormley/waitron/actions/runs/44368424650/job/135029629332) finished it at 149.2 MiB/s. The 17 retained main archives of 10–17 November span 176.8–177.5 MB. The slow path was the archive download to our server. The underlying network bottleneck and cold install throughput under the same load are unverified.
- The jobs fetched [setup-node revision 949feb2](https://github.com/actions/setup-node/blob/949feb2413d6458794dcd2491c4babbbce0c15c1/src/main.ts#L60-L87). It awaits the explicit cache restore after setting up Node. An empty input takes the automatic npm detection path, and [that detector](https://github.com/actions/setup-node/blob/949feb2413d6458794dcd2491c4babbbce0c15c1/src/main.ts#L146-L169) accepts npm declarations. GitHub describes [runner.environment](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#runner-context) as “the environment of the runner executing the job.”

## One change

1. In `scripts/ci-workflow.test.mjs`, add “restores the pnpm cache only on GitHub-hosted CI runners.” Find jobs with a self-hosted route and a frozen pnpm install using `jobBlocks` and `workflowSteps`. Check both setup attempts. Evaluate any cache expression with `expressionValue` and use a literal cache input as written. Expect empty for `self-hosted` and `pnpm` for `github-hosted`. Run `pnpm exec vitest run scripts/ci-workflow.test.mjs -t 'restores the pnpm cache only'` first. The old literal `pnpm` fails the self-hosted assertion.
2. In `.github/workflows/ci.yml`, make both explicit `cache` inputs in those jobs select `pnpm` when `runner.environment == 'github-hosted'` and the empty string otherwise. Reuse the pinned pnpm setup and frozen install. Keep both Node attempts bounded with identical inputs. The frozen install still uses the enclosing job deadline. A new lockfile key may miss on hosted PRs until a hosted main job saves it. The first-attempt full-run coverage merge jobs use GitHub and can save it. This change needs no runner image, proxy or routing change.
3. Run `pnpm exec vitest run scripts/ci-workflow.test.mjs scripts/setup-node-pnpm.test.mjs` and `actionlint` if available. Keep the current-head logs for a hosted job restoring the archive and a disposable batch reaching the checks after a frozen install with no archive. Record head, run, attempt, runner identities, overlap, job and install durations and downloaded package counts. Use a batch comparable to the 11 simultaneous disposable jobs that failed, with no scheduling changes for the experiment. If the batch cannot be exercised, or a cold install misses its job deadline, keep the qualification open.

Record the result beside “Every Node setup is bounded” in `docs/developers/ci-and-gates.md` and cross-reference the CI incidents entry in `docs/backlog/ci.md` if the transfer problem still needs tracking. Expected change is 64 input lines replaced, about 25 test lines and a short evidence note.
