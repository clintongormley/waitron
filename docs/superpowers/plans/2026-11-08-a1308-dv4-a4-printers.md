**Goal:** One table for every printer (owner, 2026-11-04). `page_printers` merges into `printers` as
rows of kind `a4` with transport `ipp`, and every reader and writer of A4 printers moves with them.
`invoice_deliveries.page_printer_id` and A790's `document_page_jobs.page_printer_id` become
`printer_id`. The two device and profile columns that name an A4 printer keep their names in this
slice and point at `printers`; [dv5](2026-11-08-a1308-dv5-device-printer-columns.md) merges them and
adds the device trigger.

(`git grep -c "pagePrinters\|page_printers\|pagePrinterId\|page_printer_id\|invoicePagePrinterId" -- '*.test.ts'`);
one pull request would pass the size cap (coordinator's review, 2026-11-08). This one moves the rows;
dv5 changes the device and profile columns.

## Decisions this plan makes

1. **Receipt fields keep their database defaults.** 41 test files insert `printers` rows relying on
   them (`git grep -l "insert(printers)" -- '*.test.ts' '*/testing/*'`). An `a4` writer passes `null`
   for `paper_width` and `resolution` and `0`/`false` for the receipt flags explicitly;
   `printers_kind_fields_ck` refuses a writer that forgets. The two A4 writers are
   `apps/server/src/page-printers.ts` (discovery add) and dv3's `insertA4Printer` test helper, which
   this slice gives the real A4 columns.
2. **API routes and wire fields do not change.** `/management-api/page-printers…` stays
   (`apps/server/src/page-printers-api.ts:82-168`), reading and writing `printers` rows of kind
   `a4`; its rows keep their shape. The till and dashboard keep `pagePrinterId`
   (`apps/till/src/api/client.ts:2479`, `apps/dashboard/src/api/client.ts:1238`); the server maps a
   delivery's `printer_id` to it on `a4` rows.
3. **Every read of `page_printers` becomes a read of `printers` with `kind = 'a4'`**; where a read
   wanted both kinds by reading both tables, it becomes one query with no kind filter (dv3 marked
   them "both in dv4"): `orderInvoicePrinters` (`apps/server/src/orders-list.ts:717-735`), the
   profile-list check (`apps/server/src/management-api.ts:711-731`), `refuseUnknownPrinters`
   (`packages/layouts/src/device-printers.ts:160-200`), the printer-info read
   (`packages/layouts/src/device-equipment.ts:193-222`), A790's offers (#2455,
   `document-printer-offers.ts:131-137`). Each must still refuse an A4 id on a receipt, slip or
   drawer list (the kind travels with the row). Joins through `devices.invoice_page_printer_id` or
   `device_profile_printers.page_printer_id` join `printers` under an alias until dv5.
4. **The configuration import keeps its two A4 rules for `printers` rows of kind `a4`:** switched
   off, and `agent_id` cleared (today `packages/provisioning/src/configuration-transfer.ts:761-763`
   for `page_printers`). `page_printers` leaves `CORE_CONFIGURATION_TRANSFER`
   (`packages/db/src/configuration-transfer.ts:101`). **The format version goes up by one**
   (rules §9; today `10` at `:123`, `:160`, `:473`, `:476` of the provisioning file; take what `main`
   holds and add one in all four, as dv2 did).
5. **Deleting an A4 printer stays unbuilt** (A405's held item,
   `docs/superpowers/plans/2026-11-05-a405-printer-details.md:270-276`).
