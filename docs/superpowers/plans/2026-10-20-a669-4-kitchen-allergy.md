**Goal:** Give every kitchen destination the assigned guest's allergy instructions, frozen with its work, and an acknowledged correction whenever those instructions change before service.

## Storage and presentation decisions

**This design needs migrations.** `packages/db/src/schema/ticket-items.ts:34–88` has no allergy/generic snapshot; venue-service `schema/kitchen-notices.ts:20,70` accepts only five existing kinds. The spec delegates storage choice; Lane G permits migrations without an item-specific STOP. Correct the queue's “Migration: no” estimate; never encode allergy in `note` or `orderNoteChange`.

Define `KitchenAllergyBlock` in `packages/module/src/party-allergy.ts`:
`{ who:string; allergens:AllergenMap; note:string|null; clashes:AllergenMap; labels:Record<"en"|"es",{avoids:string[];clashes:string[]}> }`.
`allergens` is what the guest avoids; `clashes` is the known as-served overlap, retaining dish/extra kinds. Canonicalise code/kind ordering and compare values, excluding guest ids. Capture English and Spanish allergen names with kinds in `labels` when constructing the block, in the same canonical order. Existing cards, reprints and notices select their stored language with English fallback; never resolve those names from an active dictionary. Dictionary edits cannot change an existing block. New exposure and explicit corrections capture their own labels through the server translation home. Also export `TicketAllergyCopy = {originalBlock:KitchenAllergyBlock|null;currentBlock:KitchenAllergyBlock|null}` for storage and replacement handoff.

Create venue-service `ticket_item_allergies`: `ticket_item_id` PK, named FK `ticket_item_allergies_ticket_fk` to **core `ticket_items.id` ON DELETE CASCADE**; nullable JSON `original_block`/`current_block`, validated blocks or null. Row presence means frozen, including an unticked copy. No guest/party/person/product/station FK. Never change original during that ticket's work; update current with the allergy command/output. Clone both on financial splits. Deleting a recalled item ends its copy; old print-job bytes remain, and a new resend ticket gets a new copy.

Classify it `state` in `VENUE_SERVICE_CLASSIFICATION`/change sources; export schema through `schema/index.ts`, operations through service/barrel/module seat. Composition `modules.ts:135` already requires `{core:"*",modules:{catalogue:"*"}}`, covering the FK; no identity dependency. Keep `VENUE_SERVICE_MIGRATIONS` and `packages/migrations/migrations.manifest.json` on this folder with only `sale_receipt_headers` append-only. Test exclusion from `VENUE_SERVICE_CONFIGURATION_TRANSFER`: live work is not setup configuration.

Add nullable `kitchen_notices.allergy_block` and kinds `allergy_changed`/`allergy_removed`. Require a block for changed, null for removed/other kinds; prohibit other correction options on allergy kinds. Preserve existing notice values. Generate ADD COLUMN/table changes **before** the separate CHECK generation, which may rebuild notices. Inventory inbound keys/trigger bodies and inspect SQL. T1 measures populated preservation; do not claim a no-reset upgrade from reading. **Deployment builder policy:** start with no outstanding pre-live kitchen work, resetting the development venue if needed, rather than synthesising historical originals. **Builder calls, distinguished from owner decisions:**

- Follow the spec's explicit frozen-screen test literally: normal dish cards and reprints read `originalBlock`; notices show the corrected `currentBlock` or removal. Acknowledgement dismisses the notice; it does not replace the card's original block. This behavior is already approved by the spec's frozen-screen test. Keep its assertion and do not reopen it as an owner question.
- A held item without queued HOLD paper has no frozen block yet; its first fire captures the then-current assignment. Freeze HOLD only for the exact line/station targets receiving a queued job, not every station in a group. A fired item freezes even with no printer. Made-here/no-preparation work has no kitchen output; independently routed extras still do.
- A destination receiving already-corrected moved/rerouted work gets the original plus a fresh acknowledged correction when `currentBlock` differs. Ordinary reprint adds no new notice. Allergy notices remain available until acknowledgement, including across business-day rollover and more than fifty notices; keep the existing day/latest-fifty policy for other kinds. This resolves the spec's “until acknowledged” against `listStationsNotices`' current cap without weakening other kinds.
- Kitchen clashes include active extras. The table dialog's clash and Send anyway already count each extra's allergens (A931, 2026-10-20); this slice leaves the dialog alone.
