# A1645. Share one Waitron typecheck slot on the Mac

A developer or pre-push hook can start a typecheck in any updated Waitron checkout. When a compiler is already running under the same macOS account, the next one waits and then runs the package's usual check. The 14:09 crash report counted eight compilers at a combined 66.3 GiB. Server alone peaked at 11.7 GiB on commit `373c1e09c4`, compared with 3.6 GiB for the next-largest app. Allow one slot because two Server invocations at the observed crash peak could take 43 GiB before the editor, Docker and other jobs. The 53 app and library checks summed to about 2½–4½ minutes of compiler time, substituting the lighter and busier Server runs. Eight full-workspace runs queued together would need about 20–36 minutes, an estimate assuming the same workload. Scoped pushes check the packages selected by the hook.

**Files and approach**

- Route the 54 workspace member typecheck scripts in `apps/`, `packages/` and `bench/sqlite-failover/` through `scripts/typecheck.mjs`. Keep their package working directory, compiler arguments and exit status, including Country ES's second project. Root `pnpm -r typecheck` and the hook both reach these scripts. Each compiler takes the slot once, so the hook cannot hold it while waiting for its own checks. List the launcher’s consumers in `scripts/changed-scope.mjs` so launcher changes select their CI jobs.
- On the Mac, open one file under the account's `~/Library/Caches/` with Darwin's exclusive-open flag (`O_EXLOCK`). Pass the open descriptor to the installed TypeScript 7 native binary as an inherited descriptor. Resolve it from the package's installed TypeScript distribution. A local probe found the descriptor on the live native compiler and confirmed that another lock request still failed after killing the wrapper alone, then succeeded after the compiler exited. Leave the file in place across runs. Tell a waiting developer once which file is held. If a sandbox denies access to the lock file, warn once and run the compiler. Report other lock or launch errors to the caller. On Linux the package's CLI runs directly and receives CI's memory target.
- Compare the default, fewer checkers, and Go’s 6 and 8 GiB soft targets using `/usr/bin/time -l`. Prefer one measured default for the Mac that protects the Server check without imposing a large run-time cost. The PR body includes the comparison, every package peak, the serial estimate, and the rollout for checkouts that predate this change.
- Use the incident's Jetsam snapshots, daemon and app logs, and live process information for the separate file-event diagnosis. Give the watcher findings and reproducible isolation steps for the owner. The queue asks for findings in the PR body and reserves editor and Docker settings changes for the owner.

**Check the behavior**

1. Start two different package typechecks in separate disposable checkouts. Hold a small first compiler at a known point. Confirm the old commands allow the second to enter early, then verify the Mac slot delays it until the first exits, even after the first reports a type error or its wrapper exits while its compiler is alive.
2. Verify compiler resolution, arguments and exit status. A workspace check catches typecheck scripts that bypass the wrapper. Run `pnpm exec vitest run scripts/typecheck.test.mjs scripts/root-scope-consumers.test.mjs scripts/pre-push.test.mjs`. The slot tests run only on macOS and are skipped by Linux CI. Record their Mac output in the PR. Run a real package from the hook’s filtered entry point and run one typecheck in a sandboxed review checkout. The normal push hook and current-head CI cover the full wired workspace.

Expect about 155 implementation lines, mostly manifest commands and their CI consumer list, about 110 test lines, this page and a short note in `docs/developers/ci-and-gates.md`.
