**Goal:** Move `tender_refunds` (money returned after the invoice) into `refunds`, re-point
`adjustment_refunds` (`tender_refund_id` → `refund_id`) and `drawer_opens.tender_refund_id` at
`refunds`, and make the tender refund's "open the drawer at most once" read `refunds.drawer_opened_at`
instead of drawer history.

**Architecture:** os12 built `refunds` whole, with the tender kind's CHECKs, indexes and trigger branch.
This PR moves the code through a committed rename script, adds kind filters by hand, and deletes
`tender_refunds`.

**Tech stack:** TypeScript, Drizzle ORM on `node:sqlite`, Vitest.

**Spec:** [tables-ordersales.md](../specs/2026-11-02-rationalisation/tables-ordersales.md) §1.11, §5,
§7 (fiscal: "`adjustment_refunds.tender_refund_id` (becomes `refund_id`)"; devices: "its key to
`tender_refunds` goes"); [tables-devices.md](../specs/2026-11-02-rationalisation/tables-devices.md) §3
("the same function claims it in one update … It claims only after a drawer printer is found");
`2026-11-08-a1308-pa5-adjustments.md:41, :78` (payments and adjustments leave `adjustment_refunds` to this
slice). Rules: [slice rules](2026-11-08-a1308-slice-rules.md).

**First line of the PR description:** "Every venue is reset: core; backups and exports from before

## What it builds

1. The tender kind's code on `refunds` (17 non-test files name `tenderRefunds` at HEAD:
   `git grep -l -w tenderRefunds -- apps packages ':!*.test.ts'`).
2. `adjustment_refunds.refund_id` (not null, key to `refunds`, restrict), replacing `tender_refund_id`;
   its unique index `adjustment_refunds_adjustment_refund_key` on `(adjustment_id, refund_id)` and the index
   renamed `adjustment_refunds_refund_idx` (`packages/db/src/schema/adjustments/refund-links.ts:16-32`).
   Readers: `packages/adjustments/src/refund-links.ts:15-63`, `packages/adjustments/src/reports.ts:376`.
   A CHECK cannot say the linked refund is the tender kind (a CHECK reads one row), so a trigger does:
   `adjustment_refunds_refund_after_invoice` (`BEFORE INSERT ON adjustment_refunds`) raises
   `ADJUSTMENT_REFUND_KIND_REFUSAL = "an adjustment refund names a refund after the invoice"` when the
   named refund's `sale_id` is null (a bill refund is never linked to an adjustment today; the writer,
   `refund-links.ts:15-21`, is called with tender refunds only).
3. `drawer_opens.tender_refund_id` keeps its name and points at `refunds(id)` (`packages/db/src/schema/drawer-opens.ts:48`);
   dv17 deletes the table later.
4. `enqueueTenderRefundDrawer` (`apps/server/src/receipt-print.ts:615-657`) replaces its read of an earlier
   `drawer_opens` row (`:636-640`) with the claim, after the printer is found: `update refunds set
   drawer_opened_at = ? where id = ? and drawer_opened_at is null`; no row changed means the drawer already
   opened, and it returns.
5. The bill path's drawer stamp, moved here from os12: `enqueueBillRefundDrawer(…, refundId: string)`
   (`receipt-print.ts:597`) passes it to `enqueueBillDrawer` (`:541-562`), which, after a printer is found,
   runs the set-once update and opens the drawer whatever it returned (no check on the bill path,
   tables-ordersales.md §1.11); its callers in `apps/server/src/bill-refunds.ts` pass the refund's id.
6. The tender kind's two `RefundRow` aliases (`apps/server/src/tender-refund-sends.ts:32`,
   `tender-refunds.ts:24`) become `TenderRefundRow` (os12 Task 1), narrowed with `requireTenderRefund`.
7. `tender_refunds` deleted.
