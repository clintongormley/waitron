# A1154 Node Registration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` for inline execution. Read `superpowers:test-driven-development` before editing implementation or tests. Track the checkboxes below; no implementation delegation.

**Goal:** Remove the obsolete operator registration path and the idea that a cash register owns fiscal identity, chain or invoice series; preserve setup, restore and promotion.

**Architecture:** Delete the standalone command and its seed runner, narrow existing operation accept-lists, rename fiscal fixtures and reuse the node's series across devices. Add one root guard with text scanning, TypeScript syntax-tree identifier checks and inspection of migrated fiscal tables.

**Tech stack:** TypeScript, Vitest, pnpm, Drizzle/SQLite, existing module-operation contracts.

**Spec:** Owner-approved A1154 scope, reproduced below so this published plan needs no campaign-file links. A1155 and A1156 are separate changes.
