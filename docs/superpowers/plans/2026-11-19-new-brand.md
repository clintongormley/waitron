# The new Waitron brand — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the blue `#1F6FEB` and the cloche logo with the new teal / sky-blue W logo and
colours on every screen Waitron draws.

**Architecture:** Waitron's default colours live in `packages/ui-core/src/tokens/colors.css`; new
values come from running the existing colour engine once (teal for light, sky blue for dark). The
logo's source drawings in `packages/ui/brand/` are replaced by the designer's, and the generator
derives the dark lockup, favicons and icons from them. The inline logo component paints only the
near-black pieces from the text colour; the two blues are literal and never repainted.

**Tech Stack:** CSS custom properties, Lit (`wt-waitron-lockup`), Node script + Inkscape
(`build-icons.mjs`), Vitest (node and browser projects).

**Spec:** `docs/superpowers/specs/2026-11-19-new-brand-design.md`. Read it before any task.

**Worktree:** `/Users/clintongormley/workspace/worktrees/waitron-new-brand-colours`, branch
`new-brand-colours`. Ledger: `docs/handoffs/2026-11-19-new-brand.md` in the worktree.

**Review weight:** light path (no risk trigger: no fiscal, data, auth or cross-package contract
change). No per-task reviewer; `/finish-branch` reviews the branch.

## Global Constraints

- Brand colours, exactly: near-black `#231f20`, teal `#007392`, sky blue `#71cfeb`. Lower-case hex
    in code. The designer's SVGs use other values for the blues (`#0c7291`, `#107391`, `#72cfed`,
    `#73cfed`); never copy those.
- Designer's files: `~/Downloads/wetransfer_waitrion-grey-svg_2026-11-18_1157/`. Use
    `Waitron Line.svg` (horizontal logo) and `Waitron IconCol.svg` (the W alone). Nothing else.
- Table-state colours (`table-seated`, `on-table-seated`, `table-calm`, `on-table-calm`,
    `table-calm-edge`, `tab-seated-tint`), calendar, palette and station colours do not change.
- Dark-mode text, backgrounds and surfaces do not change.
- The W's two blues are never painted from a token, in any file.
- Every commit `git commit -s`. Every task's verification includes
    `pnpm exec prettier --check <the files it changed>` (and `--file-info` for anything under
    `docs/`, which prettier ignores).
- Browser test packages (`ui`, `dashboard`, `setup`, `till`) run real Chromium: check
    `memory_pressure | grep free` first; run them only above 15% free.
- A test that used `#1f6feb` merely as an arbitrary input colour stays as it is. Only expected
    values that were Waitron's own defaults change.
- Old plans and specs under `docs/superpowers/` are not edited.

## Review Focus

1. A venue with its own brand colour **and** a hand-set text colour, on the dashboard: the logo's
    blues stay `#007392` / `#71cfeb`; its near-black pieces take the venue's text colour. (Task 4)
1. The Theme setting forced to dark on a device whose system is light (and the reverse): the logo's
    near-black pieces and the brand colour follow the forced theme, not the system. (Tasks 1, 4)
1. A browser tab in dark mode: the favicon's near-black stroke turns to the dark text colour; its
    blues do not change. (Task 3)
1. The till installed as a home-screen app: its `theme-color` and manifest colour are the teal.
    (Task 2)
1. A venue's public guest menu without a paper design: links and headings are teal in light mode,
    sky blue in dark. With a paper design: unchanged. (Task 6, visual check)
