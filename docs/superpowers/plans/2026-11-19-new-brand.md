# The new Waitron brand — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the blue `#1F6FEB` and the cloche logo with the new teal / sky-blue W logo and
colours on every screen Waitron draws.

**Architecture:** Waitron's default colours live in `packages/ui-core/src/tokens/colors.css`; the
new values come from running the existing colour engine once (teal for light, sky blue for dark).
The logo's source drawings in `packages/ui/brand/` are replaced by the designer's, and the generator
derives the dark lockup, favicons and icons from them. The inline logo component paints only the
near-black pieces from the text colour; the two blues are literal and never repainted.

**Tech Stack:** CSS custom properties, Lit (`wt-waitron-lockup`), a Node script plus Inkscape
(`build-icons.mjs`), Vitest (node and browser projects).

**Spec:** `docs/superpowers/specs/2026-11-19-new-brand-design.md`. Read it before any task.

**Branch:** `new-brand-colours`, holding the spec and this plan. It was created in the worktree
`/Users/clintongormley/workspace/worktrees/waitron-new-brand-colours`; build there, or remove that
worktree and make your own on the same branch. Keep a ledger at
`docs/handoffs/2026-11-19-new-brand.md` in the worktree (gitignored).

**Review weight:** light path (no risk trigger: no fiscal, data, auth or cross-package contract
change). No per-task reviewer; `/finish-branch` reviews the branch.

## Global Constraints

- Brand colours, exactly: near-black `#231f20`, teal `#007392`, sky blue `#71cfeb`. Lower-case hex
    in code. `Waitron IconCol.svg` uses other values for the blues (`#107391`, `#73cfed`); never
    copy those.
- Designer's files: `~/Downloads/wetransfer_waitrion-grey-svg_2026-11-18_1157/`. Use only
    `Waitron Line.svg` (horizontal logo, already in the guide's exact colours) and
    `Waitron IconCol.svg` (the W alone).
- Table-state colours (`table-seated`, `on-table-seated`, `table-calm`, `on-table-calm`,
    `table-calm-edge`, `tab-seated-tint`), calendar, palette and station colours do not change.
    Dark-mode text, backgrounds and surfaces do not change.
- The W's two blues are never painted from a token, in any file.
- Every commit `git commit -s`. Every task's verification includes
    `pnpm exec prettier --check <the files it changed>`; for a file under `docs/`, which prettier
    ignores, check `pnpm exec prettier --file-info <file>` says `"ignored": true` and keep its lines
    under 100 characters.
- Browser test packages (`ui-core`, `ui`, `dashboard`, `setup`, `till`) run real Chromium: check
    `memory_pressure | grep free` first and run them only above 15% free.
- A test whose purpose depended on the old colours is not "fixed" by changing its expected value if
    that would make its name false: give it a new input that still shows its behaviour, or retire it
    and say why in the commit. Only expected values that were simply Waitron's own defaults are
    updated in place. A test using `#1f6feb` as an arbitrary input colour stays.
- Old plans and specs under `docs/superpowers/` are not edited.

## Review Focus

1. A venue with its own brand colour **and** a hand-set text colour, on the dashboard: the logo's
    blues stay `#007392` / `#71cfeb`; its near-black pieces take the venue's text colour. (Task 4)
1. The Theme setting forced to dark on a device whose system is light (and the reverse): the logo's
    near-black pieces and the brand colour follow the forced theme, not the system. (Task 4)
1. A browser tab in dark mode: the favicon's near-black stroke turns to the dark text colour; its
    blues do not change. (Task 3)
1. The till installed as a home-screen app: its `theme-color` and manifest colour are the teal.
    (Task 2, `scripts/till-theme-color.test.ts`)
1. The logo at phone width (400 px) in the dashboard banner and the till's Powered by line: it fits
    and stays readable at its new shape. (Task 4 sizing, Task 6 screenshots)
