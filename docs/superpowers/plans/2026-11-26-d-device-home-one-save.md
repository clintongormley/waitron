# Device home page Save implementation plan

[Device home page design, piece 3](../specs/2026-11-24-device-home-page-design.md#delivery)

A manager can add, remove and reorder shortcuts and choose what appears first on the Device home page tab. The page shows each edit immediately, and one Save replaces the working home page. Publishing still makes saved changes available to devices.

## Save the whole page

- Add `saveMenuHome(tx, menuId, input)` in `packages/menu/src/menu-home.ts` and `PUT /management-api/menus/:id/home` in `apps/server/src/menu-home-routes.ts`. Use the existing menu management gate and its transaction. Send `{ order, shortcuts: [{ memberId, ref, name }] }` in display order and return the saved `MenuHome`. Share `MenuHomeSaveInput` beside `MenuHome` and add `saveMenuHome` in `apps/dashboard/src/api/menu-api.ts`. Check the full input at the route and use the existing home section and member rules. Keep retained ids and server-stored missing names. If a chosen product or section was deleted before Save, use its held name for a missing tile. Keep already-unreachable tiles and check that new live references are admissible to this menu. Refuse duplicate ids or live targets and ids belonging to another list. Scope the replacement to this menu's home section. Use existing storage and batched writes.
- Begin with failing `packages/menu/src/menu-home.test.ts` cases for replacement, a target deleted after selection, and a refused list leaving the old list and order intact. Add one mounted route case in `apps/server/src/menu-api.test.ts` for the request, its gate and its saved response. Update the dashboard client route assertion. Existing single-change server requests stay available; the dashboard switches to the combined request.

## Edit one page

- In `apps/dashboard/src/screens/menus-screen.ts`, replace the Home tab's immediate writes with a small draft beside `widgets/menu-structure-save.ts`. Reuse `MenuReadController`, `draftScopeFor`, `saveActionState` and Structure's fixed `wt-form-actions` placement. Compare Shown first and shortcut ids in order. Keep a dirty draft over live refreshes and restore the latest saved page on confirmed Cancel or Discard. Use the existing menu-screen navigation wait for an already-sent Save, including the shell call in `dashboard-app.ts`. A refusal leaves edits in place with a message by Save. On success commit the returned state, then refresh the working preview and publish status. Keep read failures separate from Save refusals.
- Rename the tab in `apps/dashboard/src/i18n/strings.ts` to Device home page and use a short Spanish label that fits at 390 px. Keep the single 792px-wide page and the existing responsive Shown first control. In `widgets/device-home-preview.ts`, replace the two add tiles with one Add shortcuts tile. Reuse `widgets/home-shortcut-picker.ts` and its multi-select combobox with a single list of reached active products and reached sections, excluding held targets and keeping selection order. Keep grip and bin focus, keys, drag, missing and not-shown treatments. Remove the old per-shortcut dashboard request handling. The till renderer, guest menu, Structure, Preview and Price overrides keep their own workflows.
- Start with a failing `menus-screen.home-shortcuts.unsaved.test.ts` case for one ordered request after mixed edits, including Shown first, and no write before Save. Check Cancel, leaving, refused Save and keeping a dirty draft through a live read there or in `menus-screen.home-tab.test.ts`. Preserve grid, keyboard, drag and missing-tile checks in `device-home-preview.test.ts`; exercise the mixed picker in its existing browser and axe suites. Replace assertions about immediate writes with checks of their staged effects. Run changed suites under the normal package entry points.

Update the English and Spanish Products guides, the till guide where its menu wording needs updating, the Device Home Page paragraphs in `docs/developers/design-system.md` and the open item in `docs/backlog/menu.md`. Show the watcher before and after screenshots of the tab and real counter till and handheld at 1440, 1280 and 390 px in both languages and themes, with and without shortcuts. The owner sees these before landing. Expect about 430 added production lines and 260 added test lines, with the old write and picker paths removed.
