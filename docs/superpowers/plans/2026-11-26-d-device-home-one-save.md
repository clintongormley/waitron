# Device home page Save implementation plan

[Device home page design, piece 3](../specs/2026-11-24-device-home-page-design.md#delivery)

A manager can add, remove and reorder shortcuts and choose what appears first on the Device home page tab. One Save replaces the working home page. Publishing makes saved changes available to devices.

## Save the whole page

- In `packages/shared/src/menu-document/section-types.ts`, define `MenuHomeSaveInput` as `{ order, shortcuts: [{ memberId, ref, sectionPath? }] }` in display order. `ref` uses `TileRef`, including a remembered missing tile. The dashboard gives new tiles a UUID and holds a section's visible path from the existing picker tree. In `packages/menu/src/menu-home.ts`, add `saveMenuHome(tx, menuId, input)`. Use the server's current reference for ids it still holds, including missing names. Reinsert draft ids removed by another Save. For a newly chosen target deleted before Save, use the product's stored name or the section's held path for a missing tile, subject to watcher confirmation of the spec's **my call**. Check reach for new live references, reject duplicate ids or targets and ids belonging to another list, then replace this home section's members in batches and change the order in the same transaction.
- In `apps/server/src/menu-home-routes.ts`, add `PUT /management-api/menus/:id/home` with the existing management gate and revision. Reuse Structure's request checks for objects, lists and ids, and return the saved `MenuHome`. Retire the five single-change routes and their dashboard client methods in `apps/dashboard/src/api/menu-api.ts`. Update `docs/developers/product-categories.md`.
- Start with failing `packages/menu/src/menu-home.test.ts` cases for replacing shortcuts and order together, preserving a kept missing tile, and a target deleted after selection. Prove refusals leave the saved page intact for duplicate ids or targets, an id held by another list, an unreachable new live target and a deleted menu. Move the mounted request, revision, permission and menu-kind assertions to the new wire call in `apps/server/src/menu-api*.test.ts` and `apps/dashboard/src/api/client-routes.test.ts`.

## Edit one page

- In `apps/dashboard/src/screens/menus-screen.ts`, replace immediate writes with a small draft beside `widgets/menu-structure-save.ts`. Reuse `MenuReadController`, `draftScopeFor`, `saveActionState` and Structure's fixed `wt-form-actions` placement. Keep draft ids in order and the Shown first choice while resolving display facts from live reads. Refresh names and reach as targets change. Confirm Cancel or leaving and restore the latest saved page on Discard. Widen the menu screen's pending Save getter and its `dashboard-app.ts` call to cover Home as well. A refusal leaves the draft and a message by Save. Commit the returned state, then refresh preview and publish status. Keep load failures separate from Save refusals.
- Keep the single 792px-wide view and responsive Shown first control. In `widgets/device-home-preview.ts` and `widgets/home-shortcut-picker.ts`, use one Add shortcuts tile and the existing searchable combobox with typed option values for reached active products and sections. Distinguish sections by name and keep selection order, keyboard, drag, focus, missing and not-shown treatments. Replace per-request picker feedback with the existing local draft and close behavior. Use consistent Device home page wording in `apps/dashboard/src/i18n/strings.ts`, with a short Spanish tab label checked at 390 px.
- Start with a failing `menus-screen.home-shortcuts.unsaved.test.ts` case for no early write and one ordered request after mixed edits and Shown first. Check Cancel, navigation during Save, refused Save and a live read while dirty in the Home browser suites. Preserve tile and picker behavior in their existing browser and axe tests, and replace partial-write assertions with staged effects. Run each changed test file.

Update the English and Spanish Products guides, the till guide where its menu wording changes, the Device Home Page paragraphs in `docs/developers/design-system.md` and the open item in `docs/backlog/menu.md`. Show the watcher before and after screenshots of the tab and real counter till and handheld at 1440, 1280 and 390 px in both languages and themes, with and without shortcuts. The owner sees them before landing. Expect about 450 added production lines and 280 added test lines, with the old write paths removed.
