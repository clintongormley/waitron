# Device home page Save implementation plan

[Device home page design, piece 3](../specs/2026-11-24-device-home-page-design.md#delivery)

A manager can add, remove and reorder shortcuts and choose what appears first on the Device home page tab. One Save replaces the working home page. Publishing makes saved changes available to devices.

## Save the whole page

- In `packages/shared/src/menu-document/section-types.ts`, define `MenuHomeSaveInput` as `{ order, shortcuts: [{ memberId, ref }] }` in display order. The dashboard gives new tiles a UUID and uses a missing reference for a previously saved missing tile. In `packages/menu/src/menu-home.ts`, add `saveMenuHome(tx, menuId, input)`. Use current references for held ids, including stored missing names. Restore live draft references whose ids another Save removed. Refuse a missing tile whose id another Save removed, with the shortcut named in the refusal. Drop newly picked targets deleted before Save and report their member ids so the dashboard can name them. Check reach for new live targets and refuse duplicate ids, duplicate live targets and ids from other lists. Replace this home section's members in batches and update the order in the same transaction.
- In `apps/server/src/menu-home-routes.ts`, add `PUT /management-api/menus/:id/home` with the existing management gate and revision. Move Structure's object, rows, bodyId and refOf checks into `menu-request-fields.ts`. Return the saved `MenuHome` and dropped ids. Retire the five single-change routes and their dashboard client methods in `apps/dashboard/src/api/menu-api.ts` when the dashboard switches. Update `docs/developers/product-categories.md`.
- Start with failing `packages/menu/src/menu-home.test.ts` cases for replacing shortcuts and order together, retaining stored missing tiles, dropping newly chosen targets deleted before Save, and refusals leaving the page intact. Shared request-field tests own malformed values, with one bad body on the Home route. Mounted Home tests check permission, revision, menu kind and the response. Check the request in `apps/dashboard/src/api/client-routes.test.ts`.
