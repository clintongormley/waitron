# A582 slice 5 — help mode on kitchen screens and monitors: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every implementer is dispatched as `subagent_type: "implementer"`.

**Goal:** on a kitchen screen (a station board, a pass screen or a pass monitor) a cook can turn help
on from a "?" in the top-right corner, see badges that explain the board's cards, colours, times and
buttons, and find help off again two minutes after the screen was last touched.

**Architecture:** the switch (`wt-help-switch`) joins the theme and language corner `till-shell`
draws when it has no bar. A small till controller, `HelpIdleController`, turns help off after two
minutes without a `pointerdown` or `keydown` inside the shell, only where that corner is drawn. The
badges are `helpBadge(…)` (slice 4) inside `till-station-queue`, `till-station-screen` and
`till-expo-screen`, so they show on a till's Kitchen and Pass screens too. On these boards a badge
sits inside its part's trailing edge instead of hanging past it (decision 5).

**Tech stack:** TypeScript, Lit 3, Vitest 4 in browser mode (real headless Chromium) for
`apps/till`; plain Vitest for `apps/server`'s guide suite and the root guards under `scripts/`.

**Spec:** `docs/superpowers/specs/2026-10-18-a582-help-mode-design.md`, §8 slice 5, drawing on §3.4
(picture `docs/backlog/mockups/a582-help-mode/05-kitchen-corner.png`), §4, §5 and §6. Slice 4's plan
(`2026-10-20-a582-4-till-help.md`) is the template; this plan reuses its `help-strings.ts`,
`helpBadge`, `help-guide.ts` and guide sheet unchanged in shape.

**Base:** `main` at `82ce81299`. Every file reference is to that commit. **(read)** marks a
conclusion from reading code. Nothing was run while writing this plan; every statement about today's

## Decisions

1. **The switch goes first in the corner, before the theme and language choosers**, as picture 05
   draws it: `<div class="language-corner">${this.#helpSwitch()}${themeChooser()}${this.#chooser()}</div>`.
   It is drawn wherever the corner is, so on a kitchen screen and in kiosk mode; never in a bar's
   place on a till or handheld (slice 4 put it in their bar). The corner keeps its condition
   (`loadLocales` set), which `till-app` always meets.

2. **What counts as a touch: `pointerdown` or `keydown`, anywhere inside `till-shell`**, listened
   for on the shell's host in the capture phase, so a component that stops an event cannot hide a
   touch. These are the two events the till's idle sign-out already counts
   (`till-app.ts:2278-2280`). Both are composed, so they reach the shell's host from inside the
   slotted boards' shadow roots, an open help box and the corner. A touch inside an open guide page
   counts too: `till-guide-sheet` relays a same-origin page's `pointerdown` and `keydown` as its own
   composed events (`apps/till/src/widgets/guide-sheet.ts:62-79`). Not counted: a pointer moving
   without a press, and a mouse wheel; a finger scroll starts with a `pointerdown`.

3. **The two minutes are a `setTimeout` in a till controller, `apps/till/src/state/help-idle.ts`,
   not in `packages/ui`.** It is a kitchen-screen policy, used by one element; `packages/ui`'s
   help-mode state stays as it is (so no mutation-tested package changes). The clock runs only while
   help is on and the corner is drawn: help turned on starts it, a touch restarts it, help turned
   off stops it, and the shell leaving the page stops it. The shell is rebuilt on a language change
   (`keyed(currentLocale(), …)`, `till-app.ts:19662`); the new shell starts a fresh two
   minutes, and the language change was itself a touch. On a till or a handheld nothing changes:
   help goes off on lock or a change of person (slice 4), never after an idle time.

4. **Two minutes without a touch also close an open guide page.** A kitchen screen is never locked,
   and a guide sheet left open covers the whole board (`wt-modal size="full"`,
   `guide-sheet.ts:90-94`). So the shell's idle callback clears `guideHref` as well as help. The
   design does not say this; it follows from its reason ("a kitchen screen is often left alone and
   nobody would think to turn it off", §3.4).

5. **On the kitchen boards a badge sits inside its part's trailing edge.** At phone width both
   boards drop their side padding (`.screen { padding-inline: 0 }`, `till-station-screen.ts:130-134`,
   `till-expo-screen.ts:110-114`), pinned by `apps/till/src/screens/device-screens.phone-margin.test.ts`
   ("content starts 8px from the edge of a 411px phone"). A badge hung 16 px past a full-width card
   or a right-aligned Columns button would then make the shell's `.body` scroll sideways. A handheld
   opens the pass at phone width, so this case is real. The fix keeps the layout untouched: a shared
   `kitchenHelpStyles` (in `apps/till/src/widgets/help-badge.ts`) sets
   `.help-anchor { position: relative }` and `.help-anchor > wt-help-tooltip { margin-inline-end: 0 }`.
   The badge still hangs half above its part's top edge. That an outer rule beats the badge's own
   `:host([mode="help-mode"][data-help-on]) { margin-inline-end: … }`
   (`packages/ui/src/components/wt-help-tooltip.ts:48-56`) is (read: CSS Cascade's rule that, for
   normal declarations, the outer tree context wins); Task 3's 390 px test is the measurement.

6. **One card badge and one lever badge per board, on the first one drawn.** A badge on every card
   would put dozens of identical "?" and Tab stops on a busy board. A render-time flag gives the
   first card drawn (and, on the pass, the first Course ready or Group ready drawn) the badge. In the
   stacked view of a screen with several stations each board has its own. A box open on the first
   card stays open across a refresh that keeps that card first (Lit reuses the element; Task 3 tests
   it); one whose card leaves the first place closes with it.

7. **Which parts get a badge (six texts), and which do not.** Station board: the first card, Columns,
   the "Changes to orders" heading; station screen: Merged / Stacked (a kitchen screen with more than
   one station only, `till-station-screen.ts:978`). Pass and monitor: the first order card; pass only:
   the first Course ready or Group ready. Not marked, because their label or their own window
   already says it: the station's Open / Close for today (its window explains the choice), Move
   station on a dish, the out-of-date banner, Printing problem, Got it on each notice (the notices
   badge covers it), the Columns window, and the "N overdue" count. The corner's own buttons carry
   none.

8. **The texts describe both colour schemes as they are, and the mismatch goes to the backlog.** A
   late card is amber on the station board (`--wt-color-warning`, `station-queue.ts:548-550`) and
   blue on the pass (`--wt-color-primary`, `till-expo-screen.ts:191-193`), whose comment calls it
   "amber-ish primary" (`:188`). `--wt-color-primary` is `#1f6feb` light and `#4c8dff` dark
   (`packages/ui-core/src/tokens/colors.css:14`, `:150`). This slice does not change either colour;
   Task 4 corrects the comment, and Task 6 adds a backlog entry asking whether the pass should use
   amber.

9. **Guide links.** Three new `GUIDE_LINKS` in `apps/till/src/help-guide.ts`, all in the kitchen
   guide, whose sections exist in English and Spanish (`apps/server/src/guide/es/kitchen-service.md`
   headings, read): `kitchen-service.kitchen-screen` (the card and Columns badges),
   `kitchen-service.corrections` (notices), `kitchen-service.service-lifetime` (the pass card). The
   root guard `scripts/guide-links.test.ts` already checks every till link against the served pages
   (`:8`, `:36-37`).

## Task 1: the two-minute clock

**Files:**
- Create: `apps/till/src/state/help-idle.ts`, `apps/till/src/state/help-idle.test.ts`

**Interfaces:**
- Produces: `export const KITCHEN_HELP_IDLE_MS = 120_000;` and
  `export class HelpIdleController implements ReactiveController`, constructed as
  `new HelpIdleController(host, { applies: () => boolean, onIdle?: () => void, idleMs?: number })`
  with `host: ReactiveControllerHost & HTMLElement`. It adds `pointerdown` and `keydown` listeners on
  the host with `{ capture: true }` in `hostConnected` and removes them in `hostDisconnected`. It
  subscribes to help mode (`subscribeHelpMode`). Whenever help is on and `applies()` is true, a timer
  of `idleMs` runs; a touch restarts it; on expiry it calls `setHelpMode(false)` and then `onIdle?.()`.
  `hostUpdated` re-checks `applies()`.

- [ ] **Step 1: Write the failing tests** with a minimal Lit host defined in the test file (a
  `till-test-idle-host` holding one button in its shadow root). `afterEach`: `setHelpMode(false)`,
  `vi.useRealTimers()`, remove the host.
  - `"help goes off two minutes after it was turned on, with no touch"` — at 119 999 ms still on, at
    120 000 ms off, `onIdle` called once.
  - `"a pointerdown inside the host starts the two minutes again"` — at 100 s dispatch a composed
    `pointerdown` from the shadow button: on at 219 999 ms, off at 220 000 ms.
  - `"a keydown inside the host starts the two minutes again"`.
  - `"a touch a child stops from bubbling still counts"` — the button's own listener calls
    `stopPropagation()`.
  - `"a touch outside the host does not count"` — `pointerdown` on `document.body` at 100 s: off at
    120 000 ms.
  - `"where it does not apply, help stays on"` — `applies: () => false`, advance 10 minutes.
  - `"turning help off by hand stops the clock, and on again starts a fresh two minutes"`.
  - `"once the host leaves the page its clock and listeners stop"` — remove it at 60 s, advance 10
    minutes: still on.
  - `"back in the page with help on, it starts a fresh two minutes"`.
  - `"when it starts to apply while help is on, the two minutes start"` — flip the predicate, call
    `host.requestUpdate()`, await `updateComplete`.
- [ ] **Step 2: Run and see them fail:** `pnpm --filter @waitron/till exec vitest run src/state/help-idle.test.ts` — module not found.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run again; all pass.** Typecheck, `pnpm format:check`.
- [ ] **Step 5: Deletion proof:** drop `{ capture: true }` → the "stops from bubbling" case fails;
