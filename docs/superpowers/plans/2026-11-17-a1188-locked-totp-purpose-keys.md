## Proposed joint input and lifetime

Supply `WAITRON_LOCKED_TOTP_KEYS` as JSON with exactly `current:{version,key}` and `previous:{version,key}|null`. Each entry has exactly those fields: `version` is a positive safe integer; `key` is canonical base64 decoding to 32 bytes and re-encoding identically. Versions must differ. Set `current.version = sourceRing.current.version` and `current.key = purposeKey(sourceRing.current,"totp").toString("base64")`. If `sourceRing.previous` exists, use its own version and the same derivation for `previous`; otherwise send `previous:null`. Preserve these **original numeric versions**, matching the stored `v2.<version>...` text; never renumber to 1/2. `sourceRing` comes from the selected copy's own backup secrets through `loadKeyRing(resolveBackupKeyInputs({secretsEnv,tradingEnv,backupEnv}))`, as identity backup verification does: later `trading.env`/`backup.env` values override `secrets.env`, and an absent current version defaults to 1. Never use placement's fresh copy ring or a later, unrelated backup. Cloud must match these reader semantics; its implementation remains Cloud's. The child receives no source vault ring. Retire/ignore `WAITRON_ACCOUNT_KEY`, with no fallback or reinterpretation of raw vault bytes as derived keys. The top-level immutable copy binding and fixed `expiresAt` are unchanged.

Cloud's launcher uses the existing `purposeKey` producer and delivers only this purpose payload in the child environment. Add no key file, database write, command-line argument, log or receipt containing it. After spawn returns or fails, drop the launcher's transient decoded-ring and derived-payload references, including the temporary environment object. The backup service's pre-existing held backup key and archives are outside this new handoff retention claim. At entry, before taking the venue lock or calling placement, the child parses and validates the payload and removes it from `process.env` on success or failure. It keeps decoded purpose keys only in memory until process exit on startup failure, locked stop or fixed expiry, whichever comes first. This promises neither physical RAM erasure nor absence of observability. Part 4 later defines the switch to activated runtime; it cannot extend the locked stop here. Add no cleanup record, acknowledgement protocol or disk persistence.

Before build, pin Cloud's amended input agreement and shared synthetic vectors: current/previous original versions (for example 7/3), no previous key, malformed/missing payload, row-version/purpose mismatch, and an absent current version variable yielding version 1. The [shared synthetic examples](2026-11-17-a1188-locked-totp-examples.md) exercise the existing producer/crypto functions; new reader/parser cases remain prospective. Existing binding/isolation/expiry vectors remain. Cloud's producer and retention changes belong to Cloud; this lane implements none of them.
