table-service writers; grouped pricing at issuance; kitchen tickets, receipts and the till's
table screens grouping identical portions; EN/ES guides; LOOK; backlog.

Out: bill names and numbers (slice 2), switcher and menus (slice 3), the picker, count selection by
id and waiting-course copies (slice 4), station ticket settings and cross-bill batching (A773-2
tail), pre-bills (slice 6), counter-order expansion (finding 1), removal of the partial-quantity
server paths (D11).

written before the release still pay. No backfill: sales filed before the release have no portion
links. The PR says both.

**Spanish.** No new till strings are planned. The guides' Spanish text is a proposal shipped only
with owner approval at land (D22). A task that finds it needs a new Spanish string stops and
records a proposal instead.

## Decisions

- **D1** Table-service writers only (finding 1).
- **D2** A portion is allocated when a working line is written, never at draft save; draft lines
  keep a quantity (`orderDraftLines.quantity`, `apps/server/src/order-drafts.ts:1753`). A lost-send
  replay writes no line, so it allocates nothing.
- **D3** Expansion splits the priced rows before they are inserted (a pure `expandPortionRows`),
  then `registerPortions` writes the registry and bindings in the same transaction. This departs
  from the master plan's proposed `expandPortions(tx, orderId, lines, soldByUnitLineIds)`, which
  splits inserted lines: before the insert no ticket item, context or allergy tick exists yet, and
  the existing in-database unit split refuses a dish with extras (`working-order.ts:4484-4485`).
- **D4** The first portion keeps the priced row's id, so `priceOrderLines`' identities
  (`working-order.ts:1044-1049`) stay real line ids for `issuancePass`
  (`apps/server/src/issuance-pass.ts:30-35`, contexts by line id).
- **D5** Only dish lines are bound. An extra belongs to its dish's portion through
  `parent_line_id`; bindings are unique by line and by portion.
- **D6** A pricing cohort is the set of portions expanded from one priced request line. A rise that
  today raises the stored row in place (`applyLineEdits` action `"free"`,
  `working-order.ts:5976-5987`; `saveRecalledLine`, `apps/server/src/draft-recall.ts:129-149`) adds
  portions to the same cohort, copying the stored row, so the filed row equals today's raised row.
  A rise that today inserts a separately priced row (`"raise"`, `"change"`, adjusted lines,
  `working-order.ts:5720-5722, 5750-5771`) starts a new cohort.
- **D7** Readers group bound dish lines by cohort plus their whole filed composition (every
  `LockedLine` field, product id, classification, list price) and identical extras; unbound lines
  stay one row each. A group sits at its first member's position; its identity id is that member's
  line id and it carries every member's line id and portion id.
- **D8** The comparison is on the multiset of filed rows (composition, quantity, gross, base, VAT
  rate, list gross), parent–extra pairing, total and VAT breakdown. Row order is not compared:
  today's order after a split is an artifact of the split row taking `max(line_no) + 1`
  (`working-order.ts:4531-4540`).
- **D9** Moving portions out and back regroups them into their cohort's original row. Today a
  carved-off part stays a separate row. Recorded for the owner.
- **D10** Each filed dish and extra row is linked to every portion it represents, inside the
  issuance transaction straight after `recordSale`, by `(sale_id, line_no = position + 1)`.
  `saleLineRows` copies each line's `lineNo` (`packages/core/src/sale-line-rows.ts:18-22`) and
  `grossRows` numbers lines `i + 1` (`pricing.ts:145-146`); Task 4 tests that `recordSale` keeps
  that order (assumption until then).
- **D11** No new remainder-cent allocator. A dish's gross is `unit × quantity` with no price
  quantity (`pricing.ts:162-164`; `grossBasketWithOptions` sets none on a dish, `:301-317`), and an
  extra's quantity is a whole multiple of its price quantity (`modifier-selection.ts:155-156`), so
  a portion's gross is exact in cents. Task 2 checks it; a mismatch is a stop.
- **D12** The partial-quantity server paths stay (partial transfer and split in `carveLines`,
  `splitUnitsWithinOrder`, partial serve, cancel, adjustment and item payment). They still serve
  measured lines and grouped lines. Their tests keep their assertions; where the test's writer now
  expands, the test builds the grouped shape with `priceTabRound` + `insertTabRound` and no
  expansion, as `apps/server/src/testing/kitchen-table-order.ts:23-24` already does.
- **D13** Refusing a partial cut of a measured line (spec §3.1, "never cut") waits for slice 4's
  picker.
- **D14** The till groups identical portions in identical state into one row (`state/portion-groups.ts`).
  An action whose request takes a list sends the member ids for a count: serve (`items[]`),
  Transfer items and Split bill (`transfers[]`). Cancel and the adjustment dialog take one line,
  so they act on one portion — the group's first member by line number — and the "all n" choice
  goes for grouped rows until slice 4.
- **D15** The Pay items list (`apps/till/src/state/bill-payment.ts:345-362`,
  `widgets/bill-pay-dialog.ts:1579-1648`) shows one row per portion unless A739 Cut B has released
  those files at Task 0; then Task 8 groups it with a units stepper that sends member line numbers.
- **D16** Kitchen screens, the pass, MOVED slips (`apps/server/src/kitchen-print.ts:1586-1623`
  lays out each line alone on purpose) and the dashboard's order detail
  (`apps/server/src/orders-list.ts:744`) show one row per portion. They belong to the A773-2 tail
  or later; Task 16 records residuals.
- **D17** Receipts and the till's sale view group filed rows that print identically and share
  unit price, VAT rate and list price and carry no adjustment entry, summing filed amounts. The
  full invoice's line table is unchanged.
- **D18** The till's `soldByTheUnit` (`apps/till/src/widgets/product-name.ts:85-88`) stays for the
  weighing view, steppers, price wording and late-send. The split consumers switch to the existing
  `takesExtras` (`apps/till/src/state/order-line.ts:69-71`, adds `measure !== true`), so a 200 ml
  line is never offered "split into 200".
- **D19** A `moved` event is recorded for each bound dish line whose order changes in
  `moveOrderLines` (`working-order.ts:3877-3886`); a `cancelled` event when a bound dish line is
  deleted with its charge (`removeFromLine`, `working-order.ts:3084-3093`; `applyLineEdits`
  removal, `:6213-6225`). A keep-charge cancellation records no event.
- **D20** A draft line's allergy tick moves to the first portion (`moveAllergyDraftTicks`,
  `packages/venue-service/src/party-allergy.ts:250-272`) and is copied to the others with
  `setAllergyLineTicks`, as a split already does (`apps/server/src/draft-source.ts:89-94`).
- **D21** The four tables go in the core migration set: `working_order_lines` and `sale_lines` are
  core and both counter and table service share permanent order identity
  (`docs/developers/conventions-data.md:365-372` requires the commit to say so).
- **D22** Guide Spanish ships only with owner approval, given at the slice's land sign-off.
- **D23** The split help "Dishes with options must be moved in full" (`table.split_options_together`,
  `apps/till/src/i18n/strings.ts:1260`, shown at `till-table-order-screen.ts:5269`) goes once
  table lines are portions; `table.split_modifier_error` (`:1261`) stays, because `carveLines`
  still refuses a directly named extra (`working-order.ts:4443-4444`).
- **D24** `scripts/schema-constraints.test.ts`'s lists are not edited (a constraint nobody listed
  "passes unseen", `:14-15`); the new constraints are proven by offending writes in Task 1.
