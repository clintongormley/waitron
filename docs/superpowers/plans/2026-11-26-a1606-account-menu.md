# A1606 PR 3 dashboard banner and account menu

Staff can see who is signed in, recognise the banner controls, and choose from the available
languages on a phone. This implements decisions 7–10 of the [approved design](../specs/2026-11-26-dashboard-sidebar-and-account-menu-design.md#7-the-banners-buttons).
The existing session, permissions, routes, profile editor, report and alert actions supply the
behaviour. Role labels and account management changes are outside this slice.

1. **Identity.** Extend the two exact response checks in `apps/server/src/me-api.test.ts` to expect
   the session person's `displayName`, with two different people. Add it to the existing no-store
   response in `me-api.ts` from `resolveManagementSession` and type it in
   `apps/dashboard/src/api/account-api.ts`. In `dashboard-app.ts`, take the display name and email
   from the existing generation-checked session read, including the profile-updated recheck, and
   clear the pair with the session. Use the related data together when rendering. In
   `dashboard-app.theme.test.ts`, check a multi-word display name, matching initials and accessible
   name, and the fallback person glyph when the name is absent. Keep the name and email in the menu
   only while signed in. Render the menu in a small `account-menu.ts` template and style module to
   keep the shell under its 4,000-line cap. Keep `wt-row-actions`, its trigger slot and the existing
   Profile, About and Log out handlers. Put the 28 px initials circle in the 44 px trigger. Inside,
   show name, muted ellipsized email, then Account settings, Theme, Language, About Waitron and Log
   out with separators after identity, Account settings and Language. Localize the named trigger
   in dashboard `i18n/strings.ts`.
2. **Banner.** Use Material Symbols Outlined weight 400 on the existing `wt-icon` grid. Put
   `notifications`, `feedback` and `person` in dashboard `icons.ts` and register `help` in the shared
   `packages/ui/src/components/wt-help-switch.ts` so the till gets the same glyph. In
   `widgets/alerts-bell.ts`, `problem-report.ts` and the help switch use 18 px glyphs on 44 px
   controls. Move the bell's existing badge to the corner clear of the glyph. Make report icon-only
   with its existing accessible name and tooltip in both dashboard states. Paint the help button
   with `--wt-color-surface-lifted` when pressed and retain its forced-colour cue. Use the existing
   bell, report, help-switch and dashboard phone-fit checks to pin size, badge clearance, name and
   pressed state. Keep report availability and existing help behaviour.
3. **Choices.** In `packages/ui/src/theme-choices.ts`, put the Theme label above three equal buttons
   with icon and text. Add short Device / Dispositivo labels in dashboard and till `i18n/strings.ts`
   and pass them from the dashboard and till `widgets/theme-chooser.ts`. Keep the existing long
   accessible labels and pressed state. Use a lifted fill and primary outline for the active choice.
   In `wt-language-chooser.ts`, add a trailing down arrow to the menu trigger wherever used and
   keep endonyms left-aligned. Keep the till's existing inline `group` layout. Use the chooser's
   existing dropdown in the dashboard account menu, with a visible Language row label and the full
   active language name at phone width. Mark the chooser `data-keep-open`, keep its existing passive
   locale loader, and close the outer menu and return focus to the account trigger on
   `wt-locale-selected` before the shell's existing locale write. Escape closes the child first.
   Constrain the dropdown to viewport space and let a long list scroll through the existing
   `MenuPopover` placement, with the outer menu dismissing both when closed. In
   `dashboard-app.help.test.ts`, drive the real triggers through a many-language phone case, check
   Escape and selection, one passive fetch and both menus' visibility. Use `theme-choices.test.ts`
   and `wt-language-chooser.test.ts` for shared appearance and placement, retaining keyboard checks.
4. **Verification.** Run the new or updated assertions red before each production change, then green
   through the `@waitron/server`, `@waitron/dashboard` and `@waitron/ui` focused Vitest files above,
   the dashboard theme/help and problem-report suites and affected till/setup consumer checks.
   Update the banner and shared control descriptions in `docs/developers/design-system.md`,
   `conventions-ui.md`, the English and Spanish Box status guides, and close A1606 in
   `docs/backlog/dashboard.md`. Capture dashboard pictures at 1440 and 390 px and the 1024 px folded
   strip, EN and ES, light and dark, including a many-language menu. Look at the changed till and
   setup controls in both themes and at phone width. Send the pictures to the watcher for the owner
   before landing.

Estimate 260 production additions and 110 removals, 145 test additions and 45 removals, plus docs.
