## Decisions

1. **No migration or venue reset.** Both declarations (`packages/db/src/schema/page-printers.ts:20`, `:30`) and shipped SQL (`packages/db/drizzle/0116_invoice_delivery_foundation.sql:44`, `:63`) already store and distinguish paths. The existing database test even inserts different paths on one host (`apps/server/src/page-printers.test.ts:345`). This is read-only evidence for the design decision, not a measured upgrade. Preserve the schema/migrations; demonstrate saved-single-queue use in Task 1 instead of regenerating H13 without a schema change.
2. **Queue identity:** case-insensitive host text + IPP port + exact, case-sensitive resourcePath. Do not equate IP addresses with DNS aliases, decode paths, lowercase paths or strip their trailing slash. Use `ipp` when announced, otherwise the device's own `office` endpoint; never a lent report to invent identity. Encode tuples without delimiter collisions. Scope `ippOnly` observations by agent/transport/queue. Raw representation identity remains agent/transport/raw-host/raw-port even when two raw ports share one queue. Saved endpoints remain location-scoped. Add separator-containing, path-case and trailing-slash controls for tuple encoding.
3. **Folding:** count distinct IPP endpoints per host after duplicate announcements are removed. Exactly one endpoint keeps the current raw+IPP fold, including raw labels/ports. With multiple endpoints keep each queue as its own `ippOnly` representation and retain raw host/ports separately, attaching no arbitrary queue to raw. Here `ippOnly` means this discovery row has no established raw counterpart, even if the host also exposes raw ports; update its explanatory comments in `packages/print-agent/src/host.ts:95`, `apps/server/src/print-api.ts:258`, `apps/dashboard/src/api/client.ts:1226`.
4. **Capabilities:** lend only between fresh observations of the same known queue. Keep `officeLent` and the named-agent-own-report registration rule. An unknown raw address may inherit the existing address-level office safety mark, but never a guessed queue's printable report. Another queue's mark/refusal must not change this queue's format, media, resolution or action. Preserve latest-report semantics; within one pull, equivalent queue observations retain printable-over-refusal precedence (`page-printers-api.test.ts:348`), rather than accidentally losing it when keys consolidate.
5. **Labels:** add optional `serverName?: string` discovery display metadata from the actual SRV target, removing a trailing dot and the terminal `.local` suffix only. Preserve it through shared `DiscoveredDevice`, server screening/remembering/listing and dashboard client types. It is never an identity, routing address or authority. For target `Back-office PC.local.` and queue names `Kitchen A4` / `Reception A4`, display exactly `Kitchen A4 (Back-office PC)` / `Reception A4 (Back-office PC)`. When no server name was announced, use the actual routing host as the explicit fallback; do not guess a friendly name, humanize hyphens or substitute the observing agent. Preserve existing single-queue raw labels and entered/saved printer names. The physical check records what the real server advertises; unavailable friendly-name metadata remains a physical qualification limit rather than a claim that this code obtains it.
