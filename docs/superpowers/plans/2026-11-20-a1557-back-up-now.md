# A1557 Back up now implementation plan

> Implement inline with test-driven development after Claude's review and watcher clearance.

A manager can press **Back up now** on the primary box's **Backups** screen once scheduled backups are on. The status card shows that the backup is running and then says whether all, some or none of its saved archive destinations stored a copy. The bucket copy remains on its own controls. The owner asked “i don't see the option to backup now” on 20 November during the A1549 rehearsal, recorded in Lane D's queue under A1557.

## Run the same backup

- [ ] In `apps/server/src/backup-supervisor.test.ts`, hold a real backup at its destination and prove a manual run and a scheduled run cannot overlap in either order. Prove reload stops and drains a manual run before closing its handles, and prove a mixed attempt reports which destinations stored a copy. Use the existing local and Cloud target fixtures. Run `pnpm --filter @waitron/server exec vitest run src/backup-supervisor.test.ts` for the failing cases and again after the change.
- [ ] In `backup-sweep.ts`, expose an immediate run from the schedule's existing dependencies and collect that run's `DestinationResult` values alongside the existing callbacks. Both calls still use `runOnce`, including the existing space checks, retention and cleanup. In `backup-supervisor.ts`, make the existing in-flight promise cover both paths through the end of Cloud delivery. `runNow()` uses the loaded settings, checks the live role and refuses when off, reloading or busy. A due scheduled pass retries through the existing retry timing if a manual run is under way. An interrupted run answers with `backup.destination_cancelled`. A manual run leaves the saved schedule and its next deadline alone.
- [ ] In `backup-api.route.test.ts`, prove a bodyless `POST /api/backup/run-now` requires `system.manage` on the primary and returns the current attempt's destination results, with a 409 refusal while busy or off. Run `pnpm --filter @waitron/server exec vitest run src/backup-api.route.test.ts` before and after wiring the route in `backup-api.ts`. Reuse its authorization and response boundary, and finish the authorization transaction before running the backup. Register `backup.run_in_progress` and `backup.not_enabled` in the server's `errors.ts`. Hold the response until this attempt settles. A1418 can reuse the same supervisor method for its later stop workflow.

## Show it on Backups

- [ ] In `apps/dashboard/src/screens/backup-screen.test.ts`, prove that an authorised manager with backups on can press once, sees the running message while the response is held, and sees a partial result when a destination fails. Check the off or unauthorised button state and a busy refusal. Run `pnpm --filter @waitron/dashboard exec vitest run src/screens/backup-screen.test.ts` before and after the change.
- [ ] Add `runBackupNow()` to `apps/dashboard/src/api/client.ts` and use the existing secondary button and status region in `backup-screen.ts`. Keep the action message through passive status refreshes and use the existing destination rows for details. Add EN/ES action and result text in `i18n/strings.ts` and refusal text in `i18n/codes.ts`, with their existing checks. Update both `apps/server/src/guide/{en,es}/backup-recovery.md` files and the A1418 backlog pointer. Look at the card in both languages and themes at phone and desktop widths.

One PR, roughly 140–200 added production lines and 120–180 added test lines. Leave backup settings, key handling, download and restore, and A1418's stop workflow outside this slice.
