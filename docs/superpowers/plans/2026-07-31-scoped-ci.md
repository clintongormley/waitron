# Scoped CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop running every check on every push — a Markdown-only change should cost seconds, not
7m20s — while keeping a full unfiltered suite on `main`.

**Architecture:** One always-running aggregate job (`ci`) becomes the sole required status check, so
job ids stop being a branch-protection interface. A `changes` job classifies the diff and every
other job gates on its output. Test work splits into two shards on separate runners, scoped on pull
requests by pnpm's own dependency walk and unfiltered on `main`.

**Tech Stack:** GitHub Actions, pnpm 9.15.0 workspaces, Vitest 3, Node 26 (`.nvmrc`).

**Design:** [2026-07-31-scoped-ci-design.md](../specs/2026-07-31-scoped-ci-design.md). Read §2
(required checks) and §3.5 (filter semantics) before starting.

> **Dated pointer, 2026-08-01 — paths below are historical.** The classifier this plan creates at
> `.github/scripts/changed-scope.mjs` now lives at `scripts/changed-scope.mjs`: the two script
> directories were merged into one, and the root `vitest.config.ts` and `eslint.config.js` snippets
> quoted here changed with them. This document records what was built at the time; read the tree for
> what is there now.

## Global Constraints

- **Every commit needs `git commit -s`.** CI's `dco` job walks the whole pull-request range.
- **Two pull requests, in order.** PR 1 (Tasks 1-3) adds the gate only. A repo admin then edits the
  ruleset. PR 2 (Tasks 4-10) does everything else. Renaming `test` inside PR 1 would block on a
  required check that can no longer report.
- **The scoping filter cannot be verified in a `git worktree`** — it reports `No projects matched`
  whatever you edit (design §3.5, measured). Verify in a clone or on a real pull request.
- **Coverage thresholds** are `statements 98 / lines 98 / functions 98 / branches 95` everywhere
  except `packages/ui`. The new root project uses the standard numbers.
- **`.mjs`, not `.ts`, for standalone scripts.** Established by `apps/server/scripts/
  copy-migrations.mjs` and `packages/provisioning/scripts/copy-migrations.mjs`, which have their own
  `eslint.config.js` block granting the `process` global (line ~246). A `.mjs` script runs under
  `node` in a workflow step with no build.
- **Do not rewrite old plans under `docs/superpowers/plans/`.** They record what was true when
  written (`CLAUDE.md` §6). Only `CLAUDE.md`, `docs/backlog.md` and `.husky/pre-push` get updated.
- **Ruleset id is `19899160`** (`main protection`), currently requiring `static-analysis`,
  `typecheck`, `test`, `mutation-verifactu`, `mutation-shared`, `LICENSE is unmodified Elastic
  License 2.0`, `Every commit is signed off`, with `strict_required_status_checks_policy: true`.

- [ ] **Step 1: Append the job to `.github/workflows/ci.yml`**

Add at the end of the file, at the same indentation as the other jobs:

```yaml
  # The single required status check. Everything above is wired into it, so job ids above this
  # point are free to be added, renamed, sharded or conditionally skipped without touching branch
  # protection — which is what makes the scoping in
  # docs/superpowers/specs/2026-07-31-scoped-ci-design.md possible at all. Before this job, each id
  # was required by name (ruleset 19899160), so any rename silently broke the ruleset and any
  # skipped job left a pull request waiting for a status that would never report.
  #
  # `if: always()` is what makes it report at all when something upstream is skipped: without it,
  # GitHub skips a job whose `needs` were skipped, and a skipped required check never satisfies
  # branch protection.
  ci:
    if: always()
    needs:
      - static-analysis
      - typecheck
      - test
      - mutation-verifactu
      - mutation-shared
    runs-on: ubuntu-latest
    steps:
      # `skipped` must PASS: scoping works by skipping, and a skipped job means "this change could
      # not affect that check", not "that check did not run". `cancelled` must FAIL: ci.yml sets
      # cancel-in-progress, and a superseded run reporting green would let a stale result satisfy
      # branch protection. Getting that pair backwards turns this job into a rubber stamp, which is
      # why Task 3 verifies both directions against the real workflow rather than reasoning about
      # them.
      - name: Fail if any needed job did not succeed
        if: >-
          contains(needs.*.result, 'failure') ||
          contains(needs.*.result, 'cancelled')
        run: |
          echo "A required job did not succeed:"
          echo '${{ toJSON(needs) }}'
          exit 1
```

- [ ] **Step 6: Write the classifier**

Create `.github/scripts/changed-scope.mjs`:

```javascript
// Decides whether a change can affect anything but prose, so CI can skip the expensive jobs when it
// cannot. Design: docs/superpowers/specs/2026-07-31-scoped-ci-design.md §3.4.
//
// The rule is an ALLOWLIST OF PATHS, never a file extension. A `**/*.md` rule looks equivalent and
// is not: packages/verifactu/schemas/README.md holds the SHA-256 of every AEAT schema file, and
// packages/verifactu/src/schemas.test.ts:40-48 asserts they match — a test whose stated purpose is
// catching someone editing a primary source to make a test pass. Extension-matching would let
// exactly that edit skip exactly that test.

/**
 * True when a change to `path` cannot affect any test, build or type-check result.
 *
 * Inert means: anywhere under `docs/`, or a Markdown file at the repository root. Everything else —
 * including Markdown inside a package — is code.
 */
export function isInertPath(path) {
  if (path.startsWith("docs/")) return true;
  // No slash means repository root. CLAUDE.md, README.md, CONTRIBUTING.md.
  if (path.endsWith(".md") && !path.includes("/")) return true;
  return false;
}

/**
 * Classifies a list of changed paths.
 *
 * Fails closed: an empty list means the diff could not be worked out (a force-push, a new branch,
 * an all-zero `github.event.before`), which is a reason to run everything rather than nothing.
 */
export function classify(paths) {
  const meaningful = paths.map((p) => p.trim()).filter((p) => p.length > 0);

  if (meaningful.length === 0) {
    return { code: true, reason: "no changed paths could be determined — running everything" };
  }

  const firstCodePath = meaningful.find((p) => !isInertPath(p));

  return firstCodePath === undefined
    ? { code: false, reason: `all ${meaningful.length} changed path(s) are documentation` }
    : { code: true, reason: `${firstCodePath} is not documentation` };
}

/** The package the heavy shard exists for: 189s of the old 387s test step, on its own runner. */
export const HEAVY_PACKAGE = "@waitron/db";

/**
 * True when the heavy shard has work to do, given the JSON output of
 * `pnpm --filter "<scope>" ls --depth -1 --json`.
 *
 * Membership of the RESOLVED SCOPE is the only formulation that is right in all three cases, and
 * the two obvious alternatives are both wrong — measured, see the design spec §3.6:
 *
 *   - a second inclusion filter (`--filter "<scope>" --filter "@waitron/db"`) is OR-ed, not
 *     intersected, so it runs the 189s suite on every code change whether or not db is involved;
 *   - `@waitron/db[<base>]` intersects with the CHANGED set rather than changed-plus-dependents,
 *     so it selects NOTHING when one of db's own dependencies changed — a false skip, which is the
 *     dangerous direction.
 *
 * Fails closed on unparseable input: running a shard that was not needed costs 189s, while skipping
 * one that was needed ships an untested packages/db.
 */
export function needsHeavyShard(scopedPackagesJson) {
  const raw = scopedPackagesJson.trim();
  if (raw === "") return false;

  let packages;
  try {
    packages = JSON.parse(raw);
  } catch {
    return true;
  }

  return packages.some((pkg) => pkg.name === HEAVY_PACKAGE);
}
```

Insert as the **first** job under `jobs:`:

```yaml
  # Works out what the rest of the workflow needs to do. Everything below gates on its outputs.
  #
  # Two independent decisions, deliberately not merged into one (design §3.2):
  #   `code`  — is there anything here that is not prose? If not, only `lint` runs, on pull requests
  #             AND on main, so a documentation merge costs nothing in either place.
  #   `scope` — on a pull request, narrow the test shards to the packages that changed and the
  #             packages that depend on them. On main, run everything, because that unfiltered run
  #             is what verifies the narrowing was right.
  changes:
    runs-on: ubuntu-latest
    outputs:
      code: ${{ steps.classify.outputs.code }}
      scope: ${{ steps.classify.outputs.scope }}
      heavy: ${{ steps.heavy.outputs.heavy }}
    steps:
      # fetch-depth: 0 is load-bearing. The default is 1, which leaves no merge base to diff
      # against and no history for pnpm's own change detection — both would then silently report
      # "nothing changed" and skip the entire suite.
      - uses: actions/checkout@v5
        with:
          fetch-depth: 0

      # Needed for the `pnpm ls` membership query below. No `pnpm install` is required — `pnpm ls
      # --filter` resolves from the workspace manifests alone (verified in a clone with no
      # node_modules present).
      - uses: pnpm/action-setup@v6
        with:
          version: 9.15.0

      - uses: actions/setup-node@v5
        with:
          node-version-file: ".nvmrc"
          cache: pnpm

      - id: classify
        env:
          BASE_REF: ${{ github.base_ref }}
          BEFORE: ${{ github.event.before }}
          SHA: ${{ github.sha }}
        run: |
          set -euo pipefail

          if [ "${{ github.event_name }}" = "pull_request" ]; then
            git fetch --no-tags origin "$BASE_REF"
            paths=$(git diff --name-only "origin/$BASE_REF...HEAD")
            # Changed packages AND THEIR DEPENDENTS. The ellipsis goes on the LEFT — `[ref]...`
            # is the other direction (a package and its dependencies) and would test the wrong set.
            scope="...[origin/$BASE_REF]"
          else
            case "$BEFORE" in
              # An all-zero `before` means a new branch or a force-push: no usable base, so no diff.
              # Emit nothing and let the classifier fail closed to a full run.
              *[!0]*) paths=$(git diff --name-only "$BEFORE" "$SHA") ;;
              *) echo "no usable base ref ($BEFORE) — running everything" >&2; paths="" ;;
            esac
            # main always runs the full suite: it is what verifies the pull request's narrowing.
            scope=""
          fi

          printf '%s\n' "$paths" | node .github/scripts/changed-scope.mjs >> "$GITHUB_OUTPUT"
          echo "scope=$scope" >> "$GITHUB_OUTPUT"

      # itself — see needsHeavyShard's own comment for the two wrong formulations and why each
      # fails. An unscoped run (main) always needs it.

        env:

        run: |
          set -euo pipefail
          if [ -z "$SCOPE" ]; then
            echo "heavy=true" >> "$GITHUB_OUTPUT"

            pnpm --filter "$SCOPE" ls --depth -1 --json 2>/dev/null \
              | node .github/scripts/changed-scope.mjs heavy >> "$GITHUB_OUTPUT"
```
