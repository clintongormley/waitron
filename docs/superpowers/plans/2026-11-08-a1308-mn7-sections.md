> `subagent_type: "implementer"`.

**Goal:** A menu's staff name lives only in `menus.name` (the root section stores none); an
include's fixed name, photo and colour leave the JSON column `section_members.folder_overrides` for
columns of their own, so the photo is a plain column the four media triggers and an ordinary index
read; and `sections.image` gets the index the 6 November review asked for.

**Architecture:** `sections.internal_name` becomes null on the root, held by a CHECK. Every read of a
section's name takes `coalesce(sections.internal_name, menus.name)` through a join on
`owner_menu_id`, so the shapes the API, the menu document and the media usage list return do not
change. The include folder keeps its in-memory shape (`IncludeFolderOverrides`, absent = follow the
included menu, `null` = fixed "none"); two small functions map it to and from five columns.

**Tech Stack:** TypeScript, drizzle on `node:sqlite`, Vitest, slice 1a's rebuild command and trigger
file (`packages/db/triggers/core.sql`).

**Spec:** [design README](../specs/2026-11-02-rationalisation/README.md) §3 R4, R6, "Additions of 6
November 2026" (`sections` index); [tables-menu.md](../specs/2026-11-02-rationalisation/tables-menu.md)
§1.14 (root-name CHECK), §1.15, §5 (`section_members`, `sections` rows), §6 (a menu's staff name);
[slice rules](2026-11-08-a1308-slice-rules.md).

## Decisions this plan makes

- **D1. Two flags keep "fixed: no photo" and "fixed: no colour".** tables-menu.md §1.15 lists
  `folder_image` and `folder_color` as plain nullable text. But the include's override has three
  states: a key absent follows the included menu, a key holding `null` fixes "show none", and a value
  fixes that value (`packages/shared/src/menu-document/section-types.ts:27-33`;
  `include-folder-presentation.ts:20-21`, `image === undefined ? own.image : image`;
  `include-folder.ts:69-70` keeps an explicit `null`). One nullable column cannot hold three states,
  so each gets a flag. README §11 leaves "the exact column lists, within each appendix's §1" to the
  builder; this is that choice, raised as an open question for the watcher with the alternative
  (an empty-string sentinel, which the photo triggers and colour checks would then have to special-case).
- **D2. Section names keep their shape on the wire.** The root's name is read through
  `SECTION_NAME`, so the menu document (`MenuDocument.sections[].internalName`), the structure tree
  and the media usage list still carry the menu's name for a root. No client changes.
