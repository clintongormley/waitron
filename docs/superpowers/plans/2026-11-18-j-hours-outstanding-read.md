# Narrow the Hours read for open and outstanding work

When staff open a week, month or pay period in Hours, they can still see open shifts, pending corrections and unconfirmed automatic clock-outs from outside that period. Hours should fetch fewer clock rows wherever it can preserve that answer. The [backlog entry](../../backlog/workforce.md#hours-open-and-outstanding-work) records what [#3706](https://github.com/clintongormley/waitron/pull/3706) left open. The change covers both the personal and manager views through `personInWindow`.

The prior PR measured 752 clock rows for this fixture. Record the measured count with the same `StatementSync.all` observer before and after. This measures rows returned to the application. In `hours-reads.test.ts`, use the existing read fixtures to pin an old open shift on break, outstanding question and correction history outside the chosen period, and ordinary old settled history staying out. Keep the existing worked-minute and frozen snapshot checks.

That event sets the open-shift state regardless of earlier entries. Read from the start of history if all such boundaries have been retimed. Keep the same-person constraint and existing ordering for equal times. Seed the other work from automatic clock-outs still eligible for a worker confirmation, directed correction requests, and the day, explicit entries and linked answer entries of active canonical questions. Keep each candidate's full family so existing code decides whether it is still outstanding. Extend the existing family read only where the new caller needs it.
