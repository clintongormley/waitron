# Narrow the Hours read for open and outstanding work

Staff can switch to any week, month or pay period in Hours and still see older open shifts, pending corrections and unconfirmed automatic clock-outs. The [backlog](../../backlog/workforce.md#hours-open-and-outstanding-work) covers the Hours read shared by the personal and manager views. [PR #3706](https://github.com/clintongormley/waitron/pull/3706) measured 752 clock rows and 5.611 ms median for one person's year fixture after its period change.

1. In `packages/workforce/src/record-read-budget.test.ts`, reuse the year fixture and pin the same 3,420 minutes with at most 80 clock rows for ordinary Hours. Watch it fail before editing product code. Measure rows with the existing observer and elapsed medians before and after, including a manager read across several people. Add a year case with later settled shifts, old outstanding work and settled corrections and automatic outs. Put the pending request far enough before the latest clock-out to distinguish the narrower read from either the latest-event cut or a full read.
2. In `record-reads.ts`, reuse the same-person correction and response family lookup from `readPeriodEntries`. For current shift state, seed the latest direct clock-in or clock-out with no approved replacement and include the whole instant and later events. Keep the existing event ordering. Add candidates for automatic clock-outs lacking a same-person worker confirmation, directed requests with no decision or a dispute, and the paired or question-linked requests their existing grouping needs. Share question and answer reads in `attendance-reads.ts`. Include the day and all explicit entry references, including `resolvedByEntryId`, for active canonical questions that can still produce prompts. Skip questions whose persisted resolution and lack of linked commands make them settled under `answerForQuestion`. Leave the final decisions to the existing projections, and check the emitted SQL and query plan on `node:26-slim`. The measurement of rows returned does not count rows visited inside SQLite.
3. In `hours-reads.ts` and `corrections.ts`, preserve the existing readiness rule for unanswered corrections. Extend the read back to an unchanged direct clock-out strictly before the earliest affected instant, including targets and replacements. The clock-out clears the state used by `scanSequence`. Compare the two sequences after it. If a fault-free changed suffix loses a previously completed start, run the existing full readiness check, because a fault in the unchanged prefix can still affect the result. Use the natural start when there is no earlier boundary. Keep the period and closure read and the merge of extra entries unchanged.
4. In `hours-reads.test.ts`, check old questions, disputed and pending work, a worker-confirmed automatic end, an open shift on break and a pending retime blocked by another shift. Exercise a pre-boundary fault that distinguishes the exact readiness result. Compare the measured case's full Hours response on both versions. Check that incomplete attribution on an unrelated old row stays outside Hours, while an included row still receives the existing refusal. Run `pnpm --filter @waitron/workforce exec vitest run src/hours-reads.test.ts src/attendance-reads.test.ts src/record-reads.test.ts src/record-read-budget.test.ts`. Remove the item from `docs/backlog.md` and `docs/backlog/workforce.md` after the row and behaviour checks pass.

Estimate 220–330 production lines and 150–250 test lines. The separate inbox and revision reads, schema, write paths and public response shape stay outside this change.
