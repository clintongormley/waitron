## Once it lands
Nothing a person sees changes. The server, asking as itself (the setup page) or for a signed-in person
it has checked holds `system.manage`, can ask the box's host to mount the plugged-in USB drives
read-only, and later to release them. The host only mounts and releases: it answers which drives it
found, never files. The container sees the drives read-only at `/run/waitron-drives`.

**For 4d:** the SERVER lists the backup files. It walks `/run/waitron-drives` as user 10001, three
folders deep, skipping hidden and system folders and never following a link, keeps names
`parseBackupArchiveKey` accepts (`apps/server/src/backup-keys.ts:32-48`) and sorts them newest first
by that stamp, never by file time. So there is no second copy of the name check on the host (the
old U6, which files, moves to 4d whole).

## Decisions
- **U1 Which drives.** Disks whose lsblk transport is `usb`. A disk is skipped whole if it holds a file
  system mounted outside the drive folder or has an encrypted, LVM or RAID child (the box's own disk).
  Inside a USB disk, each partition (or the bare disk, if it has a file system and no partitions) is
  taken on its own: no file system, skipped; `vfat`, `exfat` or `ntfs`, mounted; any other, reported
  `fileSystem: "other", readable: false`, so 4e can say why. `lsblk` is util-linux, which every Debian
  has; the installer stick's script already reads `lsblk --json` (`deploy/box/install-dev.sh:9`).
  *Alt:* `RM=1`, which misses USB disks that report "not removable".
- **U2 Mount folder.** `/run/waitron-drives/<kernel name, e.g. sdb1>`, same path in the container. `/run`
  is wiped at reboot. Outside the state folder, so the layout guard does not care. *Alt:* `/media/waitron`.
- **U3 Container wiring.** The one-variable form above. The image's `.env` (`deploy/box/build.sh:99`)
  sets it; declared in `environment-variables.ts` beside `WAITRON_BOX_SOCKET_DIR` (`:103`) with kind
  `text` (it is a whole mount line, not a path); a commented line in `deploy/.env.example`. *Alt:* a
  second compose file on the box only, refused by the checked upgrade, which requires the one installed
  compose file (`scripts/box/upgrades/host.mjs:219-223`).
- **U4 Looking again.** A drive is the same drive when its kernel name, device number AND file-system
  id are unchanged: its mount is kept. Anything else under that name is unmounted and mounted again;
  pulled drives are unmounted. *Alt:* remount everything each time, which would pull a file out from
  under 4d's read.
- **U5 How long a mount stays.** Until `storage.release`, the next list finding it gone, or a reboot.
- **U7 Reply size.** Replies are at most 4,096 bytes (`scripts/box/host-protocol.mjs:31-33`). A list
  names at most 16 drives (the first 16 by kernel name), each name matching `sd[a-z]{1,3}[0-9]{0,3}`; a
  test formats the largest reply this allows and checks it fits in 4,096 bytes.
- **U8 Answers.** `storage.list` → `{ok, drives:[{drive, fileSystem, readable}]}`, `fileSystem` one of
  `vfat`, `exfat`, `ntfs`, `other`. `storage.release` → `{ok, released}`. The only refusal of each is
  `busy`, from a lock like `tag.lock` (`deploy/box/waitron-box.sh:316-322`).
- **U9 Who may ask.** A person (server checked `system.manage`) or the server, as `network.read`
  (`host-protocol.mjs:59-67`). The host checks no permission: it logs verb, actor and permission
  before acting, as `scripts/box/network-host.mjs:37` does. The real check is 4d's route.
- **U10 Client in 4c.** `storageList`/`storageRelease` join `BoxHostRequests` (`box-host-client.ts:401-421`).
  Nothing forces it: the types test lists each request by hand (`box-host-client.types.test.ts:146-167`).
  It goes in 4c so the reply shape and its parser are reviewed together, and 4d adds only routes. Cost:
  the five host stand-ins (`boot.box-host`, `boot.management-origin`, `box-host-api`,
  `box-host-api.calls`, `box-host-api.join` tests).
- **U11 Hand-set-up boxes (new; watcher decides).** Host modules reach a box only from the image
  (`build.sh:58-61`). `waitron.sh install` and every checked upgrade refresh `waitron.sh` and
  `box/upgrades/*.mjs` (`deploy/waitron.sh:1031-1046`, `:1076-1083`) and, through
  `install_box_service` (`:419-455`, called at `:1188` and `:1331`), `waitron-box.sh` and its units, but
  never `/opt/waitron-host/box/*.mjs`. Reviewer's measurement on the spare (I could not repeat it: ssh
  refused my key): set up with `waitron.sh install`; `/opt/waitron-host/box/` holds only `upgrades/`.
  So it has no host modules, and an image box upgraded past 4c gets the new `waitron-box.sh` without
  `storage-host.mjs`. **Without A or B, 4e removes restore-from-file on the owner's own boxes.**
  - **A (recommended).** `install_box_service` also fetches the `build.sh:58` modules, plus
    `storage-host.mjs` and `upgrades/contracts.mjs`, into `/opt/waitron-host/box/`, and sets
    `WAITRON_BOX_DRIVES_MOUNT` once the socket has started (as `:450` does for the socket). One place
    covers first installs and checked upgrades, and keeps image boxes' modules level with their
    `waitron-box.sh`. Cost: about 25 lines in `waitron.sh` and a test. `host-protocol.mjs` imports
    `name-tag`, `upgrades/contracts`, `wifi-boot-copy` (which imports `disk-key`) and `wifi-record`,
    all in that set. `waitron-box.sh:320` runs a bare `node`, and no install step puts one on PATH (grep
    of `deploy/` and `scripts/box/` finds none), so storage requests run on the retained runtime
    `/opt/waitron-host/node-v26.7.0/bin/node` (`bootstrap.sh`, run by `build.sh:54` and `waitron.sh:1156`)
    and answer `unknown_request` without it. **Open:** copying the whole set also turns on Wi-Fi and
    `tag.write` on hand-set-up boxes; `name-tag-host.mjs` writes tokens into a LUKS header with
    `cryptsetup`, and what it does on a hand-installed disk is unchecked. Narrower A: copy only
    `storage-host.mjs` and its imports, which leaves image boxes with mixed module versions.
  - **B.** 4e keeps the browser upload when the host answers "unsupported".
- **U12 Mount options.** `mount -t vfat|exfat|ntfs3 -o ro,nosuid,nodev,noexec,noatime,nosymfollow,fmask=0133,dmask=0022`.
  The type is always named. Files must be readable by user 10001 (`deploy/Dockerfile:230-231,338`).
- **U13 Release.** `umount`, then a lazy unmount if busy.
- **U14 Real stick, before landing.** The owner plugs one into the spare; the lane runs the module there
  and pastes the reply into the PR.
- **U15 Time limits.** The request service is killed after 15 s (`RuntimeMaxSec=15`,
  `waitron-box@.service`); the client waits 5 s for reads, 20 s for changes (`box-host-client.ts:423-425`).
  `storageList` uses the 20 s wait. One 12 s deadline covers the whole request, as `tagCommand`'s does
  (`name-tag-host.mjs:11-23`); each mount gets its own limit within it; a drive that runs out of time,
  or is reached after the deadline, is `readable: false`.
