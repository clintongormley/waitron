**Goal:** independent Demo/dev device proofs and sign-ins, preserving appliance cookies.
**Spec:** [A271](../specs/2026-11-17-a271-tab-device.md).
**Approach:** existing join/device hashes and till-session hashes; no schema changes.

## 1. Transport and issuing credentials

- [ ] In `apps/server/src/device-session.test.ts`, add “tab proof never borrows a valid cookie”.
  Cover correct, absent, malformed, wrong and revoked proofs beside another device's valid cookie.
  In `device-api.test.ts`, cover pending/approved join polling and disabled-device rejoin using the
  tab proof; cookie responses remain unchanged. Observe the expected assertion failures first.
- [ ] In `device-session.ts`, add `readDeviceCredential(c: Context): string | null`, selecting
  `x-waitron-device` in tab mode; reuse parsing, hash validation and transaction rechecks.
  Any tab/proof header suppresses both cookie readers and dev-id override; only marker `1` is valid.
  In `device-api.ts`, use that reader for rejoin/status; tab join returns existing fields plus
  `deviceProof: string`, sets `Cache-Control: no-store`, and writes no cookie.
- [ ] Add dev-only `POST /api/dev/devices/:id/adopt` returning `{deviceProof}`. Use the existing
  32-byte random secret/hash pattern; atomically replace an active device's hash and call
  `endDeviceSessions`. Test non-dev refusal and old-proof rejection. Retain existing dev-only
  bare-id compatibility, but stop emitting it from this client. Pass the named tests.

## 2. Per-tab sign-in

- [ ] Extend `apps/server/src/till-api.session-person.test.ts` and `till-api.test.ts` with
  A/B session isolation, mixed-device proofs, sign-out and retained wrong-person refusals.
  Watch failure, then update `till-session.ts`'s `readSessionToken(c)` for `x-waitron-session`.
  Require matching device proof on every tab session read, including reads without an action;
  retain `signedInPersonOn` and `x-waitron-person` checks. Bind tab sign-out to its proven device.
  In `till-api.ts`, tab login adds `sessionToken` to JSON, no cookie, no-store.
- [ ] Update `own-page.ts` and `cors.ts` for all three headers; extend their sibling tests to prove
  trusted-origin acceptance and foreign-origin refusal without cookies. Check captured logs/diagnostics
  exclude proof headers and response secrets. Pass these tests.

  Test reload, storage failure blocking with Retry, sign-out and header preservation before implementation.
